# Tentex — требования к системе

> Полный продуктовый замысел и backlog, а не жёсткий текущий контракт.
> Редакция 7 от 22.08.2026. Приоритеты уточняются по реальной разработке и эксплуатации.
> Человеческое описание проекта — в BRIEF.md.

Фактическое состояние находится в `STATUS.md`, порядок реализации — в `PLAN.md`,
реализованное поведение — в `docs/architecture/`, интерфейс — в `SCREENS.md`.
При конфликте эти источники приоритетнее. Ни одна функция ниже не считается отменённой:
часть реализована, часть запланирована, Студия, бот и внешний поиск отложены в конец.

| **Лицензия** | MIT |

### Правило разрешения конфликтов

Курсовая с защитой первична. Критерий «пригодно для ежедневного использования» применяется **только к сквозному сценарию** «загрузил материал → получил программу → вижу покрытие в обе стороны → занимаюсь по темам». Всё остальное делается по критерию «достаточно для демонстрации на защите».

При выборе между простым и мощным решением выбирается простое, если оно не ломает сквозной сценарий.

### Глоссарий

| Термин | Значение |
|---|---|
| **Тема** | Центральный объект системы. То, что нужно освоить. Может быть экзаменационным билетом, главой учебника или личной целью «разобраться, как работают индексы» |
| **Программа** | Дерево узлов проекта до 4 уровней вложенности. Узел имеет тип: `раздел`, `тема`, `подпункт` |
| **Паспорт цели** | Ответы пользователя о том, зачем он берёт материал и что хочет получить. Вход для всех алгоритмов |
| **Фрагмент** | Кусок материала со ссылкой на файл, страницу и координаты |
| **Блок** | Структурная единица материала: заголовок вместе с подчинёнными ему фрагментами. Единица классификации при соотнесении |
| **Привязка** | Связь «тема ↔ фрагмент» |
| **Среда темы** | Рабочее пространство одной темы: материал, карточки, конспект, история |
| **Рабочая область проекта** | Ежедневная поверхность с деревом программы и Средой выбранной темы; имеет компактную экзаменационную и развёрнутую учебную конфигурации |
| **Урок** | Редактируемый сценарий изучения одной или нескольких тем: объяснения, источники, медиа, интерактивные блоки и активности |
| **Учебный артефакт** | Сохранённый результат навыка: карточка внешнего источника, иллюстрация, интерактивный блок или черновик Урока |
| **Студия** | Постоянная правая панель Рабочей области для создания и просмотра производных учебных материалов по выбранным Темам и источникам |
| **Студийный артефакт** | Версионируемый результат Студии с типом, настройками, запросом, происхождением, цитатами и состоянием генерации |
| **Кандидат источника** | Найденная во внешнем поиске публикация. Не считается Материалом и не влияет на покрытие до явного добавления в проект |
| **Активность** | Единица работы над темой (чтение, ответ, карточка, SQL...) |
| **Попытка** | Факт выполнения активности |
| **Сила свидетельства** | Вес активности как доказательства того, что тема освоена: 0, 1, 2 или 3 |
| **Проход 1** | Построение программы из материала: map-reduce по главам |
| **Проход 2** | Соотнесение: полный перебор структурных блоков материала |
| **Агент свободного вопроса** | Модель, пишущая код против API проекта для ответа на произвольный вопрос по всему материалу |

## 1. Ключевые принципы

Инварианты. Если решение нарушает один из них — неверно решение, а не принцип.

**П1. Программа первична, документ вторичен.**
Центральный объект — список тем, которые нужно освоить. Материалы существуют как доказательная база под эти темы. Проект может существовать с программой и нулём материалов — это штатное состояние, а не ошибка.

**П2. Знания не извлекаются — они привязываются.**
Система не строит независимую базу фактов. Она хранит привязки «тема ↔ фрагмент источника (файл + страница + координаты)». Любая производная сущность, основанная на материале (карточка, эталонный ответ, задача, блок Урока), сохраняет ссылку на фрагмент-источник и помечается при его исчезновении; внешнее или модельное происхождение хранится отдельно и не маскируется под материал проекта.

**П3. ИИ действует открыто и обратимо.**
Всё, что породила модель, помечено как машинное, несёт свой источник, отменяется одним движением и хранит историю. Модель применяет изменения сама там, где однозначна, и спрашивает там, где нет. Пользователь никогда не обнаруживает изменение, о происхождении которого не может узнать.

**П4. Детерминированное ядро не зависит от внешних моделей.**
Без интернета и без внешних моделей работают: разбор файлов и OCR, программа по оглавлению и импортом, полнотекстовый и векторный поиск, ручная привязка, чтение, конспект, карточки, тесты, пропуски, свободный ответ с проверкой по терминам, SQL-задачи, повторения по SM-2, план, карта покрытия, статистика.

**Явные исключения, требующие внешних моделей:** построение программы из материала (проход 1), соотнесение материала с темами (проход 2), свободный вопрос, ИИ-судья, генерация активностей, программа из знаний модели (слой 4), распознавание речи, автозаполнение паспорта цели.

Базовый путь входа A с известным списком и готовыми ответами не требует внешних моделей. Необязательные модельные функции и построение предварительной программы, когда официального списка ещё нет, включаются отдельно.

**П5. Пользователь выбирает свой процесс.**
Карточки, повторения, устные ответы, SQL — модули, каждый включается и выключается. Кто-то хочет только читать и выписывать в тетрадь — система должна быть полезна и в этом режиме, и не должна за это упрекать.

**П6. Каждое утверждение системы имеет источник.**
Ссылка на страницу, внешнюю публикацию, попытку, дату или слой каталога. Где источника нет — система прямо говорит, что источника нет, вместо того чтобы выдавать уверенное число.

**П7. Данные принадлежат пользователю.**
Локальное хранение, полный экспорт, отсутствие привязки к одному поставщику модели. Внешнему провайдеру уходит только то, что требуется явно включённой функции: показанные пользователю фрагменты извлечённого текста и параметры запроса — модели, аудио устного ответа — сервису распознавания. Исходный файл целиком не отправляется без отдельного действия; состав и объём передачи показываются до запуска.

**П8. Ничто из материала не теряется.**
Покрытие двустороннее: система следит не только за тем, чтобы у каждой темы был материал, но и за тем, чтобы каждый содержательный блок материала был рассмотрен. Нерассмотренного не остаётся по построению (§6.4); неотнесённое показывается пользователю как результат, а не замалчивается.

## 2. Три входа в систему

**FR-E1.** Система поддерживает три способа начать работу. Они различаются не настройками, а тем, какие механизмы запускаются.

| Вход | Что есть у пользователя | Откуда программа | Какие проходы работают |
|---|---|---|---|
| **A. Экзамен** | Отдельные вопросы, вопросы и задачи либо готовые билеты; готовые ответы и учебные материалы необязательны. Если точного списка пока нет — только материалы | При известном списке программа = импортированная структура. Без списка строится предварительная программа, которую позже можно сопоставить с официальной | Для известного списка проходы не нужны. Для предварительной структуры доступны оглавление или проход 1; после её подтверждения — проход 2 |
| **B. Учебник** | Один или несколько учебников, методичек, курсов, конспектов или статей + собственная цель, готовой программы нет | Строится по всем выбранным источникам под паспорт цели (проход 1), но не копирует оглавление целиком | Оба прохода |
| **C. Цель** | Только формулировка цели | Из каталога или знаний модели (слой 4) с меткой «источника нет» | Проход 2 — по мере добавления материалов |

**FR-E2.** Входы соответствуют трём шаблонам проектов (§3.2), но не жёстко: проект, начатый как C, после загрузки учебника может использовать проход 1.

**FR-E3.** Вход C стартует с нулевым покрытием: программа есть, материалов нет, все темы в «Пробелах» (§6.5). Это корректное состояние, а не ошибка. По мере добавления материалов пробелы закрываются.

**FR-E4.** Система ищет внешние источники только по явному запросу пользователя. Найденный результат считается кандидатом и не входит в Материалы, Программу или покрытие, пока пользователь явно не выбрал «Добавить в проект». Автоматическое фоновое закрытие Пробелов не выполняется.

**FR-E5.** Вход B отличается от входа C наличием фактической основы: источники задают содержание, а цель пользователя — границы, глубину и порядок программы. Знания модели могут обнаружить обязательную предпосылку, которой нет в материалах, но такая тема получает явную метку «нужно найти материал», а не выдаётся за подтверждённую источником.

**FR-E6.** Для входа B по умолчанию программа строится по всему содержательному материалу. При узкой цели в текущую программу входят сама цель, необходимые предпосылки и связанные темы; остальное содержание сохраняется как «вне текущей программы» и возвращается одним действием.

**FR-E7.** Экзамен без официального списка остаётся входом A из-за внешней обязательной программы и дедлайна. Предварительная структура из материалов не выдаётся за официальный список; после его появления система предлагает сопоставление и диф, не удаляя накопленную работу.

## 3. Проекты

### 3.1. Проект как пространство обучения

**FR-P1.** Система поддерживает произвольное число независимых проектов. Проект = предмет, курс, экзамен, тема или книга. Содержимое проектов изолировано: своя программа, привязки, настройки, статистика.

**FR-P2.** Проект имеет: название, описание, иконку/цвет, необязательную дату дедлайна, статус (`черновик` / `активный` / `в архиве` / `завершён`), паспорт цели (§5.1), набор включённых модулей (§13).

**FR-P3.** Карточка проекта остаётся короткой: знак, название и действия «Продолжить изучение» / «Повторить». Сводные показатели активных проектов — покрытие программы, пройдено/подтверждено (§11.3), дедлайн, долг и дата последнего занятия — доступны в общей панели и внутри проекта. Отключённые метрики не показываются и не заменяются нулями.

**FR-P4.** Проекты можно архивировать и восстанавливать. Архивный проект не участвует в повторениях и напоминаниях.

**FR-P5. Разделение общего и проектного.** Файл, Страница, Блок, Фрагмент и векторные представления — **общие** для установки, дедупликация по хешу файла. Роль, приоритет и пояснение к источнику задаются отдельно для каждого проекта. Программа, Привязка, Активность, Попытка, Карточка, Конспект, Повторение — **принадлежат проекту**.

Следствие: один и тот же учебник, добавленный в два проекта, разбирается и OCR-ится один раз. Экспорт проекта включает копии общих файлов, на которые он ссылается.

**FR-P6.** Очередь дня работает внутри проекта. Сквозная очередь между проектами не реализуется (§22).

### 3.2. Шаблоны проектов

**FR-P7.** При создании проекта пользователь выбирает шаблон. Шаблон — **преднастроенный паспорт цели и набор включённых модулей, а не жёсткий класс**: любую настройку можно поменять.

| Шаблон | Вход | Что включено по умолчанию |
|---|---|---|
| **Подготовка к экзамену** | A | Импорт вопросов, задач или билетов; при неизвестном списке — предварительная программа из материалов · свободный и устный ответ · план до даты · повторения · без экрана «Неразобранное» для чистого импорта |
| **Изучение по учебнику** | B | Несколько источников с ролями · оба прохода · чтение · Уроки · карточки · конспект · повторения · оба экрана покрытия |
| **Свободное изучение** | C | Программа из каталога/модели · богатая среда темы · карточки · без плана и дедлайна · мягкие напоминания |

**FR-P8.** Два разных подхода к одному предмету оформляются **двумя проектами**, а не переключением режима внутри одного. Типовой случай: проект «БД — экзамен» с файлом вопросов и ответов, и проект «БД — разбираюсь» с учебником. Решение принято сознательно: переключение режимов внутри проекта усложняет логику без выигрыша.

**FR-P9.** Настройки проекта можно сохранить как пользовательский шаблон.

### 3.3. Мастер создания проекта

**FR-P10.** Все шаблоны начинаются на общем экране «Как вы хотите учиться?», но после выбора получают отдельную ветку. Экзамен с пока неизвестным официальным списком остаётся экзаменационным проектом; проект по учебнику используется, когда внешней обязательной программы нет и маршрут определяется собственной целью пользователя.

**FR-P10.1. Экзаменационная ветка.** Пользователь выбирает одну из четырёх структур: отдельные вопросы; вопросы и задачи; готовые билеты; точного списка пока нет. В первых трёх случаях список или структура билетов обязательны, а готовые ответы и учебные материалы добавляются независимо. В последнем случае обязательны учебные материалы, из которых строится явно предварительная программа.

**FR-P10.2. Экзаменационный паспорт.** Дополнительно сохраняются ожидаемое число вопросов, задач или билетов для проверки импорта и необязательные сведения о требованиях преподавателя. Эти поля помогают плану и модельным подсказкам, но не заменяют распознавание структуры входа.

**FR-P11. Черновик мастера.** После добавления первого источника мастер сохраняет скрытый проект со статусом `черновик`. Он не показывается среди активных проектов, но хранит файлы, паспорт, текущий шаг, частично построенную программу и состояние фоновой задачи. Мастер возобновляется после закрытия вкладки или перезапуска приложения.

**FR-P12.** Ветка учебника проходит последовательность: источники → предложенный профиль → проверка запуска → построение и редактор программы → итоговая сводка. Это один маршрут с сохранением введённых значений при возврате назад.

**FR-P13. Быстрый анализ.** Сразу после добавления источника система без полного прохода читает метаданные, встроенную структуру, оглавление и несколько содержательных фрагментов из разных частей документа. Результат — предполагаемые предмет и тип источника, короткое описание, крупные разделы и предупреждения о качестве; эти сведения используются для автозаполнения паспорта. Первые страницы не считаются достаточными, если на них только титул и выходные данные.

**FR-P14. Проверка запуска.** Пользователь не обязан выбирать технический алгоритм. Система рекомендует построение программы по всем выбранным источникам под текущую цель, а в раскрываемых подробностях показывает локальные и модельные операции, состав отправляемого, время, стоимость и офлайновый резервный путь.

**FR-P15. Построение в мастере.** После запуска пользователь сразу попадает в редактор программы. Этапы и прогресс видны по источникам и главам, готовые разделы появляются постепенно. До первого редактируемого раздела помощник справа показывает состояние и не принимает команды; затем становится доступен для уже готовой части. Задачу можно продолжить в фоне, приостановить, возобновить, повторить после ошибки, принять частичный результат или заменить программой по оглавлению.

**FR-P16. Итоговая сводка.** Перед активацией проекта мастер показывает название и предмет, цель, стартовый и целевой уровень, срок и темп, формат обучения, источники с ролями, состав программы, число тем без материала, включённые модули и операции после создания. Из сводки можно вернуться к источникам, паспорту или программе без потери данных. Пустая программа показывается как допустимое состояние с пояснением, что её можно составить позже в разделе «Программа»; это не блокирует активацию.

**FR-P17.** Кнопка «Создать проект» переводит черновик в активный проект. Для входа B пользователь переходит в тот же редактор «Программа»; если утверждённая программа уже есть, запускается проход 2 и соотнесение продолжается в фоне. Если программа пуста, проект всё равно активируется, а проход 2 не запускается до появления и утверждения дерева, чтобы не пересчитывать привязки после каждой ручной правки.

## 4. Материалы и конвейер обработки

### 4.1. Приём

**FR-M1.** Поддерживаемые форматы: PDF (текстовый и сканированный), DOCX, TXT, MD, изображения (JPG/PNG), вставка текста напрямую, локальное аудио с транскрипцией, добавление по URL веб-страницы и публичного YouTube-видео с субтитрами. Для URL хранится снимок полученного содержимого, исходная ссылка и дата получения; для YouTube Материалом становится транскрипт с временными метками, а не видеопоток.

**FR-M2.** Материал добавляется через веб (drag-and-drop, выбор файла), через бота (пересылка документа/фото/текста) и из инбокса проекта.

**FR-M3.** Ограничения фиксируются явно и показываются до загрузки: до 500 страниц и до 100 МБ на файл. Превышение — понятная ошибка, а не падение.

**FR-M4.** До запуска обработки система показывает **оценку времени и стоимости**: сколько страниц, сколько из них требуют OCR, сколько примерно займёт разбор, сколько вызовов модели потребуют проходы и во сколько это обойдётся. Для облачного режима отдельно показаны провайдер, передаваемый файл или страницы и цена разбора; запуск — только по подтверждению. Оценка стоимости прохода 2 вычисляется точно: число блоков ÷ размер батча × цена вызова.

**FR-M4.1. Роль источника в проекте.** Для каждого добавленного материала пользователь выбирает или принимает предложенную роль:

- **основной** — определяет структуру и содержание программы;
- **дополнительный** — расширяет и уточняет основные источники;
- **справочный** — используется для объяснений и ответов, но по умолчанию не расширяет программу.

Внутри роли источники упорядочиваются по приоритету. К источнику можно добавить свободное пояснение, например «отсюда брать теорию, а из методички — практические примеры». Роль, порядок и пояснение принадлежат связи материала с проектом, а не глобальному файлу.

**FR-M4.2. Режим разбора.** Пользователь выбирает понятный режим, а не отдельную модель. Все режимы приводят результат к одному виду: Markdown страницы, структура и элементы с типом, иерархией, координатами и уверенностью.

| Режим | Исполнитель | Назначение | Доступность |
|---|---|---|---|
| **Быстро** | локальный PP-OCRv5 для русского (CPU) | Обычный текст, фотографии лекций и сканы без отправки данных | этап 5 |
| **Учебник** | локальный PaddleOCR-VL 1.6 (GPU) | Сложная вёрстка, таблицы и печатные учебники | этап 5 при совместимой GPU; иначе честно недоступен |
| **Облако** | Gemini 3 Flash | Дешёвый облачный разбор PDF и документов | заглушка до этапа 7 |
| **Максимум** | Nanonets OCR-3 | Структурированный Markdown, таблицы, иерархия и координаты | заглушка до этапа 7 |
| **Эксперт** | Nanonets OCR-3 → выбранная сильная модель | Повторная проверка сложных элементов после разбора | заглушка до этапа 7 |

Точные версии, аппаратные требования и тарифы фиксируются перед подключением, а не считаются вечной частью формата данных. Наличие режима не включает передачу исходного файла: для облачного режима она всегда подтверждается отдельно.

### 4.2. Конвейер разбора

**FR-M5.** Разбор идёт фоновой задачей в отдельном процессе с постраничным прогрессом и оценкой оставшегося времени. Пользователь может продолжать работать, приостановить задачу и возобновить её.

**FR-M6.** Этапы конвейера:

1. Валидация файла (тип, размер, читаемость, защита паролем)
2. Извлечение структуры документа (для PDF — встроенный outline/закладки)
3. Постраничное извлечение текста; выбранный document parser при необходимости разбирает весь файл или страницу, включая PDF с текстовым слоем
4. **Детекция скана:** если плотность извлечённого текста на странице ниже порога — страница считается изображением
5. Для таких страниц: рендер в растр → предобработка (выравнивание, бинаризация, шумоподавление) → выбранный локальный или явно подтверждённый облачный разбор → оценка уверенности. Локальный разбор выдаёт текст и координаты; document parser дополнительно может выдать Markdown, таблицы и иерархию элементов
6. Присвоение странице флага источника текста: `native` · `ocr` · `ocr_low`
7. Разбиение на фрагменты **по структуре** (заголовки, абзацы, списки, таблицы). Для страниц с флагом `ocr` и `ocr_low`, где структура не восстанавливается, применяется деградированное разбиение по абзацам — этот факт помечается на фрагменте
8. **Сборка блоков:** фрагменты группируются в структурные блоки по заголовкам. Блок — единица классификации на шаге соотнесения (§6.4)
9. **Классификация блока:** `содержательный` / `служебный` (титул, оглавление, колонтитул, список литературы, предисловие, выходные данные). Служебные не участвуют в покрытии материала
10. Каждый фрагмент хранит: файл, страницу, координаты, уровень в структуре, флаг качества, ссылку на блок; страница хранит нормализованный Markdown и элементы разбора, если они были получены
11. Индексация: полнотекстовый индекс (BM25) + векторные представления

**FR-M7.** Флаг качества виден везде, где показывается фрагмент. Фрагмент со страницы `ocr_low` подсвечен предупреждением и никогда не выдаётся за достоверный текст.

**FR-M7.1. Формулы.** Если материал содержит много формул или качество их извлечения сомнительно, система сообщает об этом до построения программы, указывает число затронутых страниц и сохраняет переход к оригинальной странице для проверки. Распознанная формула не выдаётся за надёжную только потому, что окружающий текст извлечён успешно. Отдельный математический конвейер — document parser → детектор формул → Formula OCR → LaTeX → проверка по оригиналу — подключается позже как часть режима «Эксперт»; до него формулы остаются предупреждением, а не имитацией точного LaTeX.

**FR-M7.2. Рекомендация повышения качества.** После локального разбора система анализирует наблюдаемые сигналы: низкую уверенность, число страниц `ocr_low`, нарушения структуры, таблицы и найденные формулы. Она показывает рекомендацию переключиться на следующий режим, но не отправляет файл в облако и не перезапускает разбор сама. Процент уверенности — диагностический сигнал конкретного распознавания, а не обещание точности документа.

**FR-M8.** Страницу можно открыть в просмотрщике: исходное изображение или страница PDF с подсветкой распознанных фрагментов и их привязок.

**FR-M9.** Текст страницы можно поправить вручную с переиндексацией затронутых фрагментов. **Подтверждённые привязки при этом сохраняются**: система переносит их на новые границы фрагментов и показывает список тех, которые перенести не удалось.

**FR-M10.** Материал можно удалить. Его привязки и производные сущности (карточки, эталонные ответы) помечаются осиротевшими, а не удаляются молча. Пользователь видит, какие темы потеряли покрытие, а их статусы пересчитываются: тема, чей статус держался только на удалённых фрагментах, возвращается в `нет материала` с явным уведомлением.

**FR-M11.** На этапе 5 реализуются только локальные режимы «Быстро» и «Учебник»; три облачных режима остаются видимыми, но недоступными с указанием этапа и причин. Для демонстрации используются фотографии страниц бумажного источника. До появления таких материалов ветка OCR может оставаться заглушкой с честным флагом в интерфейсе.

### 4.3. Дозагрузка

**FR-M12.** При добавлении материала в проект с уже собранной программой система показывает **дельту**: какие темы получили новые фрагменты, какие пробелы закрылись, какие фрагменты дублируют уже привязанные, какие содержательные блоки не отнеслись ни к одной теме.

**FR-M13.** Проход 2 при дозагрузке выполняется **только по новым блокам**. Уже классифицированные блоки не пересчитываются.

### 4.4. Длинные задачи

**FR-M14.** Любая задача длительностью более минуты обязана быть **возобновляемой**. Для проходов 1 и 2 чекпоинт — счётчик обработанных единиц («обработано 640 блоков из 1500»); после падения или перезапуска работа продолжается с последнего чекпоинта.

**FR-M15.** Результаты выдаются **прогрессивно**: программа появляется по разделам, привязки — по мере готовности. Пользователь может начать работать с первым готовым разделом, пока остальное досчитывается.

**FR-M16.** Сбой или недоступность внешней модели не удаляет уже построенные разделы. Пользователь может повторить задачу, принять частичную программу, продолжить вручную или перейти на офлайновый вариант по оглавлению.

### 4.5. Поиск внешних источников

**FR-M17.** В Материалах доступен явный поиск новых источников в интернете. Два режима используют одну поверхность:

- **Быстрый поиск** возвращает список релевантных публикаций с названием, URL, автором или изданием, датой при наличии и кратким объяснением релевантности;
- **Глубокое исследование** выполняется в фоне и возвращает связный отчёт, а также полный список использованных и найденных публикаций.

**FR-M18.** Результат поиска — Кандидат источника. Пользователь просматривает результаты, отмечает нужные и только отдельным действием добавляет их в проект. После добавления веб-страница или PDF проходит обычный конвейер Материала; до этого она не участвует в Программе, привязках и покрытии.

**FR-M19.** Поиск запускается из Материалов, Пробелов, Чата и Студии через одну и ту же поверхность. Переход из Пробелов предварительно заполняет запрос формулировкой Темы, но не запускает поиск и не импортирует результаты автоматически.

**FR-M20.** У запуска поиска хранятся запрос, режим, необязательная Тема, состояние, провайдер, время начала и завершения, стоимость, найденные ссылки и решение пользователя по каждому результату. У импортированного результата неизменно сохраняются исходный запрос, URL и дата получения.

**FR-M21.** Быстрый и глубокий поиск могут быть отключены независимо. При выключенной сети или недоступном провайдере ранее импортированные Материалы и сохранённые отчёты продолжают работать; недоступность поиска показывается как штатное ограничение, а не как ошибка проекта.

## 5. Формирование программы

> Ключевой раздел системы. Именно здесь определяется, будет ли продукт полезен.

### 5.1. Паспорт цели

**FR-G1.** У проекта есть **паспорт цели** — структурированный ответ на вопрос «зачем я это беру и что хочу получить». Оси паспорта:

| Ось | Варианты |
|---|---|
| **Зачем** | экзамен · рабочая задача · собеседование · общий интерес |
| **Срок** | есть дата · нет даты |
| **Стартовый уровень** | с нуля · что-то знаю · повторяю забытое |
| **Целевой результат** | знать о существовании · понимать · уметь применять · владеть свободно |
| **Конкретная цель** | что именно пользователь хочет уметь сделать, понять или объяснить — свободным текстом; для учебника по умолчанию «последовательно изучить весь материал» |
| **Критерий результата** | по какому наблюдаемому результату пользователь поймёт, что достиг цели — свободным текстом |
| **Фокус** | что важно и что не важно — свободным текстом или отметками по разделам |
| **Формат работы** | только теория · теория и задачи · много практики |
| **Бюджет времени** | минут в день · учебных дней в неделю · предпочтительная длительность занятия |
| **Экзамен, если применимо** | структура (`вопросы` / `вопросы и задачи` / `билеты` / `список неизвестен`) · ожидаемое число элементов · необязательные требования преподавателя |

**FR-G2.** Паспорт заполняется **формой**, а не диалогом. У формы есть кнопка **«предложить заполнение»**: один вызов модели по быстрому анализу всех выбранных материалов (§3.3) или по формулировке цели подставляет значения, пользователь правит. Машинно заполненные поля помечаются. Ветвящееся интервью не реализуется (§22).

**FR-G2.1.** Поля, нужные детерминированным механизмам — дата, бюджет времени, стартовый и целевой уровень, формат и включённые модули — остаются структурированными. Смысловые сведения — текущие знания, конкретная цель, критерий результата, важное и исключаемое — допускают свободный текст для модели.

**FR-G3.** Паспорт берётся из шаблона проекта, заполняется вручную или автозаполнением. Меняется в любой момент. При изменении система **предлагает** пересобрать программу и план, но не делает этого молча.

**FR-G4.** Паспорт — вход для построения программы, планировщика и генератора активностей.

### 5.2. Четыре способа получить программу

**FR-G5.** Программа проекта — **дерево узлов до 4 уровней вложенности**. Узел имеет тип: `раздел`, `тема`, `подпункт`. Раздел и тема — не разные сущности, а разные типы одного узла; это позволяет и произвольную вложенность, и групповые операции по поддереву.

**FR-G6.** Способы получения программы:

| № | Режим | Как работает | Нужна внешняя модель |
|---|---|---|---|
| 1 | **Импорт списка** | Готовый список билетов: TXT/DOCX/CSV/MD, с распознаванием нумерации | нет |
| 2 | **По оглавлению** | Извлекается структура PDF (outline/закладки) либо распознаётся страница оглавления. Главы → разделы, параграфы → темы | **нет** |
| 3 | **Из материала (проход 1)** | Map-reduce по главам: выделение тем, слияние, устранение дублей (§5.4) | да |
| 4 | **Из каталога** | Типовая программа предмета накладывается на материалы; при отсутствии предмета в каталоге — из знаний модели (§5.5) | зависит от слоя |

**FR-G7.** Режимы комбинируются в любом порядке. Типовая цепочка для учебника: извлечь оглавление → пройти все содержательные главы под паспорт цели → объединить темы нескольких источников → сверить обязательные предпосылки с каталогом или знаниями модели → исправить руками и с помощью ассистента.

**FR-G8.** Режимы 1 и 2 — гарантированный офлайновый путь. Они обеспечивают работоспособность §5 без внешних моделей и являются резервным путём, если проход 1 прерван или слишком дорог.

**FR-G9. Дедупликация и слияние.** При добавлении темы система предупреждает о похожих и предлагает: объединить, сделать подпунктом существующей, оставить отдельно. Слияние импортированного списка билетов с собранной программой — отдельный экран, где сопоставление показывается парами с обоснованием.

**FR-G9.1. Экзаменационный редактор.** Для шаблона экзамена пользовательское название экрана — «Вопросы экзамена». Импортированный плоский список является штатным состоянием: пользователь может оставить его плоским, вручную создать разделы или попросить модель предложить группировку. Активный редактор показывает только состав экзамена; отдельные столбец и переключатель «в подготовке» не используются. Удаление из списка реализует внутреннее состояние «вне текущей программы» по FR-G11 без постоянного отображения этой служебной логики. До модельного запуска показываются состав отправляемого, стоимость и время; результат приходит как диф дерева, применяется выборочно, маркируется машинным и отменяется одним действием.

**FR-G9.2. Редактор программы учебника.** Одна поверхность используется как главный шаг мастера и как раздел активного проекта «Программа». Программа занимает примерно две трети экрана, помощник — правую треть. Одно дерево переключается между тремя представлениями: иерархия, последовательный текст и список вопросов для самопроверки. Представления не создают копий данных; изменение в одном сразу отражается в остальных. Свободный граф связей не реализуется, пока модель программы хранит только родительскую иерархию.

**FR-G9.3. Ручное редактирование.** Пользователь может добавить раздел, тему или подпункт, изменить формулировку, порядок и вложенность, перенести узел, объединить похожие темы, убрать узел из текущей программы, вернуть его и пачкой изменить уровень цели по поддереву. Все операции попадают в журнал и отменяются.

**FR-G9.4. Помощник программы.** Пользователь выбирает область контекста: вся программа, раздел или тема. Помощник умеет предложить добавление, объединение, перенос, изменение формулировки, порядка и уровня цели, вывод из текущей программы, недостающие предпосылки и тип материала, который нужно найти. Он не ищет и не загружает источники из сети. Любой ответ, меняющий дерево, приходит дифом и не применяется до подтверждения пользователя.

### 5.3. Пересборка программы

**FR-G10. Пересборка не удаляет ничего.** Она показывает **диф** добавления, объединения, переноса, изменения формулировки и уровня цели, а также вывода узла из текущей программы. Каждое изменение принимается отдельно или вместе с остальными.

**FR-G10.1.** Правки из чата, повторного прохода 1 и наложения каталога используют один механизм дифа. Принятые изменения помечаются машинными, хранят обоснование и источник предложения и отменяются одной командой.

**FR-G11.** Тема, отсутствующая в новой версии программы, не удаляется. Она получает признак **«вне текущей программы»**: уходит из плана, очереди дня и метрик покрытия, но сохраняет привязки, карточки, конспект и всю историю попыток. Возврат в программу — одно действие.

**FR-G12.** Обоснование: любое другое поведение означает, что нажатие «пересобрать» может стереть накопленную работу, и пользователь перестанет им пользоваться.

### 5.4. Построение программы из материала (проход 1)

**FR-G13.** Проход 1 — **map-reduce по главам всех выбранных основных и дополнительных источников**, а не рекурсивная агрегация:

1. **map:** каждый материал делится на главы (по структуре документа; при её отсутствии — по фиксированному числу страниц). На каждую единицу — один вызов модели: выделить темы и их связь с паспортом цели
2. **reduce:** списки сливаются с учётом роли, приоритета и пояснения к источникам; дубли между главами и файлами устраняются, темы раскладываются по разделам, определяется порядок изучения

**FR-G13.1.** Если источники расходятся по структуре, терминологии или содержанию, система не смешивает версии молча: сохраняет происхождение, показывает расхождение и предлагает объединить темы, оставить отдельно либо выбрать основной вариант.

**FR-G14.** Порядок обработки — по приоритету источников и порядку глав. Чекпоинт — источник и номер обработанной главы. Ориентировочный объём: около тридцати вызовов на учебник.

**FR-G15.** Каждая тема, выведенная из материалов, несёт ссылки на страницы и источники, из которых она получена. Если тема добавлена как необходимая предпосылка, но в материалах не найдена, отсутствие источника показывается явно.

**FR-G16.** Паспорт цели влияет на результат: глубина дробления тем и их количество зависят от целевого результата и фокуса.

**FR-G16.1. Полнота прохода.** При построении программы рассматривается каждая содержательная глава, а не только результаты поиска по формулировке цели. Для узкой цели темы делятся на целевые, обязательные предпосылки, непосредственно связанные и находящиеся вне текущей программы; тем самым смежное содержание не теряется из-за ограничения top-k.

**FR-G16.2. Пробелы источников.** После сборки тем из материалов система сверяет программу с доступными слоями каталога и, если разрешено, знаниями модели. Необходимая для цели тема без подтверждения материалом остаётся в программе с меткой «нужно найти материал» и происхождением «источника нет».

**FR-G16.3.** По умолчанию учебниковый проект включает всё содержательное дерево на разумной для целевого результата глубине. Узкая цель сужает текущую программу, но не удаляет остальную структуру источников.

**FR-G16.4.** Проход 2 запускается после одобрения программы. До этого редактор не показывает ложные нулевые показатели привязок: видны только происхождение темы и наличие или отсутствие опорного источника.

**FR-G16.5.** Если загруженные материалы почти не покрывают конкретную цель, система сообщает об этом до подтверждения программы и предлагает изменить цель, добавить источники либо продолжить с необходимыми темами, помеченными «нужно найти материал».

### 5.5. Каталог эталонных программ

**FR-G17.** Система умеет предлагать программу, опираясь на то, как предмет преподают вообще. Источники организованы **слоями с явным уровнем доверия**:

| Слой | Источник | Когда | Метка |
|---|---|---|---|
| 1 | **Встроенный каталог** | Предмет есть в поставке | «проверенная программа» |
| 2 | **Оглавление классического учебника** | Учебник в материалах или его структура в каталоге | «по структуре учебника *Название*» |
| 4 | **Знания модели** | Всё остальное | «не проверено, источника нет» |

**FR-G18.** Слой 3 (веб-поиск) не реализуется: это отдельная интеграция с парсингом выдачи и разметкой доверия к источникам, а пользы поверх слоя 4 она почти не добавляет.

**FR-G19.** Каждая тема, пришедшая из каталога, хранит свой слой и источник, и они видны в интерфейсе. Так П6 соблюдается даже на слое 4 — система прямо сообщает, что источника нет.

**FR-G19.1.** Для темы без материала интерфейс пишет «Нужно найти материал по теме» и позволяет сразу открыть добавление источника. Это полезный пробел программы, а не ошибка проекта; общая метрика покрытия не окрашивается как проблема (FR-D17).

**FR-G20.** Слой 4 отключается тумблером. При выключенном работают слои 1 и 2 — офлайновый путь сохраняется.

**FR-G21.** Встроенный каталог поставляется с системой в виде набора файлов, пополняется вручную и является частью репозитория. На старте наполняется по демо-предмету «Базы данных».

**FR-G22.** Наложение эталонного курса на материалы даёт **сравнение**: какие темы стандартного курса в материалах есть, каких нет, что в материалах есть сверх курса.

### 5.6. Свойства темы

**FR-G23.** Тема имеет: формулировку, **тип узла**, положение в дереве, **уровень цели**, теги, статус, признак «вне текущей программы», признак «нужно найти материал», эталонный ответ (необязательный), список ключевых пунктов, способ проверки (§9), настройки активностей, источник происхождения (импорт / оглавление / проход 1 с одним или несколькими файлами / каталог со слоем / вручную).

**FR-G24. Уровень цели** — четыре градации, заменяющие числовой вес:

| Уровень | Что значит | Что делает система |
|---|---|---|
| **Знать о существовании** | Узна́ю термин, понимаю, о чём речь | Одна карточка, один проход, в плане почти не занимает места |
| **Понимать** | Могу объяснить своими словами | Материал и свободный ответ, редкие повторения |
| **Уметь применять** | Могу решить типовую задачу | Плюс задачи, повторения по расписанию |
| **Владеть свободно** | Могу объяснить, вывести, применить в новом | Всё, включая устный ответ, частые повторения |

**FR-G25.** Уровень цели ставится **пачкой по поддереву** одним действием, а не по одной теме. Значение по умолчанию берётся из паспорта цели (ось «целевой результат»).

**FR-G26.** Уровень цели определяет три вещи: набор предлагаемых активностей, численный порог перехода в статус `отработан` (§11.3), долю времени в плане (§12).

**FR-G27.** Эталонный ответ может быть: введён вручную, импортирован из файла с ответами (вход A), собран из привязанных фрагментов, сгенерирован моделью.

**FR-G28.** Ключевые пункты — короткий список того, что должно прозвучать в ответе. Используются детерминированной проверкой, проверкой устного ответа и ИИ-судьёй.

### 5.7. Карта покрытия

**FR-G29.** Карта покрытия — главный аналитический экран проекта: таблица программы, где у каждой темы показано:

- число привязанных фрагментов и из каких источников;
- худшее качество распознавания среди привязанных фрагментов;
- уровень цели;
- есть ли эталонный ответ;
- сколько раз отвечали и с каким результатом;
- статус: `нет материала` · `есть материал` · `разобран` · `отработан` · `освоен`.

**FR-G30.** Правило перехода между статусами численно и **показывается пользователю по нажатию**: видно, чего именно не хватает до следующего статуса. Пороги выводятся из уровня цели.

**FR-G31.** Фильтры и сортировки: по статусу, разделу, уровню цели; «только непокрытые», «только просроченные», «только машинные привязки», «вне текущей программы».

## 6. Среда темы и привязка материала

### 6.1. Среда темы

**FR-D0. Рабочая область проекта.** Ежедневная работа идёт на одном маршруте с деревом программы и Средой выбранной темы. Конфигурация определяется шаблоном и модулями проекта: компактная экзаменационная показывает ответ и подготовку, развёрнутая учебная — источники, Уроки, конспект, историю и модельные инструменты. Это две конфигурации одной поверхности, а не два независимых экрана.

**FR-D1.** **Среда темы** — рабочее пространство одной темы. Содержит: формулировку, эталонный ответ, привязанные фрагменты со ссылками, карточки этой темы, личный конспект, историю попыток, статистику, панель свободного вопроса.

**FR-D2.** Состав среды зависит от настроек проекта: в проекте-марафоне она компактна (материал, ответ, история), в проекте свободного изучения — развёрнута.

### 6.2. Прямая привязка: от темы к материалу

**FR-D3.** Сборка материала под тему:

1. Результат прохода 2 (основной источник привязок)
2. BM25-поиск по ключевым словам темы → топ-50
3. Векторный поиск по представлению темы → топ-50
4. Слияние рангов (RRF), склейка соседних фрагментов, дедупликация

**FR-D4.** Шаги 2–4 работают без обращения к внешним сервисам и являются резервным путём, а также движком поиска для свободных вопросов и дозагрузки.

### 6.3. Применение привязок

**FR-D5. Числовой уверенности у привязки нет.** Проход 2 возвращает решение, а не балл; калиброванной вероятности из него не извлечь, и любой порог был бы выдуманным. Обучаемый переранжировщик не реализуется (§22).

**FR-D6.** Правило применения:

- проход вернул **одну тему** → привязка применяется автоматически и помечается машинной;
- вернул **несколько тем** или явное «не уверен» → привязка идёт в очередь предложений.

**FR-D7.** Очередь предложений — вспомогательный инструмент, а не обязательный этап. Работа с темами не блокируется её наличием.

**FR-D8.** В среде темы каждая машинная привязка снимается одним действием («это не по теме»). Отмена обратима.

**FR-D9.** Каждое решение пользователя по привязке записывается в журнал действий (для undo, §19) и в статистику качества привязки.

**FR-D10.** Фрагмент можно привязать вручную: выделить кусок текста на странице в просмотрщике и указать тему.

**FR-D11.** Один фрагмент может быть привязан к нескольким темам. Система показывает это явно.

### 6.4. Обратная привязка: от материала к темам (проход 2)

**FR-D12.** Помимо прямой задачи «найти материал под тему» система решает обратную: **к какой теме относится каждый содержательный блок материала**.

**FR-D13. Единица классификации — структурный блок**, а не фрагмент. Заголовок вместе с подчинёнными абзацами классифицируется целиком, фрагменты наследуют решение блока.

Обоснование: абзац — слишком мелкая единица, соседние абзацы одной секции классифицировались бы независимо и давали бы шум. Блоками получается втрое дешевле по вызовам и точнее по контексту.

**FR-D14. Алгоритм прохода 2:** система идёт по всем содержательным блокам материала **ровно один раз**, батчами по несколько блоков за вызов, и для каждого получает решение. Полнота здесь — свойство конструкции, а не качества модели: непросмотренных блоков не остаётся по построению.

**FR-D15. Исходов классификации три:**

| Исход | Что значит | Куда идёт |
|---|---|---|
| `отнесён к теме` | Блок относится к одной или нескольким темам программы | Привязки |
| `служебный` | Титул, оглавление, колонтитул, список литературы, предисловие | Никуда, в метрику не входит |
| `содержательный, вне программы` | Содержательный материал, которому нет темы в программе | Экран «Неразобранное» |

**FR-D16.** Вводятся две метрики покрытия:

| Метрика | Формула | О чём говорит |
|---|---|---|
| **Покрытие программы** | доля тем, обеспеченных материалом | Хватает ли источников |
| **Покрытие материала** | отнесённые ÷ (отнесённые + вне программы) | Полна ли программа |

**FR-D17. Покрытие материала не обязано стремиться к 100%.** Категория «вне программы» — результат работы системы, а не дефект: именно из неё формируется экран «Неразобранное». Интерфейс не должен подавать значение ниже 100% как проблему.

**FR-D18.** Классификация служебности и отнесения исправима пользователем в обе стороны.

### 6.5. Экраны покрытия

**FR-D19.** Экран **«Пробелы»** — темы, под которые в материалах ничего не нашлось. Для каждой показывается, что именно искали и какой был лучший отвергнутый кандидат.

**FR-D20.** Экран **«Неразобранное»** — блоки с исходом «содержательный, вне программы». Для каждого показывается источник, страница и предложение: создать новую тему, привязать к существующей, пометить как служебное.

**FR-D21.** Оба экрана — равноправные результаты работы системы: «Пробелы» говорят, что не хватает источников, «Неразобранное» — что неполна программа.

### 6.6. Свободный вопрос по всему материалу

**FR-D22.** Свободный вопрос разрешён в среде темы, в сессии и в боте. Ответ всегда сопровождается ссылками на фрагменты. Если релевантного материала нет во **всём материале проекта**, система прямо говорит, что этого в материалах нет, и не выдумывает.

**FR-D23.** Простые вопросы («что такое третья нормальная форма») обслуживаются гибридным поиском (§6.2).

**FR-D24. Сложные вопросы обслуживаются агентом.** Материал **не кладётся в контекст модели**: он остаётся в базе, а модель получает небольшой API проекта (`pages`, `fragments`, `search`, `outline`, `sub_llm`) и пишет против него код, который сам решает, как обойти материал. Ответ копится в переменной и возвращается из неё.

Обоснование: форма таких вопросов заранее неизвестна, фиксированный цикл под них не напишешь. Примеры: «в каких главах упоминается нормализация и чем объяснения различаются», «что есть в методичке про транзакции, чего нет в файле с теорией». Второй — попарное сопоставление двух источников, задача класса, на котором поиск по замеру из [Recursive Language Models](https://arxiv.org/abs/2512.24601) даёт 24.7 против 58.0 у агента.

**FR-D25.** Реализация — библиотека [alexzhang13/rlm](https://github.com/alexzhang13/rlm), исполнение генерируемого кода — в песочнице (§10.4).

**FR-D26.** Перед запуском агента система показывает оценку стоимости вызова. Агент отключается тумблером; при выключенном свободные вопросы обслуживаются только поиском.

### 6.7. Палитра учебных навыков

**FR-D27.** В веб-чате есть кнопка `+` слева от поля ввода. Она открывает палитру **учебных навыков**; навык запускается только явным выбором пользователя, а не самовольным действием модели.

**FR-D28.** В первой версии палитра содержит пять навыков:

| Навык | Результат |
|---|---|
| **Найти источники** | Краткий ответ и карточки внешних публикаций по вопросу или теме |
| **Найти иллюстрации** | Подходящие рисунки, схемы и изображения из публикаций с атрибуцией |
| **Показать интерактивно** | Параметрический график, таблица, схема или пошаговая модель понятия |
| **Собрать в урок** | Черновик Урока из выбранных сообщений, источников и учебных артефактов |
| **Создать тренировку** | Один выбранный вид Активности по текущему объяснению |

**FR-D29.** Перед запуском чат показывает, что станет запросом и какой контекст будет передан: текущая тема, выбранные фрагменты, сообщение пользователя и — только по отдельному согласию — личный конспект. Внешний поиск не получает материал проекта, если пользователь не выбрал фрагменты явно.

**FR-D30.** Результат внешнего поиска содержит карточки источников с названием, автором или изданием, датой при наличии, прямой ссылкой, датой получения и краткой причиной релевантности. Изображение всегда показывает источник и условия использования, если они известны. Нельзя выдать внешнее утверждение или картинку за материал проекта.

**FR-D31.** Интерактивный блок — воспроизводимый учебный артефакт с описанием данных, параметров и допустимых взаимодействий. Первая версия поддерживает графики с параметрами, таблицы с пересчётом, пошаговые схемы и сравнение сценариев. Он не исполняет произвольный код из сообщения; сложные исполняемые демонстрации остаются задачей песочницы (§10.4).

**FR-D32.** Любой результат навыка можно сохранить в Урок или Конспект только явным действием. При сохранении сохраняются происхождение, использованный запрос, ссылки на источники, время получения и версия интерактивного описания. Сохранение не меняет программу, привязки и покрытие.

**FR-D33.** Манипуляция интерактивным блоком сама по себе не является Попыткой и не влияет на прогресс. Навык «Создать тренировку» создаёт обычную Активность по правилам §7.

**FR-D34.** Внешние навыки отключаются по одному и глобально вместе с внешними моделями. При выключенной сети или недоступном провайдере сохранённые переписки, Уроки и артефакты остаются доступны, но новый диалог с ИИ не работает. Палитра объясняет недоступность и не показывает её как ошибку обучения; резервная форма сдачи описана в `FR-D40`.

### 6.8. Уроки

**FR-L1.** **Урок** — редактируемый сценарий изучения одной или нескольких Тем: объяснения, цитаты и ссылки на материалы, медиа, интерактивные блоки и обычные Активности. У одной Темы может быть несколько Уроков; один Урок может охватывать несколько Тем.

**FR-L2.** Урок создаётся вручную либо моделью. Модельный путь сначала показывает темы, цель, сложность, длительность, основание (`только источники проекта` / `источники + знания модели` / `только знания модели`), план блоков и стоимость; результат всегда создаётся как черновик и не перезаписывает существующий Урок.

**FR-L3.** Статусы Урока: `черновик` · `готов` · `архив`. Архивный Урок сохраняется, но не предлагается для изучения по умолчанию. Готовый Урок открывается для изучения в Рабочей области; создание и редактирование выполняются в отдельном разделе «Уроки».

**FR-L4.** Документ Урока состоит из версионируемых блоков со стабильными идентификаторами. Первая версия поддерживает текст, заголовок, определение, цитату, изображение, декларативный интерактив, адаптивную строку/колонки и ссылку на Активность. Свободное пиксельное размещение и полноценный rich-text-движок не требуются.

**FR-L5.** Каждый блок хранит происхождение: ручное, модельное или смешанное; ссылки на использованные Фрагменты, внешние публикации и Учебные артефакты. Удаление источника не удаляет Урок: затронутый блок получает состояние «Источник недоступен».

**FR-L6.** Изменение Программы не удаляет Уроки. Если состав или смысл связанных Тем изменился, Урок получает состояние «Требует проверки» до подтверждения пользователя.

**FR-L7.** Раздел «Уроки» поддерживает одиночную и массовую подготовку по выбранным Темам или поддереву. Массовая операция пропускает существующие готовые Уроки по умолчанию, показывает будущие действия по каждой строке и не перезаписывает их молча.

**FR-L8.** Ручное создание и изучение сохранённых Уроков работают без внешних моделей. При отсутствии материала ручной Урок допустим; модельные основания, использующие знания без источников проекта, показываются явно.

**FR-L9.** Просмотр Урока и взаимодействие с его объясняющими блоками имеют силу свидетельства 0. Прогресс и повторение меняются только обычной Активностью с Попыткой.

### 6.9. Студия

**FR-S1.** **Студия** — постоянная правая панель Рабочей области для создания и просмотра производных учебных материалов по выбранным Темам и источникам. Она не заменяет Программу, Уроки, Карточки, Конспект или Сессию и не становится центральным сценарием проекта.

**FR-S2.** Панель имеет два состояния. В свёрнутом состоянии остаётся узкая вертикальная полоса: кнопка раскрытия, девять иконок генераторов, разделитель, компактная история артефактов и закреплённая снизу кнопка «Добавить заметку». В развёрнутом состоянии показываются заголовок, сетка генераторов 3×3 с подписями, история с названием, числом источников, временем и состоянием, а также та же кнопка заметки. Состояние запоминается отдельно для проекта и не занимает одну из трёх рабочих колонок Темы.

**FR-S3.** Студия содержит восемь генераторов в фиксированном порядке:

| | Колонка 1 | Колонка 2 |
|---|---|---|
| **Строка 1** | Аудиопересказ | Презентация |
| **Строка 2** | Ментальная карта | Отчёты |
| **Строка 3** | Карточки | Тест |
| **Строка 4** | Инфографика | Таблица данных |

**FR-S4.** Клик по генератору открывает единый диалог настройки. До запуска он показывает связанные Темы, выбранные источники, язык, форматные параметры, пользовательскую инструкцию, модель или сервис, объём передаваемых данных, время и стоимость. Источники можно включать и исключать; по умолчанию выбраны доступные привязанные источники текущей Темы. Нулевой набор источников не маскируется: генерация из знаний модели требует отдельного явного основания.

**FR-S5.** Полный состав каждого генератора фиксируется так:

| Генератор | Настройки до запуска | Просмотр и действия результата |
|---|---|---|
| **Аудиопересказ** | формат `подробный разбор` / `краткий выпуск` / `критика` / `дебаты`; язык; длина; инструкция; источники | проигрывание, пауза, перемотка, скорость, фоновое воспроизведение, скачивание; позднее — явное подключение пользователя к разговору голосом |
| **Презентация** | формат `подробная` / `слайды докладчика`; язык; длина `короткая` / `обычная` / `длинная`; инструкция; источники | прокрутка слайдов, полноэкранное слайд-шоу, масштаб, инструкции к правке отдельных слайдов, новая версия после правок, экспорт PDF и PPTX |
| **Ментальная карта** | язык; инструкция о фокусе; источники | масштабирование и перемещение, раскрытие и сворачивание ветвей, выбор узла для вопроса в Чате, скачивание |
| **Отчёты** | шаблон `FAQ` / `учебное руководство` / `обзорный документ` / `свой` / `предложенный моделью`; язык; инструкция; источники | документ с цитатами, переименование, экспорт Markdown, PDF и DOCX; таблицы внутри дополнительно экспортируются как CSV/XLSX |
| **Карточки** | количество `меньше` / `обычно` / `больше`; сложность `легко` / `средне` / `сложно`; инструкция; Темы и источники | объяснение ответа, перемешивание, удаление, перезапуск, `знаю` / `не знаю`, продолжение, повтор всех или ошибочных, CSV; после проверки — перенос в существующий Банк |
| **Тест** | количество; сложность `легко` / `средне` / `сложно`; инструкция; Темы и источники | прохождение, объяснение ответа, итог, повтор всего теста или ошибок; после проверки — сохранение как обычных Активностей |
| **Инфографика** | язык; подробность `краткая` / `обычная` / `подробная`; ориентация `квадрат` / `портрет` / `альбом`; визуальный стиль `авто` / пресет / собственное описание; инструкция; источники | масштабирование, полноэкранный просмотр, скачивание PNG |
| **Таблица данных** | язык; описание требуемых строк и колонок; инструкция; источники | таблица с цитатами на строки или ячейки, сортировка и просмотр происхождения, экспорт CSV и XLSX с отдельным листом источников |

Справочная база состава зафиксирована на 07.08.2026 и не требует повторной разведки перед реализацией: [общий обзор Студии](https://support.google.com/notebooklm/answer/16206563?hl=en), [Аудиопересказ](https://support.google.com/notebooklm/answer/16212820?hl=en-GB), [Ментальные карты](https://support.google.com/notebooklm/answer/16212283?hl=en), [Карточки и тесты](https://support.google.com/notebooklm/answer/16958963?hl=en), [Инфографика](https://support.google.com/notebooklm/answer/16758265?hl=en-GB), [Презентации](https://support.google.com/notebooklm/answer/16757456?hl=en) и [Заметки](https://support.google.com/notebooklm/answer/16262519?hl=en-PH). Это исходная точка Tentex, а не обязанность автоматически повторять будущие изменения NotebookLM.

**FR-S6.** **Заметка Студии** — независимый редактируемый Студийный артефакт в Markdown. Она создаётся вручную либо сохранением ответа Чата, может быть объединена с другими заметками, преобразована в план, сводку или учебное руководство и отдельным действием превращена в Материал. «Мой конспект» остаётся непрерывным документом Темы и не подменяется Заметками.

**FR-S7.** Общие состояния Студийного артефакта: `черновик` · `в очереди` · `создаётся` · `готов` · `ошибка` · `отменён` · `требует проверки`. Генерация выполняется в фоне; несколько артефактов могут создаваться одновременно. Операции дольше 10 секунд показывают прогресс, дольше минуты возобновляются по NFR-2/3.

**FR-S8.** Общие действия готового артефакта: открыть, переименовать, показать исходный запрос и настройки, повторить генерацию как новую версию, скачать или экспортировать, вставить в Урок или Конспект, удалить с подтверждением. Новая генерация и правка не перезаписывают прежнюю версию молча.

**FR-S9.** Каждый артефакт хранит происхождение: Темы, точный набор и версии источников, запрос, настройки, модель или сервис, дату, цитаты и ЗапускМодели. Изменение или удаление источника не удаляет артефакт: он получает «Источник недоступен» или `требует проверки`.

**FR-S10.** Просмотр Студийного артефакта имеет силу свидетельства 0 и сам по себе не меняет Программу, привязки, покрытие, прогресс или повторения. Карточки после пользовательской проверки переходят в существующий Банк; Тест — в существующие Активности. Параллельные сущности карточек и тестов не создаются.

**FR-S11.** При выключенных внешних моделях генераторы остаются видны с объяснением недоступности; готовые артефакты и ручные Заметки открываются офлайн. Конкретный генератор доступен только при наличии всех нужных возможностей провайдера: текст, изображения, TTS или экспорт.

**FR-S12.** На текущем подготовительном срезе Студия — честный интерактивный прототип: раскрытие панели и диалоги работают, но генерация, сохранение Заметок, история и экспорт используют демонстрационные данные и прямо помечены как неподключённые. Сущности и API Студии не добавляются до её этапа в PLAN.md.

### 6.10. Экзаменационный чат

**FR-D35. Чат — поверхность сдачи, а не только объяснения.** Помимо свободного вопроса (§6.6) чат ведёт проверку ответа: задаёт вопрос программы, принимает ответ и возвращает разбор. Чат открывается в любой зоне Рабочей области и не занимает её целиком.

**FR-D36. Сообщение чата может нести интерактивный блок.** Первая версия: форма ответа, разбор ответа, задание. Блок описывается видом и данными; интерфейс блока рисует система, модель его только **выбирает**. Модель не присылает разметку и не исполняет код — исполняемые демонстрации остаются задачей песочницы (`FR-D31`, §10.4).

**FR-D37. Ответ, данный в чате, — обычная Попытка** (§7). Он проходит тот же движок проверки (§9), даёт ту же Оценку и ту же силу свидетельства, что и ответ, введённый вне чата. Отдельного хранилища результатов у чата нет: сообщение ссылается на Попытку, а не заменяет её.

**FR-D38. Персона экзаменатора выбирается из пресетов**, строгость — отдельным параметром. Свободный системный промпт пользователя не предусмотрен: он ломает сопоставимость оценок и метрику калибровки (`FR-V5`).

**FR-D39.** Перед отправкой видно, что уходит в запрос: вопрос, эталон, привязанные фрагменты, история попыток. Любую часть контекста можно исключить — в том числе эталон, чтобы проверить себя честно. Правило `FR-D29` про явное согласие на личный конспект действует и здесь.

**FR-D40.** При выключенных внешних моделях собеседник и обычный диалог недоступны. Отдельная форма сдачи ответа остаётся доступной и использует детерминированные ступени (`FR-V1`) и самооценку. Это резервный контур проверки, а не «чат без ИИ».

## 7. Учебные активности

**FR-A1. Активность** — единица работы над темой. Активность порождает **Попытку**, попытка порождает **Оценку**. Это позволяет считать прогресс одинаково независимо от способа работы.

**FR-A2.** Виды активностей:

| Вид | Что делает пользователь | Как проверяется | Сила свидетельства |
|---|---|---|---|
| **Чтение** | Читает материал темы, отмечает «разобрался» | Самооценка, факт времени | **0** |
| **Карточка** | Вспоминает, открывает обратную сторону | Самооценка (4 градации) | **1** |
| **Тест с вариантами** | Выбирает вариант | Детерминированно | **1** |
| **Пропуски** | Заполняет пробелы в определении | Детерминированно, с нормализацией | **2** |
| **Свободный ответ текстом** | Пишет ответ по памяти | §9 — от терминов до ИИ-судьи | **3** |
| **Устный ответ** | Отвечает голосом | STT → сверка с ключевыми пунктами (§16) | **3** |
| **SQL** | Пишет запрос | Сравнение результирующих множеств (§10) | **3** |

**FR-A3.** Конспект — **отдельная сущность, а не активность** (§13). Он не порождает осмысленной попытки.

**FR-A4. Сила свидетельства** определяет вклад активности в прогресс. Активности силы 0 двигают статус темы, но **не двигают интервалы повторения и не входят в подтверждённый прогресс**. Это не ограничение пользователя, а условие достоверности прогноза.

**FR-A5.** Для каждой темы настраивается, какие активности к ней применимы. Набор по умолчанию берётся из уровня цели и настроек проекта.

**FR-A6.** Активности создаются: вручную, детерминированно из привязанных фрагментов (пропуски — чистый алгоритм), генерацией моделью, извлечением из материала (§7.1).

**FR-A7.** Дистракторы для тестов подбираются из терминов того же раздела по близости — детерминированный алгоритм, внешняя модель не обязательна.

### 7.1. Извлечение задач из материала

**FR-A8.** Система находит в материале **готовые задачи и упражнения** (характерные заголовки, нумерация, форма изложения) и предлагает их как активности с привязкой к теме и ссылкой на страницу.

**FR-A9.** Если в материале есть ответы или решения к этим задачам, они привязываются как эталон. Если нет — задача помечается «без эталона», и проверка ограничивается самооценкой либо ИИ-судьёй.

### 7.2. Сессия занятия

**FR-A10.** Сессия — единый интерфейс для всех видов активностей. Система выдаёт активность, принимает ответ, показывает разбор, идёт дальше. Один каркас, рендерящий блоки под тип активности: формулировка, поле ответа, запись голоса, редактор SQL, разбор, карточка, фрагмент материала, итог сессии.

**FR-A11.** Порядок активностей в сессии определяется очередью дня проекта либо выбором пользователя (раздел, тема, «всё подряд»).

**FR-A12.** Лента сессии сохраняется, к прошлой сессии можно вернуться и перечитать разбор.

## 8. Карточки

**FR-K1.** Карточки — **отдельный раздел проекта** со своим экраном: список, поиск, фильтр по темам и разделам, редактор, массовые операции, режим повторения.

**FR-K2.** Карточка привязана к одной или нескольким темам, но живёт в общем банке проекта. Карточка без темы допустима.

**FR-K3.** Способы создания: вручную, из фрагмента (выделил текст → «в карточку», с автоматической ссылкой на источник), генерацией по теме, массовой генерацией по разделу.

**FR-K4.** **Режим повторения карточек**: выбрать темы, разделы или «всё подряд», задать длину сессии, пройти. Повторение карточек участвует в общем учёте на общих основаниях (§11).

**FR-K5.** Карточка, созданная из фрагмента, помечается осиротевшей при удалении источника (П2, FR-M10).

## 9. Движок проверки ответов

**FR-V1.** Способ проверки настраивается на уровне темы, по умолчанию — из уровня цели и настроек проекта:

| Уровень | Как работает | Требует внешней модели |
|---|---|---|
| **Точное совпадение** | Нормализация (регистр, пробелы, ё/е, пунктуация) и сравнение | нет |
| **Ключевые термины** | Наличие обязательных и отсутствие запрещённых терминов с учётом словоформ | нет |
| **SQL** | Сравнение результирующих множеств (§10) | нет |
| **Семантическая близость** | Векторное представление ответа против эталона, порог | нет (локальная модель) |
| **ИИ-судья** | Оценка по рубрике: покрытые пункты, ошибки, что упущено — с цитатами | да |
| **Самооценка** | Пользователь ставит оценку сам | нет |

**FR-V2.** Уровни комбинируются: сначала дешёвые и детерминированные, внешняя модель подключается, только если они не дали однозначного результата.

**FR-V3.** Результат проверки всегда объясним: показывается, какие ключевые пункты засчитаны, какие нет и почему. Оценка ИИ-судьи сопровождается цитатами из ответа пользователя и из эталона.

**FR-V4.** Пользователь может оспорить оценку одной кнопкой. **Оценка системы и решение пользователя хранятся раздельно, обе.**

**FR-V5.** Система показывает пользователю его собственную долю оспоренных оценок за период как метрику калибровки. Это не упрёк, а информация: систематическое завышение делает прогноз готовности недостоверным.

**FR-V6. Движок один на все поверхности.** Ответ из чата, из Рабочей области, из Урока и из бота проходит одну и ту же лесенку и даёт Оценку одного формата. Поверхность влияет на подачу вопроса и разбора, но не на способ проверки и не на вес свидетельства.

**FR-V7.** ИИ-судья не получает переписку чата и сокращённую память раздела — только вопрос, эталон, привязанные фрагменты и, только если чип явно оставлен включённым, историю попыток раздела. Это исключает эффект «подсказки в диалоге ответили вместо пользователя» и держит оценку сопоставимой с ответом, данным вне чата.

## 10. SQL и учебная база

**FR-X1.** Проект может содержать банк SQL-задач. Задача имеет: условие, эталонное решение, разбор, теги навыков, сложность, привязку к темам.

**FR-X2. Проверка — сравнение результирующих множеств** (с учётом порядка строк или без, настраивается на задаче), а не сравнение текста запроса.

**FR-X3.** В проекте может быть **учебная база** — схема и наполнение, поставляемые как файл.

**FR-X4.** Учебная база выполняется на **том же движке, что и основная БД системы** (SQLite), в изолированной копии файла, открытой на чтение. Отдельный сервер БД не поднимается, песочница для SQL не требуется.

**FR-X5.** Диалект SQL явно указывается в условии задачи. Места, где диалект существенно отличается от PostgreSQL, помечаются в разборе. Целевой охват — типовые аналитические запросы: соединения, группировки, подзапросы, `EXISTS`, оконные функции, CTE. Планы выполнения и настройка производительности разбираются **теоретически**, без практических задач.

**FR-X6.** Задачи с кодом на Python не реализуются (§22). Архитектура — адаптеры, добавление языка не требует переделки.

**FR-X7.** Результат прогона показывается таблицей: тест, статус, время, ожидалось/получено.

**FR-X8.** Ошибка синтаксиса, таймаут, неверный результат — отдельные, понятно оформленные состояния интерфейса, а не «что-то пошло не так».

**FR-X9.** История решений задачи сохраняется, прошлые попытки можно сравнить.

**FR-X10.** Модель может дать **подсказку следующим шагом**, но не готовое решение, пока пользователь не запросил разбор явно.

**FR-X11. Исполняемые демонстрации.** Система может сгенерировать и выполнить запрос для показа правильного ответа. Результат сохраняется вместе с темой.

### 10.4. Песочница

**FR-X12.** Песочница нужна для двух вещей: исполнения кода, который пишет агент свободного вопроса (§6.6), и исполняемых демонстраций.

**FR-X13.** Изоляция: Docker-контейнер с жёсткими лимитами (время, память, размер вывода). Сеть закрыта для демонстраций и открыта только к шлюзу моделей для агента.

## 11. Повторения и прогресс

### 11.1. Планировщик повторений

**FR-R1.** Алгоритм повторений — **SM-2**, реализованный полностью. Обучаемая модель памяти не реализуется (§22, §25).

**FR-R2.** Повторением считается любая активность с **силой свидетельства 1 и выше**. Устный ответ, SQL, свободный ответ, карточка — всё обновляет память по теме, но с разным весом.

**FR-R3.** Настройки: лимит новых в день, лимит повторов в день, максимальный интервал, поведение при провале, тихие дни, **граница суток** (во сколько начинается новый учебный день — по умолчанию 4:00, чтобы занятия ночью относились к предыдущему дню).

**FR-R4.** Очередь дня собирается алгоритмом с приоритетами: просроченные → по плану → новые, с перемешиванием по разделам и ограничением по прогнозируемому времени (алгоритм А1, §20).

**FR-R5. Прощение долга.** Если пропущено больше N дней, система предлагает не «догнать 200 повторений», а пересобрать очередь по приоритету и списать остаток. Накопленный долг не показывается как красное число без предложения выхода.

### 11.2. Статусы темы

**FR-R6.** Статусы и правила перехода:

| Статус | Условие |
|---|---|
| `нет материала` | привязок нет |
| `есть материал` | есть привязки, попыток не было |
| `разобран` | отмечено «разобрался» или ≥1 успешная попытка любой силы |
| `отработан` | набрано N успешных попыток силы ≥1 |
| `освоен` | `отработан` + последняя проверка успешна + пройдено ≥1 повторение по SM-2 |

**FR-R7.** Порог N выводится из уровня цели:

| Уровень цели | N | Дополнительно |
|---|---|---|
| Знать о существовании | 1 | — |
| Понимать | 2 | — |
| Уметь применять | 3 | — |
| Владеть свободно | 4 | минимум одна попытка силы 3 |

**FR-R8.** Правило перехода показывается пользователю по нажатию на статус (FR-G30).

### 11.3. Два показателя прогресса

**FR-R9.** Прогресс по проекту выражается **двумя независимыми числами**:

| Показатель | Определение | Куда идёт |
|---|---|---|
| **Пройдено** | доля тем в статусе `разобран` и выше | Темп, план, ощущение движения |
| **Подтверждено** | доля тем в статусе `отработан` и выше | Прогноз готовности |

**FR-R10.** Система **не упрекает** за расхождение между показателями. Прочитать и отметить галочкой — законный способ работы.

**FR-R11.** Прогноз готовности (§12) строится **только на подтверждённом**. При недостатке данных выводится «прогноз недоступен: недостаточно данных» вместо числа.

## 12. Планирование подготовки

**FR-S1.** У проекта может быть дата дедлайна. Тогда система строит **план до даты**: раскладывает темы по дням с учётом уровня цели и ограничений (лимит в день, не больше K новых, просроченные вперёд, темы одного раздела рядом). Алгоритм А3, §20.

**FR-S2. Прогноз готовности** — доля программы, которую пользователь будет помнить на дату экзамена при соблюдении плана. Показывается **интервалом, а не точкой**, с указанием, на скольких наблюдениях построен. При недостатке данных не показывается вовсе (FR-R11).

**FR-S3.** При отставании план пересчитывается, и система прямо говорит о последствиях, называя объём работы и предлагая приоритет: какие темы дадут наибольший прирост готовности за оставшееся время.

**FR-S4.** Темы уровня «знать о существовании» и «понимать» не расходуют бюджет плана наравне с «уметь применять» и «владеть свободно». Указание уровня по разделу — основной инструмент управления нагрузкой.

**FR-S5.** Режим без дедлайна: свободный темп, только повторения и мягкая дневная норма.

**FR-S6.** Долг переносится с настраиваемым правилом: догонять сразу, размазать по остатку, простить (FR-R5).

**FR-S7. Календарь нагрузки** вперёд: сколько повторений выпадет на каждый день ближайшего месяца.

**FR-S8.** Сквозная очередь дня между проектами не реализуется (§22). Приоритизация между проектами — задача пользователя, список проектов на главном экране показывает дедлайны и долг.

**FR-S9. Базовый план.** Планировщик всегда строит офлайновый детерминированный черновик. При семи и более учебных днях около 60% срока занимает первичный проход, дни между ним и финальным днём — повторения и пробелы, последний день — общее повторение с пониженной новой нагрузкой. При трёх–шести днях первичный проход занимает все дни кроме последнего. Если объём вопросов неизвестен, они распределяются равномерно; иначе используются уровень цели, тип активности, подпункты, объём эталона и фактическое время предыдущих попыток.

**FR-S10. Ручной план.** Пользователь может переносить вопрос или билет на дату и закреплять его. Закреплённый элемент сохраняет дату при пересчёте, пока закрепление не снято. Пересчёт показывает диф нагрузки и не применяет новую версию молча.

**FR-S11. Уточнение Плана моделью.** Внешняя модель может только предложить качественную оценку объёма, перенос тяжёлых элементов, порядок связанных вопросов и вариант восстановления после отставания. Перед запуском пользователь может свободным текстом указать ограничения и пожелания к распределению, например недоступный день; это пожелание входит в состав отправляемых данных и явно отражается в дифе. Модель не вычисляет прогноз готовности, не меняет SM-2 и не переносит вручную закреплённые элементы. Результат показывается дифом дней с причиной каждого изменения, применяется выборочно, маркируется машинным и отменяется одной командой. При выключенных внешних моделях базовый План остаётся полностью доступен.

**FR-S12. Отставание.** После пропуска система предлагает догнать сразу, распределить остаток по оставшимся дням, простить часть долга или рассмотреть модельный вариант приоритизации. Она всегда показывает объём и последствия каждого варианта; красный долг без действия не используется.

## 14. Telegram-бот

**FR-B1.** Бот — второй клиент к тому же серверу. Всё, что сделано в боте, немедленно видно в вебе и наоборот.

**FR-B2.** Привязка аккаунта одноразовым кодом из веб-интерфейса.

**FR-B3.** В боте доступны: сессия занятия, разбор ответа, «объясни» и «подсказка», свободный вопрос, карточки и их повторение, прогресс, инбокс, напоминания.

**FR-B4.** В боте **недоступны** функции, нечитаемые в формате чата: редактор SQL, редактирование программы, просмотрщик страницы с координатами, карта покрытия, «Пробелы» и «Неразобранное». Там бот присылает ссылку на веб.

**FR-B5.** Ответ принимается текстом, голосовым сообщением, кнопками самооценки — в зависимости от типа активности.

**FR-B6.** После ответа приходит разбор: оценка, что упущено, цитата из материала со ссылкой, кнопки «дальше», «показать материал», «отложить», «стоп».

**FR-B7.** Сессия прерывается в любой момент без потери прогресса и продолжается в вебе.

**FR-B8.** Типы напоминаний: по плану · по отставанию · по дедлайну · по накопленному долгу · утренняя сводка и вечерний добор.

**FR-B9.** Настройки: время, дни недели, тихие часы, **единый глобальный максимум сообщений в день поверх всех проектов**, отключение по проекту и глобально.

**FR-B10.** Напоминание всегда несёт кнопку немедленного действия («начать», «отложить на 2 часа», «не сегодня»).

**FR-B11.** Антиспам: после трёх подряд проигнорированных напоминаний частота автоматически снижается и бот предлагает изменить расписание.

**FR-B12.** Команда «Прогресс» присылает сводку: покрытие, пройдено и подтверждено, серия дней, что сделано за неделю, ближайший дедлайн, топ-3 просевших раздела.

**FR-B13.** Любое пересланное боту сообщение (текст, фото, документ, ссылка) попадает в **инбокс** выбранного проекта и разбирается: стать материалом, темой, заметкой или карточкой.

**FR-B14.** Сущности, созданные через бота, помечаются машинными и обратимы на общих основаниях (П3).

## 15. Подсистема внешних моделей

### 15.1. Роли

**FR-I1.** Полный реестр задач, где применяются внешние модели:

| Роль | Что делает |
|---|---|
| Автозаполнение паспорта цели | Один вызов, предлагает значения формы |
| Построение программы (проход 1) | Map-reduce по главам всех выбранных источников с учётом паспорта, ролей и приоритетов; проверка обязательных предпосылок |
| Соотнесение материала и тем (проход 2) | Классификация блоков батчами |
| Программа из знаний модели (слой 4) | Один вызов, метка «источника нет» |
| Помощник редактора программы | Предлагает структурные правки и недостающие материалы; изменения только через диф |
| Организация вопросов экзамена | Предлагает разделы, порядок и вероятные дубли плоского списка; только через диф |
| Оценка объёма и уточнение Плана | Предлагает качественный объём и выравнивает нагрузку поверх локального черновика |
| Восстановление Плана | Предлагает приоритетную версию после отставания; пользователь выбирает вариант |
| Извлечение задач из материала | Находит упражнения и их решения |
| Генерация активностей | Карточки, тесты, дистракторы |
| Сборка Урока | Предлагает storyboard и создаёт черновик блоков по выбранным Темам и разрешённым источникам |
| Проверка свободного ответа (ИИ-судья) | Оценка по рубрике с цитатами |
| Оценка полноты устного ответа | Какие ключевые пункты прозвучали |
| Агент свободного вопроса | Пишет код против API проекта |
| Объяснения и подсказки | Со ссылками на материал |
| Исполняемые демонстрации | Генерация запроса для показа ответа |
| Веб-исследование | По явному запросу находит внешние публикации и возвращает карточки с происхождением |
| Поиск иллюстраций | По явному запросу находит изображения в публикациях и возвращает их с атрибуцией |
| Учебные интерактивы | Создаёт декларативное описание графика, схемы, таблицы или сравнения сценариев |
| Студийные текстовые артефакты | Отчёты, Ментальные карты, Таблицы данных и черновики Карточек и Тестов по выбранным Темам и источникам |
| Студийные визуальные артефакты | Презентации и Инфографика с происхождением и цитатами |
| Студийные медиапересказы | Сценарий и сборка Аудиопересказа; доступность зависит от настроенного TTS |
| **Распознавание речи (STT)** | Транскрипт с пословными таймингами. Внешний сервис |

**FR-I2.** Каждую роль можно отключить отдельно. Есть глобальный тумблер «работать без внешних моделей». При выключении соответствующие функции становятся недоступны, и об этом сообщается прямо.

### 15.2. Механизмы обработки материала

**FR-I3. Проход 2 (полный перебор блоков) — основной механизм соотнесения.** Полнота обеспечивается конструкцией: каждый содержательный блок рассматривается ровно один раз.

**FR-I4. Поиск (BM25 + векторы) — вспомогательный механизм.** Применяется для: свободных вопросов простой формы, дельты при дозагрузке, работы без внешних моделей, подсказки кандидатов в интерфейсе. Результат поиска — не ответ, а набор фрагментов со ссылками.

**FR-I5.** Поиск **не используется как основной механизм привязки**. Обоснование: поиск оптимизирует топ-k под запрос и структурно оставляет часть материала непросмотренной (§25).

**FR-I6.** Векторные представления считаются **локальной моделью**, а не через внешний API — иначе нарушается П4.

### 15.3. Провайдеры и стоимость

**FR-I7.** Внешние модели подключаются через **единый OpenAI-совместимый интерфейс** — этого достаточно для OpenRouter, Groq, локальных серверов и большинства провайдеров. Отдельные адаптеры под каждого не пишутся.

**FR-I8.** Модель выбирается под каждую роль отдельно. Роль «агент свободного вопроса» требует модели, уверенно пишущей код; остальные роли работают на дешёвых моделях.

**FR-I9.** Ключи хранятся на сервере в зашифрованном виде и никогда не попадают на клиент.

**FR-I10.** Учёт расхода: токены и стоимость по каждому вызову, сводка по проекту, лимиты (дневной и на операцию) с предупреждением **до** превышения. Цены задаются в конфигурации с указанием даты актуальности — система не выдаёт их за проверенные.

**FR-I11.** Кэширование: одинаковый запрос по неизменившимся данным не оплачивается дважды. Проход 2 при дозагрузке считает только новые блоки (FR-M13).

**FR-I12.** Перед отправкой материала во внешнюю модель система показывает **объём и состав отправляемого** и запрашивает подтверждение при превышении настраиваемого порога.

**FR-I13.** Недоступность провайдера — штатное состояние интерфейса, а не ошибка: система сообщает и продолжает работать в детерминированном режиме.

**FR-I14.** Веб-исследование доступно из Материалов, Пробелов, Чата, Уроков и Студии, но не является пятым способом сформировать программу и не влияет на метрики покрытия само по себе. Найденная публикация начинает участвовать в Программе и покрытии только после явного добавления как Материала и обычного разбора.

## 16. Устная речь

**FR-W1.** Устный ответ записывается в браузере или присылается голосовым сообщением в бот.

**FR-W2. Распознавание — внешний сервис (Groq Cloud, Whisper).** Транскрипт запрашивается с **пословными таймингами** (`timestamp_granularities: ["word"]`).

**FR-W3.** Облачное распознавание **вычищает слова-паразиты, запинки и фальстарты**. Это принято сознательно. Метрики по паразитам не реализуются и не имитируются: их отсутствие фиксируется явно, а не скрывается.

**FR-W4.** Метрики, доступные на очищенном транскрипте с таймингами: **темп речи, время до начала ответа, длительность и число пауз, доля молчания**.

**FR-W5. Проверка устного ответа — содержательная:** транскрипт сверяется с ключевыми пунктами темы тем же движком, что и текстовый ответ (§9).

**FR-W6.** Устный ответ и метрики речи — **два независимых модуля**. Замена провайдера распознавания на локальный verbatim-вариант (CrisperWhisper, §22) не требует переделки устного ответа.

**FR-W7.** Исходное аудио сохраняется вместе с попыткой. Политика хранения настраивается: по умолчанию аудио хранится ограниченный срок или до заданного объёма, транскрипт и метрики — бессрочно.

**FR-W8.** Две попытки одной темы можно сравнить рядом: транскрипты, метрики, подсветка различий.

**FR-W9.** При включении устного ответа система показывает, что аудио будет отправлено внешнему сервису (П7).

## 19. Нефункциональные требования

| **NFR-7** | Все ключи и секреты — только на сервере, в зашифрованном виде |
| **NFR-8** | Выполнение сгенерированного кода — только в изолированной среде с лимитами времени, памяти и размера вывода |
| **NFR-9** | Пользовательские данные отправляются только явно настроенным провайдерам и только для включённой операции: показанные фрагменты извлечённого текста и параметры запроса — модели, аудио — распознаванию речи. | **NFR-11** | Работа без интернета для всех детерминированных функций (П4) |
| **NFR-12** | Интерфейс на русском, архитектура допускает локализацию |
| **NFR-13** | Адаптивная вёрстка: настольная как основная, мобильный веб — как минимум для сессии повторения |
| **NFR-14** | Полная навигация с клавиатуры в сессии повторения и в очереди предложений |

| **NFR-17** | Свёрнутая Студия остаётся доступной узкой правой полосой и не уменьшает рабочую область больше чем на 72 px; раскрытие управляется кнопкой с `aria-expanded`, состояние сохраняется по проекту, а все иконки имеют доступные названия и клавиатурный фокус |

### Алгоритмы для блок-схем записки

**А1. Составление очереди дня.** Отбор просроченных, плановых и новых по проекту; приоритет по дедлайну и уровню цели; лимиты по числу и прогнозируемому времени; перемешивание по разделам; откат при переполнении; прощение долга.

**А2. Соотнесение материала и программы (проход 2).** Обход содержательных блоков батчами; классификация на три исхода; применение привязок при однозначном решении и отправка в очередь предложений при неоднозначном; чекпоинт по счётчику; подсчёт двух метрик покрытия.

**А3. Обратный планировщик до даты.** Распределение N тем по D дням с учётом уровня цели; расчёт прогноза готовности с интервалом; пересчёт при отставании.

**А4 (запасной).** Построение программы из материала (проход 1): map по главам, reduce со слиянием дублей.
**А5 (запасной).** Конвейер разбора материала с автодетекцией сканов и OCR.

## 21. Экраны

### Проектные

1. **Проекты** — короткие карточки активных проектов, продолжение и повторение, архив и общая сводка
2. **Мастер создания проекта** — общая развилка и три ветки; для экзамена — структура, входы, паспорт и проверка импорта; для учебника — источники с ролями, быстрый анализ, предложенный паспорт, проверка стоимости, прогрессивное построение, редактор «программа + помощник», итоговая сводка и возобновляемый черновик
3. **Рабочая область проекта** — дерево программы, Среда выбранной темы и постоянная правая Студия; компактная экзаменационная и развёрнутая учебная конфигурации
4. **Уроки** — одиночное и массовое создание, редактор блоков, статусы и переход к изучению в Рабочей области
5. **Карта покрытия** — аналитическая таблица программы со статусами и фильтрами, вкладка статистики
6. **Покрытие** — два таба: «Пробелы» и «Неразобранное»; из Пробелов запускается явный поиск источников с запросом по Теме
7. **Программа / Вопросы экзамена** — одна поверхность редактора дерева с пользовательским названием по шаблону. Для экзамена: массовый ввод, импорт и группировка; для учебника: дерево/текст/вопросы, ручные правки, помощник справа, темы без материала; для обоих: уровни цели пачкой и пересборка с дифом
8. **Материалы проекта** — поиск внешних источников, явный импорт результатов, список файлов, прогресс разбора, качество распознавания, дельта
9. **Просмотрщик источника** — страница с подсветкой фрагментов и привязок, ручная привязка выделением
10. **Очередь предложений** — быстрый разбор неоднозначных привязок клавиатурой
11. **Сессия занятия** — единый каркас под все виды активностей, включая редактор SQL и разбор ответа
12. **Карточки** — банк, фильтры, редактор, режим повторения
13. **План подготовки** — календарь до дедлайна, прогноз готовности
14. **Инбокс** — что прислали через бота
15. **Настройки проекта** — свойства и модули проекта, паспорт цели; проектные модели и лимиты, напоминания, пользовательский шаблон и экспорт добавляются здесь вместе со своим серверным контуром

### Глобальные

16. **Библиотека материалов** — общие файлы установки, качество, использующие их проекты и последствия удаления
17. **Параметры установки** — внешние модели, бот, резервные копии и файловое хранилище

Настройки проекта действуют только внутри одного учебного проекта и не меняют его подход к обучению: по FR-P8 другой вариант Рабочей области создаётся отдельным проектом. Параметры установки действуют глобально; учётные данные провайдеров, бот, резервные копии и хранилище не дублируются в проектах.

## 22. Чего мы НЕ делаем

**Принципиально не входит в продукт:**

- **Не чат с документом.** Свободные вопросы разрешены, но это не главный сценарий и всегда со ссылками на материал.
- **Не универсальная база знаний.** Никакого извлечения «фактов» — только привязки со ссылкой на страницу.
- **Не платформа онлайн-курсов.** Нет авторов, учеников, продаж, проверки преподавателем.
- **Не соцсеть.** Нет лент, лайков, рейтингов, публичных профилей.
- **Не coding-агент.** Песочница выполняет демонстрации и код агента, а не пишет за пользователя решение.
- **Не мобильное приложение.** Мобильный сценарий закрывается ботом и адаптивным вебом.
- **Не многопользовательская система.** Одна установка — один пользователь.
- **Не система, объявляющая ответ верным без объяснения.** Любая оценка объяснима и оспорима.

**Отложено** (реализуется без переделки архитектуры):

| Что | Почему отложено |
|---|---|
| Интервью как ветвящийся сценарий | Форма с автозаполнением даёт почти всю пользу за долю работы |

## 25. Обоснование ключевых решений

Методичка ТРПС требует прямо: обоснований вида «удобнее» и «целесообразнее» быть не должно — надо пояснить, **чем** удобнее и **почему** целесообразно. Ниже три решения, определяющие архитектуру, с основаниями.

### 25.1. Почему полный перебор блоков, а не поиск

**Основание структурное.** Поиск перебирает *запросы* и возвращает по каждому топ-k. Блок материала, не попавший ни в один топ, не просматривается вообще и молча исчезает. Полный перебор идёт по *блокам* и рассматривает каждый ровно один раз — потерять нечего по построению.

**Основание эмпирическое.** В работе [Recursive Language Models](https://arxiv.org/abs/2512.24601) (MIT CSAIL, 2026) сравниваются подходы к обработке длинного контекста на задачах разной сложности. На OOLONG — задаче, где ответ зависит почти от каждой строки входа, то есть структурно совпадающей с нашей задачей соотнесения, — агент с BM25-поиском набирает **38.0** против **44.0** у модели вообще без поиска и **56.0** у рекурсивного подхода. На OOLONG-Pairs (попарное сопоставление) — 24.7 против 58.0.

Вывод: на задачах, где нужен весь вход, поиск не просто уступает — он хуже отсутствия поиска.

### 25.2. Почему фиксированный проход, а не агент

Форма задач соотнесения и построения программы известна заранее, поэтому цикл пишется один раз инженером. Фиксированный проход выигрывает у агента по четырём осям, каждая из которых для нас обязательна:

| Свойство | Фиксированный проход | Агент |
|---|---|---|
| Повторный запуск на тех же данных | тот же результат | результат меняется |
| Чекпоинт (FR-M14) | счётчик обработанных единиц | естественного чекпоинта нет |
| Оценка стоимости до запуска (FR-M4) | точное число | в источнике разброс до ±$3.25 при среднем $1.10 |
| Блок-схема для записки | рисуется | код порождается в рантайме, схемы нет |

Агент оставлен ровно там, где форма задачи неизвестна и цикл не написать заранее, — на свободном вопросе (§6.6).

### 25.3. Почему SM-2, а не обучаемая модель памяти

Для честного сравнения обучаемой модели с SM-2 и FSRS нужна выборка повторений с интервалами в месяцы. За семестр у одного пользователя основная масса наблюдений придётся на интервалы 1–14 дней, правый хвост будет пуст, и сравнение по log-loss даст шум. Вывод на вырожденной выборке хуже отсутствия вывода, поэтому обучаемая модель отложена, а SM-2 реализуется полностью.

## 26. Соответствие требованиям курсовой

| Требование методички | Чем закрывается |
|---|---|
| Диаграмма вариантов использования | ~20 прецедентов, актор «Обучающийся», внешние системы: Telegram, провайдер модели, сервис распознавания речи |
| Концептуальная модель предметной области | §20, около 30 сущностей со связями |
| Диаграмма состояний интерфейса | Сессия занятия: выдача → ответ (текст/голос/SQL) → проверка → разбор → следующая/конец, с ветками «нет микрофона», «модель недоступна», «ошибка выполнения», «отложить» |
| Структурная схема | Клиент · API · Воркер · Обработчик материалов (OCR) · Поисковый индекс · Формирователь программы · Движок активностей · Движок проверки · Песочница · Планировщик · Шлюз моделей · Бот |
| Информационные потоки | Файл → страницы → блоки → фрагменты → привязки ↔ темы → активности → попытки → повторения → план → напоминания |
| 2–3 алгоритма схемой с таблицей переменных | А1, А2, А3 (§20) |
| Обоснование проектных решений | §25 — три ключевых решения с основаниями, включая ссылку на литературу |
| Стратегия тестирования | Юнит (разбиение на блоки, планировщик, интервалы SM-2, нормализация ответов, сравнение результатов SQL) · обработка данных (парсер на подготовленных PDF и сканах, сверка OCR по расстоянию Левенштейна) · серверные тесты API · функциональные Playwright · ошибочный ввод (битый PDF, пустой файл, PDF без текста, превышение размера, запрос с ошибкой синтаксиса) · режимы работы |
| Демонстрация в различных режимах | Три входа (§2), работа без внешних моделей, два проекта по одному предмету (FR-P8) |
| Пользовательская документация | README + руководство пользователя (приложение Б записки) |

### Сценарии демонстрации на защите

1. **Вход A.** Методичка + файл ответов + список билетов → программа импортом → карта покрытия. Полностью офлайн.
2. **Вход B.** Одна методичка → проход 1 строит программу → проход 2 → экран «Неразобранное»: что в материале есть сверх программы.
3. **Вход C.** «Хочу разобраться в векторных БД» → программа из знаний модели с меткой «источника нет», покрытие 0% → добавление материалов → пробелы закрываются.
4. **Свободный вопрос агентом.** «Что есть в методичке про транзакции, чего нет в файле с теорией?»
5. **Без внешних моделей.** Тумблер выключен: программа по оглавлению, поиск, карточки, тесты, SM-2, план.
6. **Бот.** Напоминание → ответ голосом в Telegram → продолжение в вебе с того же места.
