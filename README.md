# Tentex

Локальная однопользовательская система подготовки к экзамену. Курсовая по ТРПС, МГТУ им. Баумана.

Сейчас работает экзаменационный контур: проекты и Программа, импорт вопросов и ответов, материалы, поиск и ручные привязки, чат, конспекты, календарная подготовка и карточки. Целевое отличие продукта — программа из материалов и измеримое покрытие в обе стороны — ещё не реализовано полностью.

Данные хранятся локально. Детерминированные функции работают без внешних моделей; облачный OCR, модельные роли, сетевые источники и загрузка пакетов Typst требуют сети и явного запуска.

## Запуск

Нужны Node **>=22.12.0** и Python 3.13+.

### API и фронтенд для разработки

```bash
npm install
cd frontend && npm install
cd ../backend && pip install -r requirements-dev.txt
```

Из корня в двух терминалах:

```bash
npm run dev:api
npm run dev:web
```

Этого достаточно для API и интерфейса, но не для обработки материалов.

### Полный локальный контур

Для worker, локального OCR и аудио дополнительно нужны зависимости `backend/requirements-worker.txt`. Для сборки Typst нужен CLI Typst 0.15.1 в `PATH` либо путь в `TENTEX_TYPST_BINARY`.

```bash
cd backend && pip install -r requirements-worker.txt
cd .. && npm run dev
```

`npm run dev` поднимает API, worker и frontend. Модели OCR устанавливаются и проверяются в `Параметры → Распознавание`; системные зависимости Paddle различаются по платформам.

Рекомендуемый полный запуск — контейнеры: worker-образ уже содержит зависимости OCR и Typst 0.15.1.

```bash
docker compose up
```

Фронтенд — http://localhost:5173, API — http://localhost:8000, документация API — http://localhost:8000/docs.

## Проверка

```bash
npm run typecheck && npm run build
cd backend && python -m pytest
```

Фронтенд проверяется typecheck и сборкой: общей команды `npm test` нет. На бэкенде используются pytest и `python -m ruff check .`. Эти команды здесь перечислены, но для синхронизации документации на commit `9acd0f7` заново не запускались; датированные результаты прежних прогонов сохранены в `STATUS.md`.

Сквозные проверки по подсистемам лежат в `backend/scripts/`: `check_stage2` … `check_stage5`, `check_manual_binding`, `check_ai_gateway`, `check_exam_chat`, `check_library_workspace`, `check_typst_material.py`. Регрессионные сценарии карточек, Подготовки и фоновых задач находятся в backend pytest-наборе.

Уровень логов — переменная `TENTEX_LOG_LEVEL` (по умолчанию `INFO`).

## Состояние

Срез на 09.09.2026 для commit `9acd0f78167a6e3d0b2f79479cfc99139b1ee298`; подробности и исторические контрольные точки — в `STATUS.md`.

Работают: экзаменационные проекты и ручная Программа, импорт вопросов и ответов, Библиотека, локальный и облачный OCR с формулами, Typst через отдельный вход Библиотеки (`.typ`, папка, ZIP), FTS5/BM25, ручные привязки и специализированная раскладка файла ответов, экзаменационный чат, конспекты, «Моя подготовка», карточки экзаменационного проекта и единый `BackgroundJob`.

Не реализованы как пригодный сквозной сценарий: учебниковое и свободное обучение, программа из материалов, проходы 1–2, embeddings/vector и общее двустороннее покрытие. Следующая **предлагаемая**, ещё не реализуемая итерация объединяет эти сценарии с гибридным lexical+vector поиском в обоих направлениях: программа → материал и материал → программа. Модель эмбеддингов и векторный движок не выбраны. Уроки исключены продуктовым решением, но их demo/localStorage-код пока остаётся; Студия и GPU OCR удалены, авторизация не входит в продукт.
