# Tentex

Локальная однопользовательская система подготовки к экзамену. Курсовая по ТРПС, МГТУ им. Баумана.

Сейчас работают два контура. Экзаменационный: проекты и Программа, импорт вопросов и ответов, материалы, поиск и ручные привязки, чат, конспекты, календарная подготовка и карточки. Учебниковый: мастер с оглавлением источника, Программа учебника (ручной редактор, импорт оглавлений и чат построения с дифами) и Уроки без модели — быстрый урок, ручной редактор, массовая подготовка и прохождение. Целевое отличие продукта — программа из материалов и измеримое покрытие в обе стороны — ещё не реализовано полностью: проход 2, embeddings и обе метрики покрытия впереди.

Данные хранятся локально. Детерминированные функции работают без внешних моделей; облачный OCR, модельные роли, сетевые источники и загрузка пакетов Typst требуют сети и явного запуска.

## Быстрый запуск: Windows

1. Один раз установите [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/),
   включите backend WSL 2 и запустите Docker Desktop. Если установщик просит
   перезагрузить компьютер, выполните перезагрузку. Нужен режим Linux containers.
2. Скачайте ZIP проекта с GitHub и **распакуйте** его в обычную доступную для
   записи папку, либо клонируйте репозиторий. Не запускайте CMD прямо из ZIP.
3. Откройте **`Запустить Tentex.cmd`** двойным кликом. При первом запуске
   собираются образы, поэтому нужны интернет и свободное место для Docker.
4. После готовности интерфейса и фонового обработчика браузер откроется сам:
   **http://localhost:5173**.

Python, Node и Git для запуска из ZIP не нужны. Docker Desktop запускатор
открывает сам, если он установлен, но выключен. Установку Docker/WSL и
системную перезагрузку пользователь выполняет один раз по инструкции Docker.

| Файл | Действие |
|---|---|
| `Запустить Tentex.cmd` | Запускает приложение; при изменении исходников пересобирает контейнеры |
| `Остановить Tentex.cmd` | Останавливает только Tentex, сохраняя данные и образы |
| `Обновить Tentex.cmd` | Получает новую версию, сохраняет копию данных, пересобирает и запускает |
| `Диагностика Tentex.cmd` | Показывает контейнеры, последние логи и пути; оставляет окно открытым |

Повторный запуск без изменений использует установленную сборку без скачивания
образов. Если Tentex уже работает, открывается его интерфейс. Закрытие браузера
не останавливает серверы — для освобождения ресурсов откройте файл остановки.
Офлайновые функции работают после установки; модели OCR/поиска устанавливаются
отдельно в Параметрах и тоже требуют интернета при первой загрузке.

### Обновление и локальные правки

- **Git-клон:** файл обновления получает upstream текущей ветки и применяет
  только fast-forward. Нужны Git и настроенная tracking-ветка. При локальных
  правках, новых неотслеживаемых файлах или расходящейся истории обновление
  останавливается, ничего не перезаписывая.
- **ZIP:** файл обновления скачивает `main` публичного репозитория
  `tneki22/Tentex` с GitHub, Git не нужен. Отпечатки файлов сохраняются при
  первом запуске; изменения исходников после него блокируют автоматическую
  замену. Личные файлы, `.env`, данные и модели сохраняются. Удалённые из новой
  версии исходники удаляются только из ранее учтённого состава проекта.
  До публикации репозитория и запускатора в `main` скачивание недоступно.
- **Разработка:** после локальных изменений достаточно снова открыть файл
  запуска. Он замечает изменения приложения, пересобирает образы и пересоздаёт
  изменённые контейнеры. Для загрузки удалённых изменений используйте обновление.

До замены версии сервисы останавливаются. Копия базы, WAL, материалов, настроек
и `installation.secret` сохраняется в `.tentex-launcher/updates/<дата>/data/`.
Модели и прежние резервные копии не дублируются и остаются в `data/`.
Для ZIP рядом сохраняются прежние исходники, для Git — идентификатор коммита.
Если обновление или сборка оборвались, копия остаётся; исправьте ошибку и
повторите запуск. После миграций базы не откатывайте только код: сначала
остановите Tentex и восстановите согласованные код и данные из копии.

Папка **`data/`** содержит пользовательские данные и ключ шифрования настроек:
не удаляйте её при обновлении. Журналы, отпечатки и копии запускатора находятся
в `.tentex-launcher/`; эта папка тоже не публикуется в Git. Копии обновлений
автоматически не удаляются — после проверки новой версии старые можно убрать.

При ошибке окно остаётся открытым. Используйте диагностику. Для второй
установки задайте в её `.env` другое `COMPOSE_PROJECT_NAME` и свободные
`TENTEX_WEB_PORT`, `TENTEX_API_PORT`, `TENTEX_SEARXNG_PORT`. Путь с пробелами
и кириллицей поддерживается. Две копии одной установки одновременно не запускайте.

## Docker из терминала: Windows и Linux

На Linux нужны Docker Engine и плагин Compose; на Windows — Docker Desktop.
Команды выполняются из распакованной папки проекта. API и web доступны только
на локальном компьютере.

```bash
# Первая установка или применение изменённых исходников
docker compose up -d --build --wait

# Повторный запуск установленной версии, в том числе без сети
docker compose up -d --no-build --pull never --wait

# Остановка без удаления данных
docker compose stop --timeout 60

# Диагностика
docker compose ps --all
docker compose logs --tail 60
```

Интерфейс — http://localhost:5173, API — http://localhost:8000,
документация API — http://localhost:8000/docs. Модели устанавливаются через
интерфейс; конфигурация API-ключей для первого запуска не нужна.

Обновление Git-клона на Linux, после сохранения собственных правок
(`git status --short` должен быть пустым):

```bash
git fetch
docker compose stop --timeout 60
# Согласованная копия существующей установки после остановки писателей
cp -a data "../tentex-data-before-update-$(date +%Y%m%d-%H%M%S)"
git pull --ff-only
docker compose up -d --build --wait
```

Для ZIP на Linux: остановите прежнюю установку, сохраните копию `data/`,
скачайте и распакуйте новую версию **в отдельную папку**, скопируйте туда
прежние `data/` и `.env` (если он был), затем выполните первую команду запуска.
Старую папку сохраняйте до проверки новой версии. Не накладывайте ZIP поверх
прежнего кода: там могут остаться файлы, удалённые в новой версии.

## Запуск из исходников для разработки

Нужны Node **>=22.12.0** и Python 3.13+.

### API и фронтенд для разработки

```bash
npm install
cd frontend && npm install
cd ../backend && pip install -r requirements-dev.txt
```

Из корня в двух терминалах:

```bash
npm run dev:api
npm run dev:web
```

Этого достаточно для API и интерфейса, но не для обработки материалов.

### Полный локальный контур

Для worker, локального OCR и аудио дополнительно нужны зависимости `backend/requirements-worker.txt`. Для сборки Typst нужен CLI Typst 0.15.1 в `PATH` либо путь в `TENTEX_TYPST_BINARY`.

```bash
cd backend && pip install -r requirements-worker.txt
cd .. && npm run dev
```

`npm run dev` поднимает API, worker и frontend. Модели OCR устанавливаются и проверяются в `Параметры → Распознавание`; системные зависимости Paddle различаются по платформам.

Рекомендуемый полный запуск — контейнеры: worker-образ уже содержит зависимости OCR и Typst 0.15.1.

```bash
docker compose up --build -d
```

Фронтенд — http://localhost:5173, API — http://localhost:8000, документация API — http://localhost:8000/docs.

Обычный контейнерный запуск отдаёт готовую сборку интерфейса и не включает
автоперезагрузку API. Для разработки с автоперезагрузкой:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

После изменения фронтенда в обычном запуске пересоберите web:
`docker compose up -d --build web`.

Руководство пользователя доступно внутри приложения по кнопке с книгой
в нижней части боковой панели.

## Проверка

```bash
npm run typecheck && npm run build
cd backend && python -m ruff check app migrations
```

Тесты, бенчмарки, диагностические скрипты и внутренняя документация разработки
сохраняются в локальном рабочем окружении автора и не входят в публичный checkout.
Для запуска приложения они не нужны.

Уровень логов — переменная `TENTEX_LOG_LEVEL` (по умолчанию `INFO`).

## Состояние

Срез на 24.09.2026.

Работают: экзаменационные проекты и ручная Программа, импорт вопросов и ответов, Библиотека, локальный и облачный OCR с формулами, Typst через отдельный вход Библиотеки (`.typ`, папка, ZIP), FTS5/BM25, ручные привязки и специализированная раскладка файла ответов, экзаменационный чат, конспекты, «Моя подготовка», карточки экзаменационного проекта и единый `BackgroundJob`. В учебниковом контуре: мастер, оглавление источника, Программа учебника (ручной редактор, импорт оглавлений одной транзакцией, чат построения с дифами и отменой) и Уроки — быстрый урок по диапазону оглавления, ручной редактор с точными кусками, медиа и переносом границ при новой ревизии, массовая подготовка черновиков и прохождение урока. Общий гибридный поиск (FTS5/BM25 + embeddings на `sqlite-vec`, слияние RRF) обслуживает поиск по проекту и Библиотеке и учебный чат с проверяемыми цитатами.

Свободное изучение (24.09.2026): мастер «Цель → Материалы → Программа → Проверка», программа по цели в чате с дифами и подсказками «Где искать» у тем без источника, подбор материалов Библиотеки без модели, «Материалы к темам», «Урок из найденного» для темы без оглавления. Поиск материалов в интернете — чат в «Материалах» на локальном SearXNG.

Не реализованы как пригодный сквозной сценарий: автоматическая программа из материала (проход 1), каталог эталонных программ, общее двустороннее покрытие (проход 2 на паузе), ИИ-сборка и дополнение урока, задания урока и «Занятия» учебникового проекта. Студия и GPU OCR удалены, авторизация и многопользовательность не входят в продукт.
