## Начало сессии

1. Загляни в `PLAN.md` — какой этап сейчас идёт.
2. Возьми `skill-router`, если задача не однострочная.
3. Проектируешь или верстаешь экран — `tentex-screens`. Нужен компонент — `tentex-ui-kit`.

## Проверка

Перед словом «готово» — запусти и покажи вывод:

```bash
npm run typecheck && npm run build
```

Тестов в проекте пока нет — оснастка вернётся на этапе 5. Пока вместо них: сборка, а для экранов — посмотреть глазами через `preview_start`.

Скилл `verification-before-completion` про это же: сначала доказательство, потом утверждение. Если проверка упала — так и скажи, с выводом. Пропустил шаг — скажи, что пропустил.

## Что делать без вопросов, а что нет

Без спроса: править код, запускать сборку и проверки, поднимать dev-сервер, читать что угодно в проекте.

Спросить сначала: менять решение из §23 требований (стек) · добавлять зависимость · трогать `BRIEF.md`, `REQUIREMENTS.md`, `PLAN.md` · коммитить и пушить · удалять данные из `data/`.

`virtex/` — только чтение. Это прошлый проект, он лежит рядом как справочник.

## Инструменты

- Индекс кода: `codebase-memory-mcp` (`search_graph`, `trace_path`, `get_code_snippet`, `get_architecture`). Проект проиндексирован под именем `Tentex` — используй его в параметре `project`, не создавай второе имя. Если `index_status` показывает `head_sha`, отличный от текущего `git rev-parse HEAD`, перед работой освежи индекс через `index_repository`.
- Документация библиотек: скилл `find-docs` или `npx ctx7@latest`. Не отвечай по памяти про версии и API — стек свежий.
- Посмотреть приложение живьём: `preview_start` с конфигурацией `web` из `.claude/launch.json`, дальше браузерные инструменты.
