# CLAUDE.md

Правила проекта живут в `AGENTS.md` — один файл на всех агентов. Он подключается целиком:

@AGENTS.md

Ниже только то, что касается Claude Code.

## С чего начать

Начни с `STATUS.md`: это текущее состояние. Затем открой только относящиеся к задаче источники по иерархии из `AGENTS.md`: `PLAN.md` для текущей работы, `REQUIREMENTS.md` для желаемых требований, `SCREENS.md` для текущего интерфейса, код и релевантный `docs/architecture/*.md` для реализованного контракта. Для конвейера Библиотеки начни также с `LIBRARY_FILE_PROCESSING.md`. Читать все эти документы целиком перед каждой правкой не надо.

Скиллов четыре, берёшь сам: `tentex-ui` — экраны, компоненты, стили · `tentex-api` — бэкенд · `tentex-code-quality` — ревью своей правки, резка модулей · `better-ui` — отделка деталей поверх `tentex-ui`.

Цикл правки (сборка → `docker compose restart` → коммит) — в `AGENTS.md`, он общий для всех агентов. Смотреть глазами здесь — `preview_start` с конфигурацией `web`.

## Границы

Без спроса: править код, запускать сборку и проверки, поднимать dev-сервер, читать что угодно в проекте, коммитить проверенную правку, перезапускать контейнеры.

Тесты и проверки здесь локальные, на одноразовых данных, без доступа наружу. Гоняй их, чини падения от своей правки и перегоняй — не спрашивая разрешения на каждом шаге.

Спросить сначала: менять решение по стеку · добавлять зависимость · трогать `BRIEF.md`, `REQUIREMENTS.md`, `PLAN.md` · **пушить** в удалённый репозиторий или создавать/обновлять PR · удалять данные из `data/`. Явный запрос пользователя в текущей задаче даёт разрешение только на названное внешнее действие; общий цикл правки никогда не включает push/PR автоматически.

`virtex/` — только чтение. Это прошлый проект, он лежит рядом как справочник.

## Инструменты

- Индекс кода: `codebase-memory-mcp` (`search_graph`, `trace_path`, `get_code_snippet`, `get_architecture`). Проект проиндексирован под именем `Tentex` — используй его в параметре `project`, не создавай второе имя. Если `index_status` показывает `head_sha`, отличный от текущего `git rev-parse HEAD`, перед работой освежи индекс через `index_repository`.
- Документация библиотек: `npx ctx7@latest`. Не отвечай по памяти про версии и API — стек свежий.
- Посмотреть приложение живьём: `preview_start` с конфигурацией `web` из `.claude/launch.json` запускает только frontend. Для сценария с API и фоновыми задачами используй `full` — он поднимает api, один worker и web; один `web` такой сценарий не проверяет.

## Мелочи

- Интерфейс и документы — по-русски. Идентификаторы — по-английски.
- Длинные объяснения не нужны. Сделал — скажи что и где, одной-двумя строками.
- Не переписывай в код то, что уже написано в `REQUIREMENTS.md` — сошлись на файл, а не пересказывай.
