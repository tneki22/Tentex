## Начало сессии

1. Загляни в `PLAN.md` — какой этап сейчас идёт.
2. Возьми `skill-router`, если задача не однострочная.
3. Трогаешь экран, компонент или стили — `tentex-ui`. Трогаешь бэкенд — `tentex-api`.
4. Пишешь новый модуль, режешь старый или ревьюишь свою правку — `tentex-code-quality`.

## Проверка

Перед словом «готово» — запусти и покажи вывод:

```bash
npm run typecheck && npm run build
```

На фронтенде тестов нет — вместо них сборка, а для экранов посмотреть глазами через `preview_start`. На бэкенде есть pytest: трогаешь бэкенд — прогоняй `cd backend && python -m pytest`.

Скилл `verification-before-completion` про это же: сначала доказательство, потом утверждение. Если проверка упала — так и скажи, с выводом. Пропустил шаг — скажи, что пропустил.

## Что делать без вопросов, а что нет

Без спроса: править код, запускать сборку и проверки, поднимать dev-сервер, читать что угодно в проекте, **коммитить проверенную правку и перезапускать контейнер**.

Правка не закончена, пока не закоммичена. Порядок один и тот же для каждой задачи, не только в конце сессии:

1. `npm run typecheck && npm run build` (и `pytest`, если тронут бэкенд) — вывод показан, зелёный.
2. `docker compose restart web` (или `api web`, если менялся бэкенд/миграции/данные) — и проверка глазами через `preview_start`, если это видно в браузере.
3. `git add` конкретных файлов → commit с осмысленным сообщением.

Не оставляй проверенную и рабочую правку не закоммиченной «на потом» — потом её не существует, следующая сессия её не увидит и всё придётся объяснять заново.

Спросить сначала: менять решение из §23 требований (стек) · добавлять зависимость · трогать `BRIEF.md`, `REQUIREMENTS.md`, `PLAN.md` · **пушить** в удалённый репозиторий · удалять данные из `data/`.

`virtex/` — только чтение. Это прошлый проект, он лежит рядом как справочник.

## Инструменты

- Индекс кода: `codebase-memory-mcp` (`search_graph`, `trace_path`, `get_code_snippet`, `get_architecture`). Проект проиндексирован под именем `Tentex` — используй его в параметре `project`, не создавай второе имя. Если `index_status` показывает `head_sha`, отличный от текущего `git rev-parse HEAD`, перед работой освежи индекс через `index_repository`.
- Документация библиотек: скилл `find-docs` или `npx ctx7@latest`. Не отвечай по памяти про версии и API — стек свежий.
- Посмотреть приложение живьём: `preview_start` с конфигурацией `web` из `.claude/launch.json`, дальше браузерные инструменты.
