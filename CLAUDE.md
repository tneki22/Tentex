## С чего начать

`STATUS.md` — что реально работает и какая вертикаль идёт сейчас. Остальные документы открывай, когда задача их касается: таблица в `AGENTS.md`. Читать `PLAN.md` и `REQUIREMENTS.md` целиком перед каждой правкой не надо.

Скиллов четыре, берёшь сам: `tentex-ui` — экраны, компоненты, стили · `tentex-api` — бэкенд · `tentex-code-quality` — ревью своей правки, резка модулей · `better-ui` — отделка деталей поверх `tentex-ui`.

Цикл правки (сборка → `docker compose restart` → коммит) — в `AGENTS.md`, он общий для всех агентов. Смотреть глазами здесь — `preview_start` с конфигурацией `web`.

## Границы

Без спроса: править код, запускать сборку и проверки, поднимать dev-сервер, читать что угодно в проекте, коммитить проверенную правку, перезапускать контейнеры.

Тесты и проверки здесь локальные, на одноразовых данных, без доступа наружу. Гоняй их, чини падения от своей правки и перегоняй — не спрашивая разрешения на каждом шаге.

Спросить сначала: менять решение из §23 требований (стек) · добавлять зависимость · трогать `BRIEF.md`, `REQUIREMENTS.md`, `PLAN.md` · **пушить** в удалённый репозиторий · удалять данные из `data/`.

`virtex/` — только чтение. Это прошлый проект, он лежит рядом как справочник.

## Инструменты

- Индекс кода: `codebase-memory-mcp` (`search_graph`, `trace_path`, `get_code_snippet`, `get_architecture`). Проект проиндексирован под именем `Tentex` — используй его в параметре `project`, не создавай второе имя. Если `index_status` показывает `head_sha`, отличный от текущего `git rev-parse HEAD`, перед работой освежи индекс через `index_repository`.
- Документация библиотек: `npx ctx7@latest`. Не отвечай по памяти про версии и API — стек свежий.
- Посмотреть приложение живьём: `preview_start` с конфигурацией `web` из `.claude/launch.json`, дальше браузерные инструменты.
