# Руководство пользователя

Рабочий документ по руководству: замысел, согласованная структура, что уже сделано и как писать страницы. Сам текст руководства — не здесь, а в `frontend/src/screens/guide/pages/*.md`. Экран описан в `SCREENS.md`, раздел «Руководство пользователя».

Живёт в ветке `fresh-install`: руководство пишется на стенде с чистой базой (`scripts/fresh.ps1`), чтобы видеть Tentex глазами человека после первой установки. Проблемы и непонятки, которые всплывают при настройке с нуля, заносятся в [Журнал наблюдений](#журнал-наблюдений) — из них вырастает содержание страниц.

## Замысел

- Экран открывается кнопкой с книгой в подвале левой панели. Пока руководство ни разу не открывали, кнопка подсвечена (акцентная точка и расходящееся кольцо), чтобы позвать. Открыли один раз — подсветка гаснет навсегда.
- Руководство запоминает страницу. При следующем открытии оно возвращается на последнюю прочитанную, а не на первую. Явная ссылка (`/guide?section=…`) важнее запомненного.
- Слева дерево разделов, справа текст. Заголовок в верхней полосе — «Руководство пользователя».
- Первая страница — «Знакомство»: приветствие и развилка «создать проект в одном из трёх режимов» либо «настроить полезные функции» (провайдеры, модели эмбеддингов, модели текста и речи). Кратко: подробности — в следующих разделах.
- В наполнении будут фотографии и диаграммы. Текст выделяется цветами, жирным и врезками.
- Содержание страниц дописывается позже; сначала каркас и первая страница.

Рекомендации провайдеров из замысла: **OpenRouter** — основной для текста, **Groq Cloud** — основной для речи, у обоих большие бесплатные лимиты. В тексте это сопровождено оговоркой, что условия тарифов меняются.

## Структура

Порядок идёт от первого запуска к редким вещам. Разделы Параметров стоят по пути данных: ИИ → распознавание → поиск (сначала текст распознан, потом его индексируют; облачное распознавание использует провайдеров из ИИ). В самом приложении порядок Параметров другой (ИИ, Поиск, Распознавание) — помни об этом при сверке.

Источник правды по дереву — `frontend/src/screens/guide/guideSections.ts`. Ниже его копия для чтения; `+` — страница написана, `·` — только место в дереве.

Решения, которые стоит помнить:

- «Задний фон» — это оформление из `Параметры → Фон`, а не очередь обработки. Очередь («Фоновые задачи») и сводка «Состояние» — панели внизу левой панели, у них своя страница.
- «Основные понятия», «Работа над проектом» и «Занятия» добавлены сверх первоначального списка: без них руководство обрывается на материалах, а половина приложения остаётся без описания.
- Бот в приложении пока заглушка («Бот пока не настроен»). Страница нужна с честным статусом, без инструкции.
- Разделы про ИИ, распознавание и поиск оставлены тремя отдельными, как просил автор; слияние в «Настройку функций» — открытая идея.

## Что реализовано

Прототип экрана и первая страница. Всё в `frontend/src/screens/guide/`:

| Файл | Что делает |
| --- | --- |
| `Guide.tsx` | Экран: выбор страницы из `?section=`, запоминание, подсветка секции при прокрутке, «Назад/Далее» |
| `GuideTree.tsx` | Дерево: сворачиваемые группы, вложенные страницы, содержание активной страницы, плавные раскрытия |
| `GuideArticle.tsx` | Отрисовка блоков страницы, заглушка «Раздел ещё пишется» |
| `guideDocument.ts` | Разбор страницы на блоки (единственный собственный «разбор» — см. ниже), тест рядом |
| `guideSections.ts` | Оглавление руководства |
| `guideState.ts` | Что хранится в `localStorage`: последняя страница и «уже открывали» |
| `GuideDiagrams.tsx` | Схемы встроенным SVG: `overview`, `structure` (общее и проектное), `transfer` (пакет проекта и копия) |
| `pages/*.md` | Тексты страниц: `welcome`, `concepts`, `projects` |
| `assets/` | Фотографии и скриншоты для страниц |
| `styles/guide.css` | Все стили руководства, значения из токенов |

Кроме того: кнопка в `AppLayout.tsx` подсвечивается через `useGuideUnopened()`, название экрана в `screens.ts` и подсказки — «Руководство пользователя».

### Переиспользование

Весь связный текст — абзацы, списки, таблицы, формулы, код, картинки — отрисовывает общий `MarkdownView` (`components/domain/markdown`): тот же разбор, что у чата и уроков. Общий разбор не менялся.

Своё только то, чего в общем Markdown нет: заголовки-якоря и контейнеры `:::` (врезки, карточки, шаги, рисунки, схемы). Это ~100 строк в `guideDocument.ts`; тело контейнера снова уходит в `MarkdownView`. Если позже понадобится новый вид блока — добавляется сюда, а не в общий разбор.

Зависимостей не добавлено.

## Как писать страницу

Файл `pages/<slug>.md`, где `slug` — из `guideSections.ts`. Страница без файла остаётся в дереве приглушённой.

Обычный Markdown, плюс:

| Что | Как писать |
| --- | --- |
| Секция страницы | `## Заголовок {#якорь}` — попадает в содержание под страницей в дереве; `{#якорь}` необязателен |
| Подзаголовок | `### Заголовок` (в содержание не попадает) |
| Врезка | `:::info Название` … `:::` — тона `info`, `tip`, `success`, `warning`, `danger`; название можно опустить |
| Термины | `:::terms` или `:::terms info` (цвет группы: `accent`, `info`, `success`, `warning`, `danger`); записи как у карточек: `[Иконка] Термин → ссылка`, затем определение. Ссылка показывается как «Подробнее» |
| Карточки-переходы | `:::cards`, внутри карточки через пустую строку: `[Иконка] Заголовок → /маршрут`, затем строки описания |
| Шаги | `:::steps` и внутри нумерованный список |
| Рисунок | `:::figure`, первая строка `![подпись для чтения с экрана](файл.png)`, дальше — подпись под рисунком |
| Схема | `:::diagram имя` и подпись; схемы заведены в `GuideDiagrams.tsx` |
| Картинка в строке | `![alt](файл.png)` — файл из `assets/` или ссылка `https://…` |

Ссылка на другую страницу руководства — карточка с `→ /guide?section=slug`; на экран приложения — `→ /setup?section=ai&subsection=providers`. Обычная Markdown-ссылка `[..](..)` откроется в новой вкладке — для переходов внутри приложения используй карточки.

Иконки карточек — список `CARD_ICONS` в `GuideArticle.tsx` (lucide); нужной нет — добавь туда.

### Как выделяется текст

Каждое выделение имеет свой смысл и цвет; соблюдай смысл, иначе цвета перестанут помогать:

| Разметка | Смысл | Вид |
| --- | --- | --- |
| `**жирный**` | главное, что стоит запомнить | акцентный маркер под словом |
| `` `код` `` | названия кнопок, разделов, полей в приложении, пути `Параметры → ИИ` | акцентная плашка |
| `*курсив*` | термин при первом упоминании, мысль на заметку | бирюзовый |
| `~~зачёркнутое~~` | так делать не нужно | красный |
| врезки | особые места: заметка, совет, «готово», «важно», «осторожно» | цвет и значок по тону |

Чего пока нет: выделения произвольным цветом внутри строки и подсветки маркером (`==текст==`). Общий разбор такой разметки не знает; добавлять её ради руководства — правка чата и уроков, поэтому решение за автором.

### Фотографии и скриншоты

Файл кладётся в `frontend/src/screens/guide/assets/` и в тексте называется по имени. Скриншоты стенда чистой установки удобно делать через `npx playwright` на `http://localhost:5273`. Картинка одна для обеих тем: делай скриншоты в той теме, которая читается на обеих, или бери отдельные файлы.

## Проверка

- `docker compose exec web npm run typecheck` и `npm run test:unit` — из папки worktree. Прошли при добавлении прототипа.
- Смотреть глазами: стенд `http://localhost:5273/guide`. Контейнер `web` на bind mount не всегда подхватывает правки — помогает `docker compose restart web`.
- Подсветка кнопки — после очистки `localStorage` (ключи `tentex-guide-opened`, `tentex-guide-last-page`) либо в новом профиле браузера.
