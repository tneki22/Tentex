## Полный результат

В учебниковом проекте можно построить программу по оглавлениям/цели или вручную, исследовать один, несколько или все подключённые источники, читать найденное и выбирать его в урок. Код учитывает каждый блок, исследователь углубляется и сопоставляет источники. Покрытие имеет Обзор, матрицу и двусторонний граф; показывает содержание вне программы, неопределённость и предложения изменить программу. Изменения не уничтожают ручные решения и не требуют безусловного повторного чтения всей коллекции.

Полноценное составление уроков с ИИ, генерация практики, изменение экзаменационного режима, эмбеддинги и новый календарный учёт не входят в реализацию этой вертикали. Полный первый проход сохранён как отдельная условная ветвь с конкретным контрактом; его включение зависит от проверки недостаточности оглавлений и поиска, как требует текущий PLAN.md.

## Рабочие решения для оставшихся деталей

Все строки этой таблицы — **рекомендации плана**, а не утверждение, что пользователь отдельно подтвердил каждое умолчание.

| Вопрос | Выбранный вариант и пример |
|---|---|
| Глубина обучения | Использовать существующий GoalPassport: текущие знания, target_outcome, goal, success_criterion, excluded. Пример: «Понимать восстановление, объяснить зачем WAL; знаю SQL; реализацию движка не изучаю». У темы уже есть target_level для локального уточнения |
| Подробность программы | Отдельное пожелание в профиле: компактная / обычная / подробная, по умолчанию обычная. Это подсказка при предложении дифа, не жёсткое число уровней. «Журнализация» — отдельная тема, если даёт самостоятельный учебный результат; подробности формата записи могут остаться внутри объяснения |
| Цена исследования | Отдельные лимиты; желаемая глубина обучения не увеличивает их молча. Нет обязательных двух моделей |
| Исследовательские виды работы | Полный обзор → автоматическое уточнение участков → сопоставление коллекции и программы. Это один запуск, три внутренних вида, без трёх отдельных кнопок |
| Источники запуска | Мастер — все готовые подключённые; строка Материалов — выбранный; Покрытие — новые/изменённые в выделении. Доступ к прочим источникам как контексту отдельным видимым переключателем, по умолчанию выключен |
| Достаточность | Содержательная связь и «есть определение с объяснением» — разные факты. Не вводить общий автоматический статус «для цели достаточно»; показывать недостающие виды материала и основания |
| Рекомендованное чтение | Сначала актуальное связное объяснение подходящего уровня с необходимым контекстом; затем альтернативы. Приоритет основного источника — критерий при равном качестве, не запрет других |
| Личный выбор | «Не предлагать для чтения» не снимает правильную связь; «Неверная связь» снимает; «Удалить из урока» меняет урок. Все действия имеют понятную область |
| Вне программы / вне цели | Нужная отсутствующая тема остаётся кандидатом. «Не нужно для моей цели» подавляет эквивалентные предложения в текущей версии цели, но не удаляет содержание |
| Подтверждения | Машинные привязки доступны сразу после проверок. Человеку — изменения программы, конфликты с его решением и выбор намерения; технические проблемы не превращаем в анкеты |
| Конкурирующие запуски | Один незавершённый запуск исследования на проект; повторный запрос показывает действующий запуск и действия продолжить/отменить. Другую область можно запустить после его завершения или отмены. Пауза освобождает worker, но не создаёт второго издателя результатов. Разные проекты работают параллельно |
| Большой граф | Разделы ↔ источники, затем тема ↔ главы, затем фрагменты. Обычный SVG с ограниченной выдачей и списком для клавиатуры; без force-layout, графовой БД и нового пакета до появления конкретной необходимости |

Подробность дерева сохранять одним nullable-полем профиля, без новой сущности «профиль исследования». Если пожелание не задано, не переписывать существующее дерево под умолчание. Изменение этой настройки влияет на предложения структуры, а не аннулирует правильность всех связей.

## Проверенные опоры кода и реальные ограничения

MCP-граф в этой сессии не предоставлен; использован адресный поиск и чтение кода. Пути ниже существуют в проверенной базе. План новых файлов обозначен в документах отдельно.

| Имеющийся код | Что переиспользовать / что изменить |
|---|---|
| `backend/app/models.py` | MaterialBlock имеет material_id/revision/order, Fragment — block_id/page_id; Binding уникальна по проекту, теме, фрагменту. PASS_TWO уже есть. Нет семантического назначения связи или полного учёта исследования |
| `backend/app/bindings/service.py` | Проверки проекта/версии, ручные связи, поиск. `create_bindings` создаёт MANUAL и восстанавливает REMOVED: не вызывать его из фонового издателя. `get_summary` не знает новых семантических различий |
| `backend/app/bindings/service.py:transfer_bindings_on_revision` | Использует точный текст, затем позиционное совпадение при равных количествах. Не считать такой перенос доказательством актуальности машинного вывода. REMOVED не входит в перенос активных связей |
| `backend/app/lessons/editing.py:_bind_fragments` | Существующая пара не меняется даже при REMOVED. Ручная вставка в урок не должна неявно восстанавливать снятую связь |
| `backend/app/lessons/refs.py` | Точные границы и перенос источников урока. Не вводить второй формат вырезок |
| `backend/app/projects/program_chat.py:apply_proposal` | Есть диф, ревизия и undo, но зависит от ChatMessage. `_apply_merge` переносит диапазоны оглавления, не связи и уроки. Нужны доменные операции без фиктивной ChatSession |
| `backend/app/projects/program.py:undo_last_project_action` | Общий журнал отмены; расширить обработку новых атомарных действий, не создавать второй стек undo |
| `backend/app/ai/gateway.py`, `roles.py` | Схемы ответов, выбор моделей, AiRun, кэш и лимиты. Повторы внутри шлюза тоже стоят ресурсов; общий лимит исследования должен учитывать каждую попытку |
| `backend/app/materials/worker.py`, `ai/jobs.py`, `background/registry.py` | Одна очередь и lease. Общий AI-dispatcher завершает done=total и трактует pause_requested как отмену; длинному исследованию нужен свой обработчик и точная семантика паузы |
| `frontend/src/screens/ProjectWorkspace.tsx`, `workspace/BoundSourceReader.tsx` | Живое чтение страниц через StructuredPage; добавить подбор объяснения без изменения экзаменационного поведения |
| `frontend/src/screens/lessons/LessonMaterialPanel.tsx` | Вкладка suggested сейчас честная заглушка; подключить общий результат исследования |
| `frontend/src/app/screens.ts`, `views.ts`, `components/domain/ProjectNav.tsx` | Регистрировать новый учебниковый раздел отдельно. Существующий coverage-map используется экзаменационной поверхностью «Ответы»; его не переименовывать в новую карту |
| `frontend/src/app/AppLayout.tsx`, `api/backgroundJobs.ts` | Панель «Фон», названия/типы задач, переходы к результатам. Новому kind нужен маршрут к покрытию и честный статус research, не только done=total первичного обхода |

Новые модули планируются в `backend/app/coverage/` (schemas, service, research, queries, router); разносить дальше только при появлении самостоятельной ответственности. Фоновые задания подключаются к текущему worker, модели — к шлюзу, фронтенд — через `frontend/src/api/coverage.ts`. Это предметная подсистема, не универсальная агентная платформа.

## Что не выдаём за завершённое

План завершает проектирование границ, поведения и этапов. Он не доказывает качество моделей. До оплачиваемого опыта проходят И0/И0а: исходный прогон и исправления потерь подготовки; выбираются реальные файлы и предел расходов. До выпуска проходят миграции, тесты и пользовательские сценарии. Не вводим проценты точности и стоимость из чужой статьи как обещания Tentex. Корневые документы текущей готовности обновляются при фактической реализации; согласованную очередь и новый UX синхронизировать на этапе И0, не переписывая историю.
