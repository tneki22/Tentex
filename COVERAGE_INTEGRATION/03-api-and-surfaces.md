# API, экраны и использование результата

Предлагаемые имена маршрутов, не существующий API. Корень `/api/projects/{project_id}/coverage`. Схемы Pydantic и TS синхронизируются при реализации; обязательны project ownership, textbook guard, writable guard и стабильные доменные ошибки. Pass2 разрешён только активному проекту; условный deep_program дополнительно допускает учебниковый draft по контракту первого прохода. Тонкий router вызывает сервис, не работает с БД напрямую.

## 1. Команды и чтение

| Метод и путь | Вход / результат |
|---|---|
| POST `/preflight` | material_ids, mode, context_material_ids, expected_program_revision, limits, role overrides. Без платного вызова: готовые/исключённые источники, текущие ревизии, объём, ограничения извлечения/модальностей, доступные модели и оценка с неопределённостью |
| POST `/runs` | То же + preflight fingerprint + request_key. Повторно проверить готовность/версии; создать manifest и BackgroundJob атомарно, вернуть 202 run_id/job_id. Повтор ключа с тем же телом возвращает тот же запуск; иное тело — 409 |
| GET `/runs/{id}` | snapshot, lifecycle, stage, primary counts, refine counts, pending synthesis, stop_reason, costs/uncertain costs, доступные действия. Проверять project принадлежность |
| POST `/runs/{id}/control` | pause / resume / cancel + expected **control_version** (не внутренний `execution_generation`: тот меняется на каждом кванте worker и давал бы ложный 409). Выполнять переход только из допустимого состояния; идемпотентный повтор текущего намерения |
| GET `/overview` | filters/scope; coverage_revision, program_revision, source revisions, распределения, basis labels, unresolved и findings counts, partial/stale и extraction diagnostic flags |
| GET `/topics?view=readable\|gaps` | Пагинированные темы для И5: группы evidence/причины выбора, наличие основы чтения либо точный вид пробела; стабильная сортировка и coverage_revision |
| GET `/blocks?view=outside_program\|needs_action` | Пагинированные блоки И5. `outside_program` не смешивается с `unresolved/error/stale`; точные source/page/range и доступные решения |
| GET `/matrix` | node/branch/material filters, cursors. Упорядоченные строки/источники и sparse cells; bounded page, counts unique blocks, role/status breakdown |
| GET `/graph` | focus/type/depth, filters, cursor. Typed nodes/edges, expandable flags, counts, truncation, total; те же агрегаты, не отдельный графовый расчёт истины |
| GET `/topics/{node_id}/evidence` | Группы «Для начала», «Другие объяснения», «Примеры и практика», «Углубление и связи»; отдельно mentions, hidden и legacy; next_cursor, reason/source/version и точные ranges. Один контракт для Источника и «Предложено» |
| GET `/sources/{id}/blocks` | Лента блоков с состояниями, partial/mixed/quality/stale и переходами к фрагментам |
| GET `/evidence/{id}` | Точный текст и границы, источник и страницы, роли, происхождение, актуальность, связанные темы и основания; locator_kind/reliability и объяснение недоступной старой версии |
| POST `/decisions` | kind, target refs, expected_coverage_revision, payload, request_key. Confirm/remove/restore/reassign на одну или несколько существующих тем, change role, service, outside_goal, hide/restore/prefer reading. Одна транзакция, один `ProjectActionLog`, delta и latest undoable action |
| GET `/findings` и `/{id}` | Группированные предложения/конфликты с доказательствами, выбранными операциями, affected objects и версиями |
| POST `/findings/{id}/preview` | Выбранные операции, отредактированные title/parent/links, варианты переноса уроков. Чистый расчёт дифа, без записи программы |
| POST `/findings/{id}/apply` | Preview fingerprint, expected revisions, request_key. Одна транзакция и одна отменяемая операция; вернуть новую программу/coverage revision и receipt |
| POST `/findings/{id}/feedback` | Уже входит в тему / вне цели / неверно / отложить + optional comment. Изменяет конкретный finding/предпочтение, не удаляет материал |
| POST `/recheck-preview` | changed node/finding/material scope. Локальный отбор кандидатов и причины без модели; count реальных кандидатов и предел выборки |

Перепроверка запускается обычным POST `/runs` с mode=incremental и серверным candidate selection token; arbitrary IDs клиента проходят ту же проверку manifest. Undo использует существующий маршрут программы/журнала с новым action handler, не новый независимый undo API. Вставка в урок использует существующие lesson commands с expected_revision; новый endpoint клонирования уроков не нужен.

### Пример запуска

Ниже условные ID заменяются реальными UUID. Выбор includes только учебник и лекции; справочник может читаться как контекст, но не входит в 1912 блоков полного обхода.

```json
{
  "material_ids": ["book-a", "lectures-b"],
  "context_material_ids": ["reference-c"],
  "mode": "initial",
  "expected_program_revision": 7,
  "preflight_fingerprint": "snapshot-hash",
  "request_key": "client-generated-uuid",
  "limits": {"max_calls": 120, "max_total_tokens": 400000},
  "roles": {"overview": "configured-model", "research": "configured-model"}
}
```

Лимиты в примере иллюстративные, не рекомендуемые настройки. Отсутствие денежного поля означает контроль calls/tokens, а не отсутствие ограничения расходов вообще. Модель выбирается среди настроенных доступных пользователю, не по присланной произвольной строке.

Ответ прогресса: `primary={total:1912, inspected:1248, error:36, pending:628}`, `research={discovered:19, finished:12, unresolved:4}`, `synthesis=pending`. Число research может расти; 12/19 не рисуется как монотонный процент всей операции. `completed` с unresolved допустим, `completed` при ещё ожидаемых действиях — нет; достигнутый лимит переводит run в paused с budget_limit.

Полнота подготовки не выражается выдуманным процентом. Пример: «Все 120 блоков подготовленного текста просмотрены; 4 изображения не исследованы; 7 блоков остаются неопределёнными». Для PDF адрес — страница/область, для DOCX/MD — раздел/элемент, для речи — временной интервал. Синтетическая «страница 1» не заменяет адрес всего аудио. Смена ревизии во время запуска показывает snapshot_changed и предложение перепланировать; сохранённые результаты остаются доступны с актуальностью.

Ошибки: `coverage_snapshot_changed`, `coverage_run_active`, `coverage_source_not_ready`, `coverage_evidence_stale`, `coverage_decision_conflict`, `coverage_budget_exhausted`, `coverage_scope_denied`. HTTP 409 для конкурентных/состояний, 422 для недопустимого выбора, существующие 404/read-only ошибки сохраняются. Модельный outage не превращать в пустой успешный список.

## 2. Общая согласованность чтения

Каждый ответ агрегатов несёт coverage_revision и fingerprints области. Один экран не смешивает страницу матрицы ревизии 12 с графом ревизии 13 как единый снимок: сбрасывает pagination/refetch при смене ревизии. SQL-агрегаты выполняются в согласованном read snapshot; группировка в UI не подменяет серверные правила подсчёта. После mutation обновить минимум overview, текущую topic/source query и затронутые findings; не сбрасывать фокус/scroll без причины.

Все collection endpoints ограничены пагинацией. Размеры страниц и ограничение раскрытого графа — измеряемые константы интерфейса; стартовый ориентир графа до 100 видимых узлов, остальное через «Показать ещё». Ограничение обязано отображаться. IDs родительских/дочерних узлов и разные виды рёбер имеют отдельные namespaces, чтобы глава и тема не совпали случайно.

## 3. Места запуска

Один переиспользуемый диалог `ResearchLaunchDialog` для мастера, Материалов, Программы и Покрытия. Он показывает источники, готовность, выбранную область, дополнительный контекст, профиль, модели, лимит и значение «новые/изменённые» против «повторно всё». Отмена диалога не создаёт job. Выключенные модели оставляют просмотр и ручные операции доступными.

Мастер: на Итоге «Создать и исследовать» / «Создать без исследования». Сначала успешная активация проекта, затем идемпотентный запуск; сбой запуска не откатывает созданный проект и не дублирует его при retry. В Обзоре показать «Проект создан, исследование не запущено» с сохранённым выбором. Неготовые материалы явно перечислены; их завершение не запускает платный проход автоматически.

Материалы: действие строки для одного и массовое для выделенных. Статусы отличаются от OCR/разбора: «разобран файл» ещё не «исследовано содержание». Основной/дополнительный/справочный источники доступны на равных, роли только помогают выбору.

Покрытие: «Исследовать материалы» для выбора области, «Продолжить» для paused, «Проверить изменения» для устаревшего. Запуск по одному источнику не скрывает сохранённую карту остальных; активные фильтры и scope поясняются рядом со счётчиками.

## 4. Покрытие: один новый раздел

Новый screen id `textbook-coverage`, путь `/projects/:projectId/coverage`, только учебниковая навигация. Внести в screens.ts/views.ts и ProjectNav.tsx, расширить ProjectNavKey. Это основная функция учебника, отдельный отключаемый ModuleKey не нужен. Старый coverage-map и экзаменационные ссылки не трогать. Реализация в `frontend/src/screens/coverage/`, API в `api/coverage.ts`, состояние в одном предметном hook. Новые компоненты используют текущий UI-kit и tokens; подробности внутри рабочей области, не новая глобальная очередь.

В панели «Фон» обновить `AppLayout.backgroundJobPath`, типы `api/backgroundJobs.ts` и TaskRow: новый kind ведёт в Обзор с run, deep_program — в Программу с proposal. После 100% primary показывать стадию углубления/сверки, а не выполненность всей задачи; старый ETA по blocks не выдавать за срок оставшегося исследования. `needs_review` для исследования вычислять по актуальным findings, требующим пользовательского намерения, а не по наличию машинных связей. Частичное решение не закрывает остальные карточки. «Убрать из панели» означает только reviewed/dismissed presentation, не принятие программы и не удаление findings; все они остаются доступны в Покрытии.

**Обзор:** просмотренные/ожидающие/ошибочные блоки, темы с content и отдельно с основой чтения, материал вне программы, unresolved, актуальность, расходы. Списки по клику: пробелы, исследуемое, требует решения, новые темы. Не окрашивать материал вне цели и покрытие ниже 100% как ошибку.

**Срез И5 поверх Обзора:** верхняя сводка И3 остаётся. Ниже переключатель
`К чтению · Пробелы · Неразобранное · Требует решения`, слева пагинированный список,
справа постоянный evidence-инспектор. Вид, фильтры и выбранные topic/source/evidence
сохраняются в URL. «Неразобранное» показывает только `outside_program` нейтрально;
`unresolved/error/stale` находятся в «Требует решения». Из темы доступны «Читать»,
«Добавить в урок» и решения связи. У блока outside доступны существующая тема, `service`
и `outside_goal`; «Создать новую тему» до И7 остаётся видимым недоступным анонсом без
пустого маршрута.

**Карта:** виртуализировать только если измеренный размер требует; сначала bounded rows/columns, свёртка дерева и pagination. Ячейка открывает тему+источник в панели. Сохранить source/topic/filter в URL, тяжёлый UI state — локально. Без материала, только mention и legacy unknown визуально различаются.

**Граф:** начально разделы ↔ источники. Клик по теме приглушает остальные и раскрывает главы; клик по ребру открывает evidence, следующий уровень — участки. Гипотезы новых тем пунктирные с текстовой меткой; prerequisite, overlap и containment различимы. Back/сброс/сохранённый фокус работают без перезагрузки всей коллекции. Эквивалентный список доступен клавиатурой и screen reader, поэтому граф не становится единственным путём к действиям. Обзор/Карта/Граф используют один backend query layer.

**Панель:** первичный текст, страницы/источник, тема/назначение, происхождение, актуальность, опоры, альтернативы, контекст. Переход в существующий viewer сохраняет return-to с фокусом. Никакого обязательного чата для решения карточки.

Состояния всех видов: пустая программа, нет материалов, ничего не исследовано, loading, частичный результат, ошибка, paused, устаревшее, read-only проект, модели выключены. «Нет найденного» отличать от «запрос не выполнен». Статусы не передаются одним цветом.

## 5. Обратная связь без потока подтверждений

| Действие | Последствие |
|---|---|
| Подтвердить content-связь | Binding CONFIRMED, защита от фона, evidence сохраняется; не подтверждает знание темы |
| Неверная связь / другая тема | REMOVED + reject_link либо явная ручная новая связь; старое снятие сохраняется, одна отменяемая операция |
| Это только упоминание | Изменить semantic role, убрать из content count, сохранить навигацию |
| Не предлагать для чтения | Скрыть в обычной выдаче темы, оставить в карте и «Показать скрытые»; можно вернуть |
| Читать это первым | Личный preferred evidence; если устарело/недоступно — объяснить и предложить актуальное, не открыть битый locator |
| Добавить недостающую тему | Preview → atomic apply; selected links подтверждаются, остальные остаются кандидатами |
| Уже входит в другую тему | Выбор существующего узла и проверка selected links; не менять всю коллекцию по одному клику |
| Не нужно для моей цели | Сохранить scoped decision; не подавлять найденное в других проектах и не удалять содержание |
| Отложить | Убрать из активных вопросов, оставить фильтр отложенного; новое evidence может вернуть явно изменившееся предложение |
| Исправить OCR / показать страницу | Открыть имеющийся инструмент исправления. После публикации ревизии выводы получают stale; модельная перепроверка запускается явно |

Свободное пояснение прикрепляется к конкретному решению и учитывается при следующем явном исследовании. Не трактовать его как команду без проверки или автоматический запуск оплачиваемого чата. Групповое действие разрешено для однородных выбранных связей с preview количества/scope; apply целиком проходит проверку ревизий либо возвращает конфликт, без скрытого частичного результата.

Эквивалентное отклонённое предложение узнаётся по kind, целевым узлам, нормализованным основаниям и версии цели. Новый текст формулировки сам по себе не повод снова задавать вопрос. Новые существенные материалы показываются как изменение оснований, а не молча обходят прежний выбор.

## 6. Чтение без урока

ProjectWorkspace в textbook-ветви запрашивает topic evidence. Ранжирование:
явный предпочтённый пользователем → актуальность/читаемость → definition/explanation
и связность → соответствие цели → роль/приоритет источника → стабильный порядок.
Числовую уверенность не вводить. Не считать число ссылок или самооценку модели
достаточным основанием ранга. Противоречащие объяснения показывать отдельно с
условиями, не сшивать.

Предпочтительный результат — группа соседних точных фрагментов одного объяснения; BoundSourceReader/StructuredPage остаются рендерером. Все найденные результаты, включая legacy, упражнения и mention, доступны через список/фильтры. Если definition/explanation отсутствуют, открывать доступное с честной подписью, не сочинять объяснение. После новой фоновой публикации не переключать пользователя с текущей страницы; показать доступное обновление.

Учебниковый «Источник» выносится из перегруженного `ProjectWorkspace.tsx` в отдельный
компонент и предметный hook. Переключатель `Вместе · Исследование · Поиск` по умолчанию
стоит на «Вместе»: сначала открывается preferred или лучшее исследованное объяснение,
BM25 запускается только по кнопке «Найти ещё». Связный диапазон показывает существующий
`StructuredPage`; участки разных авторов не склеиваются.

Чтение не ставит автоматическую CONFIRMED-связь и не помечает урок/тему завершёнными. Состояние просмотра сохранять существующим механизмом Рабочей области, не создавать новую сущность занятия. Машинный материал можно читать до завершения run и без разбора всех findings.

## 7. Уроки: только ручной выбор в этой вертикали

В LessonMaterialPanel подключить «Предложено» к тому же topic evidence и постоянному
инспектору. Использовать существующий LessonSourcePicker и команды вставки
фрагментов/блоков/границ. При нескольких темах урока явно выбрать целевую; выделить уже
включённые точные интервалы и пересечения, не только совпадение номера страницы. Место
вставки выбирается явно.

«Добавить в урок» из Источника/Покрытия открывает выбор существующего урока или создание ручного черновика, preview границ и позиции. GET ничего не добавляет; commit использует expected lesson revision. Добавление может создавать ручную связь по существующим правилам урока, но REMOVED не восстанавливает: для восстановления отдельный явный выбор. Простая вставка не вызывает модель.

Новые машинные связи показываются предложениями, не перестраивают урок. Снятие связи не удаляет уже вставленный фрагмент; устаревание исходника показывает состояние существующего LessonSourceRef. Удаление из урока сохраняет действующий отдельный механизм предложения отвязки, а не неявно снимает всё связанное.

Автоматический порядок, пояснения и практика остаются будущим «Составить урок с ИИ». В этой работе подготовлен только входной контракт: точные источники, роли, уровень, необходимые контексты, альтернативы, конфликт/актуальность. Новая служба генерации урока, кнопка и бюджет на неё не создаются.
