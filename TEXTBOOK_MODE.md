## 1. Что это за режим

Три входа в систему различаются не настройками, а тем, откуда берётся программа.

| Режим | С чего начинается | Откуда программа |
|---|---|---|
| **Подготовка к экзамену** | Есть готовый список вопросов, задач или билетов | Программа = импортированный список |
| **Изучение по учебнику** | Есть учебник, методичка или курс и своя цель; готового списка нет | Программа строится по источникам под цель |
| **Свободное изучение** | Есть только цель, главного источника может не быть | Программа по цели из знаний модели и оглавлений подключённых материалов; каталога эталонных программ пока нет |

Учебниковый и свободный режимы по логике почти одинаковы. Единственное различие:
в учебниковом обязателен источник, на котором строится программа, в свободном его
может не быть вообще. Поэтому свободный режим проектируется после учебникового и
переиспользует его механизмы — отдельной логики у него почти не будет.

**Уточнено 20.09.2026: свободное изучение — не отдельный тип учебной среды.** Под
капотом это `template_key=free` и общий учебниковый `workspace_variant=textbook`, те же
данные, разделы и механизмы. Отличаются ветка общего мастера, промпт чата программы
(от цели, а не от оглавления) и то, что видно у тем без материала. Отдельного типа
данных, навигации и редактора не заводится. Режим доведён до сквозного сценария
24.09.2026; фактический контракт — `docs/architecture/free-study-wizard.md`.

### 1.1. Свободное изучение: от цели до урока

**Мастер — четыре шага: «Цель → Материалы → Программа → Проверка»** (до 23.09.2026 —
три, без отдельного шага программы). Цель обязательна; предмет, фокус и срок
необязательны, стартовый уровень выбирается чипами «С нуля / Что-то знаю / Повторяю
забытое». Срок используется календарём готовых уроков после включения
«Планирования занятий» в настройках проекта.

- **Материалы.** Первым идёт блок «Подходит к вашей цели»: материалы Библиотеки,
  найденные по смыслу цели гибридным поиском без модели, с числом совпадений, фрагментом
  и «Подключить». Ниже — вся Библиотека, файл, веб-страница/YouTube и «Найти в
  интернете». Прямой URL на PDF не обещается. Продолжить без материалов разрешено.
- **Программа.** Тот же `TextbookProgramEditor` с «Вручную / С ИИ». С доступной моделью
  и пустым деревом шаг открывается чатом с быстрым стартом «Составь программу по моей
  цели». Импорт принимает оглавления всех подключённых материалов, основа идёт первой;
  проверку оглавления (`TextbookOutlineReview`) проходит основа.
- **Проверка.** Итог отдельно считает темы по оглавлению и темы без источника — второе
  штатно, материал подбирается после создания.

**Программа по цели.** Чат программы у свободного проекта строит дерево от цели:
предпосылки → целевые темы → связанные. Пункт оглавления берётся, если он есть; иначе
тема помечается «Предложено ИИ · знания модели» и получает подсказку «Где искать» — 1–3
поисковых запроса и вид источника (лекция, статья, видео…). Любое изменение — диф с
подтверждением (§3, шаг 4). Сам помощник программы в сети не ищет.

**Консультант по пробелам.** «Без материала: N» в шапке Программы открывает «Материалы к
темам»: по каждой теме подсказка «Где искать», до трёх материалов Библиотеки по теме,
«Искать в материалах проекта», «Найти в интернете», «Загрузить своё». Консультант
реализован без прохода 2: пробелы читаются по сводке привязок, материалы — общим
`HybridRetriever` по всей Библиотеке.

**Поиск в интернете — только по явной кнопке.** С 24.09.2026 это чат «Поиск в интернете»
в разделе «Материалы»: модель планирует запросы, SearXNG даёт выдачу, сервер читает
страницы и возвращает карточки источников только из настоящей выдачи. Прежний поиск через
плагин `web` OpenRouter удалён. Контракт — `docs/architecture/source-search-chat.md`.

**Урок без оглавления.** Тема без диапазона страниц собирается «Уроком из найденного»:
отмеченные в поиске страницы становятся черновиком одной командой (§8.2).

**Откуда взялась идея.** Исходный сценарий: загрузить большой учебник и вытащить
оттуда всю мудрость автора по нужной теме, ничего не пропустив, не сжигая токены на
чат с документом. Отсюда и главное отличие продукта — **покрытие в обе стороны**:
система следит не только за тем, чтобы у каждой темы был материал, но и за тем, чтобы
каждый содержательный кусок учебника был рассмотрен.

**Два проекта, а не переключатель.** Разбираться в предмете по учебнику и готовиться
к экзамену по нему же — это два проекта: «БД — разбираюсь» и «БД — экзамен». Внутри
одного проекта режим не переключается (FR-P8).

## 2. Материалы

Помимо главного учебника в проект добавляются любые другие источники: методички,
статьи, лекции, конспекты, веб-страницы по ссылке, видеолекции с YouTube (Материалом
становится транскрипт, а не видеопоток), локальное аудио, Typst-проекты. Форматы,
пределы и состояния — в `LIBRARY_FILE_PROCESSING.md`.

У каждого источника **в рамках этого проекта** есть роль и приоритет:

| Роль | Что делает |
|---|---|
| **основной** | Определяет структуру и содержание программы |
| **дополнительный** | Расширяет и уточняет основные источники |
| **справочный** | Используется в объяснениях и уроках, но программу не расширяет |

К источнику можно дописать свободную инструкцию: «отсюда брать теорию, а из методички —
практические примеры». Роль, приоритет и инструкция принадлежат связи материала с
проектом: тот же файл в другом проекте может использоваться иначе.

## 3. Мастер создания проекта

Пять шагов: **Источники** → **Профиль** → **Проверка** → **Программа** → **Итог**.
Черновик создаётся сразу и переживает закрытие вкладки; возврат назад ничего не теряет.

### Шаг 1 — Источники

«Добавьте материалы, на которых строить программу». Загрузка файлов и выбор из
Библиотеки без копирования. Первый источник становится основным, остальные —
дополнительными; роль меняется здесь же.

У каждой строки: имя, число страниц, состояние готовности текста, действие
«Подготовить текст», удаление и раскрываемое поле роли, приоритета и инструкции.
Под списком — четыре показателя: сколько файлов готово, сколько всего, сколько
найдено страниц-сканов, сколько страниц требуют проверки.

Построение программы здесь **не запускается**.

### Шаг 2 — Профиль

«Чему именно вы хотите научиться?» Форма, а не диалог (FR-G2). Две колонки.

**Что изучать.** Название проекта и предмет; **охват** — «весь материал» или
«конкретная цель»; поле цели; описание текущих знаний; желаемый результат; критерий
успеха; «Что особенно важно» и «Что можно пропустить».

При охвате «конкретная цель» поле «Ваша цель» обязательно. При «весь материал» оно
скрыто, а критерий успеха явно необязателен.

**Как учиться.** Необязательный срок; минут в день; дней в неделю; переключатели
модулей проекта.

Профиль может быть заполнен результатом быстрого анализа источников; предложенные
значения помечены, правка снимает метку.

**Охват — главный вход для шага 4.** «Весь материал» означает: программа покрывает
всё содержательное дерево источников. «Конкретная цель» означает: в текущую программу
входят сама цель, обязательные предпосылки и связанные темы, а остальное содержание
сохраняется как «вне текущей программы» и возвращается одним действием (FR-E6).

### Шаг 3 — Проверка

Краткая сводка: цель, предмет, источники, готовность их текста.

Переключатель **«Составить программу автоматически»**. Включён — шаг 4 открывается
в режиме «С ИИ». Выключен — в режиме «Вручную». Значение по умолчанию берётся из
доступности внешних моделей: модели выключены — переключатель выключен и объясняет
причину.

В раскрываемых подробностях — что уйдёт наружу, сколько вызовов, время, стоимость и
офлайновый резервный путь (FR-P14). Технический алгоритм пользователь не выбирает.

### Шаг 4 — Программа

Главный экран мастера, занимает почти всё окно. Он же используется как раздел
«Программа» активного проекта — это одна поверхность, а не два похожих экрана
(FR-G9.2).

Сверху — переключатель **«Вручную» / «С ИИ»**. Он меняет раскладку, но не данные:
переключение туда-обратно ничего не теряет, дерево одно и то же.

Верхняя строка: **«Отменить»**, переключатель режима, **«Импортировать программу из
оглавления»**, **«Удалить все»** и справа основная кнопка **«Утвердить программу»**.
Пустая программа — допустимое состояние: кнопка честно превращается в
**«Продолжить без программы»**, дерево можно составить позже в разделе «Программа».
Название проекта, подпись автосохранения и отдельный чип ручного режима здесь не
дублируются.

#### Режим «Вручную»

Дерево занимает всю ширину. Над ним — три представления **«Дерево» / «Текст» /
«Вопросы»** и поиск. Отдельного фильтра «Нужно найти материал» нет: подбор материала к
темам в свободном проекте идёт из «Без материала: N» в шапке раздела (§1.1).
Представления не создают копий: правка в одном сразу видна в остальных.

Доступны: добавить раздел, дочернюю тему или соседний подпункт, изменить формулировку
и тип, удалить, продублировать, поднять или опустить, изменить вложенность (до четырёх
уровней), отменить последнее действие. Те же операции — в контекстном меню по правой
кнопке или `Shift+F10`; видимые кнопки остаются основным путём.

**Импорт оглавления.** Отдельное действие в панели. Открывает диалог:

- чекбоксы одного или нескольких добавленных источников;
- спокойное состояние «оглавления нет» у каждого источника без дерева;
- импортируются все уровни оглавления;
- отдельное дерево кандидатов каждого источника с каскадными чекбоксами ветвей;
- счётчик «Будет создано 47 узлов»;
- кнопки «Импортировать» и «Отмена».

Заполненный пример для учебника «Компьютерные сети»:

```
Оглавление · закладки PDF · 214 записей          Глубина: 3
[x] 1     Введение                        с. 7     → раздел
[x] 1.1     Что такое компьютерная сеть   с. 9     → тема
[x] 1.2     Топологии                     с. 14    → тема
[x] 2     Физический уровень              с. 31    → раздел
[ ] 2.1     Среда передачи                с. 33    → тема
[x] 3     Канальный уровень               с. 88    → раздел
...
Будет создано 47 узлов из 214
```

Уровень оглавления определяет тип узла: 1 → раздел, 2 → тема, 3 и глубже → подпункт.
Источники добавляются последовательными корневыми ветвями по их приоритету, без
искусственных разделов с именами файлов. Похожие пути предупреждают о возможном
пересечении, но не склеиваются. Каждый созданный узел запоминает источник, стабильный
ключ пункта и диапазон полных страниц до следующего пункта того же или более высокого
уровня (FR-G15). Импорт применяется одной операцией и отменяется одной командой;
повторный импорт узнаёт прежние пункты по стабильному ключу и не создаёт дубли молча.

У учебникового узла отдельно хранятся основание (`outline` или `custom`) и автор
последнего происхождения (`origin_kind`). Поэтому ручная правка формулировки не стирает
связь узла с оглавлением, а новый ручной узел всегда получает основание `custom`.

Импорт оглавления **не требует внешних моделей** — это гарантированный офлайновый путь
получения программы (FR-G8).

Если оглавления у источника нет ни в закладках, ни в заголовках, диалог говорит это
прямо и предлагает добавить темы вручную или перейти в режим «С ИИ». Это не ошибка.

#### Режим «С ИИ»

Чат занимает основное место (примерно две трети), справа — дерево программы как живой
предпросмотр. Это **полноценный чат**, а не узкая панель подсказок: в нём удобно
обсуждать состав программы, вносить замечания и улучшать её итеративно.

Над перепиской выбирается область контекста: вся программа, выбранный раздел или
выбранная тема.

**Что модель видит всегда:** паспорт цели (охват, цель, желаемый результат, важное и
исключения, срок и темп), оглавление каждого источника с числом страниц по главам,
роли и приоритеты источников, текущее дерево программы. Полные страницы источников
в этот контекст не входят.

Пустой чат не заставляет выбирать отдельный сценарий. Он объясняет единый способ работы:
можно описать нужные разделы или написать «Составь программу по моей цели». Модель
выбирает подходящие пункты из оглавлений с учётом паспорта цели. Следующими сообщениями
пользователь уточняет программу, углубляет отдельные темы или просит убрать ненужное.
До принятия дифа дерево не меняется.

По умолчанию в контекст идут паспорт цели, оглавления подключённых источников и текущее
дерево программы. Полный текст учебников не передаётся: на этом шаге нужна карта их
содержания, а не страницы целиком.

**Примеры реплик, которые обязаны работать:**

> — Ты пропустил транспортный уровень, добавь его из оглавления тоже.
>
> — Оставь почти все темы из оглавления, убери только исторические разделы.
>
> — Оставь только раздел про канальный уровень, остальное вынеси из программы.
>
> — Раздели «Маршрутизация» на три темы: алгоритмы, протоколы, практика настройки.
>
> — Мне не нужна теория информации, я её знаю.

#### Диф — единственный способ, которым модель меняет дерево

Любой ответ, меняющий программу, приходит **карточкой предложения**. До принятия
дерево не меняется.

Карточка показывает каждую операцию со старым и новым значением, объяснение модели и
чекбокс. Внизу — «Принять выбранное» и «Отклонить».

Заполненный пример:

```
Предложение · 4 изменения

[x] Добавить тему «Транспортный уровень: TCP и UDP»
    в раздел «3. Канальный уровень» → после «3.4»
    Есть в оглавлении (с. 142–171), но не попало в программу

[x] Переименовать «Протоколы» → «Протоколы маршрутизации»
    Формулировка не отличала тему от «4.2 Протоколы канального уровня»

[ ] Вынести из программы «1. Введение»
    Обзорный раздел, содержание повторяется в темах 2–4

[x] Перенести «Коммутация пакетов» из «1. Введение» в «3. Канальный уровень»
    По смыслу относится к канальному уровню

              [ Принять выбранное · 3 ]  [ Отклонить ]
```

Правила, которые нельзя нарушать:

- **Пересборка ничего не удаляет.** Тема, которой нет в новой версии, получает признак
  «вне текущей программы»: уходит из плана и метрик покрытия, но сохраняет привязки,
  карточки, конспект и историю. Возврат — одно действие (FR-G11).
- Принятые изменения помечаются машинными, хранят объяснение и источник предложения и
  **отменяются одной командой** (FR-G10.1, NFR-5).
- Принять можно часть: непринятые пункты остаются в карточке.
- Если дерево изменилось руками, пока предложение висело, оно не применяется молча.

#### Во время первого построения

Дерево заполняется разделами постепенно; видно, сколько источников и глав обработано.
Поле ввода недоступно с пояснением «Сначала закончим черновик программы». Можно
продолжить в фоне, принять частичный результат, повторить упавший шаг или перейти на
сборку по оглавлению. Ошибка одной главы сохраняет уже готовые разделы (FR-M15, FR-M16).

#### Что мастер на этом шаге НЕ делает

Не ищет материал под темы, не создаёт привязки, не строит уроки и не запускает
проход 2. Задача шага одна — получить хорошее дерево тем.

### Шаг 5 — Итог

Сводка профиля, фактически добавленных источников с ролями и состоянием текста и
программы (число разделов и тем, компактное дерево либо спокойное пустое состояние).
Блок «После создания» честно перечисляет, что произойдёт. Кнопки — «Создать проект» и
«Вернуться к программе».

После создания открывается раздел «Программа» активного проекта.

## 5. Рабочая область

Формат тот же, что у экзамена: слева дерево программы, справа одна–три изменяемые
рабочие зоны с вкладками. Раскладка запоминается. Разница только в наборе вкладок.

| Вкладка | Что показывает |
|---|---|
| **Источник** | Привязанные фрагменты темы подряд, в том виде, в каком они набраны в источнике: заголовок остаётся заголовком, формула рисуется, схема — картинкой. Selector переключает источники по ролям. Машинная привязка снимается действием «Это не по теме» с отменой |
| **Урок** | Урок выбранной темы для изучения, без редакторских панелей: переключатель «Страницы / Текст», задания урока с проверкой. Уроков несколько — компактный selector, выбор запоминается по теме; черновик помечен и ведёт в редактор. Урока нет — «Быстрый урок» и «Собрать вручную»; у темы без диапазона оглавления — «Найти в материалах» с переходом в поиск раздела «Уроки» |
| **Мой конспект** | WYSIWYG Markdown с формулами и изображениями, автосохранение. Работает уже сейчас |
| **История** | Вид работы, дата, длительность, результат |
| **Чат** | Общий RAG-тьютор: объясняет, ищет подтверждения, сравнивает и находит расхождения с проверяемыми цитатами; область — тема, проект или выбранные материалы, доступен полный обзор корпуса |

Эталонный ответ не считается обязательным содержимым темы учебника. Вместо кнопки
«Проверить себя» — «Начать занятие».

Дерево слева показывает два состояния: «нет материала» и «разобран». «Нужно найти
материал по теме» — штатное состояние, а не ошибка. В свободном проекте вкладка
«Источник» такой темы объясняет это и под поиском по материалам проекта показывает блок
«Где ещё искать»: подсказку «Где искать», материалы Библиотеки и «Найти в интернете».
Чип состояния в шапке темы — нейтральный «Нужно найти материал».

## 7. Привязки и покрытие в обе стороны

**Проход 2** запускается после того, как программа утверждена, и идёт фоновой задачей.
Он берёт **каждый содержательный блок** каждого материала, батчами по
несколько блоков за вызов, и получает решение:

| Исход | Куда идёт |
|---|---|
| `отнесён к теме` | Привязка ставится; при нескольких кандидатах — предложение, а не молчаливый выбор |
| `служебный` | Титул, оглавление, колонтитул, список литературы, предисловие. В метрику не входит |
| `содержательный, вне программы` | Экран **«Неразобранное»** |
| `не решён` | Рассмотрен, но решения нет: не хватило контекста, нечитаемое изображение, плохой OCR, не успело углубление. Виден отдельно, с причиной |

Полнота здесь — свойство конструкции, а не качества модели: непросмотренных блоков не
остаётся по построению. Это главный алгоритм проекта.

Две метрики: **покрытие программы** (доля тем, обеспеченных материалом) и **покрытие
материала** (отнесённые ÷ отнесённые + вне программы, **среди разобранных блоков**).
Покрытие материала **не обязано стремиться к 100 %** и не окрашивается как проблема: из
категории «вне программы» и формируется «Неразобранное» (FR-D17).

> **Уточнено 18.09.2026 по итогам стенда** (`COVERAGE_Tests/local/series-01`, полный обход
> 424 блоков учебника по ОС). Три изменения формулировки выше, каждое по измерению:
>
> - «Ровно один раз» относится к первичному обходу. Он обязателен и однократен для каждого
>   блока — именно это даёт полноту. Углубление вправе перечитать тот же блок ради контекста
>   соседнего решения; второго решения и второго учёта из этого не возникает.
> - Появился четвёртый исход `не решён`. На измеренном обходе таких блоков около 13%, и это
>   незавершённая работа, а не свойство материала. Раньше их было некуда деть, кроме как
>   молча отнести к «вне программы» — это исказило бы и «Неразобранное», и обе метрики.
> - Знаменатель покрытия материала не меняется, но доля обязана называться долей среди
>   разобранных блоков, и рядом всегда стоят числа нерешённых и нерассмотренных. Без этой
>   подписи 82% на том же источнике прячут 56 блоков, по которым работа не доделана.
>   Пока такие блоки есть, главный показатель — распределение всего набора, а не процент.
>
> Обязательные правила реализации — [контракт П5](COVERAGE_INTEGRATION/06-verified-contract.md).
> Сам контракт не обещает точность связей: она не измерена на большой разметке.

**Где это живёт (решение 17.09.2026).** Две метрики, «Пробелы» и «Неразобранное»
собраны в раздел проекта **«Покрытие»** — он встаёт в навигацию учебникового проекта
на место снятых «Карточек» (§4, §10) и появляется вместе с проходом 2. Серверная часть
прохода 2 и метрик пишется **без ветвления по виду проекта**: в экзаменационных
проектах раздел включается позже, если останется время, и ничего переписывать для
этого не придётся.

**Отдельного экрана привязок нет.** Привязки правятся там, где они нужны:

- в разделе «Уроки» — добавил кусок материала в урок, привязка создалась: выбранное
  пользователем — ручная, диапазон оглавления из «Быстрого урока» — машинная, её проход 2
  может подтвердить или оспорить (§8);
- во вкладке «Источник» Рабочей области — «Это не по теме» снимает привязку;
- в виде «Неразобранное» раздела Покрытия — привязать к существующей теме, пометить
  служебным или «вне цели»; создание новой темы приходит только в И7, а до него
  показывается недоступным анонсом.

**Порядок срезов покрытия (решение 19.09.2026): И3 → И5 → И4 → И6 → И7.** И5
реализован: чтение, ручная вставка в Уроки и контроль опубликованных связей работают
поверх первичного обзора И3. Следующим И4 добавляет углубление, синтез и визуальный
разбор; И6 — Карту и Граф; И7 — изменение Программы и инкрементальный цикл. И0а
остаётся диагностикой. Чтение не подтверждает связь, вставка в Урок
не вызывает модель, не перестраивает Урок и не восстанавливает снятую связь.

При дозагрузке материала проход 2 идёт **только по новым блокам**; система показывает
дельту: какие темы получили фрагменты, какие пробелы закрылись, что не отнеслось.

## 8. Уроки

> **Модель урока согласована 14.09.2026.** Здесь — решения; подробности, заполненные
> примеры, порядок разработки и журнал этапов — в
> `docs/superpowers/plans/2026-09-14-lessons-vertical.md`. Реализации пока нет: маршрут
> показывает честную заглушку.

**Урок — не новый текст, сгенерированный из учебника, а упорядоченный сценарий:** ссылки
на страницы и фрагменты материала, свои или модельные пояснения, медиа и задания.
Материал остаётся первичным доказательством, урок расставляет его и дополняет.

- У одной темы может быть несколько уроков; один урок может охватывать несколько тем.
- **Создание и изучение разведены.** Урок собирается в разделе «Уроки», проходится во
  вкладке «Урок» Рабочей области.
- Статусы: `черновик` · `готов` · `архив`. Модельный результат не перезаписывает
  существующий урок: новый урок — черновиком, дополнение существующего — предложением.
- Ручное создание и изучение сохранённых уроков работают **без внешних моделей**.
- Просмотр урока — сила свидетельства 0. Прогресс меняют только задания урока.

### 8.1. Документ урока

Упорядоченный список блоков четырёх видов:

| Вид | Что внутри |
|---|---|
| **Материал** (`source`) | Ссылка на материал проекта: диапазон страниц, структурный блок, диапазон фрагментов или область страницы |
| **Текст** (`note`) | Markdown с формулами. Оформление: текст · заголовок · пояснение · важно · пример · определение · предупреждение |
| **Медиа** (`media`) | То, чего нет в материалах: своё изображение, фото доски, внешняя ссылка (без автоматического предпросмотра) |
| **Задание** (`activity`) | Ссылка на Активность вида `study_task` |

- **Вставка в середину страницы — разрез** блока материала на два куска по границе
  фрагмента; отдельных якорей нет. При новой ревизии материала граница переносится тем же
  сопоставлением, что и привязки; не нашлась — сдвигается к границе страницы с пометкой.
- **Один документ — два способа показа:** «Страницы» (оригинал) и «Текст» (распознанные
  фрагменты, `ocr_low` — рядом с вырезом оригинала). Двух видов уроков нет.
- **Происхождение у каждого блока:** ручное · из оглавления · модельное · смешанное; у
  модельного — основание `только источники проекта / источники + знания модели / только
  знания модели` и опорные фрагменты. Ссылку модели сервер принимает, только если фрагмент
  был в её контексте.
- **«Требует проверки»** вычисляется сравнением со снимком: тема вне программы или
  переименована → урок требует проверки; материал удалён → блок «Источник недоступен».

### 8.2. Раздел «Уроки»

Три колонки: **программа** (дерево с состояниями `нет урока` / `черновик` / `N уроков` /
`требует проверки`, чекбоксы массового выбора) · **урок** (обзор раздела, редактор урока
темы или таблица массовой подготовки нескольких тем) · **материал для урока** с вкладками
«Оглавление», «Страницы», «Поиск» и «Предложено». «Предложено» — стартовая вкладка:
она читает опубликованные опоры прохода 2, показывает точные включения/пересечения и
вставляет выбранный диапазон вручную в указанное место Урока.

**Ручное создание.**

- **«Быстрый урок»** у темы ничего не спрашивает: берёт диапазон страниц из оглавления у
  основного источника, уточняет границы по заголовкам (диапазон оглавления теряет конец
  темы на странице, где начинается следующий пункт), режет по подпунктам с заголовками,
  создаёт черновик. Ноль вызовов модели.
- **«Из источников»** — то же по нескольким источникам с выбором: основной и
  дополнительные отмечены, справочный — нет.
- **Вручную** — из правой панели: добавить страницу, структурный блок, выделенные
  фрагменты или область страницы; свои пояснения и медиа.
- **Массовая подготовка** — таблица `быстрый урок / вручную / пропустить`; готовые уроки
  по умолчанию пропускаются.

**Тема без диапазона оглавления** (типично для свободного проекта, 23.09.2026). Вместо
одинокого «Собрать вручную» — три пути: «Найти в материалах проекта» (вкладка «Поиск»
с «Отметить» у страниц и «Создать урок из отмеченного»; у открытого урока — «Добавить
отмеченное в урок»), «Подобрать материал» (материалы Библиотеки и «Найти в интернете» по
теме) и «Собрать вручную». Отмеченные страницы становятся кусками черновика в порядке
выбора одной командой и одной записью отмены; привязки ручные.

**Добавление в урок создаёт привязку к теме.** Выбранное пользователем — ручная привязка;
диапазон оглавления из «Быстрого урока» — машинная (её может оспорить проход 2).
Существующая привязка не трогается: снятая не воскресает, ручная не понижается. Удаление
блока привязки молча не снимает.

### 8.3. ИИ поверх урока

Три сценария, основание выбирается явно до запуска:

| Сценарий | Что делает модель | Результат |
|---|---|---|
| **Дополнить урок** | Пояснения, переходы, примеры, определения между блоками; материал не удаляет. Контекст — сам урок, поиск не нужен | Карточка изменений: частичное принятие, одна отмена |
| **Добавить практику** | Задания по материалу урока; опирается на упражнения учебника, если они есть | Карточка с заданиями |
| **Собрать урок** | Кандидаты локально (оглавление, привязки, проход 2, BM25) → storyboard по компактной карте кандидатов → правка пользователем со стоимостью → генерация по блоку фоновой задачей | Черновик нового урока |

Сделано 28.09.2026 (`docs/architecture/lessons.md`, «Модельные сценарии»): «Собрать урок» —
уровни «Черновик» (один вызов, без плана), «Обычный» и «Подробный» (план-предложение с
редактором, шаг за вызов, у «Подробного» рецензент); четыре шаблона; «Дополнить урок» —
предложение карточками в документе, частичное принятие, одна отмена; «Добавить практику»
— предложение заданий; массовая сборка «Черновиков» в порядке программы. Урок пишется для
новичка: каждое специальное слово объясняется при первом появлении, примеры конкретны.

### 8.4. Задания

**Заданий без модели нет:** самопроверка по эталону и составление заданий вручную
отклонены 14.09.2026. Задания создаёт модель и хранит их как Активности нового общего
вида учебникового режима `study_task` (условие, форма, ключ или эталон, опорные фрагменты).
Форм семь (уточнено 28.09.2026): выбор одного, несколько верных, пропуски, числовой ответ,
порядок шагов, сопоставление, открытый ответ. Шесть проверяются по ключу без вызова модели
— это работает и при выключенных моделях; открытый ответ проверяет ИИ-судья по заданию,
эталону и опорным фрагментам, без моделей ответ сохраняется и проверяется позже. Одно и то
же задание потом используют Занятия, тренировка и чат.

## 9. Планирование занятий

Раздел выключен по умолчанию и включается в настройках учебникового проекта, в том
числе «Свободного изучения». Включить его можно заранее; пустое состояние ведёт к
подготовке программы и уроков. Календарь распределяет **готовые непустые уроки**,
каждый урок с несколькими темами остаётся одной единицей плана. Срок необязателен;
расчётная дата окончания учитывает длительность уроков и ритм из паспорта цели.

Таймер в верхней панели Рабочей области считает активное время только при открытом
готовом непустом уроке, пока вкладка видима и пользователь активен. Включение
раздела разрешает учёт без отдельной команды «Начать день». В календаре показаны
время сегодня и уроки, за которыми оно проведено. Отметка «Урок пройден» не
стирает время. Экзаменационные периоды, повторения, долг и глубокая аналитика в
этот раздел не переносятся. Фактический контракт — `docs/architecture/lesson-planning.md`.

## 10. Что в режим не входит

**Решено 17.09.2026: карточек в учебниковом режиме нет.** Учебниковая конфигурация
карточек не проектируется и не делается. Причина не в объёме работ: самопроверка в
учебнике — это задания урока (§8.4, решение 14.09.2026), и карточки были бы вторым
механизмом проверки на ту же роль. ТЗ (п. 4.1.1.1 к) обещает карточки только
экзаменационному проекту, поэтому решение ничего в ТЗ не меняет. Освободившееся место
в навигации занимает раздел «Покрытие» (§4, §7).

**Решено 14.09.2026:** проверка себя в учебнике — это задания урока (§8.4), отдельного
аналога «Сдать ответ» по теме нет.

**Не входит принципиально** (общие границы продукта, `REQUIREMENTS.md` §22): чат с
документом как главный сценарий, универсальная база знаний, платформа курсов,
многопользовательский режим.

## 11. Порядок работ

Вертикали идут по одной; каждая заканчивается тем, что можно показать.
**Редакция очереди — 24.09.2026.** Retrieval стал общей вертикалью, покрытие поставлено
на паузу; свободное изучение по просьбе владельца сделано раньше «ИИ поверх урока».
Датированное обоснование прежнего порядка ниже остаётся историей решения.

| № | Вертикаль | Что в ней |
|---|---|---|
| 1 | **Программа учебника** — реализована | Мастер целиком: импорт оглавления, чат с дифами, оба сценария. Рабочая область с честными заглушками |
| 2 | **Уроки без модели** — реализованы этапы 1–3 | Весь интерфейс раздела и вкладки «Урок», быстрый урок, ручной редактор, массовая подготовка и прохождение. Осталась ручная проверка на 2–3 учебниках — её прогоняем одним заходом с тест-циклом программы |
| 3 | **RAG и гибридный поиск** — реализован | Общий retrieval, поиск проекта/Библиотеки, учебниковый и free-чат, цитаты, полный обзор |
| 4 | **ИИ поверх урока** — реализовано 28.09.2026 | «Дополнить урок», уровни сборки «Обычный / Подробный», задания урока и массовая подготовка (`docs/architecture/lessons.md`) |
| 5 | **Свободное изучение** — реализовано 24.09.2026 | Мастер из четырёх шагов, программа по цели с подсказками «Где искать», подбор материалов Библиотеки без модели, «Материалы к темам», «Урок из найденного» (`docs/architecture/free-study-wizard.md`); поиск в интернете — чат на SearXNG (`docs/architecture/source-search-chat.md`) |
| пауза | **Проход 2 и покрытие** | И2–И3 и И5 сохранены; И4/И6/И7 ждут отдельного решения по benchmark |
| далее | **Ручная проверка Уроков** | Совместный прогон программы и уроков на 2–3 учебниках; базовое планирование занятий по готовым урокам реализовано |

В проходе 2 И2, И3 и И5 реализованы. Следующая работа по нему не назначена: И4 → И6 →
И7 остаются сохранённым продолжением после отдельного продуктового решения.

**Что обязательно.** Приёмка по §8.3 ТЗ (11-я неделя, 10–16.11.2026) показывает функции
п. 4.1.1.1 а)–к) и 4.1.1.2 в двух сквозных сценариях: подготовка к экзамену без внешних
моделей (работает) и изучение по учебнику с программой из оглавления и Уроками. В а)–к)
входят «Дополнить урок», задания урока и «Собрать урок» (е), а также базовое
планирование занятий учебникового проекта (к), реализованное 28.09.2026.
Проход 2, поиск внешних источников, устный ответ и бот — п. л), расширенные функции по
согласованию: в обязательную приёмку не входят и режутся первыми.

**Почему Уроки раньше прохода 2** (решение 14.09.2026). Ручные уроки от прохода 2 не
зависят: быстрый урок строится по диапазонам оглавления, ручной — через поиск и страницы.
Проходу 2 остаётся вкладка «Предложено» и кандидаты для «Собрать урок», поэтому эти части
идут после него. Сам проход 2 не отодвигается за необязательные этапы: это главный
алгоритм проекта.

**Почему «Собрать урок» стоит рядом с «Дополнить урок»** (решение 20.09.2026). Оба
сценария работают над одним документом урока и одной карточкой изменений, поэтому дешевле
сделать их одним заходом, чем возвращаться к модели урока дважды. Кандидатов «Собрать
урок» получает из общего `HybridRetriever`: оглавление, привязки и результаты прохода 2
остаются сигналами, но отдельный поиск для Уроков не создаётся.

**Почему свободное изучение — не отдельный тип проекта** (решение 17.09.2026). Логика
та же, что у учебникового: программа, привязки, покрытие, уроки, занятия. Различается
только то, как программа появляется на свет и что видно, пока источников нет, — значит
различие живёт в интерфейсе раздела «Программа», а не в отдельной модели данных,
отдельном мастере и отдельной навигации. Консультант, который говорит «по этим темам
источника нет, поищи ещё», — это чтение «Пробелов», поэтому вертикаль и стояла после
прохода 2. **Уточнено 24.09.2026:** консультант сделан без прохода 2 — пробелом считается
тема без содержательных привязок по сводке привязок, а материал подбирается общим
`HybridRetriever` по Библиотеке. Когда проход 2 вернётся, он только добавит привязок, и
список «Без материала» сократится сам.

**Решение по retrieval от 20.09.2026.** Общий lexical+dense-контур реализован отдельной
вертикалью, а покрытие временно поставлено на паузу. Он не заменяет полный перебор
прохода 2 и не создаёт привязки. Выбор embedding-модели делается встроенным benchmark;
следующий потребитель — ИИ-сборка Урока через тот же `HybridRetriever`.

**Почему нет полного прохода 1.** Проход 1 — это map-reduce по содержанию всех глав,
около тридцати вызовов на учебник. Программа по оглавлению с метаданными обходится
одним–тремя. Пока не показано, что оглавления и поиска не хватает, дорогой путь не
делается. Тест-цикл первой вертикали и должен это показать: если на учебнике без
оглавления и без распознаваемых заголовков результат негодный — проход 1 заводится
отдельной работой.

## 12. Тест-цикл первой вертикали

Не приёмка кода, а замер качества. Он же даёт числа для обоснования в записке.

**Материалы подбираются с разными входными данными**, иначе замер ничего не покажет:

1. PDF с полными закладками;
2. PDF без закладок, но с распознаваемыми заголовками;
3. скан или фотографии страниц, прошедшие OCR;
4. методичка без оглавления вообще.

Каждый учебник прогоняется тремя способами: ручной импорт оглавления, ИИ по оглавлению,
ИИ по своей цели. Для каждого прогона фиксируется:

| Показатель | Зачем |
|---|---|
| число разделов и тем, глубина дерева | сопоставимость результатов |
| сколько записей оглавления потерялось | видно, режет ли модель лишнее |
| сколько тем помечено «нужно найти материал» | честность метки, а не молчаливый пропуск |
| токены, стоимость, время | сравнение дешёвого и дорогого пути |
| оценка 1–5 и одна строка «что пошло не так» | то, ради чего всё и делается |

Результат — файл в `docs/research/`.
