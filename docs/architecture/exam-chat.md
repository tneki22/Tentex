# Экзаменационный чат: фактический контракт

Дата фиксации: 12.08.2026, дополнено 29.08.2026 (AI-CHATS.md §21 — первая
кодовая итерация управляемого экзаменатора). Реализован письменный протокол
сдачи одного вопроса: чат с потоковым ответом → неизменяемая Попытка →
проверка → отдельная Оценка → история во вкладке «Ответ». Внешние модели
проходят только через существующий `ModelGateway`.

## Граница итерации

Работают:

- несколько чатов на одном вопросе, сохранённый черновик и потоковый ответ;
- остановка потока с сохранением уже полученного текста;
- форма письменного ответа, неизменяемая Попытка и её порядковый номер по теме;
- лесенка `точное совпадение → ключевые термины → ИИ-судья`;
- три группы пунктов разбора с проверенными на сервере позициями цитат;
- фактическая модель, токены, стоимость в USD/рублях и признак exact-кэша;
- независимая самооценка пользователя;
- история попыток вне чата, повторная проверка незавершённой попытки;
- резервный офлайн-контур сдачи: форма и Попытка работают без модели, но это
  не диалог и не «чат без ИИ»;
- `ChatSession.mode/model_override/context_flags`, частичный PATCH настроек,
  персона и строгость применяются к обычному ответу через слоистый prompt;
- профиль проекта в контексте как недоверенные данные (`<profile_data>`);
- context flags исключают профиль/эталон/фрагменты из вызова, manifest несёт
  `included/reason`, preview и фактический вызов проверяемо делят один
  `fingerprint`;
- общий `ChatToolRun`-реестр и единственный настоящий Tool
  `search_project_materials` поверх FTS5/BM25, без обращения к модели;
- `GET .../chat/capabilities` — режимы, навыки и Tools с `available` и
  стабильной причиной недоступности;
- SSE `completed` несёт финальный `ChatMessageRead` — фронтенд не перечитывает
  сессию целиком.

Не реализованы и не имитируются: палитра навыков `/вопрос`, `/подсказка`,
`/точность`, `/задание`, билет и доспрос, возражение, память раздела, устная
Попытка, диктовка, внешний поиск источников. Это граница итерации 2 и
последующих этапов; соответствующие Tools зарегистрированы без `handler` и не
выполняются в обход интерфейса.

## Граница модулей

```text
Рабочая область
  ├─ обычное сообщение ──> exam_chat_reply ──SSE──> ChatMessage
  └─ «Сдать ответ» ──────> Attempt ──> deterministic_check
                                      ├─ однозначно ──> Grade
                                      └─ неоднозначно ─> exam_answer_judge ─> Grade

ChatMessage ссылается на Attempt/Grade; Оценка не живёт внутри переписки.
```

| Модуль | Ответственность |
|---|---|
| `app/exam/chat.py` | сессии, сообщения, черновик, настройки (`update_settings`), capabilities, preview контекста, последовательность и завершение потока |
| `app/exam/context.py` | вопрос, профиль проекта, эталон, ручные привязки, хвост чата, context flags и manifest с fingerprint |
| `app/exam/prompts.py` | слои prompt `base → mode → persona → strictness` для обычного ответа; отдельный prompt судьи |
| `app/exam/checking.py` | нормализация, ключевые термины и детерминированные пороги |
| `app/exam/judge.py` | схема судьи, prompt, вызов шлюза (с учётом `model_override`) и проверка цитат |
| `app/exam/attempts.py` | снимок Попытки, Оценка, история, повторная проверка и самооценка |
| `app/exam/router.py` | HTTP и SSE-контракт |
| `app/chat_tools/registry.py` | неизменяемый реестр `ToolSpec`; настоящий Tool и заблокированные specs будущих |
| `app/chat_tools/executor.py` | `run_tool`: проверка доступности/режима, валидация входа, `ChatToolRun`, типизированное сообщение |

Для обычного ответа контекст ограничен 12 последними сообщениями, 6 фрагментами
по 1500 символов и общим бюджетом 12 000 символов для эталона, профиля и
фрагментов. Судья никогда не получает хвост чата: только вопрос, снимок
профиля и эталона, привязанные фрагменты и текст конкретной Попытки — он же
использует `Attempt.context_snapshot["model_override"]`, замороженный на
момент сдачи, а не текущую настройку сессии.

`ChatSession.context_flags` (`profile`/`reference`/`fragments`/`attempts`/
`section_memory`) управляют и обычным ответом, и проверкой ответа: обе стороны
читают один и тот же `build_context`. `attempts` и `section_memory`
зарегистрированы в модели заранее, но контекст их пока не заполняет —
`ContextChips` показывает их как честно недоступные.

## Данные и миграции

`20260812_0012_exam_chat.py` добавляет:

- `chat_sessions` — проект, тема, заголовок, будущие persona/strictness и черновик;
- `chat_messages` — монотонный `sequence`, роль, текст, состояние потока,
  типизированный payload, manifest и ссылка на `ai_runs`.

`20260812_0013_attempts_grades.py` добавляет:

- `attempts` — неизменяемый текст, номер по теме, persona/strictness и полный
  снимок контекста проверки;
- `grades` — системный исход, метод, три группы пунктов, резюме, отдельная
  самооценка и ссылка на запуск модели;
- `chat_messages.attempt_id` и `grade_attempt_id`, обе связи используют
  `ON DELETE SET NULL`.

`20260812_0014_backfill_legacy_attempts.py` переносит формы ответа, сохранённые
подэтапом 1a, в `attempts`, не создавая вымышленных Оценок. Поэтому следующая
сдача продолжает видимую нумерацию, а старые ответы доступны для кнопки
«Проверить ещё раз».

`20260829_0026_exam_chat_foundation.py` добавляет:

- `chat_sessions.mode` (`exam`/`study`, default `exam`), `model_override`
  (JSON-снимок `{provider_id, model_id}` — не FK, запись переживает удаление
  подключения провайдера) и `context_flags` (JSON, default —
  `{"profile": true, "reference": true, "fragments": true, "attempts": false,
  "section_memory": false}`);
- `chat_messages.skill` (nullable) — какая операция создала сообщение;
  `chat_payload_kind` расширен значением `tool_result`;
- таблицу `chat_tool_runs` — `project_id`/`session_id`/`tool_key`/`state`
  (`queued/running/succeeded/failed`)/`tool_input`/`result`/`error_code` и
  nullable unique `message_id` на созданный типизированный блок.

Каждая колонка/таблица добавлена отдельным top-level вызовом (`op.add_column`,
не сгруппированным `batch_alter_table`): SQLite-батч, пересобирающий несколько
колонок разом, теряет привязку CHECK-ограничения Enum к дропаемой колонке.
Единственный сгруппированный `alter_column` — расширение `chat_payload_kind`.

Все миграции проверены на пустой базе и копии рабочей SQLite;
upgrade/downgrade сохраняют пустой `PRAGMA foreign_key_check`.

Удаление проекта или узла каскадно удаляет его чаты и попытки. Удаление Попытки
удаляет Оценку, а сообщения теряют только ссылку. `parent_attempt_id` зарезервирован
для будущего доспроса и в этой итерации не заполняется.

## HTTP

Префикс всех путей: `/api`.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/projects/{project}/chat/sessions?node_id=…` | чаты темы по времени изменения |
| POST | `/projects/{project}/chat/sessions` | новый чат для `program_node_id` |
| GET | `/projects/{project}/chat/sessions/{chat}` | чат, черновик и полная лента |
| PUT | `/projects/{project}/chat/sessions/{chat}/draft` | сохранённый черновик |
| PUT | `/projects/{project}/chat/sessions/{chat}/settings` | частичный PATCH mode/persona/strictness/model_override/context_flags |
| GET | `/projects/{project}/chat/sessions/{chat}/context` | manifest, fingerprint, объём и источник модели — preview перед вызовом |
| GET | `/projects/{project}/chat/capabilities?node_id=…` | режимы, навыки и Tools с `available`/`unavailable_reason` |
| POST | `/projects/{project}/chat/sessions/{chat}/tools/{tool_key}/runs` | синхронный запуск Tool через `ToolExecutor` |
| POST | `/projects/{project}/chat/sessions/{chat}/messages` | поток обычного ответа |
| POST | `/projects/{project}/chat/sessions/{chat}/answer` | сохранить Попытку и сразу проверить |
| POST | `/projects/{project}/attempts/{attempt}/check` | идемпотентно проверить прежнюю Попытку |
| PUT | `/projects/{project}/attempts/{attempt}/self-assessment` | сохранить `passed/partial/failed` отдельно |
| GET | `/projects/{project}/attempts?node_id=…` | краткая история темы, новые сверху |
| GET | `/projects/{project}/attempts/{attempt}` | полный текст и Оценка, если она есть |

`POST …/answer` возвращает `{messages, attempt, grade}`. Первая запись ленты
имеет `payload_kind=answer_form` и `attempt_id`; карточка разбора имеет
`payload_kind=verdict` и `grade_attempt_id`. Повторный `POST …/check` не создаёт
вторую Оценку. Если внешний судья вернул невалидный структурный ответ, Попытка
и форма уже сохранены, а Оценки нет — интерфейс предлагает повторить проверку.

`PUT …/settings` использует `model_fields_set`: неуказанное поле не трогается,
`context_flags` мержится по ключу, а не заменяется целиком. `model_override:
null` явно возвращает сессию к `Auto`; неизвестная пара `provider_id/model_id`
или модель без одновременных `streaming`+`structured_output` отклоняются
кодом `ai_model_not_in_catalog`/`ai_capability_unsupported` — одна модель
обслуживает и обычный ответ, и судью той же сессии. `mode: study` отклоняется
стабильным `chat_mode_unavailable`.

`POST …/tools/{tool_key}/runs` принимает `{"input": {...}}`. Неизвестный ключ
даёт `chat_tool_not_found`; зарегистрированный, но не опубликованный Tool
(нет `handler`) — `chat_tool_unavailable`. Единственный реализованный Tool —
`search_project_materials` (`effect=read`, `confirmation=never`): вызывает
существующий `bindings.service.search_project_materials` поверх FTS5/BM25,
не создаёт Привязку и не обращается к `ModelGateway`. Результат сохраняется в
`ChatToolRun.result` и как `ChatMessage(payload_kind=tool_result, skill=tool_key)`
— повторное открытие истории не перезапускает поиск.

## SSE

`POST …/messages` отвечает `text/event-stream`, без буферизации и кэширования.
Каждый кадр имеет две строки `event:` и `data:` с JSON, затем пустую строку:

```text
event: started
data: {"message_id":"…","run_id":"…"}

event: delta
data: {"text":"часть ответа"}

event: completed
data: {"message_id":"…","message":{…ChatMessageRead…},"usage":{…},"cached":false}
```

`completed.message` — полный `ChatMessageRead` сохранённого сообщения,
записанный в базу **до** отправки кадра. Фронтенд заменяет оптимистичную
запись этим объектом по `id` и не перечитывает сессию целиком. Сохранение
происходит ровно один раз за поток: успешный `completed` сохраняет прямо в
обработчике события; отмена (`CancelledError`) и любая другая ветка выхода
сохраняют `stopped`/`failed` в `finally`, если сохранение ещё не произошло.

При доменной ошибке после старта приходит `event: error` с `code` и `detail`.
Отмена клиентом сохраняет накопленный текст как `stream_state=stopped`; обычное
завершение — `complete`, ошибка — `failed`. Частичный JSON никогда не является
payload: типизированные карточки приходят только обычным JSON API.

## Лесенка проверки

Нормализация точного совпадения приводит регистр, `ё/е`, пунктуацию и пробелы.
Если нормализованные тексты равны, Оценка сразу получает `passed` и
`method=exact_match`, без вызова модели.

Иначе из эталона извлекается не больше 12 русских содержательных лемм с учётом
формулировки вопроса. Доля найденных терминов считается так:

```text
coverage = найденные термины / термины эталона
```

| Условие | Предварительный исход | Окончательно без модели |
|---|---|---|
| `coverage >= 0.80` | `passed` | да |
| `0.25 < coverage < 0.80` | `partial` | нет |
| `coverage <= 0.25` | `failed` | нет |
| эталона/терминов нет | `unscored` | нет |

Неоднозначный результат передаётся роли `exam_answer_judge` со strict JSON
Schema. Судья возвращает `passed/partial/failed`, пункты `credited/missed/wrong`
и краткое резюме. Для каждой заявленной цитаты сервер независимо ищет точное
вхождение в ответе и записывает `quote_start/quote_end`; несуществующая цитата
остаётся видимой, но без координат и не подсвечивает чужой текст.

Exact-кэш судьи привязан к теме, SHA-256 текста ответа и ревизии эталона вместе
с каноническим запросом шлюза. Та же формулировка в новой Попытке использует
проверенный кэш, создаёт новый `AiRun(status=cached)` и показывает нулевую новую
стоимость. Изменение ответа или ревизии эталона требует новой проверки.

## Выключенный ИИ и ошибки

Обычное сообщение сначала проходит preflight шлюза. При выключенном глобальном
ИИ или роли оно не создаёт платного запуска, а клиент показывает `OfflineNotice`.
Форма ответа от шлюза не зависит и всегда сохраняет Попытку.

Если детерминированная ступень неоднозначна, коды `ai_disabled`,
`ai_role_disabled`, `ai_provider_unavailable`, `ai_timeout` и `ai_daily_limit`
дают честную предварительную Оценку `method=key_terms` с предложением оценить
себя. `self_assessment` не переписывает системный `outcome`; только у исхода
`unscored` отображаемый метод становится `self_assessment`.

Стабильные доменные коды самого модуля:

| HTTP | Код | Причина |
|---|---|---|
| 404 | `project_not_found` | проект не существует |
| 409 | `chat_exam_only` | проект не экзаменационный |
| 404 | `chat_node_not_found` | тема не существует или не учебная |
| 404 | `chat_session_not_found` | чат не принадлежит проекту |
| 404 | `attempt_not_found` | Попытка не принадлежит проекту |
| 409 | `attempt_grade_missing` | самооценка запрошена до проверки |
| 422 | `self_assessment_unscored` | вместо самооценки прислан `unscored` |
| 422 | `chat_mode_unavailable` | `mode=study` — зарегистрирован, но пока недоступен |
| 422 | `chat_context_flag_unknown` | неизвестный ключ в `context_flags` |
| 404 | `chat_tool_not_found` | такого Tool не существует |
| 422 | `chat_tool_unavailable` | Tool зарегистрирован, но не опубликован (нет `handler`) или не подходит режиму сессии |
| 422 | `chat_tool_input_invalid` | вход Tool не прошёл Pydantic-схему |
| 422 | `chat_tool_confirmation_required` | Tool требует подтверждения — политика `always` не реализована в первой итерации |

`ai_model_not_in_catalog` и `ai_capability_unsupported` при сохранении
`model_override` принадлежат общему шлюзу (`app/ai/settings.py`), но
проверяются здесь же — `validate_model_selection` требует одновременно
`streaming` и `structured_output`. Остальные коды preflight и структурной
валидации описаны в `docs/architecture/ai-model-gateway.md`.

## Интерфейс

Вкладка «Чат» показывает потоковую Markdown-ленту, не прыгает вниз, если
пользователь читает историю, и держит live-region стабильным. Форма сдачи после
отправки неизменяема. Карточка Оценки всегда показывает три группы; наведение
или клавиатурный фокус пункта подсвечивает связанную цитату и использует
`aria-describedby`. Ни один смысл не передаётся только цветом.

Внизу карточки видны метод проверки, фактическая модель, токены, `$`, `≈ ₽` и
кэш. Самооценка показана рядом, но отдельно от решения системы. Вкладка «Ответ»
содержит «Мои попытки»: краткий список, раскрытие полного разбора и повторную
проверку незавершённых записей. Состояние переживает перезагрузку.

Сетевое состояние вынесено в `useExamChat.ts`: сообщения хранятся
нормализованно (`messagesById` + `messageOrder`), обычная реплика заводится по
`started` и обновляется на месте по `delta`/`completed` — без промежуточного
исчезновения. Шапка (`ChatHeader.tsx`) держит историю чатов области и
`ExaminerControl.tsx` — единый попап персоны, строгости и модели
(`ProviderModelPicker`, отфильтрованный по `streaming`+`structured_output`).
`ContextChips.tsx` заменяет прежнюю строку «В запрос уходит: …»: каждый чип
раскрывает состав и объём из preview, переключает `context_flags` и не
включается обратно молча. Композер (`ChatComposer.tsx`) открывает
`SkillPalette.tsx` по `+` и по `/` в пустом поле; недоступные команды показывают
причину и не создают сообщений. Типизированные блоки идут через единый
`TypedMessage.tsx` (`answer_form` / `verdict` / `tool_result` / обычная
реплика / неизвестный `payload_kind` — честный fallback, а не падение);
результат `search_project_materials` рисует `ToolRunCard.tsx` +
`MaterialSearchResults.tsx` со ссылкой на страницу/фрагмент через уже
существующий маршрут `/projects/:id/materials/:materialId?page=…&focus=…`.

Интерфейс проверен в светлой и тёмной темах, на ширине 390 px и клавиатурой,
на реальных данных демо-проекта (`app.projects.demo.seed_demo_project`) в
браузере: настройки экзаменатора, контекстные чипы, палитра, локальный поиск
через Tool и сдача ответа с детерминированной проверкой. На 390 px документ не
имеет горизонтального переполнения; рабочие панели по настольному baseline
остаются отдельными внутренними горизонтальными областями (композер и строка
чипов переносятся/скроллятся внутри своей панели, не наружу).

## Проверка

`python backend/scripts/check_exam_chat.py` поднимает временную SQLite и fake-
провайдер, затем проверяет поток (включая `completed.message`), точное
совпадение, ИИ-судью, повтор через кэш, самооценку, глобальный выключатель,
частичный PATCH настроек (persona/strictness сохраняются раздельно, `study` и
неизвестная модель отклоняются стабильными кодами), `capabilities`, preview
контекста с fingerprint, запуск `search_project_materials` через Tool-реестр
(без обращения к модели, результат виден в истории без повтора), отклонение
неизвестного Tool, историю и `PRAGMA foreign_key_check`.

Точечные pytest покрывают нормализацию, лемматизацию и пороги, снимок контекста,
верификацию цитат, кэш, сохранение Попытки при поломанном судье, резервную
сдачу без модели, порядковые номера и HTTP-проекцию (`test_exam_chat.py`);
