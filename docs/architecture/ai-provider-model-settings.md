# Провайдеры и модели ИИ: фактический контракт

Дата фиксации: 14.08.2026. Этот документ уточняет и заменяет части
`ai-model-gateway.md`, где описаны ровно два подключения `text/speech`.

## Инварианты

- Провайдер — самостоятельное подключение с UUID, названием, профилем каталога, URL,
  зашифрованным ключом и диагностическим статусом.
- Идентичность модели — только пара `(provider_id, model_id)`. Одинаковый `model_id`
  у двух провайдеров означает две независимые записи.
- Избранное не участвует в наследовании. Оно хранит быстрые ярлыки: boolean у
  провайдера и `favorite_order` у модели.
- Для `text` и `speech` хранится ровно по одной явной паре по умолчанию. Override роли
  также задаётся только полной парой.
- Consumer по-прежнему передаёт роль и содержимое запроса, но не знает URL, ключ,
  цену или способ разрешения модели.

```text
request override (если роли разрешено)
        ↓
полная пара роли
        ↓
полная пара модальности по умолчанию
        ↓
провайдер + каталог + параметры → ModelGateway
```

## Хранение

Миграция `20260814_0015_ai_providers.py`:

- заменяет `ai_connections` на `ai_provider_connections`;
- меняет ключ `ai_model_catalog` с `(modality, model_id)` на
  `(provider_id, model_id)`;
- добавляет в модель максимум ответа, reasoning metadata, provider defaults,
  ручные overrides, cutoff/expiration, источник ручного добавления и порядок избранного;
- добавляет две пары default в `ai_settings` и `confirm_cost_usd`;
- добавляет `provider_override_id` роли;
- пишет в каждый новый run UUID провайдера и неизменяемый снимок его названия.

Старые текстовое и речевое подключения мигрируют в провайдеры только если содержат URL,
ключ, default или каталог. Старые каталоги, default и ролевые overrides получают UUID
соответствующего провайдера. Миграция проверена на пустой базе, на legacy-снимке с
моделью/default/override и в направлении downgrade.

## Каталог и параметры

Профиль `openrouter` сохраняет расширенные поля ответа `/models`: цены за токен,
контекст, модальности, supported parameters, максимум ответа, reasoning metadata,
provider defaults, cutoff и expiration. `openai_compatible` использует те же поля,
если сервер их возвращает, и безопасные пустые значения в остальных случаях.

Refresh сначала помечает старый снимок недоступным, затем upsert-ит текущий ответ.
`manual_overrides` и `favorite_order` при этом сохраняются и накладываются поверх нового
снимка. Ручная модель начинается с `text → text`, пустых параметров и неизвестной цены,
если пользователь не указал дополнительные поля.

Параметры вызова объединяются в порядке:

```text
provider/model defaults → validated role parameters → request parameters
```

В hash exact-кэша входит UUID провайдера, поэтому одинаковый model id другого
провайдера не может переиспользовать чужой результат.

## Проверки

`Тест` провайдера вызывает только каталог и обновляет диагностический статус. `Тест`
модели выполняет короткий вызов скрытой роли `settings_model_test`, не кэширует и не
сохраняет ответ, но создаёт обычный безопасный `AiRun` с токенами, стоимостью и временем.

Удаление ключа оставляет каталог, defaults и журнал. Удаление провайдера каскадно удаляет
его каталог, но блокируется с `409 ai_provider_in_use`, если UUID используется default
или ролью. Старые run сохраняются, а FK провайдера становится `NULL`; читаемое название
остаётся в `provider_label_snapshot`.

|---|---|---|
| GET/PUT | `/api/settings/ai` | безопасный снимок и глобальные лимиты |

| PUT/DELETE | `/providers/{id}` | изменить или удалить провайдера |
| DELETE | `/providers/{id}/credential` | удалить ключ |

| POST | `/providers/{id}/models/refresh` | обновить каталог |
| PUT | `/providers/{id}/models/manual` | добавить/исправить модель вручную |

| PUT | `/provider-favorites` | заменить набор избранных провайдеров |

| PUT | `/defaults/{text|speech}` | задать/очистить пару по умолчанию |

| GET | `/runs` | журнал с фильтрами |
| GET | `/usage` | агрегация по роли, провайдеру или модели |

## Экран

`/setup?section=ai&subsection=...` имеет семь самостоятельных поверхностей:
`overview`, `providers`, `models`, `defaults`, `functions`, `limits`, `usage`.
`provider=<uuid>` делает прямую ссылку на каталог конкретного провайдера. На мобильном
окне подразделы становятся вторым горизонтальным рядом внутренней навигации.

Один `ProviderModelPicker` используется для defaults и функций: провайдер выбирается
первым, модель — только из его совместимого локального каталога. Компонент показан в
`/ui-kit`; ручной ввод id остаётся только в добавлении модели.
