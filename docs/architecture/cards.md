# Карточки: фактический контракт

Срез реализован 06.09.2026. Карточки повторяют только то, что пользователь назначил в календаре «Моей подготовки», либо явно выбранную свободную подборку. Они не создают, не переносят и не рассчитывают календарные назначения.

## Модель данных

`Activity` — общий владелец Попыток. Она принадлежит проекту, необязательно ссылается на один узел программы и имеет вид `free_answer` или `card`, силу свидетельства и происхождение. Миграция `20260906_0038` создаёт одну активность свободного ответа на каждую существующую пару проект–узел и переводит старые `Attempt.program_node_id` на `Attempt.activity_id`. Публичный экзаменационный контракт по-прежнему получает `program_node_id` через Activity.

`Card` имеет собственную Activity вида `card`, максимум одну единицу программы или `null`, обе стороны, необязательную подсказку, состояние `active / suspended`, ревизию, даты и `deleted_at`. Источник бывает `none`, `fragment` или `reference`. Вместе со ссылкой хранится снимок названия материала, страницы, координат и текста, поэтому удаление исходного Фрагмента не уничтожает карточку. Потерянным считается ссылочный источник, текущая сущность которого больше недоступна.

`CardSession` хранит состав `today / hard / selected / all`, выбранные единицы, темп `calm / fast`, мягкий лимит, упорядоченный JSON-снимок карточек, позицию, активное время, состояние и ревизию. В установке может быть один активный сеанс проекта.

Карточная оценка — обычные `Attempt` и `Grade(method=self_assessment, confidence=1..4)`. UUID Попытки приходит с клиента и делает повтор запроса идемпотентным. «Отложить» создаёт Attempt без Grade, поэтому отложенная карточка не входит в среднюю уверенность.

## Правила выборок

- `today` берёт только активные карточки единиц с `kind=review` на текущий учебный день принятого Плана; порядок повторяет План.
- `hard` берёт активные карточки с последней оценкой 1–2 и сортирует от худшего среднего последних трёх оценок.
- `selected` разворачивает выбранные вопросы или целые билеты; билет нельзя раздробить выбором одной темы.
- `all` следует порядку Программы, затем добавляет карточки без вопроса.
- Оценка времени обзора равна `ceil(active_cards / 2)` минутам — 30 секунд на карточку.
- Аналитические окна 7/30 дней используют учебные сутки с границей 04:00 и всегда возвращают число реально попавших в окно Grade.

Сложной для карточки считается последняя оценка 1–2. Для порядка подборки используется среднее последних трёх оценок. Самый сложный вопрос в мини-аналитике выбирается по доле 1–2, затем по числу наблюдений.

## Открытие календарной единицы

`POST .../card-sessions/{sessionId}/open` вызывается при показе первой карточки текущей единицы. Общая функция `record_unit_opening` пишет событие `opened:{study_date}:{topic_id}`: для вопроса — один узел, для билета — все входящие темы. Уникальный ключ делает повторный запрос безопасным. Функция не меняет JSON Плана и не создаёт будущих повторений.

Карточные Activity исключены из старой проекции подготовки: её наблюдаемое время, открытия и экзаменационные свидетельства читают только `free_answer`. Это сохраняет совместимость до отдельного удаления оставшегося legacy-кода SM-2 из «Моей подготовки».

## HTTP API

- `GET /api/projects/{projectId}/cards/overview?period=7|30` — состояние Программы и Плана, сегодняшние повторения и покрытие, единицы, недавние/сложные карточки, аналитика и активный сеанс.
- `GET|POST /api/projects/{projectId}/cards` — поиск/фильтры и создание.
- `PATCH|DELETE /api/projects/{projectId}/cards/{cardId}` — редактирование и мягкое удаление; `POST .../restore` — восстановление.
- `POST /api/projects/{projectId}/cards/bulk` — активация, приостановка, удаление или восстановление списка с ожидаемыми ревизиями.
- `GET /api/projects/{projectId}/cards/fragments/{fragmentId}/prefill` — доступный проекту Фрагмент, снимок источника и предложенная единица по активной Привязке.
- `POST /api/projects/{projectId}/card-sessions` — создание снимка очереди; `replace_active=true` явно отменяет предыдущий сеанс.
- `GET .../card-sessions/active`, `GET .../card-sessions/{sessionId}`, `PATCH .../{sessionId}` — восстановление и позиция.
- `POST .../{sessionId}/open`, `.../cards/{cardId}/review`, `.../defer`, `.../finish`, `.../retry` — открытие единицы, оценка, откладывание, завершение и точный повтор карточек с оценкой 1–2 или отложенных.

Все изменяющие запросы карточек и сеансов проверяют ожидаемую ревизию. Конфликт карточки стабилен как `stale_card_revision`, конфликт сеанса — `stale_card_session_revision`. Чтение архивного проекта разрешено, запись отвечает `project_read_only`; все запросы проверяют принадлежность проекту.

## Клиент

Типы находятся в сгенерированном `frontend/src/api/generated/preparation.ts`; ручных копий DTO нет. Тонкий клиент — `frontend/src/api/cards.ts`, состояние разделено между `useCardsOverview`, `useCardBank` и `useCardSession`. Экран не использует локальных демо-наборов. Ручной редактор общий для создания и инспектора Банка. Путь из Материалов передаёт `fragment` в query string и заново проверяет Фрагмент на сервере.

ИИ-генерация, типы карточек, автоматическая обратная карточка и назначение сроков по уверенности в этот контракт не входят.
