# Карточки: фактический контракт

Срез реализован 06.09.2026. Карточки повторяют только то, что пользователь назначил в календаре «Моей подготовки», либо явно выбранную свободную подборку. Они не создают, не переносят и не рассчитывают календарные назначения.

## Модель данных

`Activity` — общий владелец Попыток. Она принадлежит проекту, необязательно ссылается на один узел программы и имеет вид `free_answer` или `card`, силу свидетельства и происхождение. Миграция `20260906_0039` создаёт free_answer Activity для каждой существовавшей в `attempts` пары проект–узел и переводит попытки на `activity_id`; новые активности свободного ответа создаются лениво. Публичный экзаменационный контракт по-прежнему получает `program_node_id` через Activity.

`Card` имеет собственную Activity вида `card`, максимум одну единицу программы или `null`, обе стороны, необязательную подсказку, состояние `active / suspended`, ревизию, даты и `deleted_at`. Источник бывает `none`, `fragment` или `reference`. Вместе со ссылкой хранится снимок названия материала, страницы, координат и текста, поэтому удаление исходного Фрагмента не уничтожает карточку. Потерянным считается ссылочный источник, текущая сущность которого больше недоступна.

Принятая ИИ-карточка дополнительно хранит `generation_run_id`; номер предложения и дословная опора находятся в `source_snapshot.generation`. Это происхождение не меняет `source_kind`, Activity и календарные правила. Миграция `20260928_0074` добавляет колонку.

`CardSession` хранит состав `today / hard / selected / all`, выбранные единицы, темп `calm / fast`, мягкий лимит, упорядоченный JSON-снимок карточек, позицию, активное время, состояние и ревизию. В установке может быть один активный сеанс проекта.

Карточная оценка — обычные `Attempt` и `Grade(method=self_assessment, confidence=1..4)`. UUID Попытки приходит с клиента и делает повтор запроса идемпотентным. «Отложить» создаёт Attempt без Grade, поэтому отложенная карточка не входит в среднюю уверенность.

## Правила выборок

- `today` берёт только активные карточки единиц с `kind=review` на текущий учебный день принятого Плана; порядок повторяет План.
- `hard` берёт активные карточки с последней оценкой 1–2 и сортирует от худшего среднего последних трёх оценок.
- `selected` разворачивает выбранные вопросы или целые билеты; билет нельзя раздробить выбором одной темы.
- `all` следует порядку Программы, затем добавляет карточки без вопроса.
- Оценка времени обзора равна `ceil(active_cards / 2)` минутам — 30 секунд на карточку.
- Аналитические окна 7/30 дней используют учебные сутки с границей 04:00 и всегда возвращают число реально попавших в окно Grade.

Сложной для карточки считается последняя оценка 1–2. Для порядка подборки используется среднее последних трёх оценок. Самый сложный вопрос в мини-аналитике выбирается по доле 1–2, затем по числу наблюдений.

## Открытие календарной единицы

`POST .../card-sessions/{sessionId}/open` вызывается при показе первой карточки текущей единицы. Календарное открытие записывается только после явного «Начать день»; до этого просмотр карточки не выполняет назначение, хотя карточная оценка остаётся отдельной явной попыткой. Общая функция `record_unit_opening` пишет событие `opened:{study_date}:{topic_id}`: для вопроса — один узел, для билета — все входящие темы. Уникальный ключ делает повторный запрос безопасным. Функция не меняет JSON Плана и не создаёт будущих повторений.

Карточные Activity исключены из старой проекции подготовки: её наблюдаемое время, открытия и экзаменационные свидетельства читают только `free_answer`. Это сохраняет совместимость до отдельного удаления оставшегося legacy-кода SM-2 из «Моей подготовки».

## HTTP API

- `GET /api/projects/{projectId}/cards/overview?period=7|30` — состояние Программы и Плана, сегодняшние повторения и покрытие, единицы, недавние/сложные карточки, аналитика и активный сеанс.
- `GET|POST /api/projects/{projectId}/cards` — поиск/фильтры и создание.
- `POST /api/projects/{projectId}/cards/generate` — предложения по `program_node_id` и режиму `connections / understanding`. Возвращает `run_id` и до шести кандидатов без сохранения в Банк; без готового ответа или привязанных Фрагментов отвечает `card_generation_no_source`.
- `PATCH|DELETE /api/projects/{projectId}/cards/{cardId}` — редактирование и мягкое удаление; `POST .../restore` — восстановление.
- `POST /api/projects/{projectId}/cards/bulk` — активация, приостановка, удаление или восстановление списка с ожидаемыми ревизиями.
- `GET /api/projects/{projectId}/cards/fragments/{fragmentId}/prefill` — доступный проекту Фрагмент, снимок источника и предложенная единица по активной Привязке.
- `POST /api/projects/{projectId}/card-sessions` — создание снимка очереди; `replace_active=true` явно отменяет предыдущий сеанс.
- `GET .../card-sessions/active`, `GET .../card-sessions/{sessionId}`, `PATCH .../{sessionId}` — восстановление и позиция.
- `POST .../{sessionId}/open`, `.../cards/{cardId}/review`, `.../defer`, `.../finish`, `.../retry` — открытие единицы, оценка, откладывание, завершение и точный повтор карточек с оценкой 1–2 или отложенных.

Изменения существующих карточек и сеансов требуют ожидаемую ревизию; создание новой карточки или нового сеанса не требует ревизии несуществующего объекта. Замена активного сеанса запрашивается явно через `replace_active=true`. Конфликт карточки стабилен как `stale_card_revision`, конфликт сеанса — `stale_card_session_revision`. Чтение архивного проекта разрешено, запись отвечает `project_read_only`; все запросы проверяют принадлежность проекту.

Генератор использует формулировку, текущий готовый ответ, до шести привязанных Фрагментов и лицевые стороны карточек этой единицы. Общий промпт запрещает пересказ заголовка, тривиальное определение, близкий дубль и сведения вне данных. `connections` проверяет различия, причины и условия; `understanding` — следствия, границы и небольшой выводимый случай. Модель возвращает одну дословную цитату-опору на кандидат. Сервер проверяет её по фактическому ответу/Фрагменту, отсеивает неподтверждённых и почти повторяющиеся вопросы. При `POST .../cards` с `generation_run_id` и `generation_candidate_index` сервер заново сверяет проект, единицу, кандидата, источник и цитату. Пользователь может изменить обе стороны и подсказку перед принятием. Уже принятое предложение повторно не сохраняется.

## Клиент

Основные типы находятся в сгенерированном `frontend/src/api/generated/preparation.ts`; новые типы ответа генерации временно описаны в тонком клиенте `frontend/src/api/cards.ts`. Полная регенерация OpenAPI-файла затрагивает множество ранее накопленных изменений схемы и выполняется отдельным обновлением контракта. Состояние разделено между `useCardsOverview`, `useCardBank` и `useCardSession`. Экран не использует локальных демо-наборов. Ручной редактор общий для создания и инспектора Банка. Путь из Материалов передаёт `fragment` в query string и заново проверяет Фрагмент на сервере.

Типы карточек, автоматическая обратная карточка и назначение сроков по уверенности в этот контракт не входят.
