# Ручная программа учебникового проекта

Фактический контракт части 1 вертикали «Программа учебника» на 11.09.2026.
ИИ-чат и дифы относятся к части 2 и здесь не описываются как готовые.

## Данные узла

`ProgramNode.basis_kind` отвечает только на вопрос, основан ли узел на оглавлении:

- `outline` — у узла есть хотя бы один проверенный пункт оглавления;
- `custom` — узел создан вне оглавления, в части 1 вручную.

`origin_kind` остаётся независимым происхождением последнего создания или изменения.
Ручное переименование либо перемещение outline-узла ставит `origin_kind=manual`, но
не меняет `basis_kind` и не удаляет диапазоны.

Диапазоны лежат в `program_node_source_page_ranges`: проект, узел, материал, снимок
названия источника, стабильный ключ пункта, `page_from`, `page_to`. Диапазон идёт до
страницы перед следующим пунктом того же или более высокого уровня; последняя ветвь
заканчивается на последней полной странице материала. Один узел может получить
несколько диапазонов в следующих вертикалях; API уже возвращает список.

## Состояние оглавлений мастера

Шаг 3 хранит не один выбранный результат, а словарь
`WizardDraft.state.outlines_by_material_id`. Ключ — id материала, значение содержит
источник обнаружения, стабильные ключи пунктов, проверенные формулировки и страницы.
Старый `state.outline` читается как совместимый одиночный черновик, но больше не
записывается.

## Импорт

`POST /api/projects/{project_id}/program/import-outlines`

```json
{
  "expected_program_revision": 7,
  "sources": [
    {
      "material_id": "11111111-1111-1111-1111-111111111111",
      "items": [
        {
          "outline_item_key": "1111:embedded:0:7:1",
          "level": 1,
          "title": "Сетевые модели",
          "page": 7,
          "selected": true
        }
      ]
    }
  ]
}
```

Сервер проверяет учебниковый вариант проекта, принадлежность каждого материала,
уникальность ключей, страницы и каскад выбранных родителей. Источники применяются по
`ProjectMaterial.priority`, а не по порядку JSON. Пропуск уровня не создаёт
искусственного узла: пункт становится ребёнком ближайшего предыдущего пункта меньшего
уровня либо корнем.

Стабильная пара `(material_id, outline_item_key)` узнаёт повторный импорт. Видимый
узел не дублируется; выведенный из программы узел возвращается с тем же id. Новые
корни каждого источника добавляются друг за другом без обёрток с именами файлов.
Операция увеличивает `program_revision` один раз и создаёт одно действие
`outline_import`; если изменений нет, ревизия не меняется.

Ответ — обычный `ProgramChangeResult`. Конфликт ревизии — `409 stale_program_revision`,
чужой материал и разорванный выбор — доменная ошибка `program_invariant`.

## Массовый вывод и undo

`POST /api/projects/{project_id}/program/remove-all` принимает
`{"expected_program_revision": 8}` и возвращает `ProgramChangeResult`. Все видимые
узлы получают `is_in_current_program=false`; строки узлов и диапазонов не удаляются.
Одна запись `program_remove_all` возвращает всю программу одним обычным
`POST /api/projects/{project_id}/actions/undo`.

Undo импорта также меняет только видимость созданных или возвращённых узлов. Поэтому
повторный импорт после undo восстанавливает прежние id и не создаёт дублей.

## Интерфейс

`TextbookProgramEditor` используется шагом 4 мастера и разделом активного проекта.
Он владеет поиском, тремя представлениями, CRUD, перемещением, контекстным меню,
диалогами импорта и массового вывода. Родитель передаёт только шапку, текущий снимок
программы и адаптер выполнения команды; экзаменационный редактор не изменён.

Диалог показывает все материалы проекта, включая спокойные строки без оглавления,
единую глубину, каскадные чекбоксы, общий счётчик и предупреждение о совпавших после
нормализации путях. Совпадения не объединяются автоматически.
