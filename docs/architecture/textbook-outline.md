# Оглавление источника: фактический контракт

Проверка: `backend/tests/test_material_outline.py`.

## Что это и чего здесь нет

Четыре источника оглавления учебникового материала, строго по приоритету:
**закладки PDF → печатная страница «Оглавление»/«Содержание» → распознанные
заголовки → модель по явной кнопке пользователя**. Первый непустой источник
побеждает в режиме `auto`; любой доступный можно выбрать вручную.

**Импорт найденного оглавления в настоящую программу (`ProgramNode`) не
реализован.** Это заведомая граница текущего захода (Работа 4 плана правок
мастера учебника, `TEXTBOOK_MODE.md`): максимум — вытащить и показать
оглавление для проверки глазами на шаге 3 мастера. `OriginKind.OUTLINE`
объявлен в `models.py`, но нигде не присваивается — присвоение понадобится
только реальному импорту, будущей работе.

## Источники

| Источник | Модуль | Когда доступен |
| --- | --- | --- |
| `embedded` | `parsers/native.extract_outline` | Сразу при загрузке PDF — закладки читаются в `library.store_uploaded_file`, до всякого разбора |
| `printed` | `materials/outline.py` | Сразу при обращении к эндпоинту — работает по текстовому слою исходного PDF, разбора не требует |
| `recognized` | `library._recognized_outline` | После завершённого разбора (`active_parse_revision > 0`) — по фрагментам `element_kind="heading"` |
| `model` | `materials/outline_ai.py`, роль `study_outline_extract` | По явной кнопке пользователя; при выключенном шлюзе честно объясняет причину, а не исчезает |

### `embedded`

Не изменился по сути — `extract_outline()` уже работал. Единственная правка:
вызывается в `library.store_uploaded_file` (при загрузке файла), а не в
`worker.claim_job` (при старте разбора, как было раньше). Оглавление из
закладок доступно сразу после загрузки, ещё до нажатия «Подготовить текст».

### `printed`

`materials/outline.py`, без OCR и без разбора — только текстовый слой PDF
(`page.get_text("dict")`). Кандидаты — первые `min(40, page_count)` страниц и
последние 10 (в русских учебниках содержание нередко печатают в конце).
Страница считается оглавлением, если первая строка начинается с
«Оглавление»/«Содержание»/«Contents»/«Table of Contents», либо не меньше 8
строк и не меньше половины из них заканчивается числом (1–4 цифры).

Строка: `^(?P<num>[\d.]+)?\s*(?P<title>.+?)[\s.·…]{2,}(?P<page>\d{1,4})$` —
точечная (или похожая) выноска; запасной путь без неё — заголовок, пробелы,
число. Уровень: по нумерации `1`/`1.2`/`1.2.3` (глубина = число сегментов,
максимум 4) при доле нумерованных строк ≥ 60 %; иначе — по левой границе
строки (`x0`), кластеризованной по соседним значениям с шагом ~6pt, максимум
третий уровень.

Две защиты от ложных срабатываний, обе нужны одновременно:

- **Невозрастающие номера страниц.** Строки идут по возрастанию; одиночный
  выброс отбрасывается, а не валит всю страницу (`backend/tests/test_material_outline.py::test_out_of_order_page_is_dropped_not_whole_page`).
- **Верхняя граница по объёму книги.** Номер страницы не может далеко уйти
  за `page_count` (запас `max(20, page_count // 4)`). Без этой границы на
  реальном учебнике (169 страниц) повторяющийся колонтитул
  «ИУ-6, МГТУ им. Н.Э. Баумана, 2023» проходил построчный regex и попадал в
  найденное оглавление как отдельный пункт с «страницей» 2023 — цифра года
  намного больше объёма книги. Та же граница отсекает страницу-обманку вроде
  списка литературы с годами изданий, которые к тому же идут вразнобой (по
  алфавиту автора), а не по возрастанию, — после фильтра почти ничего не
  остаётся (`test_bibliography_page_is_not_mistaken_for_outline`,
  `test_page_footer_with_year_is_not_mistaken_for_entry`).

Найденное оглавление может занимать несколько соседних страниц (до 5) —
`find_printed_outline` продолжает читать следующую страницу, пока она тоже
проходит проверку, и возвращает `source_pages` — список всех найденных
листов. Они же дают левую половину экрана сверки на шаге 3 (страница
документа рядом с деревом).

Проверено на трёх реальных учебниках (не только на синтетических PDF из
тестов): пособие на 169 страниц (найдено на страницах 2–4, 122 пункта),
методичка на 38 страниц (страница 3, 24 пункта), конспект с оглавлением на
первых двух страницах (61 пункт).

### `recognized`

Не изменился — `library._recognized_outline`, фрагменты `element_kind="heading"`
активной ревизии, лимит `RECOGNIZED_OUTLINE_LIMIT`. Требует законченного
разбора.

### `model`

`materials/outline_ai.py`. Текст кандидатных страниц (та же логика диапазона,
что у `printed`: первые 40 + последние 10, суммарно не больше
`MAX_PROMPT_CHARS` = 24 000 символов) уходит одним вызовом роли
`study_outline_extract` (`ai/roles.py`) со структурным ответом
`{items: [{level, title, page}]}`. Вызывается только явным действием
пользователя (кнопка «Попробовать с ИИ» в состоянии «ничего не нашлось»);
запрос идёт с `confirmed=True` без отдельного экрана подтверждения стоимости
— вход уже ограничен объёмом, слишком дёшево для полноценного preflight.

## Эндпоинты

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` | `/api/projects/{project_id}/materials/{material_id}/outline?source=auto\|embedded\|printed\|recognized` | `library.resolve_outline` → `{items, source, source_pages, available_sources}`. `auto` идёт по приоритету embedded → printed → recognized; конкретный источник возвращает только его данные (или `source="none"`, если для него ничего нет) |
| `POST` | `/api/projects/{project_id}/materials/{material_id}/outline/model` | `service.run_outline_model` → `outline_ai.run`; синхронно, один вызов |

Оба — через `materials/service.py` (`get_outline`, `run_outline_model`),
которые проверяют принадлежность материала проекту тем же способом, что
`get_page`/`update_material` (`_project` + `_link`), и делегируют в
`library`/`outline_ai`.

`OutlineSource` (`materials/schemas.py`) расширен значениями `printed` и
`model` (было только `embedded`/`recognized`/`none`) — используется и новым
эндпоинтом, и старым `LibraryMaterialDetailRead.outline_source`
(`library._outline`, приоритет `embedded → printed → recognized`, без
`model` — там кнопки нет).

## Хранение в мастере

`WizardDraft.state.outline` (JSON, без миграции — `state` уже
`Record<str, Any>`):

```json
{
  "material_id": "8bfe51ee-...",
  "source": "printed",
  "items": [{ "level": 1, "title": "БАЗЫ ДАННЫХ", "page": 8 }],
  "source_pages": [2, 3, 4],
  "edited": true,
  "checked_at": "2026-09-10T17:10:00Z"
}
```

Пишется существующим автосейвом черновика мастера (debounce 400 мс),
отдельного эндпоинта нет. `edited` отличает автоматически найденный список от
руками поправленного; `checked_at` — когда источник последний раз опрашивался
или проверялся. Правки (переименование, вложенность, порядок, удаление,
добавление) переживают переход на другой шаг мастера и обратно — проверено
вживую на реальном материале.

## Конфликт ревизий

Не отслеживается: если материал переразобрался между тем, как оглавление
было проверено, и следующим открытием шага 3, `WizardDraft.state.outline`
показывает то, что сохранил пользователь в прошлый раз, без автоматической
сверки с текущим состоянием материала. Ревалидация и явное предупреждение —
за пределами этого захода; при реализации импорта в программу (следующая
работа) это должно быть решено явно, а не унаследовано молча.
