# Общий retrieval, RAG и гибридный поиск

Фактический контракт вертикали от 20.09.2026. Модуль `backend/app/retrieval` — единая
точка поиска для проекта, Библиотеки и чатов; потребители не собирают собственные
embedding-запросы и не читают векторные таблицы напрямую.

## Поток данных

```text
активная ревизия материала
  → структурные chunks с локаторами
  → EmbeddingBackend
  → candidate RetrievalIndex
  → benchmark и ручная активация

запрос + scope
  → FTS5/BM25 ─┐
                ├→ weighted RRF → optional rerank → ContextAssembler
  → sqlite-vec ─┘                                  → манифест цитат
```

Retrieval-кусок не равен фрагменту или блоку. Малые фрагменты одного содержательного
блока агрегируются, крупный блок режется по странице, абзацу и предложению; блоки не
смешиваются. База: target 384, max 480, overlap 64 токена. Каждый `RetrievalChunk`
хранит материал, ревизию, блок, фрагменты, страницы, качество и точный локатор. Typst
индексируется из source chunks с путём и строками, без OCR.

`[Изображение]` не индексируется как знание. Такие страницы перечисляются в причинах
деградации и в ограничениях полного обзора; без vision-модели ответ не имеет права
считать их проверенными. `ocr_low` участвует в выдаче с понижением и предупреждением.

## Контракты

- `EmbeddingBackend`: локальный internal service или OpenAI-compatible `/embeddings`;
- `SqliteVecIndex`: закреплённый `sqlite-vec 0.1.9`, filtered exact cosine;
- `HybridRetriever`: lexical, semantic и hybrid, области и RRF;
- `ContextAssembler`: соседние куски, дедупликация и token budget;
- benchmark: сохранённые контрольные запросы и воспроизводимые метрики.

Публичные перечисления: `SearchStrategy = lexical | semantic | hybrid`,
`RetrievalScope = linked_topic | topic_project | project | selected_materials`,
`RetrievalDepth = fast | exhaustive`, `KnowledgePolicy = sources_only | allow_model`.

Пресеты: «Быстро» — 30+30 кандидатов, 8 результатов; «Сбалансированно» — 50+50 и 10;
«Точно» — 80+80, local reranker top-30 и 12. RRF по умолчанию имеет `k=60` и равные
веса. Экспертные параметры меняют веса, глубину, окно и бюджет; модель, размерность,
шаблоны и chunking требуют нового индекса.

## Индексы и отказоустойчивость

На установку активен один индекс. Новая модель или несовместимый chunking строит
кандидата через `BackgroundJob`; чтение до ручной атомарной активации идёт по старому.
Новая ревизия материала немедленно делает старые векторы непригодными и ставит локальную
инкрементальную переиндексацию. До её завершения материал остаётся в BM25 с текстом
«часть источников — только поиск по словам».

Облачная сборка сначала возвращает 409 `retrieval_cloud_consent_required` с перечнем
материалов, ревизий, объёмом и признаком Typst. Только повтор с `cloud_consent=true`
может поставить задачу. Активный индекс удалить нельзя.

Скачивание модели, embeddings корпуса и map-reduce идут вне транзакции, а каждая запись
состояния задачи проходит через `retrieval/jobs.py`: новый снимок, резерв единственного
писателя и повтор при блокировке. Иначе SQLite отказывает в записи результата после
долгой работы, и выполненная задача отмечается провалом.

Локальный model service имеет `/health`, `/embed`, `/rerank` и OpenAI-compatible
`/v1/embeddings`, загружает модель один раз и запрещает `trust_remote_code`. Каталог:
`paraphrase-multilingual-MiniLM-L12-v2`, `multilingual-e5-base`,
`Qwen3-Embedding-0.6B`; Qwen3 reranker используется только точным профилем. Ручной HF
профиль фиксирует pooling, normalize и query/document templates. У Qwen3 Embedding на
CPU один HTTP-запрос ограничен четырьмя кусками: пакет из 32 крупных кусков превышает
таймаут model service до записи первого материала; задача продолжает сборку следующими
checkpoint-пакетами.

OpenAI-compatible индексирование ограничивает пакет четырьмя кусками и повторяет до
трёх раз только временные отказы соединения, таймауты и rate limit. Это необходимо и
для локального LM Studio: большой OpenAI batch превращается у него во внутреннюю очередь,
после которой сервер может оборвать следующее соединение. Ошибка сборки остаётся в общей
панели фоновых задач до явного удаления пользователем.

## Чат и цитаты

Экзаменационный режим остаётся прежним. Study-сессия «Разобраться», учебниковый чат и
project-level чат свободного проекта используют `HybridRetriever`. Области: связанные с
темой опоры, поиск по теме, весь проект, выбранные материалы Библиотеки. Источники из
Библиотеки не подключаются к проекту автоматически.

Каждое переданное место получает ID `S<number>`. Неизвестная inline-цитата отклоняется;
шлюз делает одну попытку исправления, повторная ошибка завершает сообщение неуспешно.
Снимок сообщения хранит индекс, профиль, scope, источники и причины деградации. Знания
модели разрешаются только `allow_model` и отделяются блоком без цитат.

«По всем источникам» фиксирует ревизии выбранного корпуса и выполняет checkpointed
map-reduce по каждому chunk. Запуск связан с `BackgroundJob`, пользовательским и
итоговым сообщениями; поддерживает отмену и продолжение после рестарта. Это отчёт в
чате, а не проход 2: `Binding` и `CoverageBlockResult` не создаются.

## API и интерфейс

- `/api/settings/retrieval`, `/profiles`, `/local-models`;
  установка модели качает в `<каталог>.partial` без onnx/openvino/tf-дублей и переименовывает
  в финальный каталог только целиком, поэтому `installed` не бывает истинным у недокачанной
  модели; повторный старт установки отдаёт уже идущую задачу, `installing` виден в списке;
- `/api/retrieval/indexes`, `/benchmarks`, `/exhaustive`;
- `/api/retrieval/indexes/materials/{material_id}` добавляет один готовый материал в
  активный локальный индекс; операция идёт отдельной фоновой задачей и становится частью
  манифеста только после успешной записи векторов;
- `/api/library/search`;
- `/api/projects/{id}/search` сохраняет старые поля и добавляет strategy/signals;
- `/api/projects/{id}/chat/...` принимает scope, materials и knowledge policy.

Глобальные Параметры → Поиск: Обзор, Модели, Индекс, Качество, Дополнительно — одна
прокручиваемая страница, последняя подсекция восстанавливается. Установка локальной
модели показывает прогресс по файлам, сборка индекса — по материалам. Библиотека разделяет
поиск по имени и по содержимому, сохраняет запрос/выдачу/историю/источники и показывает
активную модель и состав корпуса. Результат открывает точную страницу или модальный
предпросмотр с оглавлением.

## Замер и границы

Выбрасываемый Windows-feasibility на копии текущей БД: 30 000 векторов × 384,
4 500 кандидатов после фильтра, p50 44,68 мс, p95 67,41 мс; без фильтра p95 206,44 мс;
размер +59,05 МиБ. Замер не является production benchmark и его код не сохраняется.

Не входят: web-search, Qdrant/ANN и предварительная подпись всех изображений. Проход 2
сохранён. Решение о его замене или дополнении возможно только после набора 100–200
русскоязычных контрольных запросов и сравнения Recall@5/10/20, MRR@10, NDCG@10,
zero-hit, p50/p95, размера и стоимости.
