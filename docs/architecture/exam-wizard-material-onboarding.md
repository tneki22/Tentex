# Живой онбординг экзаменационного проекта

Дата фиксации: 28 августа 2026 года.

Документ описывает восстановленный мастер `/projects/new?track=exam`. Визуальный
baseline — тег `ui-stage-1-baseline`; фактическое поведение — API этапов 2–5.

## Причина регрессии

В этапе 1 полный пятишаговый мастер существовал как моковый экран. Коммит
`2b399d5` подключил экзаменационную ветку к `WizardDraft` и реальному текстовому
импорту, но заменил файловые панели обещанием «появится на этапе 5». Когда в
`fce8973` появился живой конвейер Материалов, мастер к нему не подключили.

Исправление возвращает исходные поверхности, не откатывая живые черновики,
ревизии, Материалы, Программу и учебниковую ветку.

## Поток данных

| Вход | В черновике | После активации |
| --- | --- | --- |
| Текст вопросов (билеты/неизвестно) | `POST /api/wizard-drafts/{id}/exam-import` заменяет черновую Программу | Узлы становятся активной Программой |
| Файл вопросов (билеты/неизвестно) | `Material` + purpose `exam_structure`; быстрый разбор; `exam-draft-import` заменяет черновую Программу | Материал остаётся источником происхождения узлов |
| Список вопросов и/или список задач (трек «Отдельные вопросы / задачи») | По `Material` + purpose `exam_structure` на выбранный слот (`question_list`, `task_list`); быстрый разбор каждого; `exam-composite-draft-import` атомарно строит одну черновую Программу из одного или обоих | Материалы остаются источником происхождения узлов; `origin_material_id` указывает на список вопросов, если он выбран, иначе на список задач |
| Текст или файл ответов на вопросы / решений задач | По `Material` + purpose `reference_answers` на выбранный слот (`question_answers`, `task_answers`); в билетах/`unknown` — один материал без слота, как раньше | Запускается быстрый разбор; готовый материал сразу импортирует эталоны и автопривязывается воркером только к узлам своего вида (`question`/`task`); материал без слота видит всё дерево |
| Учебные файлы | Несколько `Material` + purpose `study_source`, роли `main` / `additional` | Запускается разбор; доступны Просмотрщик, FTS-поиск и ручная привязка |
| Точного списка нет | Обязателен `study_source`, Программа пуста | Проект активируется; официальный список импортируется позже |

`WizardDraft.state` хранит `exam_format`, режимы `files/text`, вставленные
тексты, предупреждения парсера и последнюю актуальную модельную рекомендацию
нагрузки. Для трека «Отдельные вопросы / задачи» состояние четырёх слотов
(`question_list`, `question_answers`, `task_list`, `task_answers`) лежит в
`state.slots` как `{selected, mode, text}` на слот; билеты и `unknown`
продолжают использовать прежние плоские поля `raw_text` / `answer_text` /
`has_answers` / `input_modes`. При восстановлении старого черновика (созданного
до этого контракта) `questions` и `questions_tasks` подставляются в слот
`question_list` одним legacy-входом, `has_answers` — в `question_answers`;
пользователь завершает такой черновик без обязательного разделения файлов, а
клиент определяет путь завершения по `exam_slot` фактически прикреплённого
материала (`null` → старый однослотовый импорт, иначе → составной). Строки
файлов восстанавливаются из `ProjectMaterial`, поэтому перезагрузка не зависит
от локального объекта `File`.

`GoalPassport` хранит время экзамена отдельно от `Project.deadline`:
`exam_time TIME NULL` и `exam_procedure TEXT NULL`. Дедлайн проекта остаётся
датой и не меняет публичный контракт карточек проектов. Оба экзаменационных
поля проходят через сохранение черновика, активацию и Настройки активного
проекта.

## Draft-safe импорт файла

Новый контракт:

```http
POST /api/projects/{project_id}/materials/{material_id}/exam-draft-import
Content-Type: application/json

{
  "expected_draft_revision": 4,
  "expected_program_revision": 2
}
```

Сервис принимает только экзаменационный проект, назначение `exam_structure` и
готовый материал. Текст собирается из страниц активной ревизии и проходит тот же
детерминированный `parse_exam_program`, что вставленный текст. Замена Программы
проверяет обе ревизии. Узлы получают `origin_kind=import`, имя материала и
`origin_material_id`; текстовый путь сохраняет происхождение «Вставленный
текст».

Preview разрешён и для черновика, и для активного проекта. Старый
`exam-program-import` остаётся активным контрактом экрана «Вопросы экзамена».

## Экзаменационные слоты и составной импорт

`ProjectMaterial.exam_slot` — необязательная узкая связь поверх широкого
`purposes`: `question_list`, `question_answers`, `task_list`, `task_answers`.
На один слот в проекте допускается не более одного активного материала
(`guard_exam_slot`); материал без слота (`exam_slot IS NULL`) остаётся легальным
и означает прежнее общее назначение — объединённый список или общий файл
ответов. Миграция не переприсваивает слоты существующим материалам.

Список вопросов и список задач разбираются независимо через
`parse_exam_list(raw_text, default_kind, expected_item_count=None)`
(`backend/app/projects/importer.py`): один уровень подпунктов `N.M`, `N.M.` или
`N.M)` отдельной строкой снимается с потока до поиска основной нумерованной
серии, затем вставляется обратно по позиции в исходном тексте с проверкой, что
`N` совпадает с номером ближайшего предшествующего пункта. Несовпадение не
создаёт узел — строка остаётся текстом того пункта, к которому не смогла
присоединиться, и добавляет предупреждение. Легаси `parse_exam_program()`
делегирует формат `questions` в `parse_exam_list`; формат `questions_tasks`
(заголовки «Вопросы»/«Задачи») остаётся на собственном путём без подпунктов —
новые черновики идут через составной импорт, а не через этот путь.

```http
POST /api/projects/{project_id}/materials/exam-composite-draft-import
Content-Type: application/json

{
  "expected_draft_revision": 4,
  "expected_program_revision": 2,
  "question_material_id": "…",
  "task_material_id": null,
  "dedupe_duplicates": false
}
```

Нужен хотя бы один из двух id; каждый должен быть материалом проекта в
соответствующем слоте (`question_list`/`task_list`), с назначением
`exam_structure` и статусом `ready`. Оба текста разбираются `parse_exam_list`
со своим видом (`question`/`task`) без сквозной нумерации между файлами: списки
задач можно начинать нумерацию заново с единицы. Результаты сливаются в одно
дерево вопросы → подпункты вопросов → задачи → подпункты задач одним вызовом
`replace_draft_program`, поэтому ревизия Программы увеличивается один раз.
Повторяющиеся формулировки верхнего уровня (без учёта регистра) не блокируют
импорт — они просто попадают в `warnings`; при `dedupe_duplicates=true` дубли
убираются вместе с их подпунктами, а счётчики пересчитываются. Ответ —
`ExamCompositeDraftImportResult` с `change: ProgramChangeResult`,
`counts: {questions, tasks, subpoints}` и `warnings`.

## Создание и фоновые ошибки

Основная кнопка сначала сохраняет текущую ревизию, затем идемпотентно активирует
проект. Только после успешной активации мастер запускает материалы ответов и
учебные источники со статусом `ready_to_process`. Уже готовый файл ответов сразу
прогоняется через существующий детерминированный импорт.

Сбой вспомогательного запуска не откатывает проект. Экран успеха показывает
количество незапущенных материалов и ведёт прямо в раздел «Материалы».

## Честная граница без векторной базы

Мнение системы на шаге 2 — клиентские правила, не внешний ИИ. Для учебного
источника мастер обещает только сохранение, разбор, Просмотрщик, лексический
поиск и ручную привязку. Проходы 1–2, эмбеддинги и автоматическое распределение
источника по темам здесь не имитируются.

## Оценка дневной нагрузки через модель

Дополнительная кнопка использует роль `exam_preparation_estimate` со
structured output и exact-cache:

```http
POST /api/projects/{project_id}/preparation-estimate/preflight
POST /api/projects/{project_id}/preparation-estimate
```

В запрос входят только `item_count`, дата/время, enum формата экзамена,
стартовый и целевой уровни, формат подготовки и два признака наличия ответов и
учебных материалов. `current_knowledge`, `important`, требования преподавателя
и описание проведения экзамена не передаются. Сервер вычисляет число учебных
дней и `ceil(item_count / study_days)`; если до экзамена не меньше двух полных
дней, последний день резервируется под отдых и повторение. При коротком сроке
ответ явно сообщает, что отдельный резерв не помещается.

Модель возвращает только `minutes_per_day` в диапазоне 60–480 с шагом 30 и
короткое обоснование. Клиент подставляет минуты в обычное редактируемое поле.
Ручная правка минут или любого входа удаляет устаревшее обоснование. Ошибка
модели не меняет текущее значение, а локальная эвристика работает независимо
от шлюза и не показывается без даты.

Отдельно проверено по текущему коду:

- черновик создаётся один раз, переживает URL и перезагрузку;
- stale draft/program revisions продолжают блокировать очередь до reload;
- удаление черновика остаётся в общей оболочке;
- пустая экзаменационная Программа допустима при активации;
- один материал ответов по-прежнему защищён серверным guard;
- активный импорт вопросов и файловый просмотрщик не заменены новым draft API;
- поиск, ручные привязки, перенос привязок после коррекции страницы и AI cleanup
  находятся вне затронутой поверхности;
- учебниковый мастер не импортирует экзаменационные компоненты и не изменён.

Потерь важного поведения в перечисленных коммитах не найдено. Намеренное
отличие от мока: структура и ответы по-прежнему принимают по одному
каноническому источнику — но не на весь проект, а на каждый явный слот
(`question_list`/`question_answers`/`task_list`/`task_answers`); материал без
слота остаётся ограничен старым правилом «один на проект». Учебных источников
может быть несколько.

## Раздельная автопривязка ответов

`_ordered_study_nodes(session, project_id, exam_kind=None)`
(`backend/app/bindings/answers_link.py`) принимает необязательный фильтр по
`ExamKind`. `link_answers_material()` определяет вид по слоту связанного
материала: `question_answers → question`, `task_answers → task`,
без слота — `None` (видно всё дерево, как раньше). Благодаря этому файл
ответов на вопросы и файл решений задач могут оба нумероваться с единицы, не
пересекаясь: раздел «1.» в одном не может связаться с узлом другого вида.
Внутри своей области действует прежний порядок доверия — точный заголовок,
подтверждённое соответствие, уверенное нечёткое совпадение, порядковый номер,
иначе — предложение на ручную проверку. Повторная обработка одного файла
по-прежнему трогает только его собственные привязки (`Binding.material_id`) и
собственные эталоны (`ReferenceAnswer.source_material_id`) — параллельный файл
другого слота не затрагивается.

## Проверка

`backend/tests/test_exam_wizard_materials.py` проверяет импорт готового
материала в draft, происхождение узлов, stale draft revision, а также составной
импорт: порядок «вопросы → задачи» с подпунктом, счётчики `{questions, tasks,
subpoints}` и дедупликацию верхнего уровня по флагу. `test_exam_importer.py`
проверяет `parse_exam_list()` отдельно от БД: подпункты `N.M`/`N.M)`, вид
подпункта, равный виду родителя, несовпадающий родитель как продолжение текста,
единственный уровень вложенности, верхнеуровневые счётчики отдельно от
подпунктов, независимость нумерации вопросов и задач. `test_answers_link.py`
проверяет, что файлы `question_answers` и `task_answers` с одинаковой
формулировкой узла не пересекаются, а старый файл без слота по-прежнему видит
всё дерево. `test_exam_passport_details.py` проверяет время и описание экзамена
через draft, активацию и Настройки. `test_preparation_ai.py` проверяет 42
элемента, резерв последнего дня, короткий срок, выключенный шлюз, минимальный
prompt и невалидный structured output. `check_stage5.py` проходит два сквозных
маршрута:

1. черновик → материал билетов → worker → preview → draft import → активация;
2. `unknown` → пустая Программа + учебный материал → активация → worker.

Фронтенд вручную проверен после запуска dev-серверов (`npm run dev`): три
формата на шаге 1; независимый выбор списка вопросов и списка задач на шаге 2,
недоступная с объяснением карточка ответа до выбора её списка; инструкция
раскрыта по умолчанию и сворачивается на шаге 3; панели загрузки в фиксированном
порядке; составной импорт вставленного текста с подпунктом `1.1` — Программа
получила вопросы, затем задачи, подпункт под верным родителем, счётчик
«3 вопроса · 2 задачи · 2 подпункта»; после активации файл ответов на вопросы и
файл решений задач с одинаковыми заголовками пунктов автопривязались каждый
только к своему виду узлов, без перекрёстных совпадений (проверено напрямую по
`ReferenceAnswer.source_material_id`). Строка без нулевых категорий, оба
текстовых режима, загрузка файла, очередь/готовность, дата/время после reload,
Tooltip мышью и клавиатурой, состояния AI-кнопки и отсутствие ошибок консоли —
не менялись, повторной ручной проверки не потребовалось.
