Реализованы этапы 1–3 вертикали «Уроки» (этап 2 — итерации 2.1 и 2.2, 15.09.2026; этап 3 —
16.09.2026). Модель и решения — `TEXTBOOK_MODE.md` §8 и
`docs/superpowers/plans/2026-09-14-lessons-vertical.md`; здесь только то, что работает в коде.

## API — `/api/projects/{project_id}/lessons`

Все запросы требуют `workspace_variant = textbook` и модуль `lessons`, иначе 409
`lessons_unavailable`. Запись — только в активном проекте (`project_read_only`). Ответ всех
изменений — `{lesson, latest_undoable_action, unbind_offer}`.

| Метод | Путь | Ответ и ошибки |
| --- | --- | --- |
| GET | `/overview` | `lessons[]`: id, название, статус, длительность, `program_node_ids`, `needs_review`. Суммы по дереву считает клиент |
| GET | `/sources?program_node_id=` | Диапазоны темы по источникам проекта: роль, приоритет, `outline_page_from/to`, уточнённые `page_from/to`, `starts_at_heading`, `ends_mid_page`, `is_parsed`, `default_selected` (справочный — `false`) |
| POST | `/quick` `{program_node_id, material_ids?}` | 201. Без `material_ids` — первый источник по роли и приоритету; со списком — «Из источников». 409 `lesson_no_ranges`, 422 `lesson_source_without_range`, 422 `lesson_requires_study_node` |
| POST | `/manual` `{program_node_id}` | 201: пустой черновик по теме, включая тему без оглавления; одна запись `lesson_create` |
| POST | `/from-search` `{program_node_id, pages:[{material_id, page}], lesson_id?, expected_revision?}` | 201 (`app/lessons/from_search.py`, 23.09.2026): «Урок из найденного». Страницы, отмеченные в поиске, становятся кусками `add_page` в порядке выбора, повторы отбрасываются, привязки ручные. Без `lesson_id` — новый черновик и одна запись `lesson_create` (отмена уносит урок и его привязки); с `lesson_id` — страницы в конец урока, одна запись `lesson_blocks`, 409 `stale_lesson_revision`, 422 `lesson_revision_required`. Материал не из проекта — 422, урок не создаётся |
| POST | `/bulk` `{items:[{program_node_id, action}]}` | 201 (`app/lessons/bulk.py`): черновики по списку тем одной транзакцией, `action` — `quick` или `manual` («пропустить» не присылается). Ответ — `{lessons[], latest_undoable_action}`; одна запись `lesson_bulk_create`. 422 `lesson_bulk_duplicate`; 409 `lesson_no_ranges` с `program_node_id` в контексте — тогда не создаётся ничего |
| GET | `/{lesson_id}` | Урок с темами, блоками и ссылками (см. «Чтение») |
| PATCH | `/{lesson_id}` `{title?, status?, expected_revision}` | Ревизия +1; 409 `stale_lesson_revision`. В журнал не пишется |
| DELETE | `/{lesson_id}` | 204: урок целиком, блоки, ссылки и темы уносит каскад. Привязки урока остаются фактами проекта; записи журнала об этом уроке гасятся (`undone_at`), поэтому «Отменить» после удаления не наткнётся на пропавший урок |
| POST | `/{lesson_id}/blocks` | Структурное действие `{expected_revision, operation, …}` — таблица ниже. Одна запись `lesson_blocks` |
| PATCH | `/{lesson_id}/blocks/{block_id}` | `{expected_revision, body_md, variant?}`: текст `note` или подпись `media` без журнала, ревизия +1; 422 `lesson_not_note` |
| POST | `/{lesson_id}/media` (multipart) | `file`, `expected_revision`, `after_block_id?`, `caption?`: изображение PNG/JPG/WEBP/GIF до 20 МБ → `media`-блок, запись `lesson_blocks`; 422 `lesson_image_unsupported` |
| GET | `/{lesson_id}/media/{block_id}` | Файл изображения блока; 404, если блок не изображение |
| POST | `/{lesson_id}/progress` `{last_block_id}` | Позиция чтения (`app/lessons/progress.py`): без ревизии и без журнала. 422 `lesson_block_foreign` |
| POST | `/{lesson_id}/completion` `{completed}` | «Урок пройден»: `completed_at` и одна запись `StudyActivity` вида `lesson`; `false` убирает обе |
| POST | `/{lesson_id}/confirm` `{expected_revision}` | «Подтвердить»: снимки живых тем обновляются, тема вне программы уходит из урока, если остаются другие; `boundary_shifted` снимается. Без журнала |
| POST | `/{lesson_id}/unbind` `{binding_ids}` | Снимает (`removed`) только активные привязки урока (`lesson`/`outline`) из списка; одна запись `lesson_unbind`, отмена возвращает прежние статусы; 422 `lesson_unbind_empty` |

Страницы и фрагменты клиент читает существующими эндпоинтами материалов.

### Операции `POST /{lesson_id}/blocks`

Вставка — перед `before_block_id`, иначе после `after_block_id`, без обоих — в конец.
`before_block_id` нужен пункту «Добавить блок выше» у самого первого блока и выбору
«В начало урока» в правой панели: «после предыдущего» там выразить нечем.

| `operation` | Поля | Что делает |
| --- | --- | --- |
| `add_note` | `variant` | Пустое пояснение: `text · heading · explanation · important · example · definition · warning` |
| `add_page` | `material_id`, `page_from`, `page_to?` | Страницы целиком; `manual/lesson` на содержательные фрагменты. 422 `lesson_page_range`, `lesson_source_unavailable` |
| `add_outline` | `material_id`, `program_node_id?` | Уточнённый диапазон оглавления темы урока; `machine/outline` по правилу быстрого урока |
| `add_fragments` | `material_id`, `from_fragment_id`, `to_fragment_id` | Отрезок фрагментов активной ревизии (порядок краёв не важен); `manual/lesson` только на выбранное. 422 `lesson_fragment_not_found` |
| `add_block` | `material_id`, `fragment_id` | Структурный блок материала, которому принадлежит фрагмент, — со всех его страниц |
| `add_region` | `material_id`, `page_from`, `region_bbox` | Область одной страницы долями листа `[x0, y0, x1, y1]`: ссылка с `region_bbox` и `always_pages = true`; `manual/lesson` на содержательные фрагменты, **центр** которых внутри рамки. 422 `lesson_page_range`, `lesson_region_required` |
| `add_link` | `media_url`, `caption?` | Карточка внешней ссылки без предпросмотра; 422 `lesson_media_url` для не-http(s) |
| `move_up` · `move_down` | `block_id` | Перестановка; 422 `lesson_block_edge` |
| `delete` | `block_id` | Удаление; привязки не снимаются, в ответе `unbind_offer` |
| `split` | `block_id`, `fragment_id` или `split_after_page`, `insert_note?`, `variant?` | Разрез куска после абзаца или страницы; с `insert_note` между частями встаёт пояснение. 422 `lesson_split_outside` |
| `merge` | `block_id` | Склейка со следующим куском того же материала и темы, если он продолжает первый. 422 `lesson_merge_not_adjacent`, `lesson_merge_topics` |
| `set_always_pages` | `block_id`, `always_pages` | «Всегда показывать страницами» |
| `add_topic` | `program_node_id` | Тема в урок со снимком формулировки; 422 `lesson_topic_exists` |
| `remove_topic` | `program_node_id` | 422 `lesson_topic_last`, `lesson_topic_in_use` (к теме привязаны куски) |
| `set_topic` | `block_id`, `program_node_id` | Тема куска: новые привязки по происхождению (`outline` → `machine/outline`, иначе `manual/lesson`), для прежней темы — `unbind_offer` |

`add_image` в этой ручке отклоняется (`lesson_block_operation`): изображение идёт через `/media`.
Кусок-область — картинка: `split`, `merge` и `set_always_pages` отвечают 422 `lesson_ref_region`.

## Быстрый урок

`app/lessons/boundaries.py` — чистые функции над позицией `(страница, индекс фрагмента)`;
кусок — полуинтервал `[начало, конец)`.

1. Диапазоны узла по материалу сливаются (`min page_from`, `max page_to`).
2. **Начало:** на `page_from` ищется заголовок, совпавший с формулировкой темы
   (номер пункта снимается, затем `normalize_answer_heading` и `HeadingIndex`). Нашёлся —
   кусок начинается с него; служебные фрагменты перед ним уходят в кусок.
3. **Следующий пункт** — первый узел после поддерева темы в порядке программы с диапазоном в
   том же материале и `page_from` не раньше темы.
   - на той же странице, что начало темы, — разрез по его заголовку на этой странице;
   - на `page_to + 1`: страница без фрагментов добавляется целиком; первый содержательный
     фрагмент — заголовок → страница не нужна; текст перед заголовком — хвост темы;
     заголовка нет — страница целиком;
   - последняя тема материала и материал без активной ревизии — без расширения.
4. **Подпункты:** потомки темы с диапазоном в том же материале режут кусок по своему
   заголовку (иначе по границе страницы) и дают `note` `heading` (`##` тема, `###` подпункт…).
   Диапазон подпункта раньше начала темы игнорируется. Пустой кусок остаётся одним заголовком.
5. **Привязки:** `machine/outline` на фрагменты содержательных блоков, начавшихся внутри
   куска. Существующая пара (тема, фрагмент) в любом статусе не трогается.
6. Длительность — символы содержательных фрагментов ÷ 1200, до 5 минут.
7. Одна запись журнала `lesson_create` `{lesson_id, binding_ids}`; отмена
   (`POST /actions/undo`, case в `projects/program.py`) удаляет урок и только эти привязки.

## Ручной редактор

`app/lessons/editing.py` — операции, текст, медиа, подтверждение и снятие привязок;
`app/lessons/refs.py` — геометрия ссылки над фрагментами активной ревизии.

- **Граница куска.** Пустая граница — край страницы. Выделение, совпавшее с краем страницы,
  хранится как граница страницы, поэтому разрез после последнего абзаца страницы даёт
  куски `…–p` и `p+1–…`, а склейка восстанавливает исходные границы.
- **Привязки.** Ручной выбор (страница, фрагменты, блок) — `manual/lesson` только на
  содержательные фрагменты выбранного; существующая пара (тема, фрагмент) не меняется в
  любом статусе. В уроке по нескольким темам кусок идёт к теме, чей диапазон оглавления в
  этом материале содержит первую страницу, иначе к первой теме урока.
- **Предложение снять.** `unbind_offer` после `delete` и `set_topic` — активные привязки
  механизмов `lesson`/`outline` к прежней теме на фрагментах куска, которые не держит ни один
  другой кусок урока той же темы. Ручные привязки из других сценариев не предлагаются.
- **Отмена.** Запись `lesson_blocks` хранит снимок блоков со ссылками и тем урока и id
  созданных привязок. Отмена возвращает порядок, границы ссылок, тему куска и темы урока,
  удаляет добавленные блоки и привязки; текст существующих пояснений и подписей не
  откатывается — он сохранялся отдельно.
- **Перенос при новой ревизии.** `transfer_bindings_on_revision` (все пять мест смены активной
  ревизии) сначала переносит границы уроков тем же сопоставлением фрагментов в пределах
  страницы. Пара не нашлась — граница становится краем страницы, `boundary_shifted = true`,
  `material_revision` = новая ревизия.

## Тема без оглавления (23.09.2026)

Теме, у которой нет диапазона страниц из оглавления (типично для свободного проекта и
тем от ИИ), «Быстрому уроку» не на что опереться. Вместо одинокого «Собрать вручную»
пустое состояние темы в разделе даёт три пути: «Найти в материалах проекта» — правая
панель открывается на вкладке «Поиск» (запрос — название темы); там у каждой найденной
страницы есть «Отметить», а внизу — «Создать урок из отмеченного» (или «Добавить
отмеченное в урок», если урок открыт) → `POST /from-search`; «Подобрать материал» —
диалог `TopicMaterialFinderDialog` с материалами Библиотеки по теме; «Собрать вручную».
Тот же путь стоит в меню «Новый урок» пунктом «Из найденного в материалах…». Вкладка
«Урок» Рабочей области без диапазона ведёт ссылкой «Найти в материалах» в раздел с
`?panel=search` — параметр открывает скрытую панель и выбирает поиск. Диапазоны
отключённого материала наружу не отдаются (`program.read_program`), поэтому «Быстрый
урок» не бывает активным зря.

## Чтение

`GET /{lesson_id}` и ответы изменений отдают:

- у темы — `title_snapshot`, `current_title` (null, если узел вне программы) и `needs_review`;
  `needs_review` урока — любая тема требует проверки (вычисляется при чтении);
- у ссылки — имя и роль источника, `is_available` (материал в проекте), `is_parsed`,
  `low_quality_pages`, `boundary_shifted` (флаг или ревизия ссылки старше активной при
  граничных фрагментах) и `pages_shown` — листы, которые рисует эта ссылка в режиме
  «Страницы»: лист принадлежит куску, где лежит его первый содержательный фрагмент, иначе
  первому по порядку урока куску, содержащему страницу;
- у блока — `media_kind` (`image · link`) и `media_url` для ссылки;
- `undo_sequence` — последнее действие проекта относится к этому уроку
  (`lesson_create`, `lesson_blocks`, `lesson_unbind`).

## Интерфейс

- `components/domain/lesson/LessonDocument.tsx` — один рендер урока для раздела и вкладки.
  «Страницы»: растры по `pages_shown`. «Текст»: `StructuredPage` с отсечением по граничным
  фрагментам, служебные блоки скрыты, у `ocr_low` — вырезы оригинала; материал без разбора —
  «Текст ещё не распознан»; кусок «всегда страницами» рисует свой диапазон растрами. У куска —
  «с абзаца / до абзаца», тема (в уроке с несколькими темами), «Разрез сдвинут»; недоступный
  источник показывает имя и страницы. В режиме разреза у абзацев «Разрезать после», в режиме
  «Страницы» — «Разрезать после страницы N». Номер страницы у имени источника не пишется:
  его несёт сам лист («Страница N») или шапка `StructuredPage`; «Текст из файла» там же скрыт
  (`showNativeQuality={false}`) — отметки распознавания остаются.
- **Выбор блока в редакторе.** Клик по любому месту блока выбирает его, средняя кнопка мыши и
  «Снять выбор» снимают выбор, правая кнопка открывает `ContextMenu` с добавлением блока выше
  и ниже, перемещением, разрезом, склейкой и удалением. Правая кнопка на пустом месте под
  уроком добавляет блок в конец. Отдельной кнопки «Выбрать блок N» нет.
- `components/domain/lesson/LessonMarkdown.tsx` — пояснения в чтении: абзацы, заголовки,

  Строка `<br />` — пустой абзац Crepe, а не текст: она пропускается. Картинка рисуется только

- Блок оформления «Заголовок» рисуется заголовком и без решёток: Crepe пишет обычный абзац,
  пока пользователь сам не сделает его заголовком, а выбранное оформление уже сказано.
- `components/domain/ProgramTreeRows.tsx` — общие строки дерева Рабочей области и Уроков.
- `screens/lessons/` — раздел; `LessonTab.tsx` — вкладка «Урок» учебникового проекта.

  - **«Поиск»** — постраничные карточки выдачи; щелчок по карточке открывает её страницу в

- `screens/lessons/LessonSourcePicker.tsx` — диалог выбора материала: рельс (найденные места

**Этапы.** `lessons/candidates.py` без модели собирает куски в порядке доверия: диапазон
темы по оглавлению (уточнённый `boundaries`), активные привязки темы, общий
`HybridRetriever` по выбранным материалам (запросы — «раздел › тема», подпункты, «Где
искать»; выдачи сливает `retrieval/vector.fuse_rankings`). Фрагмент принадлежит первому
куску, который его взял; блок крупнее 1200 токенов режется по фрагментам; тот же текст в
другом материале становится `also_in`. Вес — роль материала × сигнал, `ocr_low` × 0,85; до 30
кусков, диапазон оглавления не вытесняется поиском. Шапка куска несёт место, раздел,
сигналы, метки (`упражнения`, `формулы`, `таблица`, OCR низкого качества) и рисунки без
описания. `lessons/ai_context.py` собирает паспорт урока: проект, читатель, тема и её путь,
подпункты, место в программе, понятия уроков предыдущих тем (`build_meta.concepts`),
материалы с инструкциями, состояние материала, конспект, заказ; пустое поле называется
«не указано». Паспорт и куски замораживаются в `checkpoint` задачи при постановке.

**Сборка черновика** (`lessons/ai_build.py`) — один вызов по шаблону из
`lessons/ai_prompts.py`. Модель выбирает куски только метками `S*` из переданного списка:
кусок встаёт целиком через `editing._create_source` с `origin = model`, свёрнутым по
умолчанию шаблона, и даёт привязки `machine/lesson` (`editing.BINDING_BY_ORIGIN`).
Ссылки пояснений проверяет сервер: неизвестная метка убирается вместе с пробелом перед
ней и попадает в `dropped`, известные переводятся в сквозные номера урока `S1…Sn` и
становятся опорами `support` с `citation_label`. Пояснение без подтверждённой опоры
получает основание `model_only`. Заголовок с абзацем под ним разносится на два блока.
Урок — один черновик с одной записью `lesson_create`: «Отменить» уносит его и привязки.
Повтор задачи не создаёт второй урок (`checkpoint.lesson_id`). Предел задачи —
`budget_state` с верхом оценки, `DEADLINE_SECONDS[ai_lesson] = 1800`.

**План и шаги** (`lessons/ai_steps.py`). План — один вызов по карте кусков `C1…Cn`
(шапка и ≈120 слов начала каждого); опора вне карты убирается с причиной. Шаг — вызов с
компактным паспортом, всем планом с отметкой текущего шага, понятиями «уже известно /
вводит этот шаг / введут позже», текстом предыдущего шага и итогами остальных, полным
текстом своих кусков и соседа по учебнику под метками `S1…Sk`; ответ сразу переводится в
метки общего списка, ссылка вне опор шага убирается. Каждый шаг пишется в `checkpoint`
(`steps`), `done/total` — прогресс «шаг N из M». У «Подробного» рецензент читает черновик и
начало опор глазами новичка и называет до восьми проблем пяти видов (слово не объяснено
до использования, логический скачок, противоречие опоре, повтор прошлого урока или шага,
пример без конкретной ситуации); до трёх шагов переписываются с замечанием (`review`,
`rewritten`). Урок из шагов: заголовок шага,
пояснение и его куски (у «Путеводителя» — куски перед пояснением). Этапы в
`AiRun.context_manifest`: `plan · step · review · rewrite`. Отмена проверяется между
вызовами.

**Читатель — новичок** (`SYSTEM_RULES`): каждое специальное слово вне «уже известно»
объясняется при первом появлении, пример — конкретная ситуация со значениями, одно
утверждение не повторяется в разных шагах, одна ссылка на абзац, обращение на «ты»; при
расхождении знаний модели с куском урок идёт по куску с оговоркой «в других источниках».

**«Дополнить урок»** (`lessons/ai_enrich.py`, `lessons/proposals.py`). Модель видит урок
блоками `B1…Bn`: кусок — с меткой `S*` и абзацами `¶1…` (метка абзаца — его первый
фрагмент), пояснение — текстом. Урок режется на порции по ≈6000 токенов: «Экономно» — одна
порция (с выбранным блоком — окно ±2 блока вокруг него), «Полностью» — до четырёх. Ответ —
`EnrichReply`: сводка и до 12 операций `insert_note` (после блока или внутри куска после
абзаца — кусок разрежется), `rewrite_note` (только пояснения), `set_collapsed`,
`rename_lesson`, `set_goal`; удалять модель не может. Сервер отбрасывает операцию с
неизвестным блоком, абзацем или меткой, правку чужого вида блока, пустой текст и повтор и
пишет причину в `dropped`. Предложение хранится итогом задачи и ждёт проверки. Принятие —
только выбранные `op_ids` в одной записи `lesson_blocks`: снимок отмены хранит тексты
переписанных пояснений и прежние название и цель, так что «Отменить» снимает всё разом.
Операция, чей блок пропал или разрез не встал, уходит в `conflicts`, остальные
применяются; ревизия урока проверяется. Опоры новых пояснений получают сквозные метки
урока — существующие переиспользуются. Задача помечается проверенной и при отклонении.

**Задания** (`lessons/tasks.py`, `task_check.py`, `task_store.py`, `ai_practice.py`).
Задание — Активность `study_task` (происхождение `lesson`) и строка `study_tasks`; в документе
его держит блок `activity`, `LessonBlockRead.task` отдаёт форму, условие, ключ, опоры,
число попыток и последнюю попытку. Модель видит урок целиком блоками `B*` (куски урезаются
до ≈9000 токенов), уже имеющиеся задания и смесь форм по шаблону и отвечает `TaskDraft` с
`after_block`. `tasks.prepare` проверяет форму: у выбора есть верный вариант (у одного —
ровно один, у нескольких — не все), ключей пропусков `{{n}}` столько же, сколько пропусков,
у числа ключ — число и допуск не отрицателен, порядок — 3–8 разных шагов, сопоставление —
3–8 пар без повторов с обеих сторон, у открытого ответа есть образец; остальное уходит в
`dropped` с причиной. Шаги и правые части пар показываются вперемешку (стабильно для
условия), ключ — номера показанных. Пояснение ответа теряет метки `[S*]`, опоры
становятся `source_snapshot.sources` (материал, страницы, текст до 3000 знаков для судьи) и
`supporting_fragment_ids`; без опор основание — `model_only`. `TaskPlacer` ставит задания
после своего блока (свёрнутые под пояснением куски пропускаются) или в конец; сборка
«Обычного» (4 задания) и «Подробного» (8) ставит их сама под заголовок «Практика» одним
вызовом после урока — сбой вызова урок не отменяет, причина уходит в `dropped`.
«Добавить практику» даёт предложение, применение — та же запись `lesson_blocks`.
`sync_lesson_tasks` держит `deleted_at` задания в согласии с блоками урока после правки и
отмены, удаление урока гасит его задания; попытки остаются. Проверка по ключу
(`task_check`): регистр, ё→е, пробелы и знаки по краям не важны; число в пропуске
засчитывается числом, если весь ответ ключа — число; числовой ответ — абсолютный или
относительный допуск, запятая и единица после числа; несколько верных — лишний выбор
снимает столько же, сколько даёт верный; порядок и сопоставление — частичный зачёт по
пунктам. Открытый ответ проверяет `exam.judge.judge_attempt` без изменений: снимок попытки
несёт условие, образец с пунктами, опоры и уровень читателя.

**Метки кусков в промптах.** `ai_enrich.lesson_view` метит кусок сквозной меткой урока из
опор пояснений (`ai_writer.citation_labels`), остальные — следующими номерами: `[S1]` в
тексте пояснения и кусок S1 в списке — одна страница.

**Правка.** Операция `set_collapsed` `{block_id, collapsed}` в `POST /blocks` — «Свернуть
под пояснением»; разрез свёрнутого куска наследует флаг, снимок отмены хранит `collapsed`
и `citation_label`. Правка текста модельного пояснения переводит блок в `mixed`.

**Чтение.** `LessonRead.build` и `LessonSummaryRead.build` — шаблон, уровень, основа,
модель, стоимость; у блока `collapsed`, у ссылки `citation_label`; опоры блока идут по
номеру S. В интерфейсе: `[S3]` в пояснении открывает окно с листом страницы и переходом к
ней, под пояснением модели — метка «ИИ · по материалам: …» или «ИИ · знания модели — не
подтверждено материалами», свёрнутый кусок — строка «В учебнике: …» с «Раскрыть».
Предложение «Дополнить» стоит в документе полупрозрачными карточками на своих местах
(флажок, метка происхождения, «кусок разрежется», причина), решение — в шапке урока.
Задание в уроке — карточка `TaskCard` с вводом по форме, «Проверить», подсказкой, итогом
по пунктам, разбором и «Опора: …»; «Пройти задания · N» ведёт по заданиям по одному.
