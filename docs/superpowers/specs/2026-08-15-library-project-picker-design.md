# Выбор материала из Библиотеки при работе с проектом

> Согласованный дизайн от 15.08.2026. Выбран вариант с двумя явными действиями:
> локальная загрузка и подключение уже существующего материала из Библиотеки.

## Зачем

Материал в Tentex глобален, а его роль, назначение и имя принадлежат связи с
проектом. Сервер уже умеет подключать общий материал к черновику или активному
проекту без копирования файла и повторного разбора. Интерфейс должен дать доступ
к этому действию во всех местах, где сейчас предлагается только новая загрузка.

## Решение

На каждой поверхности сохраняется текущая загрузка и рядом появляется отдельное
вторичное действие **«Выбрать из Библиотеки»**. Оно открывает общий диалог выбора.
Drag-and-drop, вставка текста, добавление URL и существующий порядок блоков не
меняются.

Это дополнение к baseline, а не перестройка экранов: пользователь по-прежнему
видит прежний основной сценарий и получает явно заметный способ переиспользовать
подготовленный материал.

## Точки входа

| Поверхность | Текущее действие | Добавляемое действие | Контекст подключения |
| --- | --- | --- | --- |
| Экзаменационный мастер, шаг «Загрузка» | «Выбрать файл» в каждом блоке | «Выбрать из Библиотеки» рядом | Вопросы и билеты — `exam_structure` + `reference`; ответы — `reference_answers` + `reference`; учебные материалы — `study_source`, первый `main`, остальные `additional` |
| Учебниковый мастер, шаг «Источники» | «Добавить материал» в зоне загрузки | «Выбрать из Библиотеки» рядом | `study_source`, первый источник `main`, остальные `additional` |
| Программа, диалог импорта вопросов | «Загрузить список вопросов» / «Загрузить другой материал» | «Выбрать из Библиотеки» рядом в обоих состояниях | Один материал, `exam_structure` + `reference` |
| Материалы проекта | «Добавить» | Отдельная кнопка «Из Библиотеки» рядом | Назначение выбирается в диалоге; для учебного источника можно выбрать роль |
| Рабочая область Библиотеки | «Добавить в проект» | Переименовать в «Подключить к проекту» | Существующий обратный сценарий использует те же подписи и правила назначения |

Для канонического списка вопросов и файла эталонных ответов выбирается один
материал. Для учебных источников доступен множественный выбор.

## Диалог выбора

Заголовок учитывает контекст: например, «Выбрать список вопросов из Библиотеки»
или «Выбрать учебные материалы из Библиотеки». Под ним находится поиск по имени,
затем компактный список материалов.

Строка показывает:

- имя и вид источника;
- число страниц, если оно известно;
- состояние подготовки текста;
- проекты-потребители краткой подписью;
- состояние выбора.

Готовые материалы идут первыми, затем ожидающие и обрабатываемые, затем материалы
с ошибкой. Материалы с ошибкой не скрываются: пользователь видит их состояние и
может подключить, после чего использует уже существующее действие повтора
обработки. Материал, уже подключённый к текущему проекту, остаётся видимым, но
недоступен с подписью «Уже в проекте».

Нижняя строка содержит «Отменить» и основное действие:
«Подключить» для одного материала либо «Подключить N» для нескольких. При пустой
Библиотеке показывается `EmptyState` с действием «Загрузить новый файл», которое
закрывает диалог и возвращает в существующий сценарий создания: в мастерах и
Программе запускает локальный выбор файла, в «Материалах проекта» открывает
текущий диалог «Добавить материал».

### Назначение и роль

В мастерах и импорте Программы назначение известно из блока, поэтому диалог не
задаёт лишних вопросов.

При входе из «Материалов проекта» над списком показывается поле
**«Использовать как»**:

- «Список вопросов» — роль `reference`, один материал;
- «Эталонные ответы» — роль `reference`, один материал;
- «Учебный источник» — роль по умолчанию `main`, пользователь может выбрать
  `main`, `additional` или `reference`, множественный выбор разрешён.

Если у проекта уже есть файл эталонных ответов, после выбора нового используется
существующее подтверждение замены. Старый материал остаётся в проекте учебным
источником, а заполненные эталоны и привязки не удаляются.

## Результат подключения

Подключение создаёт только `ProjectMaterial`. Файл, активная версия, страницы,
OCR, структура и полнотекстовый индекс остаются общими и не копируются.

После успеха диалог закрывается, а выбранные материалы появляются в текущем
списке теми же строками, что и загруженные. Отдельный toast не нужен: обновлённый
список и короткое сообщение `aria-live` подтверждают действие.

Дальнейшее поведение совпадает с новой загрузкой:

- выбранный необработанный список вопросов запускает или предлагает быстрый
  разбор в соответствии с текущей поверхностью;
- готовый список сразу переходит к предпросмотру импорта;
- готовые эталонные ответы используют существующее сопоставление по заголовкам;
- учебниковый мастер сохраняет ручное действие «Подготовить текст»;
- удаление материала из мастера или проекта снимает только связь с проектом.

## Ошибки и частичный успех

- Ошибка загрузки Библиотеки показывается внутри диалога с действием «Повторить».
- Если материал подключили в другой вкладке, ответ
  `material_already_attached` обновляет список и помечает его как уже подключённый.
- При множественном выборе успешно подключённые материалы сразу появляются в
  проекте; неуспешные остаются выбранными с ошибкой у соответствующей строки.
- Архивный или завершённый проект сохраняет текущее состояние только для чтения;
  кнопки подключения недоступны.
- Закрытие диалога не меняет проект и не теряет уже загруженные материалы.

## Компоненты и данные

Общий доменный диалог отвечает только за выбор библиотечных материалов и создание
связей. Вызывающая поверхность передаёт `projectId`, один или несколько выбранных
материалов, фиксированное либо редактируемое назначение и правило роли. После
успеха она обновляет собственный список материалов и выполняет уже существующее
пост-действие: запуск разбора, предпросмотр импорта или обычное отображение строки.

Диалог использует существующие `listLibraryMaterials` и
`attachLibraryMaterial`. Новый серверный маршрут и копирование данных не нужны.
Обратный диалог из рабочей области Библиотеки остаётся отдельной композицией:
там выбирают проект, а не материал, но подписи назначения, правила ролей и текст
«Подключить» должны совпадать.

## Доступность и визуальные правила

- Диалог строится существующим Radix-примитивом `Dialog` с фокус-ловушкой.
- Строки выбора доступны с клавиатуры, состояние передаётся не одним цветом.
- Поиск имеет видимую подпись для скринридера; количество выбранных объявляется
  через `aria-live`.
- Новая кнопка использует вторичный вариант существующего `Button`; новые цвета и
  токены не вводятся.
- Состояние подготовки текста показывается обычными статусами Материала и не
  превращается в оценку качества или покрытие.

## Проверка

В браузере проверяются пять точек входа, пустая и заполненная Библиотека, поиск,
одиночный и множественный выбор, уже подключённый материал, замена эталонных
ответов, ошибка и частичный успех. Отдельно проверяются клавиатура, обе темы и
ширина около 900 px.

После реализации выполняются `npm run typecheck`, `npm run build`, перезапуск
контейнера `web`, ручная проверка на `http://localhost:5173` и существующая
сквозная проверка `python backend/scripts/check_library_workspace.py`.
Изменённые действия экранов фиксируются в `SCREENS.md`, а согласованное дополнение
к baseline — в `docs/ui/stage-1-interface-baseline.md`.

## Вне задачи

- загрузка новых материалов непосредственно внутри диалога Библиотеки;
- пакетный серверный endpoint подключения;
- изменение конвейера обработки, ревизий или переноса привязок;
- выбор библиотечного Материала для пользовательских вложений к эталонному
  ответу: такие вложения не являются источниками проекта.
