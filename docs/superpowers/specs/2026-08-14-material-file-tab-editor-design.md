# Редактируемая вкладка «Файл» в Материалах

Дата: 14.08.2026

## Задача

Вкладка «Файл» рядом с «Обработкой» сейчас только показывает свойства материала. Она должна стать практическим местом управления тем, как общий файл используется в текущем проекте, и одновременно показывать технический паспорт файла.

## Интерфейс

Вкладка состоит из двух основных секций.

### Настройки в проекте

Редактируемая форма содержит:

- отображаемое название;
- назначения «Используется как»: учебный источник, список вопросов и эталонные ответы;
- роль источника: основной, дополнительный или справочный;
- неотрицательный приоритет;
- необязательное пояснение, как использовать источник.

Форма сохраняется одной кнопкой. Кнопка недоступна без изменений, при пустом названии, отрицательном приоритете и во время запроса. Поля не сохраняются автоматически, чтобы случайная смена назначения не меняла поведение проекта.

Назначения показываются группой флажков: один файл может одновременно быть, например, списком вопросов и учебным источником. Хотя бы одно назначение обязательно. Так форма не уничтожает уже поддерживаемые сервером сочетания и позволяет как заменить «Учебный источник» на «Эталонные ответы», так и оставить оба назначения осознанно.

`affects_program` не редактируется напрямую: сервис продолжает выводить его из роли источника. Служебный флаг не должен позволять создать противоречивую конфигурацию.

### Сведения о файле

Постоянно видны исходное имя, тип источника, формат, размер, число страниц, сканов и страниц низкого качества, состояние и режим разбора, активная ревизия, дата загрузки и дата последнего изменения. Для URL и YouTube дополнительно показываются дата получения и исходная ссылка.

Отдельно показывается дата добавления общего файла в текущий проект. Для этого `MaterialRead` получает поле `attached_at` из `ProjectMaterial.created_at`; миграция не нужна, данные уже хранятся.

Оглавление остаётся раскрываемым. Технические сведения также раскрываются и содержат ID материала, MIME-тип и номер активной ревизии. Хеш и путь хранилища наружу не отдаются: для повседневной диагностики они не нужны.

Действие «Убрать из проекта» остаётся внизу и визуально отделяется от обычных настроек.

## Замена файла эталонных ответов

В экзаменационном проекте может быть только один материал с назначением `reference_answers`. Если пользователь выбирает это назначение для другого файла, интерфейс показывает подтверждение с именем текущего файла ответов.

После подтверждения одна серверная операция:

1. снимает `reference_answers` со старого материала;
2. оставляет старому материалу `study_source`, если других назначений не осталось;
3. назначает текущий материал новым файлом ответов;
4. применяет остальные поля формы.

Операция атомарна. Уже созданные эталоны и привязки старого файла не удаляются. Без флага подтверждённой замены существующая серверная защита возвращает конфликт.

Для атомарности `MaterialUpdate` получает необязательный флаг `replace_reference_answers`, по умолчанию `false`. Он допустим только вместе с назначением `reference_answers`; в остальных случаях сервер отклоняет команду как некорректную.

## Поток данных и ошибки

`FileTab` хранит локальный черновик формы и синхронизирует его с материалом только при открытии другого файла либо после успешного сохранения. Фоновое обновление задач обработки не должно стирать несохранённые изменения.

Сохранение идёт через существующий `useProjectMaterials.update`. После успеха список материалов обновляется, форма принимает сохранённые значения, а во вкладке появляется сообщение «Настройки файла сохранены». Ошибка API остаётся видимой в той же вкладке; введённые значения сохраняются.

Если требуется замена файла ответов, первое нажатие «Сохранить» открывает `ConfirmDialog`. Подтверждение повторяет ту же команду с `replace_reference_answers: true`; отмена ничего не меняет.

## Проверка

- серверные тесты: обычное обновление всех полей, конфликт второго файла ответов, подтверждённая атомарная замена, некорректный флаг замены;
- фронтенд: typecheck, lint и production build;
- браузер: изменение названия, роли, приоритета и пояснения; смена учебного источника на эталон; подтверждение замены существующего эталона; проверка дат и технического паспорта в светлой и тёмной темах;
- после фронтенд-правок контейнер `web` перезапускается.

## Вне задачи

Физический файл, исходное имя, MIME-тип, даты глобальной загрузки, результаты OCR и исходная ссылка не редактируются. Переразбор остаётся во вкладке «Обработка», а управление привязками — во вкладке «Привязки».
