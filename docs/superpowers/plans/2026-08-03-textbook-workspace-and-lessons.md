# Textbook Workspace and Lessons Roadmap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Спроектировать, описать в `SCREENS.md` и сверстать на выдуманных данных рабочую область учебного проекта, не начиная реализацию Уроков; одновременно сохранить полный согласованный контекст подсистемы Уроков для следующего цикла проектирования.

**Architecture:** Корневой маршрут `/projects/:projectId` остаётся одной Рабочей областью с двумя конфигурациями из FR-D2: компактной экзаменационной и развёрнутой учебной. На этапе 1 конфигурация и данные выбираются по демонстрационному проекту, позднее придут из настроек проекта; общая механика дерева, вкладок, колонок, сохранения раскладки и пометок не дублируется. Уроки станут отдельным включаемым модулем после завершения учебной Рабочей области и будут использовать её темы, источники, активности и Сессии.

**Tech Stack:** React 19, TypeScript, React Router, Radix-backed Tentex UI kit, Lucide icons, CSS Grid, localStorage, выдуманные данные этапа 1. Для будущего редактора уроков исследованы Tiptap/BlockNote-подход, JSON Schema, Mermaid и существующая SQL-песочница, но новые зависимости этим планом не добавляются.

## Global Constraints

- Русские тексты интерфейса, английские идентификаторы.
- Сначала агент предлагает текстовую концепцию учебной Рабочей области пользователю; только после согласования меняет `SCREENS.md`, затем сразу верстает экран.
- Текущий исполняемый объём — только учебная конфигурация Рабочей области. Раздел Уроков, Конструктор урока, рендерер урока и модельная генерация в этот объём не входят.
- Не создавать второй конкурирующий корневой экран и не копировать `ProjectWorkspace`: экзамен и учебник используют `/projects/:projectId` и общую механику.
- Шаблон проекта остаётся пресетом настроек, а не жёстким классом (FR-P7). Выбор демо-конфигурации по `projectId` — только замена отсутствующего API на этапе 1.
- Экзаменационный проект и учебный проект по одному предмету остаются разными проектами (FR-P8).
- Учебная конфигурация — развёрнутая Среда темы из FR-D2; экзаменационная конфигурация остаётся компактной и не должна регрессировать.
- В центре учебной Рабочей области сейчас источник и работа с темой. Урок появится как отдельный модуль и новый тип открываемого содержимого только после проектирования экранов Уроков.
- Чат остаётся одной из боковых вкладок. Он не является механизмом составления урока и не занимает центр по умолчанию.
- Любой показанный ответ или объяснение по материалам сопровождается ссылкой на фрагмент; при отсутствии материала интерфейс не выдумывает содержание (FR-D22).
- Тема без материала — полезный пробел с текстом «Нужно найти материал по теме», а не ошибка (FR-G19.1).
- Покрытие материала ниже 100% не показывается как проблема ни в одном состоянии (FR-D17).
- Машинная привязка явно помечена и снимается одним действием с возможностью отмены (FR-D8–D9).
- Флаг `ocr_low` виден рядом с фрагментом и не маскируется аккуратной вёрсткой.
- Никаких API-запросов, моделей, фоновых воркеров и реального выполнения SQL на этапе 1; только интерактивный прототип на выдуманных данных.
- Не добавлять новую библиотеку для учебной Рабочей области: имеющихся примитивов и CSS Grid достаточно.
- Если до согласования понадобятся уточнения, собрать связанные вопросы в один пакет из 3–5 пунктов; не останавливать обсуждение отдельным сообщением после каждого вопроса.
- Цвета только через токены из `frontend/src/styles/tokens.css`; поведение через существующие UI-примитивы.
- Не адаптировать попутно Материалы, Карточки, План и Настройки под учебный проект. Непроверенный переход лучше показать отключённым с честной подсказкой, чем вести на экзаменационный вариант.
- В проекте нет тестовой оснастки этапа 1 и TDD выключен сознательно. Проверка: `npm run typecheck`, `npm run lint`, `npm run build`, `docker compose restart web`, браузерный проход и `git diff --check`.
- Не трогать пользовательские изменения вне перечисленных файлов и не коммитить без отдельной просьбы.

#### Обязательная концепция учебной Рабочей области

**Назначение.** Это постоянная среда свободного изучения одной темы программы. Она должна позволять открыть методически связанный фрагмент основного учебника, переключиться на другой привязанный источник, держать рядом конспект или чат и видеть состояние темы. Это ещё не экран Уроков и не Конструктор урока.

**Левая проектная панель.** Сверху: возврат к Проектам, название «Индексы в векторных базах данных», компактный нейтральный счётчик вроде `6 / 14 тем`, без экзаменационной окраски срочности. Затем поиск «Найти тему», фильтры `Без материала`, `Не начаты`, `С пометками`, дерево до четырёх уровней. Статусы используют существующий словарь `нет материала / есть материал / разобран / отработан / освоен`.

**Поведение дерева.** Клик по шеврону только раскрывает раздел. Клик по названию раздела выбирает его и показывает обзор раздела. Клик по теме или подпункту открывает рабочее пространство этой темы. Предыдущая/следующая тема обходят только изучаемые узлы, а не заголовки разделов.

**Обзор раздела.** Не открывать произвольную страницу PDF. Показать назначение раздела, список вложенных тем со статусами, число источников, прогресс и действие «Открыть первую тему» или «Продолжить». Это отдельное состояние центральной области, не новая страница.

**Рабочая область темы.** В шапке — только формулировка выбранной темы, спокойное сообщение о пробеле при отсутствии материала, навигация `N из M`, «Открыть», разделение панели, пометка и отключённое до проектирования Сессии действие «Начать занятие». Большая центральная область сохраняет существующие одну–три изменяемые колонки.

**Вкладки учебной конфигурации.** `Источник`, `Мой конспект`, `История`, `Чат`. «Ответ» не показывать как обязательный центр: у темы учебника нет канонического экзаменационного ответа. «Сводный конспект» можно оставить в меню как проектный документ, если это не перегружает прототип. Будущая вкладка `Урок` не появляется до отдельного проектирования Уроков.

**Начальная раскладка.** Первая колонка открыта на `Источник`, вторая пуста с текстом «Откройте здесь другой инструмент темы: конспект, историю или чат». Сохранить возможность закрыть пустую колонку и восстановить раскладку после возврата.

**Выбор источника.** Вкладка `Источник` содержит компактный selector над текстом. Источники сгруппированы по материалам и показывают роль `основной / дополнительный / справочный`, страницу или диапазон, число привязанных фрагментов, статус привязки и качество. По умолчанию выбирать подтверждённый или ручной фрагмент основного источника; затем машинный основного; затем дополнительный. Выбор запоминается отдельно для каждой темы.

**Содержимое источника.** Показать название файла, роль, страницу, `SourceChip`, происхождение привязки, текст связанного фрагмента, соседний контекст и действие «Открыть полностью». Для `ocr_low` показать предупреждение и ссылку на оригинальную страницу. У машинной привязки есть «Это не по теме» и обратимое снятие. В прототипе полный Просмотрщик может быть отключён с честной подсказкой, если его view ещё не зарегистрирован.

**Несколько источников.** Selector меняет активный источник внутри вкладки; параллельное сравнение двух разных источников отдельными идентичными вкладками не входит в первую итерацию. Колонки используются для сочетания `источник + конспект`, `источник + история` или `источник + чат`.

**Мой конспект.** Автосохранение по теме, состояния «Сохранение… / Сохранено», возможность вставить цитату со ссылкой появится вместе с Просмотрщиком. Конспект не считается Активностью и не подтверждает знание.

**История.** На выдуманных данных показать последнюю работу по теме: чтение, карточка или ответ, дату, длительность, результат, использованную подсказку и следующий срок. Пустая история объясняет, что подтверждённых попыток пока нет. Не придумывать прогноз при недостатке данных.

**Чат.** Отдельная вкладка с показанным составом контекста: текущая тема, выбранный источник, подтверждённые фрагменты и только по согласию конспект. Быстрые действия `Объяснить проще`, `Привести пример`, `Задать проверочный вопрос`. При выключенных моделях вкладка недоступна, остальные функции полностью работают. Чат ничего не записывает в конспект и не меняет привязки без подтверждения.

**Нижняя навигация учебного проекта в текущей фазе.** Активно вести только в подготовленную учебную Программу (`?mode=textbook`). Материалы, Карточки и Настройки отображать только если соответствующая учебная конфигурация уже корректна; иначе оставить отключёнными с объяснением. План не показывать в демонстрации без дедлайна. Уроки не показывать до следующей фазы.

**Состояния.** Обязательно описать: первый вход; восстановленный вход; выбран раздел; одна/несколько привязок; материала нет; проход 2 продолжается; машинная привязка снята; `ocr_low`; источник удалён/недоступен; внешние модели выключены; чат недоступен; конспект сохраняется; пустая история; узкое окно.

## Следующая фаза: полный контекст подсистемы Уроков

Этот раздел — обязательная передача следующему агенту. Он не является разрешением реализовывать Уроки в текущей фазе. После приёмки Рабочей области для Уроков начинается отдельный цикл: уточнение концепции → описание экранов → согласование → вёрстка на фиксированном JSON → только затем проектирование модельной генерации.

### Продуктовое решение

**Урок** — сохраняемый и редактируемый документ для изучения одной или нескольких Тем. Он содержит теоретические, медийные и интерактивные блоки. У одной Темы может быть несколько Уроков: простое объяснение, практика, повторение или углублённый разбор.

Урок не заменяет Тему и не заменяет Активность:

```text
Тема → Урок → запуск Урока как Сессии → Активности → Попытки → Оценки
```

- Тема отвечает на вопрос «что осваиваем».
- Урок задаёт сохраняемую последовательность объяснений, медиа и практики.
- Сессия — конкретное прохождение Урока.
- Активность — отдельное проверяемое действие внутри Урока.
- Теоретический блок и чтение имеют силу свидетельства 0; SQL, свободный ответ и другие проверки создают Попытки на общих основаниях.

Tentex по-прежнему не становится платформой онлайн-курсов: нет преподавателей, учеников, публикации, продаж и совместного класса. Это личный конструктор внутри локального проекта.

### Раздел и маршруты

После проектирования добавить отдельный включаемый модуль `Уроки`:

- `/projects/:projectId/lessons` — дерево Тем, выбор и прохождение сохранённого Урока;
- `/projects/:projectId/lessons/new` — мастер brief/storyboard;
- `/projects/:projectId/lessons/:lessonId/edit` — полноэкранный блочный редактор;
- существующий `/projects/:projectId/session` — конкретный запуск Урока или другой очереди Активностей.

В учебном шаблоне Уроки включены по умолчанию после появления модуля. В экзаменационном шаблоне выключены, но могут быть включены пользователем. План и Уроки — независимые модули: при дедлайне можно показывать оба, без дедлайна План исчезает по FR-U4.

### Экран «Уроки»

Слева — то же дерево Программы с количеством Уроков и последним состоянием прохождения. Клик по разделу показывает обзор, клик по Теме — список её Уроков. В центре:

- переключатель сохранённых Уроков;
- длительность, уровень, основание и прогресс;
- `Начать / Продолжить / Редактировать / Создать урок`;
- непрерывная страница выбранного Урока;
- пустое состояние `Собрать с ИИ` и `Создать вручную`.

Источник, Конспект и Чат открываются рядом в изменяемой панели. Чат остаётся отдельным инструментом и не считается редактором Урока.

### Мастер и редактор Урока

Мастер до дорогой генерации проходит:

1. Тема или несколько Тем.
2. Цель, сложность, длительность и свободное пожелание пользователя.
3. Основа Урока: только источники проекта; источники + знания модели; только знания модели; веб — отдельный будущий режим.
4. Предпочитаемые активности и медиа.
5. Storyboard: цели, разделы, типы блоков и расположение без полного текста.
6. Оценка отправляемого, времени и стоимости.

После подтверждения Storyboard открывается редактор:

- слева — оглавление Урока;
- в центре — блочный холст;
- справа — свойства выбранного блока, источники и действия ИИ;
- сверху — название, статус черновика, undo/redo, версии, предпросмотр и `Начать урок`;
- блоки добавляются, удаляются, перетаскиваются и меняют разрешённый layout preset;
- действия ИИ над блоком: `Объяснить проще`, `Добавить пример`, `Заменить визуал`, `Сделать короче`, `Добавить подсказку`;
- действия над всем Уроком: `Сбалансировать теорию и практику`, `Уложить в 20 минут`, `Добавить проверку`, `Перестроить для начинающего`;
- крупные машинные изменения показываются дифом или новой версией и не перезаписывают ручную работу молча.

### Формат Урока и адаптивная компоновка

Модель не генерирует HTML, CSS, React, JavaScript или координаты. Она возвращает валидируемый декларативный документ:

```text
Урок → Разделы Урока → адаптивные строки → типизированные блоки
```

Модель выбирает смысловой layout preset, приложение отвечает за размеры:

- обычный поток;
- медиа слева;
- медиа справа;
- сравнение;
- две равные колонки;
- ряд коротких карточек;
- широкая диаграмма;
- практика на всю ширину.

Детерминированные ограничения renderer:

- SQL, большие таблицы и сложные задания всегда на полной ширине;
- длинный текст не попадает в узкую колонку;
- три колонки разрешены только для коротких однородных карточек;
- при нехватке ширины колонки складываются вертикально в смысловом порядке;
- изображение имеет допустимое aspect ratio, подпись и alt text;
- цвета, шрифты, интервалы и focus states задаёт дизайн-система;
- невалидная комбинация нормализуется приложением, а не доверяется модели;
- пользователь меняет порядок, preset и смысловой акцент, но не двигает элементы по пикселям как в Figma.

### Каталог блоков

Первая полноценная схема должна предусматривать:

**Теория:** заголовок, rich text, список, определение, формула, таблица, callout, вывод.

**Источники и медиа:** цитата/фрагмент, изображение, Mermaid-диаграмма, видео, аудио, файл, пример кода.

**Интерактив:** карточка, тест, пропуски, свободный ответ, SQL-задача, промежуточная самопроверка.

SQL-блок использует существующую модель `SQLЗадача`: условие, редактор, `Запустить`, `Проверить`, результат, объяснение ошибки, следующая подсказка и явное действие показа разбора. Неверный ответ не уводит на отдельную страницу.

### Происхождение и источники

Каждый блок хранит основание:

- фрагменты проекта с материалом, страницей и координатами;
- `Знания модели · без источника`;
- для созданного визуала — модель и prompt;
- для будущего веб-режима — URL, автор, дата получения и лицензия.

Режимы генерации:

- `Только источники проекта`: теоретические утверждения требуют ссылок; непокрытый блок отмечается для исправления.
- `Источники + знания модели`: добавления модели отделены и не маскируются под цитаты.
- `Только знания модели`: весь Урок получает заметную метку отсутствия источника.
- `Веб`: не включать, пока не спроектированы поиск, доверие, загрузка, лицензии и атрибуция; текущий §22 сознательно откладывает эту функцию.

Удаление или изменение исходного материала не удаляет Урок. Затронутые блоки получают `Источник недоступен` или `Требует проверки`. Изменение структуры Программы также может пометить связанный Урок для проверки.

### Роли моделей

Добавить в будущий FR-I1 логические роли:

- планировщик структуры Урока;
- автор теоретического содержания;
- генератор Активностей;
- генератор диаграмм и визуалов;
- проверяющий Урок.

По умолчанию все роли могут использовать одну модель. Глобальные настройки позволяют назначить разные модели под роли согласно уже существующему FR-I8. Проектные переопределения не включать в первую версию; они могут быть добавлены отдельным решением.

Mermaid генерируется обычной текстовой моделью и рендерится локально в strict/sandboxed режиме. Генерация растровых изображений требует отдельной способности провайдера и не гарантируется текущим текстовым OpenAI-совместимым шлюзом.

Долгие генерации выполняются через существующий будущий worker, показываются прогрессивно по блокам, переживают сбой и сохраняют частичный черновик. Перед запуском видны состав отправляемого, модель, оценка времени, стоимость и дата цены.

### Сущности, которые потребуется добавить

- `Урок`: проект, название, цель, Темы, статус `черновик / готов / архив`, длительность, авторство и текущая версия.
- `ВерсияУрока`: JSON-документ, номер, время, происхождение, prompt, модели и причина создания версии.
- `БлокУрока`: стабильный id, тип, содержимое, layout hint, ссылки на источники, связанная Активность или медиа-ресурс.
- `МедиаРесурсУрока`: файл/изображение/аудио/видео/диаграмма, происхождение, alt text, prompt, лицензия и доступность.
- связь Урока с одной или несколькими Темами;
- связь интерактивного блока с существующей Активностью;
- Сессия хранит id и версию запущенного Урока, позицию и попытки.

На первом этапе хранения разумно нормализовать метаданные Урока, Активности и ресурсы, а сам версионируемый документ хранить как валидируемый JSON. Не превращать каждый абзац в отдельную таблицу без доказанной необходимости.

### Изменения документации перед реализацией Уроков

После согласования будущих экранов обновить:

- глоссарий и §3: Урок принадлежит проекту;
- §6: развёрнутая Среда темы открывает Уроки и источники;
- §7: Урок — контейнер, Активность — проверяемая единица, Сессия — запуск;
- §13: включаемый модуль Уроков;
- §15: пять модельных ролей и особенности генерации визуалов;
- §20: Урок, ВерсияУрока, БлокУрока, МедиаРесурсУрока и связи;
- §21: Уроки, мастер/storyboard и редактор;
- §22: уточнить границу «не платформа онлайн-курсов», сохранив запрет публикации и многопользовательского обучения;
- NFR: сохранённый Урок читается офлайн, формат версионируется и мигрируется, модель не исполняет произвольный UI-код;
- FR-M10: удаление материала осиротит ссылки Урока, но не удалит содержание молча.

### Исследованные ориентиры

- Mindsmith: сначала Storyboard, затем tile-based Editor с AI-черновиком — https://help.mindsmith.ai/en/articles/12037477-the-lesson-editor
- Articulate Rise: адаптивные модульные блоки, AI для блоков, изображений и knowledge checks — https://www.articulate.com/360/rise/
- LearnHouse: открытый пример React + FastAPI + Tiptap, блочный редактор, тесты и code playground; использовать только как ориентир из-за AGPL — https://github.com/learnhouse/learnhouse
- H5P: интерактивные типизированные компоненты и `content.json`, но интеграция несёт отдельный runtime/формат и PHP/GPL-часть — https://h5p.org/documentation/developers/h5p-specification
- Open edX XBlocks: композиция независимых текстовых, медийных и problem-компонентов — https://docs.openedx.org/en/latest/educators/olx/organizing-course/course-structure-overview.html
- Tiptap: JSON-дерево и custom node views для интерактивных блоков — https://tiptap.dev/docs/editor/extensions/custom-extensions/node-views
- OpenAI/Gemini Structured Outputs: модель может возвращать структуру по JSON Schema, но семантическая проверка остаётся обязанностью приложения — https://platform.openai.com/docs/api-reference/responses-streaming/response/output_item?lang=node.js и https://ai.google.dev/gemini-api/docs/structured-output
- Mermaid: текстовые диаграммы с `strict`/`sandbox` security level — https://mermaid.js.org/config/usage.html?id=usage
- NotebookLM: сохраняемые AI-артефакты из источников и явное предупреждение о возможных визуальных/фактических ошибках — https://support.google.com/notebooklm/answer/16757456?hl=en

### Порядок следующего цикла

1. Согласовать предметную модель Урока и два экрана: `Уроки` и `Конструктор урока`.
2. Описать их в `SCREENS.md` по пяти обязательным пунктам.
3. Сверстать `Уроки` на одном готовом Уроке, нескольких Уроках одной Темы и пустом состоянии.
4. Сверстать Конструктор на фиксированном JSON: текст, изображение, Mermaid-диаграмма, двухколоночная секция и SQL-задача.
5. Сверстать прохождение того же документа в существующей Сессии без редакторских элементов.
6. Проверить, что схема действительно покрывает нужные layouts и состояния.
7. Только после этого проектировать API, хранение версий, фоновые задачи и multi-model pipeline.
