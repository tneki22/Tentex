## Контекст

«Предложено» из И5). Кнопки «Собрать с ИИ», «Дополнить с ИИ» и «Добавить практику» пока
неактивны (`LessonTopicPane.tsx:321, 486–487`), таблица `study_task` не заведена. По ТЗ это
пункт е) обязательной приёмки: недели 5–10, сдача 10–16.11.

Главная функция — **составление урока моделью**. Для каждой темы урок собирают один раз, а
читатель в теме не разбирается, поэтому логика и точность урока важнее цены. Основа урока —
материалы проекта, знания модели или то и другое вместе, по выбору пользователя.

## 1. Как собирается урок

```
Тема ─► A. Область ─► B. Кандидаты ─► C. План ─► D. Шаги ─► E. Рецензент ─► F. Задания ─► Черновик
        бесплатно     локально,        1 вызов   по вызову   1 вызов +        1 вызов
                      без модели                 на шаг      ≤3 правки
```

**A. Область.** Тема, путь в программе, подпункты, соседние темы (предыдущая и следующая).
Из паспорта — стартовый уровень, цель, желаемый результат и «минут за занятие» (из него длина
урока по умолчанию). Ещё — понятия, уже введённые предыдущими уроками программы
(`build_meta.concepts`).

**B. Кандидаты** (`lessons/candidates.py`, модель не вызывается). Источники:
- диапазоны оглавления, уточнённые `boundaries.py`;
- привязки темы и опоры И5;
- `HybridRetriever.search` с областью `TOPIC_PROJECT`, запросами «тема + подпункты + подсказка
  „Где искать“».

Кандидаты взвешиваются по роли материала (основной > дополнительный > справочный), `ocr_low`
получает штраф. Затем дедупликация по блоку материала и отбор 15–30 кусков в бюджет токенов.
Каждый кандидат — `C1…Cn`: материал, блок, страницы, `fragment_ids`, размер, роль, начало
текста. Блоки с заголовками «Вопросы для самопроверки», «Упражнения», «Задачи» помечаются —
задания опираются на них.

**C. План** — один вызов по компактной карте кандидатов. Модель отвечает:
- списком понятий в порядке зависимости;
- шагами `{вид, намерение, опорные C*, свёрнут ли материал}`.

**D. Шаги.** По вызову на шаг. На вход — полный текст 1–3 опорных кусков, план, краткое
содержание предыдущего шага. На выход — Markdown с `[S*]`. Чекпоинт на каждый шаг, как в
`program_chat.run_build`: упавший шаг повторяется отдельно, готовые не теряются.

**E. Рецензент** (только «Подробный»). Читает черновик целиком глазами новичка и ищет четыре
проблемы:
- термин использован раньше определения;
- логический скачок;
- противоречие опоре;
- повтор предыдущего урока.

Найденное переписывается — не больше трёх шагов.

**F. Задания** — один вызов по опорам урока (срез 4).

### Уровни

Оценки для дешёвой модели. Точная цена считается в preflight по каталогу, верхняя граница
становится пределом `JobBudget`.

| Уровень | Что делает | Вызовов | ≈ цена |
|---|---|---|---|
| **Черновик** | План и короткие тексты одним ответом: карта кандидатов плюс начало их текста | 1 | $0,005 |
| **Обычный** | План, затем шаги с полным текстом опор, 3–5 заданий | 7–9 | $0,03 |
| **Подробный** | То же плюс предпосылки, разбор ошибок, рецензент с правками и 6–10 заданий | 11–16 | $0,08–0,10 |

### Шаблоны

Шаблон — это модуль промпта плана и шагов в `lessons/ai_prompts.py`. Код пайплайна один на все
шаблоны.

| Шаблон | Скелет урока | Материал |
|---|---|---|
| Объяснение с нуля | Зачем → что нужно знать заранее → понятия по одному (простое определение → пояснение → мини-пример) → как работает целиком → разобранный пример → типичные ошибки → итог → «Проверь себя» | Свёрнут под шагом |
| Путеводитель | Что узнаешь → [кусок учебника + «на что обратить внимание»] × N → итог | Развёрнут, тексты модели короткие |
| Через практику | Задача-мотиватор → решение по шагам с теорией по ходу → минимум теории → вторая задача с подсказками → практика | Свёрнут |
| Шпаргалка | Определения → формулы и правила → таблица сравнения → частые ошибки → быстрая проверка | Свёрнут, всё коротко |

### Основа урока

«Только материалы» · «Материалы + знания модели» · «Только знания модели» — поле `LessonBasis`
уже есть. «Только материалы» недоступно, если у темы нет кандидатов, и диалог объясняет почему.
При «Только знания модели» этап B пропускается, урок состоит из одних пояснений.

### Как держится качество

1. **Модель знает читателя и контекст программы.** Она не пересказывает следующую тему и не
   пропускает предпосылки.
2. **Понятия идут по порядку зависимости.** Рецензент проверяет, что термин не использован
   раньше определения.
3. **Шаг пишется по тексту опоры, а не по памяти.** Сервер сверяет каждый `[S*]` с контекстом
   вызова (`retrieval/citations.py`). Неизвестная ссылка отбрасывается, а основание блока
   понижается до «знания модели» — метка видна в уроке.
4. **Связность между уроками.** Понятия каждого урока сохраняются в `build_meta.concepts`, и
   следующий урок получает их как «уже известно».
5. **Детерминированные проверки ответа.** Диапазон фрагментов лежит внутри кандидата. Длина
   шага в пределах. Задание проходит проверку своей формы (§4). Невалидное отбрасывается с
   причиной в итоге задачи.

## 1а. Контекст каждого вызова — точный состав (уточнено 28.09.2026)

Правило: **всё, что есть в проекте о теме и читателе, попадает в контекст явно или явно
помечается как отсутствующее.** Пустое поле не выдумывается, а называется: «цель не указана».
Состав собирается одной функцией `lessons/ai_context.py::build_brief()` один раз на запуск и
замораживается в `checkpoint` задачи. Поэтому все вызовы одной сборки видят одно и то же, даже
если во время сборки поменялась программа или материал. Каждый кусок пишется в
`AiRun.context_manifest`.

Страховка от забытого:
- тест `test_brief_carries_every_filled_field` заполняет все поля паспорта, узла, связи
  материала и конспекта и проверяет, что каждое значение дошло до текста промпта;
- в диалоге запуска есть свёрнутый блок «Что увидит модель» — тот же `brief` в читаемом виде, как
  чипы контекста в чате поиска.

### Кандидат материала — что несёт каждый `C*`

Строка-шапка плюс текст:

```
[C4] Олифер · основной · стр. 147–150 · «2.3 Ethernet › 2.3.1 Формат кадра»
     сигналы: оглавление темы, ручная привязка · рисунок 2.14 (описание есть) · формулы · OCR ок
     также в: Конспект лекций
     <текст>
```

- **Путь раздела** — из куска индекса или блока материала.
- **Страницы**, а у расшифровок — **время** «12:30–15:00».
- **Сигналы:** в диапазоне оглавления; привязка к теме (ручная / подтверждённая / машинная);
  опора И5; найдено поиском с оценкой. Всё это — «насколько точно это про тему».
- **Рисунки на этих страницах:** есть описание — оно входит в текст куска. Нет описания —
  строка «рисунок без описания, стр. 148», чтобы модель ссылалась на страницу, а не выдумывала
  содержание схемы.
- **Метки:** `упражнения` у блоков «Вопросы для самопроверки / Упражнения / Задачи»; `формулы`;
  `таблица`; `OCR низкого качества — сверяться со страницей`.
- **`also_in`** — дубли в других материалах.
- **Порядок** — по материалу и страницам: модель видит собственную последовательность учебника.

| **Рецензент** | Компактный `brief` · план и понятия · весь черновик по шагам · начало (≈300 токенов) каждого опорного куска для сверки фактов | ≈12 000 |
| **Задания** | Компактный `brief` · тексты урока (пояснения целиком и опорные куски S\*) · список понятий · **полные блоки-упражнения учебника** · формулировки уже имеющихся заданий урока (без повторов) · смесь форм, число и сложность по уровню | ≈10 000 |
| **Дополнить** | Компактный `brief` · просьба и выбранный блок · урок блоками по порядку: у материала — S-ID, страницы и текст абзацами с якорями `¶f12` (место разреза); у пояснений — оформление и текст (не повторять); у медиа — подпись; у заданий — формулировка. Длинный урок режется на порции, и каждая порция получает оглавление всего урока одной строкой на блок | ≈8 000 на порцию |
| **Судья открытого ответа** | Формулировка задания, эталон и пункты рубрики, опорные фрагменты задания, ответ, стартовый уровень читателя. **Не весь урок** | ≈3 000 |

### Поиск — одна точка входа

`candidates._search()` — единственное место, где урок зовёт `HybridRetriever`. Область поиска —
`SELECTED_MATERIALS` (материалы из диалога): на ней работает `no_relevant_match`.

Запросы:
- «путь раздела › тема»;
- каждый подпункт;
- подсказка «Где искать».

Выдачи сливаются RRF (`retrieval/vector.fuse_rankings` — бывшая `exam/sources._fuse`), дубли
текста снимает `ContextAssembler` (`also_in` уже есть в `main`). Изменения параллельной
доработки поиска — порог релевантности и `no_relevant_match` — подхватываются здесь, а не во
всех вызовах; до их слияния пустая выдача считается «поиск не нашёл».

## 2. Что видит пользователь

### Диалог «Собрать урок с ИИ»

Точки входа:
- «Новый урок ▾ → Собрать с ИИ…»;
- пустые состояния темы — с диапазоном оглавления и без него;
- пустая вкладка «Урок» Рабочей области — ведёт в раздел с `?topic=…&build=1`.

```
Собрать урок с ИИ · «Протокол Ethernet»

Как строить урок
[Объяснение с нуля ✓] [Путеводитель] [Через практику] [Шпаргалка]      ← карточки с описанием
Основа     (•) Материалы + знания модели  ( ) Только материалы  ( ) Только знания модели
Материалы  ☑ Олифер · основной · стр. 143–158   ☑ Методичка · доп.   ☐ Конспект · справочный
           Найдено 18 кусков · ≈14 000 токенов
Глубина    ( ) Черновик · 1 вызов · ≈$0,005   (•) Обычный · 8 · ≈$0,03   ( ) Подробный · 14 · ≈$0,09
Длина      ≈25 мин (из паспорта)        Модель [gpt-6-luna ▾]     Предел $0,05
Пожелания  [больше примеров из жизни, без истории протокола          ]
☑ Учитывать мой конспект темы (320 слов)
▸ Что увидит модель — паспорт урока, 18 кусков, инструкции к источникам
☐ Собрать сразу, без плана
                                                      [Отмена]  [Составить план]
```

Внешние модели выключены → `OfflineNotice`, ручные пути остаются.

### Редактор плана

```
План «Протокол Ethernet» · Объяснение с нуля · Обычный · ≈25 мин
Понятия: общая среда → MAC-адрес → кадр → коллизия → CSMA/CD
1 Вступление   Зачем Ethernet и что будет в уроке                         ↑ ↓ ✕
2 Предпосылки  Общая среда и широковещание           опора C3            ↑ ↓ ✕
3 Объяснение   MAC-адрес                              ▸ Олифер 144 · C1   ↑ ↓ ✕ ⇄
4 Объяснение   Формат кадра                           ▸ Олифер 147–150    ↑ ↓ ✕ ⇄
5 Пример       Две станции начали передачу            Методичка 24 · C6   ↑ ↓ ✕
6 Объяснение   CSMA/CD по шагам                       ▸ Олифер 150–153    ↑ ↓ ✕ ⇄
7 Ошибки · 8 Итог · 9 Задания (4: выбор, пропуски, порядок шагов)
[+ Шаг]                              8 вызовов · ≈$0,03 · ~1,5 мин   [Отмена] [Собрать урок]
```

- `⇄` заменяет опору другим кандидатом, намерение шага правится прямо в строке.
- План — результат фоновой задачи, поэтому к нему можно вернуться из панели «Фон».
- Сборка идёт фоном с прогрессом «шаг 4 из 9». В конце открывается новый черновик с меткой
  шаблона.

### Несколько уроков у темы

В списке уроков темы и в селекторе вкладки «Урок» у каждого урока подпись:
«Объяснение с нуля · ≈25 мин · готов» или «Быстрый урок · черновик». Селектор уже есть —
к нему добавляется шаблон из `build_meta`.

### Блок модели в уроке

- Под пояснением подпись «ИИ · по материалам: Олифер, с. 150» или «ИИ · знания модели — не
  подтверждено материалами».
- `[S1]` в тексте открывает окно со страницей — это общий `MarkdownView` с `renderCitation`,
  как в чате.
- Правка текста переводит блок в `mixed`.
- Свёрнутый материал: строка «▸ В учебнике: …» и «Раскрыть». Переключатель — в настройках
  куска рядом с «Всегда показывать страницами».

### «Дополнить урок» — предложения прямо в документе

Предложения встают на свои места среди блоков урока, а не отдельным списком.

```
Предложение ИИ · 5 изменений · материалы + знания · $0,004   [Принять выбранное · 4] [Отклонить]
┌ Олифер · стр. 143–146 ┐
┆ ☑ + Пояснение «Что такое MAC-адрес»           ИИ · Олифер с. 144 [S2]
┆   MAC-адрес — это 48-битный…
┌ Олифер · стр. 147–150 ┐
┆ ☐ + Определение «Преамбула»                    ИИ · знания модели
```

Запуск: шаблон не выбирается, есть основа, глубина («Экономно» — одна порция текста урока,
«Полностью» — до четырёх порций) и необязательная просьба. Быстрые просьбы: «Объясни проще»,
«Добавь примеры», «Определи термины». Если в уроке выбран блок, просьба касается только его.

### Задание в уроке

```
Проверь себя · 2 из 3
Почему в полнодуплексном Ethernet нет коллизий?
( ) Кадры короче 64 байт
(•) У станции отдельные пары для передачи и приёма
( ) Используется CSMA/CA
[Проверить]  Подсказка
✓ Верно. В полном дуплексе передача и приём идут по разным парам…  Опора: Олифер, с. 152
```

- **Размещение.** 1–2 задания «Проверь себя» после ключевых разделов и «Практика» в конце урока.
- **«Пройти задания · 8».** Во вкладке «Урок» режим по одному заданию, в конце сводка
  «6 верно, 2 ошибки · Повторить ошибки».
- **Ввод по формам.** Порядок шагов — кнопками ↑↓ с клавиатуры. Сопоставление — выпадающим
  выбором у каждого левого пункта. Новых зависимостей нет.
- **Открытый ответ.** Проверяет ИИ-судья. Модели выключены — «Проверка недоступна без внешней
  модели», ответ сохраняется без оценки, «Проверить» доступно позже.
- **В редакторе раздела:** «Показать ответы», «Перегенерировать задание» (1 вызов), «Удалить».

## 4. Срезы

Большая задача, поэтому отдельный worktree: `.worktrees/lessons-ai`, ветка
`codex/lessons-ai` от `main`. Каждый срез заканчивается демонстрацией; перенос в `main` — по
просьбе.

### Срез 1. Фундамент и «Собрать урок · Черновик»

Бэкенд:
- миграция `0071` целиком;
- роли;
- `lessons/ai_context.py`: ссылки урока → S1…Sn с текстом фрагментов в границах через `refs.py`,
  манифест S-ID → `fragment_ids`, проверка ссылок;
- `lessons/candidates.py`: этапы A и B;
- `lessons/ai_prompts.py`: четыре шаблона;
- `lessons/ai_build.py`: вызов «Черновик» и сборка урока. Материал идёт через внутренние функции
  `editing.py` и `refs.py` (`_create_source(origin=model)`, `refs.fragment_range`) с привязками
  `machine/lesson` — `_bind_fragments` получает статус и механизм явно.
  Пояснения — `origin=model`, `basis`, `ai_run_id`, опорные ссылки с ролью `support` и
  `citation_label`. Одна запись `lesson_create`: её `case` отмены уже удаляет урок и его
  привязки;
- `ai/jobs.py`: диспетчер `ai_lesson`.

API:
- `POST /lessons/ai/preflight` → кандидаты, токены, вызовы и цена по уровням;
- `POST /lessons/ai/build` → `202 {job_id}`; результат задачи — `{lesson_id}`.

Фронтенд:
- `screens/lessons/LessonBuildDialog.tsx` (модель — `ChatModelPicker`, цена — `CostEstimate`);
- точки входа из §2;
- в `LessonDocument` и `LessonMarkdown` — подпись происхождения, `[S*]`, свёрнутый материал;
- метка шаблона в списках уроков.

**Демо:**
- тема Олифера → «Черновик» → урок с пояснениями и свёрнутыми кусками → «Отменить» убирает урок
  и привязки;
- тема свободного проекта без оглавления с основой «только знания модели».

### Срез 2. План, «Обычный» и «Подробный»

- Подвид `plan`, затем подвид `build` с чекпоинтом на шаг и повтором упавших шагов.
- Рецензент с правками.
- `screens/lessons/LessonStoryboard.tsx` из §2 с живым пересчётом цены: оценка шага приходит из
  preflight.
- Галочка «без плана» в диалоге.
- По возможности — шаги «Рисунок»: кандидаты с изображением и описанием (описания уже в
  `main`) ставятся областью страницы.

**Демо:** на одной теме три урока трёх шаблонов, в плане убран шаг и заменена опора, урок
«Подробный» уложился в предел.

### Срез 3. «Дополнить урок»

- `lessons/proposals.py`. Операции:
  - `insert_note` — после блока или с разрезом куска по фрагменту;
  - `rewrite_note`;
  - `set_collapsed`;
  - `rename_lesson`, `set_goal`.

  Удалять материал модель не может.
- Контекст — текст урока порциями.
- Применение: `POST /lessons/{id}/proposals/{job_id}/apply {op_ids, expected_revision}` — одна
  запись `lesson_blocks`, отмена через существующий `case`. Если блок пропал или ревизия ушла,
  операция помечается «конфликт», а не применяется молча.
- Фронтенд: `LessonProposalBar.tsx` и призрачные блоки предложений в `LessonDocument`.

**Демо:** быстрый урок → «Дополнить» → принять 3 из 4 → «Отменить» одним действием.

### Срез 4. Практика

- `lessons/tasks.py` — генерация: 3–10 заданий, смесь форм по шаблону, упражнения учебника как
  основа.
- Проверка формы, всё невалидное отбрасывается:
  - у выбора есть верный вариант;
  - ключей пропусков столько же, сколько пропусков;
  - у числового ответа ключ — число;
  - у порядка шагов ключ — перестановка;
  - у сопоставления ключ — биекция.
- В существующий урок задания приходят предложением (механизм среза 3), в «Собрать урок» — сразу
  в черновик.
- `lessons/task_check.py` — чистые функции по формам:
  - пропуски: регистр, ё→е, пробелы, список допустимых ответов;
  - числовой ответ: абсолютный или относительный допуск;
  - несколько верных, порядок, сопоставление — частичный зачёт по пунктам.

  Результат — `Attempt` → `Grade` (`exact_match`). Открытый ответ — обобщённый `judge_attempt`,
  `ai_judge`.
- API:
  - `POST /lessons/{id}/tasks/{activity_id}/attempts`;
  - `GET` попыток;
  - `POST …/regenerate`.
- Фронтенд: `components/domain/lesson/tasks/` — `TaskCard` и семь вводов, `LessonPracticeRun.tsx`,
  попытки во вкладке «История».
- Уровни «Обычный» и «Подробный» начинают добавлять задания сами.

**Демо:**
- выбор и пропуски проверяются мгновенно при выключенных моделях;
- числовой ответ засчитывается с допуском;
- открытый ответ проверяет модель.

### Срез 5. Массовая сборка

- Действие «с ИИ» в `LessonBulkTable.tsx`: один шаблон, уровень и основа на все строки, общая
  оценка и общий предел.
- Одна задача с чекпоинтом на тему в порядке программы — это даёт связность через `concepts`.
- Без плана: FR-L7, результат — черновики.

**Демо:** раздел из пяти тем → пять черновиков, у каждого «уже известно» из предыдущих уроков.
