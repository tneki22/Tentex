## 1. Суть

- **Урок — не новый текст, сгенерированный из учебника.** Это упорядоченный сценарий:
  ссылки на страницы и фрагменты материала, свои или модельные пояснения, медиа и
  Активности.
- Материал остаётся первичным доказательством (`REQUIREMENTS.md`, принцип
  происхождения): урок расставляет его и дополняет, у каждого блока видно, откуда он.
- **Один документ — два способа показа:** «Страницы» (оригинал) и «Текст» (распознанные
  фрагменты). Содержимое между режимами не копируется.
- **Первый демонстрируемый срез работает без модели:** диапазон оглавления → страницы →
  ручная правка → оба режима просмотра. Офлайновый путь — не «бедная версия без ИИ», а
  самостоятельная полезная функция.
- **ИИ — второй слой поверх уже собранного урока.** Первым идёт «Дополнить урок»: его
  контекст — сам урок, поиск и эмбеддинги ему не нужны.
- Эмбеддинги, векторный движок и reranker урокам первой версии не нужны; их выбор остаётся
  в вертикали 5.

## 2. Раздел «Уроки» — `/projects/:projectId/lessons`

Три колонки: программа, редактор урока, материал для урока.

```
┌ Программа ─────────────────┬ Ethernet · черновик ─────────────────┬ Материал для урока ───────────┐
│ Найти тему или урок        │ [Страницы | Текст]   ↶  В архив  Готов │ Оглавление Страницы Поиск     │
│                            │                                        │ Предложено                    │
│ ▾ Компьютерные сети        │ ## Ethernet                            │                               │
│   Физический уровень   ✓ 1 │ ┌ Олифер · стр. 143–146 ─────────────┐ │ Олифер · основной             │
│   ▾ Канальный уровень      │ │ [страница 143] [страница 144] …    │ │   стр. 143–158  [Добавить всё]│
│ ☐   Ethernet           ●   │ └────────────────────────────────────┘ │ Методичка · дополнительный    │
│ ☐   Wi-Fi              —   │ 💡 Пояснение · ручное                  │   стр. 22–28    [Добавить всё]│
│ ☐   Коммутаторы        ⚠   │ ┌ Олифер · стр. 147–150 ─────────────┐ │ Конспект · справочный         │
│   Сетевой уровень      ✓ 2 │ │ …                                  │ │   стр. 11–12    [Добавить всё]│
└────────────────────────────┴────────────────────────────────────────┴───────────────────────────────┘
```

**Слева — программа.** Состояние темы: `—` нет урока · `●` черновик · `✓ N` готовых
уроков · `⚠` требует проверки. У раздела — сумма по поддереву. Чекбоксы собирают
массовый выбор; чекбокс раздела выбирает все изучаемые узлы под ним.

**В центре** — по выбору, как уже описано в `SCREENS.md`: раздел → обзор тем; одна тема →
список её уроков и редактор; несколько тем → таблица массовой подготовки (§4.5).

**Справа — материал для урока.** Вкладки появляются по мере готовности подсистем:

| Вкладка | Что показывает | Когда появляется |
|---|---|---|
| **Оглавление** | Диапазоны страниц темы из `program_node_source_page_ranges` по всем источникам, с ролью; «Добавить всё» | У1–У2 |
| **Страницы** | Листание любого источника проекта; выбор страницы, структурного блока, фрагментов, области | У2 |
| **Поиск** | Существующий FTS5/BM25, выдача сгруппирована по файлу и странице | У2 |
| **Предложено** | Привязки прохода 2 с оценкой: `95 % Ethernet: принцип работы · стр. 146–149` | После вертикали 2 |

Вкладки «Уже в уроке» нет: центр и так показывает состав урока, а в выдаче поиска и на
страницах уже добавленное помечается «в уроке».

## 3. Модель документа урока

### 3.1. Четыре вида блоков

| Вид | Что внутри | Пример |
|---|---|---|
| `source` | Ссылка на материал проекта: диапазон страниц, структурный блок, диапазон фрагментов или область страницы | Олифер, стр. 150–153 |
| `note` | Markdown с формулами. Оформление: текст · заголовок · пояснение · важно · пример · определение · предупреждение | 💡 Почему возникает коллизия |
| `media` | То, чего нет в материалах проекта: своё изображение, фото доски, внешняя ссылка | Фото схемы с лекции |
| `activity` | Ссылка на обычную `Activity` | Почему CSMA/CD не нужен в полном дуплексе? |

Оформления `note` — это одно поле `variant`, а не шесть сущностей. Заголовок — тоже
вариант `note`; отдельного разделителя нет. Вырез страницы материала — это `source` с
областью, а не `media`: у него есть происхождение в материале, и он должен вести себя как
остальные ссылки на материал (перенос между ревизиями, «Источник недоступен», привязка).

Заполненный пример документа:

```
#  вид       оформление / форма         содержимое                                   происхождение
1  note      заголовок                  «Ethernet»                                   оглавление
2  source    страницы                   Олифер · стр. 143 (с «2.3») — стр. 146 ¶5    оглавление
3  note      пояснение                  «MAC-адрес — это…»                           модель · Олифер с. 144
4  source    фрагменты                  Олифер · стр. 146 ¶6 — стр. 149              оглавление
5  note      заголовок                  «Коллизии и CSMA/CD»                         оглавление
6  source    фрагменты                  Олифер · стр. 151 ¶3 — стр. 153 ¶1           ручное
7  activity  вопрос                     «Почему коллизии невозможны в дуплексе?»     ручное
8  source    область                    Методичка · стр. 24 · схема                  ручное
```

### 3.2. Вставка «в середину страницы» — это разрез source-блока

Документ — только упорядоченный список блоков. Отдельного якоря `after_fragment` нет.

Действие «Вставить после этого абзаца» режет source-блок на два по границе фрагмента:

```
было:   source  Олифер · стр. 143–158
стало:  source  Олифер · стр. 143 — стр. 144 ¶5
        note    💡 Пояснение
        source  Олифер · стр. 144 ¶6 — стр. 158
```

«Убрать разрез» склеивает соседние куски одного материала обратно.

Почему так: одна система порядка вместо двух (позиция + якорь). Перетаскивание, отмена и
ответ модели (storyboard — это тоже список) работают без случая «блок перетащили, а якорь
остался на старом месте».

**Граница куска** хранится как `from_fragment_id` / `to_fragment_id` плюс денормализованные
`page_from` / `page_to`. При новой ревизии материала ссылка переносится тем же сопоставлением
фрагментов в пределах страницы, что и привязки (`transfer_bindings_on_revision`). Если
фрагмент не нашёлся, граница **деградирует до границы страницы**, а блок получает пометку
«Разрез сдвинут» — урок не ломается.

### 3.3. Два способа показа

| | «Страницы» | «Текст» |
|---|---|---|
| source-блок | Изображения страниц оригинала, ленивая загрузка; область — вырез страницы | Фрагменты активной ревизии по порядку: заголовок остаётся заголовком, формулы через KaTeX, рисунки и таблицы — вырезами оригинала |
| Разрез внутри страницы | Страница рисуется один раз — в куске, где лежит её первый фрагмент; вставка идёт после этой страницы | Вставка стоит ровно на месте разреза |
| `ocr_low` | Не важно — показан оригинал | Рядом с фрагментом вырез оригинала и `QualityBadge` |
| Служебные блоки (колонтитулы) | Видны, это часть страницы | Скрыты |
| `note` / `media` / `activity` | Между страницами | В потоке текста |

Для source-блока можно включить «Всегда показывать страницами» — для страниц, где текстовый
слой бесполезен (формулы, схемы, плохой скан).

Переключатель режима запоминается по проекту. Прецеденты в коде уже есть: вкладка «Ответы»
экзамена (`useAnswerViewMode`, текст/сканы) и просмотрщик Материалов («Оригинал / Текст»).

### 3.4. Происхождение блока

| Поле | Значения |
|---|---|
| `origin` | `manual` · `outline` (быстрый урок) · `model` · `mixed` (модельный блок, отредактированный пользователем) |
| `basis` (у модельных `note` и `activity`) | `sources` · `sources_and_model` · `model_only` |
| опорные ссылки | Фрагменты и страницы, на которые блок опирается |
| `ai_run_id` | Какой вызов модели его создал |

Как это видно в уроке:

```
💡 Почему используется преамбула
   Основание: 📚 Олифер, стр. 156 · ✨ дополнено знаниями модели

💡 Современный коммутируемый Ethernet
   ✨ Только знания модели — нет подтверждения в материалах проекта
```

**Ссылки модели проверяются на сервере.** Опорный фрагмент принимается, только если он был
в переданном модели контексте; иначе ссылка отбрасывается, а основание понижается до знаний
модели. Тот же принцип уже работает в чате программы: `basis_kind` выводится по
перепроверенной ссылке на пункт оглавления, а не по слову модели.

### 3.5. Хранение

```
lessons             id, project_id, title, goal, status (draft | ready | archived),
                    duration_minutes, revision, last_block_id, completed_at,
                    created_at, updated_at
lesson_topics       lesson_id, program_node_id, sort_order, topic_title_snapshot
lesson_blocks       id, lesson_id, sort_order, kind, variant, body_md, origin, basis,
                    ai_run_id, activity_id, media_path, bound_program_node_id
lesson_source_refs  id, block_id, role (content | support), material_id,
                    source_name_snapshot, material_revision, page_from, page_to,
                    from_fragment_id, to_fragment_id, region_bbox, always_pages
```

Заполненный пример строки ссылки для блока 6 из §3.1:

```
role=content  material=Олифер  source_name_snapshot="Олифер — Компьютерные сети"
material_revision=3  page_from=151  page_to=153
from_fragment_id=…c41  to_fragment_id=…d07  region_bbox=null  always_pages=false
```

Ссылки лежат отдельной таблицей, а не в JSON блока: «какие уроки используют эту страницу»,
перенос при новой ревизии и «Источник недоступен» становятся обычными SQL-запросами — так же
устроены привязки. Удаление материала не каскадит на урок: ссылка теряет `material_id`, но
сохраняет снимок имени и страниц.

Прохождение (`last_block_id`, `completed_at`) хранится прямо в уроке: пользователь один.

### 3.6. «Требует проверки» считается при чтении

Состояние не пишется флагом из каждого места, где меняется программа, а вычисляется
сравнением со снимком:

| Условие | Что видит пользователь |
|---|---|
| Тема урока вне текущей программы или переименована (`topic_title_snapshot` не совпал) | Урок: «Требует проверки» (FR-L6) |
| Ревизия материала сменилась, граница куска не перенеслась | Блок: «Разрез сдвинут» |
| Материал убран из проекта или удалён | Блок: «Источник недоступен», с именем и страницами |

«Подтвердить» обновляет снимки. Почему при чтении: программа меняется из ручного редактора,
импорта оглавления, дифа чата, слияния и отмены — подвешивать флаг на каждый путь хрупко,
а сравнение со снимком — одна функция.

### 3.7. Сохранение и отмена

- **Структурные операции** — добавить, удалить, переместить, разрезать, склеить блок,
  быстрый урок, принять предложение модели — идут через журнал действий проекта и
  отменяются одной записью (`POST /api/projects/{id}/actions/undo`).
- **Текст `note`** сохраняется автоматически с ожидаемой ревизией, как конспект: конфликт
  показывается, а не перезаписывается. В журнал набор текста не пишется.
- **Редактор текста** — один экземпляр Crepe на выбранном `note`; остальные блоки рисуются
  существующим Markdown-рендером с KaTeX. Десятки редакторов на одной странице тяжелы.

## 4. Ручное создание

### 4.1. «Быстрый урок»

Кнопка у темы — в дереве раздела «Уроки» и в пустой вкладке «Урок» Рабочей области. Ничего
не спрашивает.

1. Берёт диапазон темы из `program_node_source_page_ranges` у первого по приоритету
   основного источника. Диапазона нет (тема `custom`) → кнопка недоступна с пояснением
   «У темы нет страниц из оглавления — соберите урок вручную».
2. **Уточняет границы.** Диапазон оглавления кончается на странице *перед* следующим пунктом
   (`program_chat.py:1238`: `page_to = max(item.page, boundary - 1)`). Если следующий пункт
   начинается с середины страницы, конец темы на этой странице теряется. Поэтому:
   - ищет фрагмент-заголовок следующего пункта на странице `page_to + 1`; нашёл — кусок
     заканчивается фрагментом перед ним;
   - не нашёл — страница добавляется целиком с пометкой «стр. 159 общая со следующей темой»;
   - начало так же: нашёл заголовок темы на `page_from` — кусок начинается с него.
3. **Разрезает по подпунктам.** Подпункты темы со своими диапазонами дают разрезы и
   `note`-заголовки с их формулировками. Структура урока получается бесплатно.
4. Название = формулировка темы, статус = черновик, происхождение = `outline`.
5. Создаёт привязки по правилам §4.4.

Результат для темы «2.3 Ethernet» с двумя подпунктами:

```
Урок «Ethernet» · черновик · ≈ 25 мин чтения
1  note    заголовок  «Ethernet»
2  source             Олифер · стр. 143 (с заголовка «2.3») — стр. 146
3  note    заголовок  «2.3.1 Формат кадра»
4  source             Олифер · стр. 147–150
5  note    заголовок  «2.3.2 CSMA/CD»
6  source             Олифер · стр. 151 — стр. 159 (до заголовка «2.4»)
```

Ноль моделей, ноль эмбеддингов. Сверху потом можно нажать «Дополнить с ИИ» — модель
работает с конкретным уроком, а не со всем учебником.

### 4.2. «Из источников»

Когда у темы диапазоны в нескольких источниках, вместо быстрого урока открывается диалог:

```
Создать урок «Ethernet» из источников

[x] Олифер · основной           стр. 143–158
[x] Методичка · дополнительный  стр. 22–28
[ ] Конспект · справочный       стр. 11–12

Порядок: основной → дополнительные     [ Создать черновик ]  [ Отмена ]
```

По умолчанию отмечены основной и дополнительные, справочные — нет (справочный источник
используется в объяснениях, но содержание не задаёт). Каждый отмеченный диапазон
обрабатывается как в §4.1.

### 4.3. Добавление вручную

На странице из вкладок «Оглавление», «Страницы» или «Поиск»:

- **Добавить страницу** — `source` на страницу целиком;
- **Добавить структурный блок** — `source` на `MaterialBlock` (заголовок и подчинённые абзацы);
- **Добавить выделенные фрагменты** — `source` на диапазон фрагментов;
- **Добавить область** — `source` с `region_bbox` (схема, таблица, кусок скана).

Вставка идёт после выбранного в центре блока, без выбора — в конец. Механику выделения
фрагментов переиспользовать из ручной привязки (`SourcePreviewDialog`, `BoundSourceReader`).

Приоритет: целые страницы и структурные блоки важнее идеального выделения фрагментов —
оригинал читаем всегда, а OCR может быть кривым. Область страницы — позже остальных (У3).

### 4.4. Добавление в урок создаёт привязку к теме

Пользователь не должен сначала привязывать материал, а потом вставлять его в урок: вставил —
система поняла, что `фрагмент → тема`, и покрытие обновилось (решение уже записано в
`TEXTBOOK_MODE.md` §7).

Но `Binding` ставится на **фрагмент**: 16 страниц — это сотни фрагментов, граничные страницы
несут хвосты соседних тем, а `manual` — самый сильный статус, который проход 2 оспаривать не
будет. Поэтому статус зависит от того, как кусок попал в урок:

| Как попало в урок | Какие фрагменты привязываются | Статус | Механизм |
|---|---|---|---|
| Пользователь выбрал страницу, блок, фрагменты или область | Содержательные фрагменты выбора | `manual` | `lesson` (новый) |
| «Быстрый урок», «Из источников», «Добавить всё» | Фрагменты содержательных блоков, **начинающихся** внутри уточнённого диапазона; служебные блоки и хвосты соседних тем — нет | `machine` | `outline` (новый) |
| Модель поставила кусок в «Собрать урок» | Как во второй строке | `machine` | `lesson` |

Дальше:

- проход 2 может подтвердить или оспорить `machine`, но не трогает `manual`;
- существующая привязка того же фрагмента к той же теме не дублируется;
- отмена добавления блока отменяет и созданные им привязки — это одна запись журнала;
- удаление блока из урока привязки молча не снимает: уведомление предлагает «Снять привязки
  к теме (N)»;
- в уроке по нескольким темам кусок привязывается к теме, чей диапазон содержит страницу,
  иначе к первой теме урока; блок показывает тему (`bound_program_node_id`), её можно сменить.

### 4.5. Массовая подготовка без модели

Выбраны несколько тем или раздел → таблица:

```
Подготовка уроков · 6 тем

#   Тема                  Материал               Уроки     Действие
1   Ethernet              Олифер 143–158         —         [быстрый урок ▾]
2   Wi-Fi                 Олифер 159–171         —         [быстрый урок ▾]
3   Коммутаторы           Олифер 172–180         ✓ 1       [пропустить ▾]
4   VLAN                  —                      —         [вручную ▾]
…
                              [ Создать 3 черновика ]
```

По умолчанию: тема с диапазоном и без урока — «быстрый урок»; тема с готовым уроком —
«пропустить» (FR-L7); тема без диапазона — «вручную». Все черновики создаются одной
транзакцией и отменяются одной командой. Демонстрация: весь учебник → черновики уроков
по всем темам без единого вызова модели.

### 4.6. Изучение — вкладка «Урок» Рабочей области

- Показываются готовые уроки темы; несколько — компактный selector, выбор запоминается по теме.
- Черновик не выдаётся за готовый: «Черновик · Продолжить редактирование».
- Переключатель «Страницы / Текст».
- Позиция чтения восстанавливается (`last_block_id`); «Урок пройден» пишет запись в «Историю».
- Просмотр урока — сила свидетельства 0 (FR-L9). Прогресс меняют только `activity`-блоки:
  форма → `Attempt` → `Grade`.
- Пустое состояние: «Для этой темы ещё нет урока» · «Быстрый урок» · «Собрать вручную».

## 5. Активности в уроке

Задание в уроке — не «ИИ-блок», а ссылка на обычную `Activity`. Одна и та же задача потом
появляется в уроке, Занятии, тренировке, чате и повторении, а движок проверки один на все
поверхности (FR-V6).

**Что мешает в коде сейчас.** `ActivityKind` = `free_answer | card`, а частичный уникальный
индекс `uq_activities_free_answer_node` разрешает один `free_answer` на узел. Урок с тремя
вопросами по одной теме в эту модель не ложится. Текста задания у `Activity` нет:
`free_answer` берёт формулировку узла и `ReferenceAnswer`.

Предложение:

- новый вид активности и таблица задания: условие, форма (`open` · `choice` · `cloze`),
  эталон или рубрика, варианты и ключ, опорные фрагменты, происхождение;
- **без модели:** `choice` и `cloze` проверяются детерминированно, `open` — самооценкой по
  эталону (как резервная форма экзамена);
- **с моделью:** ИИ-судья получает только задание, ответ, эталон или рубрику и опорные
  фрагменты — не весь урок;
- **часть задач без модели:** пропуск из определения (`CSMA/CD — метод ______ доступа…`),
  дистракторы теста — термины того же раздела; упражнения учебника находятся по заголовкам
  «Вопросы для самопроверки», «Упражнения», «Задачи» и импортируются, а не придумываются.

Это отдельный кусок работы (У4), и он упирается в ещё не принятое решение
`TEXTBOOK_MODE.md` §10 «Проверка себя» — см. §10, вопрос 5.

## 6. ИИ поверх урока

### 6.1. Три сценария

| Сценарий | Что делает модель | Контекст | Нужен поиск | Результат |
|---|---|---|---|---|
| **Дополнить урок** | Пояснения, переходы, примеры, определения, мини-проверки между блоками. Source-блоки не удаляет | Source-блоки урока + цель темы | Нет | Карточка изменений |
| **Добавить практику** | Вопросы, тесты, пропуски, задачи. Учебный материал не меняет | Source-блоки урока | Нет | Карточка с заданиями |
| **Собрать урок** | Выбирает фрагменты, расставляет, пишет пояснения и задания | Кандидаты (§6.3) | Да | Storyboard → черновик нового урока |

Порядок реализации тот же: первые два не требуют поиска кандидатов, контекст у них маленький;
качество третьего зависит от кандидатов и заметно выигрывает от прохода 2.

**«Дополнить» не перезаписывает урок, а предлагает.** FR-L2 запрещает модельному результату
перезаписывать существующий урок, поэтому изменения приходят карточкой, как диф программы:

```
Предложение · 4 изменения · основание: источники + знания модели

[x] Вставить пояснение «MAC-адрес» после стр. 144 ¶5
    📚 Олифер, стр. 144 · ✨ знания модели
[x] Вставить пример «Столкновение двух станций» после блока «CSMA/CD»
    📚 Олифер, стр. 152
[ ] Вставить определение «Преамбула» перед стр. 155
    ✨ Только знания модели
[x] Вставить 2 вопроса на понимание в конец урока

              [ Принять выбранное · 3 ]  [ Отклонить ]
```

Операции: `insert_note`, `split_and_insert`, `insert_activity`, `rename_lesson`. Операции
удаления source-блока у модели нет. Частичное применение, перебазирование непринятых
операций на новую ревизию урока и одна отмена на всё применение — тот же механизм, что в
`program_chat.py` и `ProgramDiffCard.tsx`.

### 6.2. Основание

Выбирается явно до запуска и хранится у каждого блока: `только источники проекта` ·
`источники + знания модели` · `только знания модели` (FR-L2). У темы без материала первый
вариант недоступен с объяснением.

### 6.3. Конвейер «Собрать урок»

```
ProgramNode ─► A. Область ─► B. Кандидаты ─► C. Storyboard ─► D. Правка ─► E. Поблочная ─► F. Проверка
               (бесплатно)   (локально,       (1 маленький    пользова-    генерация       ссылок →
                             без модели)       вызов)          телем        (фон)           черновик
```

**A. Область.** Тема, подпункты, цель из паспорта, длительность, источники с ролями. Почти
ничего не стоит.

**B. Кандидаты — локально, без модели.** Единица — содержательный `MaterialBlock`. Источники
кандидатов по убыванию силы: диапазон оглавления → существующие привязки → проход 2 (когда
будет) → BM25 по формулировкам темы и подпунктов → векторный поиск (после вертикали 5). Роль
источника: основной > дополнительный > справочный; `ocr_low` — штраф. Итог — 15–30 блоков.
Веса подбираются по ручной проверке, а не заранее.

**C. Storyboard.** Модель получает компактную карту, а не текст:

```
1. Олифер, блок #341 · «Ethernet: общий принцип» · стр. 143–146 · ≈1700 ток. · основной
2. Олифер, блок #344 · «CSMA/CD» · стр. 150–153 · ≈1300 ток. · основной
3. Методичка, блок #82 · «Пример коллизии» · стр. 24 · ≈600 ток. · дополнительный
…
```

и отвечает планом:

```
План урока · ~25 минут
1. [SOURCE]    Основы Ethernet — Олифер 143–146
2. [NOTE]      Кратко объяснить MAC и общий принцип
3. [SOURCE]    CSMA/CD — Олифер 150–153
4. [NOTE]      Разобрать столкновение двух станций — опора: Методичка #82
5. [ACTIVITY]  3 вопроса на понимание
6. [SOURCE]    Формат кадра — Олифер 155–157
7. [ACTIVITY]  Назначение полей кадра
```

Выбор 8–12 блоков из 30 и есть переранжирование: **отдельный reranker в первой версии не
нужен**. Он добавляется, только если на проверке модель по карте выбирает плохо.

**D. Правка storyboard.** Убрать шаг, поменять порядок, заменить кусок, сменить основание.
Видна стоимость (`CostEstimate`) до дорогой генерации.

**E. Поблочная генерация.** Каждый `note` и набор заданий — отдельный вызов с минимальным
контекстом: тема, цель урока, соседние шаги storyboard, 1–3 опорных блока. Не весь учебник и
не весь урок. Исполняется `BackgroundJob(ai_lesson_build)` с чекпоинтом на блок — как
`ai_program_build`: падение одного блока не теряет готовые, повтор идёт только по упавшим,
кэш ответов (`AiCacheEntry`) удешевляет повтор.

**F. Проверка ссылок** (§3.4) → новый урок в статусе черновик.

### 6.4. Массовая сборка с ИИ

В таблице §4.5 появляется действие «с ИИ». Одна задача на тему, последовательно в полосе
`ai`. Проверять storyboard по каждой из 20 тем утомительно — нужен ли вариант «принять
storyboard без проверки», решает владелец (§10, вопрос 6). Результат в любом случае —
черновики.

## 7. Поиск кандидатов и эмбеддинги — не в этой вертикали

Урокам нужен только шаг B конвейера, и он работает на оглавлении, привязках и BM25.
Векторная часть подключается к нему как ещё один источник кандидатов, ничего в модели урока
не меняя. Ниже — вход для вертикали 5, а не решение; сведения о моделях перед выбором
перепроверить по первичной документации.

- **Единица индекса — `MaterialBlock`** (заголовок + подчинённые абзацы), не страница и не
  фрагмент. Выбранный блок раскрывается во фрагменты для точных ссылок.
- **Гибрид:** BM25 top-N + векторный top-N → слияние (RRF или нормированные оценки) →
  при необходимости reranker → top-K. Числа N и K задаёт замер, а не записка.
- **Проход 2 остаётся полным перебором**: top-k туда не подходит (FR-D14).
- **Кандидаты моделей из обсуждения:** `Qwen3-Embedding-0.6B` (+ `Qwen3-Reranker-0.6B`),
  `BAAI/bge-m3` как базовый вариант. Мерить на своих запросах по русским учебникам с OCR и
  формулами, а не по MTEB.
- **Векторный движок:** `sqlite-vec` (в той же SQLite, без отдельного процесса; pre-v1 —
  возможны несовместимые изменения) против Qdrant (отдельный сервис; оправдан только при
  большой нагрузке).
- **Железо:** 8 ГБ VRAM — модели 0.6B помещаются, но не одновременно с другой крупной моделью.

## 10. Открытые вопросы

Каждый с рекомендацией по умолчанию.

1. **Порядок вертикалей.** Ручные уроки (У1–У4) не зависят от прохода 2. Делать их до
   прохода 2? *Рекомендация: да* — вкладка «Предложено» подключится, когда проход 2 будет
   готов, а «Собрать урок» (У7) идёт уже после него. Требует правки `PLAN.md`.
2. **Уроки в экзаменационном проекте.** *Рекомендация: в первой версии только учебник*;
   модуль `lessons` у экзамена остаётся скрытым.
3. **Статусы привязок из урока** — таблица §4.4. *Рекомендация: принять как есть.*
4. **Урок по разделу.** *Рекомендация:* выбор раздела по умолчанию — массовая подготовка
   «один урок на тему»; обзорный урок раздела — отдельным явным действием.
5. **Задания в уроке и «Проверка себя».** `TEXTBOOK_MODE.md` §10 откладывает «Проверку
   себя» в учебнике, а задания урока (У4) — это она и есть. *Рекомендация:* принять, что
   в учебнике проверка себя живёт в `activity`-блоках урока и первой версии хватает
   `choice` / `cloze` / `open` с самооценкой.
6. **Массовая сборка с ИИ.** *Рекомендация:* разрешить «принять storyboard без проверки» —
   результат всё равно черновики.
7. **Ссылки с предпросмотром** (§8, строка 12). *Рекомендация:* в первой версии без
   автоматического предпросмотра.
8. **Линия отсечения к защите.** *Рекомендация:* обязательно У1–У3 и У5; У4, У6, У7 — если
   останется время. У1–У3 показывают главную идею «урок = материал + сценарий» офлайн, У5 —
   ИИ-слой с происхождением на каждом блоке за пару вызовов.

**Тесты** — там, где поведение легко ломается:

- расчёт границ быстрого урока: следующий пункт с середины страницы, заголовок не найден,
  два подпункта на одной странице, последняя тема материала;
- разрез и склейка source-блоков, в том числе порядок страниц в режиме «Страницы»;
- перенос границ при новой ревизии с деградацией до страницы;
- привязки: без дублей, отмена добавления снимает созданные привязки, `machine` не
  перекрывает существующую `manual`;
- «Требует проверки» по снимкам темы;
- частичное применение карточки «Дополнить урок» и её отмена.
