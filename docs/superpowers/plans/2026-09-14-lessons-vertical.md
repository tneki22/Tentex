## 1. Суть

- **Урок — не новый текст, сгенерированный из учебника.** Это упорядоченный сценарий:
  ссылки на страницы и фрагменты материала, свои или модельные пояснения, медиа и задания.
- Материал остаётся первичным доказательством: производная сущность хранит происхождение
  (`REQUIREMENTS.md`, принцип «каждое утверждение имеет источник»). Урок расставляет
  материал и дополняет его, у каждого блока видно, откуда он.
- **Один документ — два способа показа:** «Страницы» (оригинал) и «Текст» (распознанные
  фрагменты). Содержимое между режимами не копируется, двух видов уроков нет.
- **Первый демонстрируемый срез работает без модели:** диапазон оглавления → страницы →
  ручная правка → оба режима просмотра. Офлайновый путь — не «бедная версия без ИИ», а
  самостоятельная полезная функция.
- **ИИ — второй слой поверх уже собранного урока.** Модель анализирует конкретный урок, а
  не весь учебник. Первым идёт «Дополнить урок»: его контекст — сам урок, поиск и
  эмбеддинги ему не нужны.
- Эмбеддинги, векторный движок и reranker урокам не нужны; их выбор остаётся в вертикали «Гибридный поиск».

## 2. Раздел «Уроки» — `/projects/:projectId/lessons`

Три колонки: программа, редактор урока, материал для урока.

```
┌ Программа ─────────────────┬ Ethernet · черновик ───────────────────┬ Материал для урока ───────────┐
│ Найти тему или урок        │ [Страницы | Текст]   ↶  В архив  Готов │ Оглавление Страницы Поиск     │
│                            │ [Новый урок ▾] [Дополнить с ИИ]        │ Предложено                    │
│ ▾ Компьютерные сети        │ ## Ethernet                            │                               │
│   Физический уровень   ✓ 1 │ ┌ Олифер · стр. 143–146 ─────────────┐ │ Олифер · основной             │
│   ▾ Канальный уровень      │ │ [страница 143] [страница 144] …    │ │   стр. 143–158  [Добавить всё]│
│ ☐   Ethernet           ●   │ └────────────────────────────────────┘ │ Методичка · дополнительный    │
│ ☐   Wi-Fi              —   │ 💡 Пояснение · ручное                  │   стр. 22–28    [Добавить всё]│
│ ☐   Коммутаторы        ⚠   │ ┌ Олифер · стр. 147–150 ─────────────┐ │ Конспект · справочный         │
│   Сетевой уровень      ✓ 2 │ │ …                                  │ │   стр. 11–12    [Добавить всё]│
└────────────────────────────┴────────────────────────────────────────┴───────────────────────────────┘
```

**Слева — программа.** Можно выбрать одну тему, целый раздел или несколько тем чекбоксами.
Состояние темы: `—` нет урока · `●` черновик · `✓ N` готовых уроков · `⚠` требует проверки.
У раздела — сумма по поддереву. Чекбокс раздела выбирает все изучаемые узлы под ним.

**В центре** — по выбору: раздел → обзор тем; одна тема → список её уроков и редактор;
несколько тем → таблица массовой подготовки (§4.5).

**Справа — материал для урока.**

| Вкладка | Что показывает | Живая с этапа |
|---|---|---|
| **Оглавление** | Диапазоны страниц темы из `program_node_source_page_ranges` по всем источникам, с ролью; «Добавить всё» | Список и создание урока — 1; «Добавить всё» в открытый урок — 2 |
| **Страницы** | Листание любого источника проекта; выбор страницы, структурного блока, фрагментов, области | Добавление — 2 (область — 3) |
| **Поиск** | Существующий FTS5/BM25, выдача сгруппирована по файлу и странице: запрос `Ethernet кадр FCS` → «Учебник, стр. 155 · Методичка, стр. 24 · Конспект, стр. 11» | Добавление — 2 |
| **Предложено** | Привязки прохода 2 с оценкой: `95 % Ethernet: принцип работы · стр. 146–149`, `88 % Коллизии и CSMA/CD · стр. 151–153` | **Заглушка до прохода 2**: «Предложения появятся после автоматического разбора материала» |

В обсуждении предлагалось кормить «Предложено» до прохода 2 диапазоном оглавления и BM25.
Решено не делать: диапазон уже есть во вкладке «Оглавление», поиск — во вкладке «Поиск».

Вкладки «Уже в уроке» нет: центр и так показывает состав урока, а в выдаче поиска и на
страницах уже добавленное помечается «в уроке».

## 3. Модель документа урока

### 3.1. Четыре вида блоков

| Вид | Что внутри | Пример |
|---|---|---|
| `source` | Ссылка на материал проекта: диапазон страниц, структурный блок, диапазон фрагментов или область страницы | Олифер, стр. 150–153 |
| `note` | Markdown с формулами. Оформление: текст · заголовок · пояснение · важно · пример · определение · предупреждение | 💡 Почему возникает коллизия |
| `media` | То, чего нет в материалах проекта: своё изображение, фото доски, внешняя ссылка | Фото схемы с лекции |
| `activity` | Ссылка на `Activity` вида `study_task` (§5) | Почему CSMA/CD не нужен в полном дуплексе? |

Оформления `note` — одно поле `variant`, а не шесть сущностей. Заголовок — тоже вариант
`note`; отдельного разделителя нет. Вырез страницы материала — это `source` с областью, а не
`media`: у него есть происхождение в материале, и он ведёт себя как остальные ссылки на
материал (перенос между ревизиями, «Источник недоступен», привязка).

Заполненный пример документа:

```
#  вид       форма / оформление   содержимое                                   происхождение
1  note      заголовок            «Ethernet»                                   оглавление
2  source    фрагменты            Олифер · стр. 143 (с «2.3») — стр. 146 ¶5    оглавление
3  note      пояснение            «MAC-адрес — это…»                           модель · Олифер с. 144
4  source    фрагменты            Олифер · стр. 146 ¶6 — стр. 149              оглавление
5  note      заголовок            «Коллизии и CSMA/CD»                         оглавление
6  source    фрагменты            Олифер · стр. 151 ¶3 — стр. 153 ¶1           ручное
7  activity  выбор                «Почему коллизии невозможны в дуплексе?»     модель · Олифер с. 152
8  source    область              Методичка · стр. 24 · схема                  ручное
```

### 3.2. Вставка «в середину страницы» — это разрез source-блока

Документ — только упорядоченный список блоков. Отдельного якоря (`after_fragment`,
`after_page`) нет.

Действие «Вставить после этого абзаца» режет source-блок на два по границе фрагмента:

```
было:   source  Олифер · стр. 143–158
стало:  source  Олифер · стр. 143 — стр. 144 ¶5
        note    💡 Пояснение
        source  Олифер · стр. 144 ¶6 — стр. 158
```

«Убрать разрез» склеивает соседние куски одного материала обратно.

Почему так: одна система порядка вместо двух (позиция + якорь). Перетаскивание, отмена и
ответ модели (storyboard — это тоже список) работают без случая «блок перетащили, а якорь
остался на старом месте».

**Граница куска** хранится как `from_fragment_id` / `to_fragment_id` плюс денормализованные
`page_from` / `page_to`. При новой ревизии материала (например, после правки OCR) ссылка
переносится тем же сопоставлением фрагментов в пределах страницы, что и привязки
(`transfer_bindings_on_revision`). Не нашёлся фрагмент — граница **деградирует до границы
страницы**, блок получает пометку «Разрез сдвинут». Урок не ломается.

### 3.3. Два способа показа

| | «Страницы» | «Текст» |
|---|---|---|
| source-блок | Изображения страниц оригинала, ленивая загрузка; область — вырез страницы | Фрагменты активной ревизии по порядку: заголовок остаётся заголовком, формулы через KaTeX, рисунки и таблицы — вырезами оригинала |
| Разрез внутри страницы | Страница рисуется один раз — в куске, где лежит её первый фрагмент; вставка идёт после этой страницы | Вставка стоит ровно на месте разреза |
| `ocr_low` | Показан оригинал | Рядом с фрагментом вырез оригинала и `QualityBadge` |
| Служебные блоки (колонтитулы) | Видны, это часть страницы | Скрыты |
| `note` / `media` / `activity` | Между страницами | В потоке текста |
| Материал ещё не разобран | Страницы видны | «Текст ещё не распознан» и переход в Материалы |

Для source-блока можно включить «Всегда показывать страницами» — для страниц, где текстовый
слой бесполезен (формулы, схемы, плохой скан).

Режим «Страницы»:

```
────────────
Страница 143
[оригинал]
────────────
Страница 144
[оригинал]
────────────
💡 Пояснение
Почему возникает коллизия…
────────────
Страница 145
[оригинал]
```

Режим «Текст»:

```
2.3 Ethernet
Ethernet использует…
💡 Пояснение
Почему возникает коллизия…
Следующий фрагмент распознанного текста…
🧠 Проверь себя
Почему CSMA/CD…
```

Переключатель режима запоминается по проекту. Прецеденты в коде: `useAnswerViewMode`
(вкладка «Ответы» экзамена, текст/сканы) и просмотрщик Материалов («Оригинал / Текст»).

### 3.4. Происхождение блока

| Поле | Значения |
|---|---|
| `origin` | `manual` · `outline` (быстрый урок) · `model` · `mixed` (модельный блок, отредактированный пользователем) |
| `basis` (у модельных `note` и заданий) | `sources` · `sources_and_model` · `model_only` |
| опорные ссылки | Фрагменты и страницы, на которые блок опирается |
| `ai_run_id` | Какой вызов модели его создал |

Происхождение показывается у конкретного блока, а не только у урока:

```
💡 Почему используется преамбула
   Основание: 📚 Олифер, стр. 156 · ✨ дополнено знаниями модели

💡 Современный коммутируемый Ethernet
   ✨ Только знания модели — нет подтверждения в материалах проекта
```

**Ссылки модели проверяются на сервере.** Опорный фрагмент принимается, только если он был в
переданном модели контексте; иначе ссылка отбрасывается, а основание понижается до знаний
модели. Тот же принцип уже работает в чате программы: `basis_kind` выводится по
перепроверенной ссылке на пункт оглавления, а не по слову модели.

### 3.5. Хранение

Четыре таблицы заводятся **сразу целиком на этапе 1**, чтобы этапы 2–3 не требовали
миграций. Колонки заданий (`activity_id`) заполняются с этапа 6.

```
lessons             id, project_id, title, goal, status, duration_minutes, revision,
                    last_block_id, completed_at, created_at, updated_at
lesson_topics       project_id, lesson_id, program_node_id, sort_order, topic_title_snapshot
lesson_blocks       id, lesson_id, sort_order, kind, variant, body_md, origin, basis,
                    ai_run_id, activity_id, media_path, bound_program_node_id,
                    created_at, updated_at
lesson_source_refs  id, block_id, role, material_id, source_name_snapshot,
                    material_revision, page_from, page_to, from_fragment_id,
                    to_fragment_id, region_bbox, always_pages
```

Перечисления:

| Перечисление | Значения |
|---|---|
| `LessonStatus` | `draft` · `ready` · `archived` |
| `LessonBlockKind` | `source` · `note` · `media` · `activity` |
| `LessonNoteVariant` | `text` · `heading` · `explanation` · `important` · `example` · `definition` · `warning` |
| `LessonBlockOrigin` | `manual` · `outline` · `model` · `mixed` |
| `LessonBasis` | `sources` · `sources_and_model` · `model_only` |
| `LessonRefRole` | `content` (что показывать) · `support` (на что опирается `note` или задание) |
| `BindingMechanism` (+2) | `lesson` · `outline` |

Заполненный пример ссылки для блока 6 из §3.1:

```
role=content  material_id=<Олифер>  source_name_snapshot="Олифер — Компьютерные сети"
material_revision=3  page_from=151  page_to=153
from_fragment_id=…c41  to_fragment_id=…d07  region_bbox=null  always_pages=false
```

- Ссылки лежат отдельной таблицей, а не в JSON блока: «какие уроки используют эту
  страницу», перенос при новой ревизии и «Источник недоступен» — обычные SQL-запросы, так же
  устроены привязки.
- Удаление материала не каскадит на урок: `material_id` и фрагменты — `ON DELETE SET NULL`,
  снимок имени и страниц остаётся.
- Прохождение (`last_block_id`, `completed_at`) хранится прямо в уроке: пользователь один.
- `duration_minutes` — грубая оценка: символы текста содержательных фрагментов ÷ 1200 в
  минуту, округление до 5 минут; пользователь может поправить.

### 3.6. «Требует проверки» считается при чтении

Состояние не пишется флагом из каждого места, где меняется программа, а вычисляется
сравнением со снимком:

| Условие | Что видит пользователь |
|---|---|
| Тема урока вне текущей программы или переименована (`topic_title_snapshot` не совпал) | Урок: «Требует проверки» (FR-L6) |
| Ревизия материала сменилась, граница куска не перенеслась | Блок: «Разрез сдвинут» |
| Материал убран из проекта или удалён | Блок: «Источник недоступен», с именем и страницами (FR-L5) |

«Подтвердить» обновляет снимки. Почему при чтении: программа меняется из ручного редактора,
импорта оглавления, дифа чата, слияния и отмены — подвешивать флаг на каждый путь хрупко, а
сравнение со снимком — одна функция. Изменение программы урок не удаляет.

### 3.7. Сохранение и отмена

- **Структурные операции** — создать урок, добавить, удалить, переместить, разрезать,
  склеить блок, принять предложение модели — идут через журнал действий проекта и отменяются
  одной записью (`POST /api/projects/{id}/actions/undo`).
- **Текст `note`** сохраняется автоматически с ожидаемой ревизией, как конспект: конфликт
  показывается, а не перезаписывается. В журнал набор текста не пишется.
- **Редактор текста** — один экземпляр Crepe на выбранном `note`; остальные блоки рисуются
  существующим Markdown-рендером с KaTeX. Десятки редакторов на одной странице тяжелы.

## 4. Ручное создание

### 4.1. «Быстрый урок»

Кнопка у темы — в разделе «Уроки» и в пустой вкладке «Урок» Рабочей области. Ничего не
спрашивает. Пример: в программе есть «2.3 Протокол Ethernet», из оглавления известно
«Основной учебник, стр. 143–158».

1. **Берёт диапазон** темы из `program_node_source_page_ranges` у первого по приоритету
   основного источника. Диапазона нет (тема `custom`) → кнопка недоступна: «У темы нет
   страниц из оглавления — соберите урок вручную». У раздела быстрого урока нет — раздел
   ведёт в массовую подготовку.
2. **Уточняет конец.** Диапазон оглавления кончается на странице *перед* следующим пунктом
   того же или более высокого уровня (`program_outline.py` `_prepare_items`, та же формула в
   `program_chat.py:1238`: `page_to = max(item.page, boundary - 1)`). Если следующий пункт
   начинается с середины страницы, конец темы на ней теряется. Поэтому на странице
   `page_to + 1`, пропуская служебные блоки:
   - первый содержательный фрагмент — заголовок → следующий пункт начинается сверху, страница
     не нужна;
   - перед первым заголовком есть текст → это хвост темы: кусок продолжается до фрагмента
     перед заголовком. Если заголовков на странице несколько, выбирается совпавший с
     формулировкой следующего узла программы того же материала (`projects/heading_match.py`),
     иначе первый с `structure_level` не глубже уровня темы;
   - у страницы нет фрагментов (не разобрана) → страница добавляется целиком с пометкой
     «стр. 159 общая со следующей темой»;
   - последняя тема материала → расширения нет.
   Особый случай: следующий пункт на той же странице, что и начало темы
   (`page_to == page_from`) → кусок режется по следующему заголовку этой же страницы.
3. **Уточняет начало.** На `page_from` ищет заголовок, совпавший с формулировкой темы; нашёл —
   кусок начинается с него, и хвост предыдущей темы в текстовом режиме не показывается. Не
   нашёл (тему переименовали вручную) — страница с начала.
4. **Разрезает по подпунктам.** Потомки темы в текущей программе со своими диапазонами того же
   материала дают разрезы (по их заголовкам, иначе по границе страницы) и `note`-заголовки с
   их формулировками; глубина заголовка — по глубине узла (`##`, `###`).
5. Название = формулировка темы, статус = черновик, происхождение блоков = `outline`,
   `lesson_topics` = эта тема со снимком формулировки.
6. Создаёт привязки по правилам §4.4 и одну запись журнала `lesson_create`.

Результат для темы «2.3 Ethernet» с двумя подпунктами:

```
Урок «Ethernet» · черновик · ≈ 25 мин
1  note    заголовок  «Ethernet»
2  source             Олифер · стр. 143 (с заголовка «2.3») — стр. 146
3  note    заголовок  «2.3.1 Формат кадра»
4  source             Олифер · стр. 147–150
5  note    заголовок  «2.3.2 CSMA/CD»
6  source             Олифер · стр. 151 — стр. 159 (до заголовка «2.4»)
```

Ноль моделей, ноль эмбеддингов, практически ноль магии. Сверху потом «Дополнить с ИИ» —
модель работает с конкретным уроком.

### 4.2. «Из источников»

Когда у темы диапазоны в нескольких источниках:

```
Создать урок «Ethernet» из источников

[x] Олифер · основной           стр. 143–158
[x] Методичка · дополнительный  стр. 22–28
[ ] Конспект · справочный       стр. 11–12

Порядок: основной → дополнительные     [ Создать черновик ]  [ Отмена ]
```

По умолчанию отмечены основной и дополнительные, справочные — нет (основной определяет
содержание, дополнительный расширяет, справочный используется в объяснениях). Каждый
отмеченный диапазон обрабатывается как в §4.1, источники идут по роли и приоритету.

### 4.3. Добавление вручную

На странице из вкладок «Оглавление», «Страницы» или «Поиск»:

- **Добавить страницу** — `source` на страницу целиком;
- **Добавить структурный блок** — `source` на `MaterialBlock` (заголовок + подчинённые абзацы,
  списки, таблицы);
- **Добавить выделенные фрагменты** — `source` на диапазон фрагментов;
- **Добавить изображение или область** — `source` с `region_bbox` (схема, таблица, кусок скана).

Вставка — после выбранного в центре блока, без выбора — в конец. Механику выделения
фрагментов переиспользовать из ручной привязки (`SourcePreviewDialog`, `BoundSourceReader`).

Приоритет: целые страницы и структурные блоки важнее идеального выделения фрагментов —
оригинал читаем всегда, а OCR может быть кривым. Область страницы — этап 3.

### 4.4. Добавление в урок создаёт привязку к теме

Пользователь не должен думать «сначала привязать материал, потом вставить в урок»: вставил —
система поняла `фрагмент 381 → тема Ethernet`, и покрытие обновилось (`TEXTBOOK_MODE.md` §7).

Но `Binding` ставится на **фрагмент**: 16 страниц — сотни фрагментов, граничные страницы несут
хвосты соседних тем, а `manual` — самый сильный статус, который проход 2 не оспаривает.
Поэтому:

| Как попало в урок | Какие фрагменты привязываются | Статус | Механизм |
|---|---|---|---|
| Пользователь выбрал страницу, блок, фрагменты или область | Содержательные фрагменты выбора | `manual` | `lesson` |
| «Быстрый урок», «Из источников», «Добавить всё» | Фрагменты содержательных блоков, **начинающихся** внутри уточнённого диапазона; служебные блоки и хвосты соседних тем — нет | `machine` | `outline` |
| Модель поставила кусок в «Собрать урок» | Как во второй строке | `machine` | `lesson` |

- Проход 2 может подтвердить или оспорить `machine`, но не трогает `manual`.
- Уже существующая привязка того же фрагмента к той же теме не меняется **в любом статусе**:
  снятая пользователем («Это не по теме») не воскресает, ручная не понижается до машинной.
- Отмена добавления блока или создания урока отменяет и созданные привязки — одна запись журнала.
- Удаление блока из урока привязки молча не снимает: уведомление предлагает «Снять привязки к
  теме (N)».
- В уроке по нескольким темам кусок привязывается к теме, чей диапазон содержит страницу, иначе
  к первой теме урока; блок показывает тему (`bound_program_node_id`), её можно сменить.
- Материал без активной ревизии разбора: source-блок создаётся по страницам, привязок нет.

### 4.5. Массовая подготовка без модели

Выбраны несколько тем или раздел:

```
Подготовка уроков · 6 тем

#   Тема                  Материал               Уроки     Действие
1   Ethernet              Олифер 143–158         —         [быстрый урок ▾]
2   Wi-Fi                 Олифер 159–171         —         [быстрый урок ▾]
3   Коммутаторы           Олифер 172–180         ✓ 1       [пропустить ▾]
4   VLAN                  —                      —         [вручную ▾]
…
                              [ Создать 3 черновика ]
```

По умолчанию: тема с диапазоном и без урока — «быстрый урок»; с готовым уроком — «пропустить»
(FR-L7, молча не перезаписывается); без диапазона — «вручную». «Создать по порядку» выбирает
изучаемые темы без готового урока в порядке программы. Все черновики — одна транзакция и одна
отмена. Демонстрация: весь учебник → черновики по всем темам без единого вызова модели.

### 4.6. Изучение — вкладка «Урок» Рабочей области

- Показываются уроки темы: готовые — сразу, несколько — компактный selector, выбор запоминается
  по теме. Архивные в выбор по умолчанию не попадают.
- Черновик не выдаётся за готовый: «Черновик · Продолжить редактирование».
- Переключатель «Страницы / Текст».
- Позиция чтения восстанавливается (`last_block_id`); «Урок пройден» пишет запись в «Историю».
- Просмотр урока — сила свидетельства 0 (FR-L9). Прогресс меняют только задания:
  форма → `Attempt` → `Grade`.
- Пустое состояние: «Для этой темы ещё нет урока» · «Быстрый урок» · «Собрать вручную».
- «Редактировать» → `/projects/:projectId/lessons?topic=:topicId&lesson=:lessonId`;
  «Открыть в Рабочей области» из раздела → `/projects/:projectId?topic=:topicId&tab=lesson&lesson=:lessonId`.

## 5. Задания в уроке

**Решение 14.09.2026: заданий без модели нет.** В обсуждении предлагались задания, которые
создаются без модели (пропуск в определении, дистракторы из терминов раздела) и проверяются
самим пользователем по эталону. Это отклонено: ценности мало, работы много.

Остаётся так:

- **Задание — ссылка на обычную `Activity`, а не особый «ИИ-блок».** Цепочка
  `Activity → Attempt → Grade`, движок проверки один на все поверхности (FR-V6). Одно и то же
  задание потом появляется в уроке, Занятии, тренировке, чате и повторении.
- **Новый вид активности `study_task`** — общий для учебникового режима. В коде сейчас
  `ActivityKind = free_answer | card`, а частичный уникальный индекс
  `uq_activities_free_answer_node` разрешает один `free_answer` на узел: три вопроса по одной
  теме туда не ложатся, и текста задания у `Activity` нет.
- **Таблица задания** хранит: условие (`prompt_md`), форму (`open` · `choice` · `cloze`),
  варианты и ключ ответа, эталон или рубрику, опорные фрагменты (`supporting_fragment_ids`),
  основание и `generated_by` (`ai_run_id`).
- **Создаёт задания модель** — сценарий «Добавить практику» (§6.1). Если в учебнике есть
  готовые упражнения (заголовки «Вопросы для самопроверки», «Упражнения», «Задачи»), модель
  опирается на них, а не придумывает новые.
- **Проверка:**
  - `choice` и `cloze` — по ключу, который модель выдала вместе с заданием: без вызова модели в
    момент ответа, мгновенно и бесплатно; работает и при выключенных моделях;
  - `open` — ИИ-судья получает только задание, ответ, эталон или рубрику и опорные фрагменты,
    не весь урок; модели выключены → «Проверка недоступна без внешней модели», ответ не
    теряется.
- Задания урока закрывают вопрос «Проверка себя» из `TEXTBOOK_MODE.md` §10: в учебнике это они.

## 6. ИИ поверх урока

### 6.1. Три сценария

| Сценарий | Что делает модель | Контекст | Нужен поиск | Результат |
|---|---|---|---|---|
| **Дополнить урок** | Объяснения, переходы, примеры, определения, мини-проверки между блоками. Исходные страницы не удаляет. Скорее всего, самый полезный режим | Source-блоки урока + цель темы | Нет | Карточка изменений |
| **Добавить практику** | Вопросы, тесты, пропуски, задачи, упражнения. Учебный материал не меняет | Source-блоки урока | Нет | Карточка с заданиями |
| **Собрать урок** | Сам выбирает фрагменты, расставляет, пишет пояснения и задания | Кандидаты (§6.3) | Да | Storyboard → черновик нового урока |

Не набор галочек, а три понятных сценария. Порядок реализации тот же: первые два не требуют
поиска кандидатов, контекст у них маленький; качество третьего зависит от кандидатов и
выигрывает от прохода 2.

Роли шлюза (предварительные имена): `lesson_enrich` — «Дополнить», `lesson_practice` —
«Добавить практику», `lesson_builder` — storyboard и блоки «Собрать урок». Судья заданий —
существующая лесенка проверки; если её роль завязана на экзамен, её обобщают, а не копируют.

**«Дополнить» не перезаписывает урок, а предлагает.** FR-L2 запрещает модельному результату
перезаписывать существующий урок, поэтому изменения приходят карточкой, как диф программы:

```
Предложение · 4 изменения · основание: источники + знания модели

[x] Вставить пояснение «MAC-адрес» после стр. 144 ¶5
    📚 Олифер, стр. 144 · ✨ знания модели
[x] Вставить пример «Столкновение двух станций» после блока «CSMA/CD»
    📚 Олифер, стр. 152
[ ] Вставить определение «Преамбула» перед стр. 155
    ✨ Только знания модели
[x] Вставить 2 вопроса на понимание в конец урока

              [ Принять выбранное · 3 ]  [ Отклонить ]
```

Операции: `insert_note`, `split_and_insert`, `insert_activity`, `rename_lesson`. Удаления
source-блока у модели нет. Частичное применение, перебазирование непринятых операций на новую
ревизию урока и одна отмена на всё применение — тот же механизм, что в `program_chat.py` и
`ProgramDiffCard.tsx`.

### 6.2. Основание

Выбирается явно до запуска и хранится у каждого блока: `только источники проекта` ·
`источники + знания модели` · `только знания модели` (FR-L2). У темы без материала первый
вариант недоступен с объяснением.

### 6.3. Конвейер «Собрать урок»

Не «вот тебе 50 страниц, напиши урок» — это дорого и плохо. Конвейер:

```
ProgramNode ─► A. Область ─► B. Кандидаты ─► C. Storyboard ─► D. Правка ─► E. Поблочная ─► F. Проверка
               (бесплатно)   (локально,       (1 маленький    пользова-    генерация       ссылок →
                             без модели)       вызов)          телем        (фон)           черновик
```

**A. Область.** Почти ничего не стоит по токенам:

```
Программа:        Канальный уровень → Ethernet → Формат кадра, CSMA/CD
Основной источник: стр. 143–158
Дополнительные:   методичка, конспект
Цель:             понимать + уметь применять
Длительность:     25 минут
```

**B. Кандидаты — локально, без модели.** Единица — содержательный `MaterialBlock`. Источники
кандидатов:

1. диапазоны из оглавления — почти бесплатный и сильнейший сигнал;
2. уже существующие привязки;
3. результаты прохода 2 (когда будет);
4. BM25 по запросам из темы и подпунктов: `Ethernet`, `Ethernet frame`, `CSMA/CD`,
   `MAC address`, `коллизии Ethernet`;
5. векторный поиск — после вертикали «Гибридный поиск».

Веса из обсуждения (стартовые, подбираются на ручной проверке):

```
диапазон оглавления     +++++
существующая привязка   +++++
основной источник       +++
дополнительный          ++
справочный              +
сходство BM25
сходство векторов (позже)
качество OCR (ocr_low — штраф)
```

RAG здесь — не магическая система, а умный выбор кандидатов. Итог — 15–30 блоков.

**C. Storyboard.** Модель получает компактную карту, а не текст:

```
1. Олифер, блок #341 · «Ethernet: общий принцип» · стр. 143–146 · ≈1700 ток. · основной
2. Олифер, блок #344 · «CSMA/CD» · стр. 150–153 · ≈1300 ток. · основной
3. Методичка, блок #82 · «Практический пример коллизии» · стр. 24 · ≈600 ток. · дополнительный
```

и отвечает планом:

```
План урока · ~25 минут
1. [SOURCE]    Основы Ethernet — учебник 143–146
2. [NOTE]      Кратко объяснить MAC и общий принцип
3. [SOURCE]    CSMA/CD — учебник 150–153
4. [NOTE]      Пример: столкновение двух станций — опора: методичка #82
5. [ACTIVITY]  3 вопроса на понимание
6. [SOURCE]    Формат кадра — учебник 155–157
7. [ACTIVITY]  Назначение полей кадра
```

Выбор 8–12 блоков из 30 и есть переранжирование, поэтому **отдельный reranker не нужен** до тех
пор, пока ручная проверка не покажет, что модель по карте выбирает плохо.

**D. Правка storyboard.** Пользователь убирает шаг, меняет порядок, заменяет кусок, меняет
основание — до дорогой генерации. Видна стоимость (`CostEstimate`).

**E. Поблочная генерация.** Урок не генерируется целиком. Каждый `note` и набор заданий —
отдельный вызов с минимальным контекстом: тема, цель урока, маленький кусок storyboard, 1–3
опорных блока (при необходимости соседний). Не весь учебник и даже не весь урок:

```
Storyboard call              маленький
AI-блок 1  → 1–3 source-блока
AI-блок 2  → 1–3 source-блока
Задания    → нужные блоки
```

Это дешевле и лучше для ссылок на источник. Исполнение — `BackgroundJob(ai_lesson_build)` с
чекпоинтом на блок, как `ai_program_build`: падение одного блока не теряет готовые, повтор идёт
только по упавшим, кэш ответов (`AiCacheEntry`) удешевляет повтор.

**F. Проверка ссылок** (§3.4) → новый урок в статусе черновик.

### 6.4. Массовая сборка с ИИ

В таблице §4.5 появляется действие «с ИИ»: одна фоновая задача на тему, последовательно в
полосе `ai`. Есть вариант «принять storyboard без проверки» — результат всё равно черновики.

## 7. Поиск кандидатов и эмбеддинги — вертикаль «Гибридный поиск», не Уроки

Урокам нужен только шаг B конвейера, и он работает на оглавлении, привязках и BM25. Векторная
часть подключается к нему как ещё один источник кандидатов, ничего в модели урока не меняя.
Ниже — всё из обсуждения как вход для вертикали «Гибридный поиск». **Это не решение**; сведения о моделях и
движках перед выбором перепроверить по первичной документации (`ctx7`). `PLAN.md` уже требует:
сначала реальный учебник и проход 2, потом выбор модели, движка и способа слияния.

**Какой RAG строить** — не классический `чанк → эмбеддинг → top-5 → LLM`, а от программы:

```
                 ProgramNode
                     │
        ┌────────────┴────────────┐
        ↓                         ↓
диапазоны оглавления      существующие привязки
        └────────────┬────────────┘
                     ↓
              область кандидатов
                     ↓
          ┌──────────┴──────────┐
          ↓                     ↓
        BM25              эмбеддинги
          └──────────┬──────────┘
                     ↓
               слияние оценок
                     ↓
          reranker (если понадобится)
                     ↓
               лучшие блоки
                     ↓
      раскрыть соседние и родительский блоки
                     ↓
          сборщик контекста для модели
```

- **Единица индекса — `MaterialBlock`** (заголовок + подчинённые абзацы, списки, таблицы), не
  страница: блок уже определён как единица смысловой классификации, абзац слишком мелкий и
  шумный. Выбранный блок раскрывается во фрагменты для точных ссылок. Позже можно добавить
  эмбеддинги фрагментов.
- **Гибрид**, стартовые числа из обсуждения: BM25 top 30 + векторный top 30 → RRF или
  нормированное объединение → top 20 → reranker → top 8. BM25 уже есть и не выбрасывается. По
  обсуждению, BGE-M3 сам рекомендует сочетать dense с sparse/BM25 и reranking.
- **Проход 2 с этим не смешивается**: он обязан пройти каждый содержательный блок, top-k туда
  не подходит (FR-D14).
- **Первый кандидат — `Qwen3-Embedding-0.6B`** (+ парный `Qwen3-Reranker-0.6B`): по обсуждению,
  мультиязычный (100+ языков), отдельная embedding-модель, контекст 32K, 1024 измерения,
  instruction-aware, поддерживает Matryoshka-размерности. 4B/8B сразу не брать.
- **Второй кандидат — `BAAI/bge-m3`**: 100+ языков, 1024 измерения, до 8192 токенов, dense,
  sparse и multi-vector retrieval. Хороший базовый вариант.
- **Сравнивать не по MTEB**, а на своих запросах по русским учебникам с OCR и формулами: тема
  программы → нужный блок; вопрос → нужный фрагмент; похожее понятие → нужная глава. В
  обсуждении — 100–200 запросов.
- **Векторный движок, кандидат 1 — `sqlite-vec`:** векторы прямо в SQLite (float, int8, binary),
  без отдельного процесса. Оговорка: проект pre-v1 и сам предупреждает о возможных
  несовместимых изменениях. Для локального приложения всё равно привлекателен:
  `SQLite: materials, fragments, blocks, bindings, vec_blocks` без Redis и Qdrant.
- **Qdrant** — если нагрузка на векторы окажется большой или понадобятся сложные фильтры и
  масштабирование. Отдельный локальный сервис, есть local/embedded варианты. Сейчас — лишняя
  инфраструктура.
- **Железо:** 8 ГБ VRAM — модели 0.6B помещаются, но не одновременно с другой крупной моделью.

|---|---|---|
| GET | `lessons/overview` | На каждый узел: число черновиков, готовых, архивных, требующих проверки; краткий список уроков (id, название, статус, темы, длительность) |

| GET | `lessons/{lesson_id}` | Урок с блоками и ссылками, готовый к показу: имя и роль источника, страницы, доступность, `quality` у страниц, вычисленные состояния |
| PATCH | `lessons/{lesson_id}` `{title?, status?, expected_revision}` | Переименование и статус; 409 при устаревшей ревизии |
