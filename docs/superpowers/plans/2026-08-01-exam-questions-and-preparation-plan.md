# Exam Questions and Preparation Plan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** После согласования заменить абстрактную «Программу» экзаменационного проекта на понятный редактор «Вопросы экзамена», спроектировать календарный «План подготовки» и убрать пересекающееся редактирование из соседних экранов.

**Architecture:** «Вопросы экзамена» остаются единственным источником структуры и состава экзамена. «План подготовки» хранит версионируемое распределение активных вопросов по дням и не меняет их структуру. Локальный детерминированный алгоритм всегда создаёт базовый план; внешняя модель может предложить группировку, оценку объёма и перераспределение, но каждое изменение показывается до применения и отменяется одним действием.

**Tech Stack:** React 19, TypeScript 5.9, React Router 8, Radix wrappers, lucide-react, token-only CSS, будущий FastAPI API, SQLite, единый OpenAI-совместимый шлюз внешних моделей.

## Global Constraints

- До отдельного подтверждения пользователя не изменять `SCREENS.md`, `REQUIREMENTS.md`, экранный реестр и файлы прототипов.
- На этапе 1 интерфейс работает на выдуманных данных без API.
- Русские тексты интерфейса, английские идентификаторы.
- «Программа» остаётся внутренним доменным термином; в экзаменационном интерфейсе пользователь видит «Вопросы экзамена».
- План полностью работает без внешних моделей.
- Любое предложение внешней модели помечается как машинное, показывает источник, применяется после просмотра и отменяется одним действием.
- Перед внешним запуском показываются отправляемые данные, число вызовов, оценка времени, оценка стоимости и дата актуальности цены.
- Прогноз готовности не показывается без достаточного числа попыток и никогда не подменяется оценкой модели.
- Покрытие материала ниже 100% не показывается как проблема.
- Редактор не требует обязательных разделов: плоский список вопросов является нормальным состоянием.
- Цвета используются только через токены из `frontend/src/styles/tokens.css`.
- После согласования сначала обновляются нормативные описания, затем по правилу этапа 1 сразу верстаются оба прототипа.

## 2. Экран «Вопросы экзамена»

**Маршрут:** `/projects/:projectId/program`

**Название в экзаменационном проекте:** «Вопросы экзамена».

**Название для других шаблонов:** «Программа» до отдельного проектирования этих шаблонов.

### 2.1. Назначение

Экран является каноническим редактором того, что пользователь собирается сдавать. Для формата с отдельными вопросами верхними узлами могут быть разделы, а изучаемыми узлами являются вопросы и задачи. Для готовых билетов дерево сохраняет билеты и их состав. Четыре уровня вложенности остаются техническим пределом, но интерфейс не предлагает создавать уровни без необходимости.

В текущих мок-данных «Основы баз данных» и «Реляционная модель» называются разделами. Расположенные внутри строки называются вопросами. Слово «тема» остаётся доменным понятием для изучаемого узла и не используется как синоним раздела в этом экране.

### 2.2. Компоновка

Экран занимает всё окно и состоит из трёх областей.

| Область | Содержимое | Назначение |
| --- | --- | --- |
| Левая проектная панель | Возврат в Рабочую область, название проекта, навигация проекта, быстрые выборки списка | Даёт контекст проекта и не дублирует дерево вопросов |
| Центральный редактор | Заголовок, действия, таблица состояния, поиск, фильтры, иерархический список | Основное место редактирования структуры экзамена |
| Правая панель свойств | Свойства выбранного узла или массовое действие | Убирает редкие настройки из перегруженной строки |

Левая панель содержит выборки «Все вопросы», «Без раздела», «Вне подготовки» и «Требуют проверки». Внизу находится та же навигация проекта, что в Рабочей области и Материалах. Отдельное дерево разделов слева не добавляется: структура уже видна в центральном редакторе.

### 2.3. Верхняя часть центральной области

Заголовок: «Вопросы экзамена».

Справа от заголовка находятся:

1. вторичная кнопка «Добавить» с меню «Раздел», «Вопрос», «Задача», «Билет»;
2. вторичная кнопка «Разложить по разделам»;
3. основная кнопка «Импортировать или обновить».

Под заголовком находится компактная таблица, а не строка значений через разделители.

| Показатель | Пример | Действие по нажатию |
| --- | --- | --- |
| Вопросы и задачи | 40 | Снять остальные фильтры |
| Разделы | 6 | Показать только корневые разделы |
| Без раздела | 8 | Включить соответствующий фильтр |
| Вне подготовки | 3 | Показать сохранённые, но исключённые узлы |
| Требуют проверки | 2 | Показать последствия переименования или повторного импорта |

Следующей строкой идут поиск по формулировкам, фильтр по типу узла, уровню цели, происхождению и состоянию включения. Сортировка может временно менять представление, но ручной порядок меняется только перетаскиванием или командами перемещения.

### 2.4. Иерархический список

Центральный список использует доступную древовидную таблицу.

| Колонка | Содержимое |
| --- | --- |
| Структура | Чекбокс, раскрытие, ручка перемещения, номер и формулировка |
| Тип | Раздел, билет, вопрос, задача или подпункт |
| Уровень цели | Знать, понимать, применять или владеть |
| Подготовка | Включён, вне подготовки или требует решения |
| Внимание | Изменён эталон, затронуты карточки, найден похожий узел или есть конфликт импорта |

Число материалов, качество OCR, попытки и учебный статус сюда не добавляются: это задачи Покрытия, Рабочей области и Материалов. В строке остаётся только сигнал, если структурное изменение требует проверить связанные данные.

Раздел раскрывает дочерние узлы. Вопрос или задача выбирается одним кликом. Двойной клик по формулировке включает редактирование на месте. `Enter` сохраняет, `Escape` отменяет. Перетаскивание показывает точное будущее положение и допускает перемещение внутрь раздела, перед строкой или после неё. Клавиатурные команды перемещения доступны через меню строки.

### 2.5. Правая панель свойств

Для одного выбранного узла панель показывает:

| Группа | Поля и действия |
| --- | --- |
| Основное | Формулировка, тип узла, родитель, положение |
| Подготовка | Уровень цели, включение в текущую подготовку |
| Происхождение | Вручную, импорт, оглавление, проход 1 или каталог; файл и дата запуска при наличии |
| Последствия | Сколько эталонов, карточек, привязок и элементов Плана затронет изменение |
| Переходы | «Открыть в Рабочей области», «Показать материалы», «Показать в Плане» |

Для раздела уровень цели применяется ко всему поддереву после подтверждения с числом затронутых вопросов. Для массового выбора панель заменяется действиями «Переместить в раздел», «Изменить уровень цели», «Включить в подготовку», «Исключить из подготовки» и «Архивировать».

Физическое удаление допускается только для пустого нового черновика без связанных данных. Узел с историей исключается из текущей подготовки или архивируется, сохраняя id, ответы, карточки, привязки и попытки.

### 2.6. Добавление и быстрое редактирование

«Добавить» создаёт строку-черновик рядом с текущим положением. Раздел можно создать над выделенными вопросами: пользователь задаёт название, после чего выбранные строки перемещаются внутрь. Новый вопрос без раздела допустим и сразу появляется в выборке «Без раздела».

Переименование сохраняет связь по id. Если формулировка существенно изменилась, эталон и карточки получают состояние «Проверить». Изменение родителя или порядка само по себе связь с эталоном не ломает.

### 2.7. Импорт и повторный импорт

Кнопка «Импортировать или обновить» открывает выбор источника: файл, вставленный текст, существующий материал структуры экзамена или повторный разбор уже подключённого файла.

Первый импорт показывает предварительное дерево и позволяет:

1. исправить распознанные формулировки;
2. изменить типы узлов;
3. подтвердить найденные разделы и билеты;
4. оставить список плоским;
5. применить импорт.

Повторный импорт всегда открывает диф.

| Группа дифа | Возможные действия |
| --- | --- |
| Новые | Добавить или пропустить |
| Изменённые | Принять формулировку, оставить текущую или объединить вручную |
| Похожие | Объединить, сделать подпунктом или оставить отдельно |
| Исчезнувшие | Оставить в подготовке или пометить вне текущей подготовки |
| Перемещённые | Принять новый порядок или сохранить текущий |

Применение показывает число затронутых эталонов, карточек, привязок и дней Плана. После применения План получает состояние «Нужно обновить», но не перестраивается молча.

### 2.8. «Разложить по разделам» и ИИ

Кнопка доступна, если есть плоские вопросы, либо через меню повторной организации существующего дерева.

Сначала система выполняет бесплатную локальную часть: сохраняет явные заголовки, нумерацию и уже существующие родительские связи. Семантическая группировка плоских формулировок требует внешней модели.

Перед запуском показывается таблица отправляемых данных.

| Данные | По умолчанию |
| --- | --- |
| Формулировки вопросов и задач | Отправляются |
| Существующие названия разделов | Отправляются |
| Типы узлов и порядок | Отправляются |
| Особый фокус и сведения о преподавателе | Отправляются, если заполнены |
| Полные материалы и личные конспекты | Не отправляются |
| Эталонные ответы | Не отправляются; можно отдельно разрешить короткие начала ответов |

Результат открывается как диф текущего и предложенного дерева. Для каждого предложения показываются новый раздел, перемещаемые вопросы и короткое объяснение группировки. Числовая уверенность не показывается. Можно применить все предложения, выбрать отдельные разделы или отклонить результат. Применённая структура получает машинное происхождение и одну общую команду отмены.

ИИ также может предложить порядок внутри разделов и отметить вероятные дубли, но не объединяет и не переименовывает узлы без отдельного подтверждения.

Если внешние модели выключены, кнопка объясняет, что автоматическая смысловая группировка недоступна. Ручные разделы, перемещение, импорт заголовков и нумерации продолжают работать.

### 2.9. Состояния

| Состояние | Интерфейс |
| --- | --- |
| Список пуст | Предложение импортировать список или добавить первый вопрос вручную |
| Плоский список | Нормальный список и заметное, но не обязательное действие «Разложить по разделам» |
| Есть только билеты | Билеты являются верхними рабочими узлами, их состав раскрывается внутри |
| Есть черновики | Черновики отделены от действующей структуры и не попадают в План |
| Идёт импорт или ИИ-группировка | Прогресс задачи, счётчик обработанных элементов, отмена запуска |
| Есть конфликт импорта | Фильтр «Требуют проверки» и переход в диф |
| План устарел | Спокойная панель «Список изменился. Обновить План подготовки» |
| Внешние модели выключены | Ручная и локальная работа доступны, модельные действия объясняют причину недоступности |
| Ошибка модели | Предложение повторить или продолжить с текущей структурой; список не блокируется |

## 3. Экран «План подготовки»

**Маршрут:** `/projects/:projectId/plan`

### 3.1. Назначение

Экран превращает активные вопросы экзамена в календарный маршрут до даты. Он отделяет первичный проход от повторений и закрытия пробелов, учитывает доступное время, уровень цели, порядок Программы, дни отдыха и уже назначенные SM-2 повторения.

План не обещает успеть, если доступного времени недостаточно. В таком случае он показывает объём, который не помещается, и предлагает конкретные способы пересчёта.

### 3.2. Компоновка

Экран занимает всё окно и состоит из трёх областей.

| Область | Содержимое | Назначение |
| --- | --- | --- |
| Левая проектная панель | Возврат в Рабочую область, проектная навигация | Сохраняет единый переход между разделами проекта |
| Центральная область | Заголовок, таблица параметров, полоска фаз, календарная лента дней | Показывает весь маршрут и позволяет менять дни |
| Правая панель | Параметры, объяснение выбранного дня, пересчёт и последствия | Не перегружает календарные строки формами |

### 3.3. Заголовок и основные действия

Заголовок: «План подготовки».

Основная кнопка зависит от состояния:

| Состояние | Кнопка |
| --- | --- |
| Плана нет | «Составить план» |
| План актуален | «Пересчитать» |
| Список вопросов или паспорт цели изменился | «Обновить план» |

Рядом находятся вторичная кнопка «Уточнить с ИИ» и меню версии Плана: история пересчётов, возврат к предыдущей версии, экспорт.

Под заголовком расположена таблица.

| Показатель | Пример |
| --- | --- |
| Экзамен | 15 августа, 10:00 |
| Осталось учебных дней | 7 |
| Доступно | 120 минут в день |
| Первичный проход | До 12 августа |
| Резерв | 2 дня и финальное повторение |
| В Плане | 40 из 40 вопросов |

Если часть вопросов не помещается, последняя ячейка сообщает «35 запланировано, 5 не помещаются» и открывает варианты пересчёта. Красное число без действия не используется.

### 3.4. Полоска фаз

Над днями находится одна горизонтальная шкала от сегодняшней даты до экзамена. Она разделена на подписанные фазы:

1. «Первичный проход»;
2. «Повторение и пробелы»;
3. «Финальное повторение»;
4. «Экзамен».

Шкала показывает границы стратегии, а не процент выполнения. Клик по фазе прокручивает календарную ленту к соответствующим дням. Ручное изменение границы сразу открывает предварительный пересчёт, а не переставляет задания молча.

### 3.5. Календарная лента

Основное представление является вертикальной лентой дней, а не месячной сеткой: в один день может быть десять вопросов, и календарная ячейка не даёт их прочитать.

Каждый день имеет заголовок и раскрываемое содержимое.

| Часть дня | Содержимое |
| --- | --- |
| Заголовок | День недели, дата, фаза, доступные минуты, запланированные минуты |
| Состояние | Сегодня, выполнен, пропущен, перегружен, закреплён или день отдыха |
| Группы заданий | Новые вопросы, повторения, пробелы и финальный прогон |
| Нижние действия | «Начать день», «Перенести остаток», «Сделать днём отдыха» |

Строка задания показывает тип работы, формулировку, раздел, ожидаемое время и причину появления в этом дне. Повторение дополнительно показывает срок SM-2. Прогнозируемое время является оценкой нагрузки, а не таймером обязательного выполнения.

Дни свёрнуты до заголовка и первых трёх заданий. Сегодня и выбранный день раскрыты. «Развернуть всё» доступно для коротких планов. Фильтры показывают перегруженные, пропущенные, незапланированные или содержащие выбранный вопрос дни.

### 3.6. Ручное изменение

Вопрос или билет перетаскивается между днями. Клавиатурное меню предлагает точную дату. Перемещённое вручную задание получает признак «Закреплено вручную» и при следующем пересчёте остаётся на выбранной дате, пока пользователь не снимет закрепление.

Доступны массовый выбор и действия:

1. перенести на дату;
2. распределить по оставшимся дням;
3. закрепить;
4. снять закрепление;
5. исключить из этой версии Плана с переходом к настройке вопроса.

Исключение из Плана не меняет каноническую структуру молча. Экран предлагает открыть «Вопросы экзамена» и пометить узел вне подготовки либо оставить его активным, но незапланированным.

### 3.7. Правая панель

Панель имеет две вкладки.

#### Параметры

| Поле | Поведение |
| --- | --- |
| Дата и время экзамена | Берётся из паспорта цели, изменение предлагает обновить паспорт и План |
| Минут в день | Значение по умолчанию и отдельные значения по дням недели |
| Учебные дни | Дни недели, в которые можно назначать новые вопросы |
| Дни отдыха | Конкретные даты без новой нагрузки; назначенные SM-2 повторения показываются отдельно |
| Максимум новых вопросов | Ограничение очереди дня |
| Стратегия | Экзаменационная по умолчанию или равномерная |
| Резерв | Число дней на пробелы и финальное повторение |
| Поведение долга | Догнать сразу, распределить по остатку или простить |

#### Почему так

Для выбранного дня показывается таблица причин.

| Решение | Основание |
| --- | --- |
| Вопросы 1–10 назначены вместе | Сохраняется порядок и раздел «Основы баз данных» |
| На день выделено 110 минут | Доступно 120 минут, оставлен резерв 10 минут |
| Вопрос 7 перенесён раньше | Высокий уровень цели и нет успешных попыток |
| Повторение вопроса 3 | Наступил срок SM-2 |

Если день уточнён моделью, строки, пришедшие от модели, помечены `MachineMark` и ведут к запуску модели. Если использован только локальный алгоритм, прямо написано «Составлено локально по настройкам проекта».

### 3.8. Создание базового Плана

«Составить план» открывает короткий диалог проверки входов, а не отдельный мастер.

| Вход | Источник | Можно изменить перед запуском |
| --- | --- | --- |
| Дата экзамена | Паспорт цели | Да |
| Доступное время | Паспорт цели | Да |
| Активные вопросы | Вопросы экзамена | Нет, есть переход к списку |
| Уровни цели | Вопросы экзамена | Нет, есть переход к списку |
| Дни отдыха | Настройки Плана | Да |
| Стратегия | Экзаменационная | Да |

Локальный алгоритм сначала строит план-черновик. Пользователь видит фазы, незапланированный остаток и перегруженные дни, затем применяет План. Первое создание также можно сразу применить, если все вопросы помещаются и предупреждений нет; отмена возвращает состояние без Плана.

### 3.9. Экзаменационная стратегия по умолчанию

Обозначение `D` означает число доступных учебных дней до даты экзамена, включая текущий день, если дневная граница ещё не пройдена, и не включая сам экзамен после его начала.

| Доступный срок | Первичный проход | Повторение и пробелы | Финальный день |
| --- | --- | --- | --- |
| 1 день | Только вопросы с наибольшим приоритетом | Внутри того же дня | Короткий итог без обещания полного покрытия |
| 2 дня | Первый день | Нет отдельной фазы | Второй день: повторение приоритетного и пробелов |
| От 3 до 6 дней | Первые `D - 1` дней | Встроено в конец каждого дня | Последний день: общее повторение |
| 7 дней и больше | Около 60% доступных дней | Все дни между первичным проходом и последним днём | Последний день: общий прогон и сниженная новая нагрузка |

Для семи дней это даёт четыре дня первичного прохода, два дня повторения и закрытия пробелов, один финальный день. Для сорока одинаковых вопросов первичный проход получает по десять вопросов в день. Для четырёх дней первые три дня получают первичный проход, четвёртый день — повторение.

Алгоритм действует в таком порядке:

1. исключает узлы вне текущей подготовки и контейнеры без собственной учебной активности;
2. добавляет просроченные повторения перед новыми вопросами;
3. сохраняет порядок Программы и по возможности не разрывает небольшой раздел между днями;
4. вычисляет ожидаемое время каждого вопроса;
5. заполняет дни до дневного бюджета;
6. размещает повторения и закрытие пробелов в соответствующей фазе;
7. оставляет последний день без новых вопросов, кроме режима одного дня;
8. возвращает незапланированный остаток и объяснение, если всё не помещается.

### 3.10. Оценка объёма без ИИ

Если о вопросах ничего не известно, они считаются одинаковыми, поэтому пример с сорока вопросами распределяется равномерно.

Когда данные есть, локальная оценка использует только наблюдаемые признаки.

| Признак | Как влияет |
| --- | --- |
| Уровень цели | Знать занимает меньше времени, владеть свободно больше |
| Тип активности | Задача обычно получает больше времени, чем чтение или краткий ответ |
| Число подпунктов | Увеличивает ожидаемое время родительского билета или вопроса |
| Объём подтверждённого эталона | Используется как грубая оценка объёма, если эталон есть |
| Собственная история | После накопления попыток медианное фактическое время заменяет грубую оценку |

Для первой детерминированной версии используются конкретные начальные значения.

| Уровень цели | Базовое время вопроса |
| --- | --- |
| Знать о существовании | 10 минут |
| Понимать | 20 минут |
| Уметь применять | 35 минут |
| Владеть свободно | 50 минут |

Практическая задача получает минимум 35 минут. Если у билета есть дочерние вопросы, сам билет является контейнером с нулевым временем, а его оценка равна сумме дочерних элементов. Подтверждённый эталон длиннее 1 200 слов добавляет 10 минут, длиннее 2 400 слов добавляет 20 минут. После трёх выполненных активностей одного вида базовое время заменяется медианой фактической длительности пользователя. Коэффициент личного темпа доступен в диапазоне от 0,5 до 2,0 и по умолчанию равен 1,0.

Эти числа являются калибруемыми параметрами алгоритма А3, а не скрытым решением модели. В интерфейсе показывается основание оценки и доступно ручное изменение времени конкретного вопроса.

### 3.11. «Уточнить с ИИ»

Это отдельное действие над уже построенным локальным черновиком. Оно не является обязательным шагом создания Плана.

Модель получает ограниченный контекст.

| Данные | По умолчанию |
| --- | --- |
| Формулировки и структура вопросов | Отправляются |
| Уровни цели и формат экзамена | Отправляются |
| Дата, дневной бюджет и дни отдыха | Отправляются |
| Локальная оценка времени | Отправляется |
| Статусы и агрегированные результаты попыток | Отправляются |
| Особый фокус и сведения о преподавателе | Отправляются, если заполнены |
| Короткие эталонные ответы | Не отправляются; можно разрешить |
| Полные материалы, чаты и личные конспекты | Не отправляются |

Модель может предложить только четыре вида изменений:

1. пометить вопрос как малый, средний или большой по объёму;
2. перенести тяжёлый вопрос в менее загруженный день;
3. сохранить рядом связанные вопросы или развести слишком тяжёлые вопросы;
4. предложить порядок первичного прохода с объяснением зависимости.

Результат показывается дифом дней.

| Изменение | Что видит пользователь |
| --- | --- |
| Перенос | Исходный день, новый день, изменение нагрузки и причина |
| Изменение оценки | Было и стало минут, качественная категория объёма, причина |
| Изменение порядка | Положение до и после, объяснение |
| Невместившийся вопрос | Какие варианты разгружают План |

Пользователь применяет все изменения или отдельные строки. Вручную закреплённые задания модель не перемещает. Применённое уточнение создаёт новую версию Плана и отменяется целиком.

ИИ не вычисляет прогноз готовности и не заменяет SM-2. Прогноз опирается только на подтверждённые попытки, а даты повторений остаются детерминированными.

### 3.12. Восстановление после отставания

Пропущенный день не превращается в красный долг без выхода. Вверху появляется панель «Осталось 12 заданий за 95 минут» с тремя действиями.

| Вариант | Предварительный результат |
| --- | --- |
| Догнать сразу | Показывает новые перегруженные дни |
| Распределить по остатку | Показывает прибавку минут по каждому оставшемуся дню |
| Простить часть долга | Показывает, какие вопросы и повторения снимаются и почему |

Дополнительно доступно «Предложить восстановление с ИИ». Модель ранжирует вопросы по ожидаемому приросту готовности, уровню цели, текущему статусу и особому фокусу. Она не снимает задания сама: результат является четвёртым вариантом предварительного пересчёта.

Если времени объективно недостаточно, интерфейс предлагает открыть массовое изменение уровня цели в «Вопросах экзамена». Уменьшение уровня всегда подтверждается там, где хранится каноническое свойство, после чего План обновляется через диф.

### 3.13. Повторения и очередь дня

SM-2 формирует динамические повторения независимо от первоначального календаря. План показывает будущую нагрузку повторений ближайшего месяца, но не фиксирует её как неизменяемый список.

Очередь текущего дня собирается в порядке:

1. просроченные повторения;
2. повторения на сегодня;
3. вопросы по Плану;
4. новые вопросы, если остался дневной бюджет.

Внутри очереди разделы перемешиваются настолько, чтобы не выдавать подряд однотипные задания, но первичный проход в календаре сохраняет порядок Программы. Кнопка «Начать день» открывает Сессию занятия с этой очередью.

Над календарной лентой находится действие «Нагрузка повторений на 30 дней». Оно открывает таблицу `дата`, `ожидаемые повторения`, `ожидаемые минуты`, `доступный бюджет`. Дни возможного переполнения получают текст «может не поместиться» и переход к настройкам повторений. Это прогноз нагрузки по текущим интервалам, а не обещание точного числа будущих заданий.

В режиме без дедлайна шкала фаз скрыта. Экран показывает повторения на 30 дней, мягкую дневную норму и список следующих новых вопросов в порядке Программы. Кнопка называется «Настроить свободный темп», а прогноз готовности к дате не показывается.

### 3.14. Прогноз готовности

Прогноз показывается в отдельной строке под таблицей параметров только при достаточном числе подтверждённых попыток.

| Состояние данных | Интерфейс |
| --- | --- |
| Данных недостаточно | «Прогноз появится после нескольких подтверждённых ответов» |
| Данных достаточно | Диапазон готовности на дату экзамена и число наблюдений |
| План изменён | Старый прогноз помечен как относящийся к предыдущей версии до пересчёта |

Точное одиночное число и модельная оценка без наблюдений запрещены.

| Уточнение Плана | План подготовки | Выравнивает тяжёлые дни и учитывает смысловые связи | Экзаменационная стратегия и ограничения | Диф дней |
| Восстановление после отставания | План подготовки | Предлагает приоритетную версию сокращённого маршрута | Догнать, распределить или простить по локальным правилам | Сравнение четырёх вариантов |

Отдельные кнопки для «объяснить план», «найти зависимости» и «оценить сложность» не создаются. Эти результаты входят в четыре роли таблицы, чтобы интерфейс не превратился в набор разрозненных ИИ-команд.

## 5. Правки соседних экранов после согласования

### 5.1. Рабочая область

| Сейчас | После согласования |
| --- | --- |
| «Переименовать» меняет вопрос внутри дерева Рабочей области | «Изменить в списке вопросов» открывает выбранный узел в редакторе |
| «Добавить вопрос рядом» создаёт локальный черновик | Команда открывает редактор с черновиком в нужной позиции |
| «Добавить подпункт» создаёт локальный черновик | Команда открывает редактор с выбранным родителем |
| Черновик живёт только в локальном состоянии Рабочей области | Черновик принадлежит каноническому редактору и не попадает в План до подтверждения |
| Нижняя ссылка называется «Программа» | В экзаменационном проекте называется «Вопросы экзамена» |
| План показывает «не составлен» | После прототипа ведёт на реальный маршрут и показывает «не составлен», «актуален» или «обновить» |

Рабочая область сохраняет быстрый переход, но не второй механизм редактирования.

### 5.2. Материалы

| Сейчас | После согласования |
| --- | --- |
| «Сверить с Программой» | «Сверить со списком вопросов» |
| «Открыть Программу» | «Открыть вопросы экзамена» |
| Диф импорта описывает изменения абстрактно | Диф ведёт в редактор с выбранным запуском импорта |
| Нижняя ссылка называется «Программа» | «Вопросы экзамена» для экзаменационного проекта |

Материалы по-прежнему не редактируют формулировки, порядок и вложенность.

### 5.3. Мастер создания проекта

После создания экзаменационного проекта текст сообщает, что вопросы сохранены, и предлагает «Проверить вопросы» перед началом подготовки. Если пользователь сразу открывает Рабочую область, дерево остаётся доступным; План создаётся только явным действием.

На шаге проверки мастер сохраняет быстрое исправление распознанной формулировки. Это исправление входного черновика до создания проекта, а не второй редактор существующей Программы.

### 5.4. Покрытие и будущая Карта покрытия

Кнопки «Пересобрать программу» и «Изменить уровень цели» ведут во «Вопросы экзамена». Фильтр «вне текущей программы» в экзаменационном интерфейсе подписывается «Вне подготовки». Сущность и семантика хранения не меняются.

### 5.5. Настройки

Изменение даты экзамена, дневного бюджета, целевого результата, формата работы или особого фокуса предлагает пересчитать План. Изменение целевого результата не переписывает уровни уже настроенных вопросов молча; оно предлагает массовое изменение во «Вопросах экзамена».

В реестр ролей внешних моделей добавляются «Организация вопросов», «Оценка объёма и уточнение Плана» и «Восстановление Плана». Роли можно выключить отдельно, глобальный режим без внешних моделей отключает их все.

### 5.6. Сессия занятия и бот

«Начать день» передаёт рассчитанную очередь в Сессию. После завершения попытки План обновляет выполненное и будущие повторения. Бот использует ту же очередь дня, но не редактирует список вопросов и календарную раскладку; для этого он присылает ссылку на веб.

### 5.7. Реестр и навигация

Маршруты `/program` и `/plan` сохраняются. Заголовок и подпись `/program` зависят от шаблона проекта: для экзамена это «Вопросы экзамена». В `screens.ts` остаётся нейтральное внутреннее id `program`, чтобы не плодить отдельный маршрут и сущность.
