# Jev в Tentex: где он полезен, а где нет

> Исследование 26.09.2026. Источники — в конце. Независимых замеров Jev на русском
> языке не нашлось ни в одном источнике, включая обе статьи на Хабре. Поэтому все
> предложения ниже нужно сначала проверить на 20–30 наших примерах (см. «Перед тем как
> строить»).

## Что такое Jev

Jev (TypeSafe, вышел 15.09.2026) — **не чат-модель**. Он не пишет текст. Ему дают текст
(«состояние») и заранее описанные вопросы, а он возвращает числа. Типов вопросов три:

| Тип | Что спрашиваем | Что приходит |
| --- | --- | --- |
| Noul | «Верно ли, что…?» | вероятность «да» от 0 до 1 |
| Choice | «Что из списка?» (до 255 вариантов) | выбранный вариант, вероятность каждого, уверенность |
| Score | «Какой уровень по шкале?» (2–10 уровней) | средневзвешенный уровень, вероятности, уверенность |

Все вопросы одного запроса проверяются параллельно и независимо по одному и тому же
состоянию. Ответ за 70–500 мс. Формат ответа гарантирован, парсить и валидировать
нечего.

**Цена.** Выход бесплатный, но вход — не ноль: $0,042 за миллион токенов. На практике это
почти даром: проверка одного экзаменационного ответа ≈ 3 тыс. токенов ≈ $0,0001, тысяча
проверок ≈ 13 центов.

**Вызов через OpenRouter** — не `chat/completions`, а отдельный путь в формате TypeSafe
(по документации TypeSafe; сам вызов в этом исследовании не проверялся):

```http
POST https://openrouter.ai/api/v1/systemone
Authorization: Bearer <ключ OpenRouter>

{"model": "~typesafe/jev-latest", "state": "...", "questions": {...}}
```

Ключ тот же, что уже лежит в «Параметрах». На OpenRouter есть ещё `typesafe/jev-router` —
это другое: обычный `chat/completions`, где Jev выбирает, какой LLM и с каким уровнем
рассуждения ответит. Выход там платный по цене выбранной модели.

## Ограничения, которые важны именно нам

1. **Русский.** Основной язык обучения — английский. Документация прямо пишет: другие
   языки понимаются хуже, проверяйте на своих данных и смотрите на уверенность.
2. **Облако.** Tentex офлайн по умолчанию. Значит, Jev — только необязательный слой: без
   него каждая функция работает как сейчас.
3. **Числа и даты.** Jev не считает, не сравнивает даты и не умеет в арифметику. Всё это
   остаётся в коде.
4. **Размер состояния.** До 32 тыс. токенов на состояние плюс самый длинный вопрос, до
   64 тыс. на весь запрос. Лишний текст снижает точность: сначала отбор кодом, потом Jev.
5. **Буквальное чтение.** Отвечает на написанный вопрос, а не на задуманный. Граничные
   случаи надо прописывать в `criteria`.
6. **Нет объяснений.** Только числа. Почему «не зачтено» — Jev не скажет.
7. **Уверенность не абсолютна.** В независимом тесте ответы с уверенностью 0,7–0,9
   оказывались верны лишь в 53% случаев, а на вопросах вне списка вариантов Jev бывал
   уверен на 0,99. Правило: всегда давать вариант «ничего из этого» и отправлять
   средние значения на LLM.
8. **Бета.** Лимиты (1200 запросов в минуту) плавают; алиас `jev-latest` переезжает на
   новые версии — пороги, подобранные на `jev-1.13.0`, надо привязывать к этой версии.

## Что Jev заменить не может

| Роль в Tentex | Почему нет |
| --- | --- |
| `exam_chat_reply`, учебный чат, `study_program_assistant`, `coverage_research` | Нужен текст |
| `material_text_cleanup`, `study_outline_extract` (сам текст оглавления) | Нужен текст |
| `exam_preparation_estimate`, `exam_preparation_distribution` | Числа, даты, ограничения по дням |
| `exam_preparation_phases`, `exam_preparation_coach` | Нужен текст рекомендации |
| `material_page_recognition`, речь | Jev не принимает картинки и звук |

Итого по «Моей подготовке»: целиком заменить её ИИ-роли нельзя — это ровно то, в чём Jev
слаб. Полезен он там только как поставщик одного входного числа для планировщика
(предложение 5).

## Предложения по приоритету

### 1. Проверка ответа за полсекунды и живой счётчик пунктов эталона

**Что на экране.** В форме «Сдать ответ» под полем появляется полоска «Раскрыто 4 из 9
пунктов эталона». Она обновляется через секунду после паузы в наборе. Сами пункты до
сдачи скрыты, иначе это подсказка. После «Сдать ответ» сразу — без ожидания LLM —
вердикт «Зачтено / Частично / Не зачтено», зелёным подсвечены места ответа, раскрывшие
пункты, и список упущенного. Кнопка «Подробный разбор» запускает нынешнего судью
`exam_answer_judge` с текстом объяснения. Если Jev не уверен, судья запускается сам.

**Как работает.**

1. Эталон режется на пункты один раз на ревизию эталона и кешируется по
   `reference_revision`: пункты списка и предложения кодом, либо один вызов LLM.
2. Каждая проверка — один запрос к Jev. Заполненный пример на теме из проекта «ОС»:

```json
{
  "model": "jev-1.13.0",
  "state": {
    "answer": "Тупик возникает, когда два процесса держат по ресурсу и ждут ресурс друг друга. Чтобы его не было, можно захватывать ресурсы в одном порядке. Ещё есть алгоритм банкира."
  },
  "questions": {
    "p1": {
      "type": "noul",
      "instructions": {
        "point": "Тупик — состояние, в котором каждый процесс группы ждёт события, которое может вызвать только другой процесс этой группы.",
        "question": "Излагает ли `answer` мысль из `point`, пусть другими словами?"
      },
      "criteria": {
        "true": "Мысль изложена по сути",
        "false": "Мысль не упомянута или названа без сути"
      }
    },
    "p2": {
      "type": "noul",
      "instructions": {
        "point": "Четыре условия возникновения тупика: взаимоисключение, удержание и ожидание, отсутствие перераспределения, круговое ожидание.",
        "question": "Излагает ли `answer` мысль из `point`, пусть другими словами?"
      }
    },
    "wrong": {
      "type": "noul",
      "instructions": {
        "reference": "<текст эталона>",
        "question": "Есть ли в `answer` утверждение, которое противоречит `reference`?"
      }
    },
    "where_p1": {
      "type": "choice",
      "instructions": "Какое предложение ответа излагает мысль о том, что процессы ждут друг друга?",
      "criteria": {
        "s1": "Тупик возникает, когда два процесса держат по ресурсу и ждут ресурс друг друга.",
        "s2": "Чтобы его не было, можно захватывать ресурсы в одном порядке.",
        "s3": "Ещё есть алгоритм банкира.",
        "none": "Ни одно предложение"
      }
    }
  }
}
```

   Приходит, например (цифры условные): `p1 = 0,86`, `p2 = 0,07`, `wrong = 0,12`,
   `where_p1 = s1` с уверенностью 0,9. Предложения для `where_*` режет код, поэтому
   цитата берётся из ответа дословно — генерации нет, выдумать цитату нельзя.

3. Решает код:
   - пункт раскрыт, если `noul` выше порога строгости: мягко 0,4, обычно 0,5, строго 0,65;
   - итог — по доле раскрытых пунктов и `wrong`;
   - если хоть один пункт попал в серую зону 0,35–0,65, вызывается LLM-судья;
   - результат укладывается в нынешний `JudgeVerdict` (`credited`, `missed`, `wrong`),
     поэтому интерфейс разбора не меняется.

**Цена и скорость.** Проверка ≈ $0,0001 и ~0,3 с. Живой счётчик с десятком
перепроверок за ответ ≈ $0,001.

**Чем хорошо для защиты.** Алгоритм рисуется блок-схемой: «эталон → пункты → Jev → пороги
→ итог или LLM». Это готовый кандидат в 2–3 алгоритма записки.

**Риск.** Перефразированный на русском ответ Jev может не узнать. Это первое, что надо
проверить.

### 2. Честное «в материалах этого нет» и отсев лишних источников чата

Закрывает пункт 1 «Доводки RAG» в `PLAN.md`. Сейчас чат всегда получает 20 источников,
даже когда в материалах ничего нет, а порог по cosine у E5 не разделяет «есть» и «нет».

**Что на экране.** В чате под ответом: «Использовано 6 источников из 20, остальные не по
теме». Если по теме нет ничего — плашка «В материалах проекта ответа нет», а модель
получает об этом честную пометку в промпте. В поиске — те же места, но нерелевантные
свёрнуты под «Ещё 7 мест, вероятно не по теме».

**Как работает.** На каждый найденный кусок — один запрос с двумя Noul: «Относится ли
`passage` к вопросу `query`?» и «Содержит ли `passage` ответ на `query`?». Код отсекает
по порогу. Так устроен рецепт TypeSafe «Classifying RAG passages»; там же вопрос «пытается
ли кусок командовать моделью» — защита от инъекций в материалах.

**Побочный выигрыш.** Основной LLM получает меньше токенов — чат дешевле и меньше шума.

**Цена.** 20 кусков ≈ 16 тыс. токенов ≈ $0,0007 на сообщение.

**Переранжирование.** Тот же Noul — это переранжировщик top-30. Он может закрыть и
пункт 2 «RRF топит лучший смысловой кусок». В рецепте TypeSafe на юридических текстах на
английском он поднял top-1 с 5% до 18%, а top-10 — с 38% до 62%, но относительно голого
BM25. С локальным Qwen3-Reranker (профиль «Точно») его никто не сравнивал, а тот
многоязычный и работает офлайн. Честная роль Jev здесь — вариант «Точно (облако)», и
выбирать между ними надо на контрольном наборе из пункта 5 доводки.

### 3. Проверка ссылок [S1] в ответе чата

**Что на экране.** Через ~0,3 с после конца ответа рядом со ссылкой, которую источник не
подтверждает, появляется значок ⚠ «Источник этого не говорит».

**Как работает.** Код режет ответ на предложения со ссылками `[S*]`. На каждую пару
«предложение + процитированный кусок» — Noul «Подтверждает ли `source` утверждение
`claim`?». Это упрощение рецепта TypeSafe «Double-checking citations». Та же проверка подходит для
просьбы «проверь меня» прямо в чате: сообщение пользователя сверяется с эталоном как в
предложении 1, и в ленте появляется карточка с раскрытыми пунктами.

### 4. Разметка файла ответов и импорт вопросов без LLM

- **`exam_answer_sections`.** Каждый раздел файла ответов — один Choice «к какому вопросу
  программы относится» (до 255 вариантов; для больших программ — сначала билет, потом
  вопрос). Уверенность ≥ 0,8 — разносится сама, ниже — «проверьте» в интерфейсе. Сейчас
  на это уходит вызов LLM с лимитом 6000 токенов выхода. Цена ≈ $0,01 за файл.
- **`exam_import_repair`.** На каждый разрыв строки — Noul «продолжает ли строка
  предыдущую?», на каждую строку — Choice «вопрос / подпункт / заголовок раздела /
  мусор». Это рецепт TypeSafe «Structure recovery». LLM остаётся запасным путём.
- **Нарезка индекса.** Спорные блоки получают Choice «оглавление / литература / выходные
  данные / колонтитул / текст» вдобавок к нынешним правилам.
- **Заголовки в книгах после быстрого OCR** (Мендельсон: 647 кусков без пути). На короткие
  строки страницы — Noul «это заголовок раздела?» и Choice уровня. Книга на 600 страниц
  стоит ≈ $0,04 — дешевле облачной переобработки.

### 5. «Моя подготовка»: разная сложность вопросов вместо одинаковых 30 минут

Сейчас `heuristics.json` даёт каждому вопросу одинаковые 30 минут. Jev ставит каждому
вопросу Score из пяти уровней:

1. одно определение;
2. определение и пример;
3. несколько понятий и связи между ними;
4. механизм или алгоритм с условиями;
5. большая тема с выводами и доказательствами.

На вход — текст вопроса и начало эталона; длину эталона считает код и передаёт словами
(«короткий / средний / длинный»), а не числом. Планировщик умножает минуты на
коэффициент уровня. Распределение по дням остаётся в коде — дат Jev не касается.
Программа из 80 вопросов стоит меньше цента.

### 6. Карточки и устный ответ

- **Карточка с вводом ответа.** Jev ставит Score «не вспомнил / частично / верно / верно
  и полно» и предлагает оценку повторения; пользователь может её поменять.
- **Устный ответ** (пункт «л» в backlog). Распознавание речи → текст → та же проверка,
  что в предложении 1.

### 7. Jev Router — без кода

В «Параметрах» для роли чата выбрать модель `typesafe/jev-router`: он сам подбирает LLM и
уровень рассуждения под каждый запрос. Работает через нынешний `chat/completions`.
Минусы:
- выход платный по цене выбранной модели;
- модель от запроса к запросу разная — качество и цена скачут;
- для ролей со структурным выходом не подходит, пока не проверено, что роутер выбирает
  только модели с `structured_output`.

### Не стоит сейчас

- **Замена LLM в поиске материалов в интернете.** Можно отсеивать выдачу SearXNG Jev'ом
  до второго вызова LLM, но поиск уже работает и стоит $0,004 за ход.
- **DeepEval с Jev для оценки ответов чата.** Новая зависимость и исследовательская
  работа, которой нет в плане.

## Как встроить в код

```text
роль (roles.py, модальность "decision")
  → gateway.decide(state, questions)      ← тот же учёт AiRun, бюджет, кеш, история ИИ
    → POST /api/v1/systemone (OpenRouter)
  ← числа → пороги в коде → решение или откат на LLM
```

- **Модальность.** В `app/ai/roles.py` добавляется `"decision"` к `AiModality`. По
  комментарию там это требует столбца `default_decision_model_id` в настройках
  (миграция) и записи `~typesafe/jev-latest` в каталоге моделей.
- **Транспорт без новой зависимости.** Клиент `openai` уже умеет произвольный запрос:
  `await client.post("/systemone", body=payload, cast_to=httpx.Response)` с `base_url`
  `https://openrouter.ai/api/v1`. Ключ и обработка ошибок переиспользуются.
  Альтернатива — официальный `typesafe-sdk`: даёт повторы и типы, но это новая
  зависимость, и на неё нужно согласие.
- **Кеш.** Ответы Jev стабильны, поэтому `cache_policy="content_hash"` по состоянию и
  вопросам.
- **Офлайн.** Переключатель «Быстрые решения (Jev)» в «Параметрах». Когда он выключен
  или нет сети, каждая функция идёт нынешним путём: LLM-судья, все 20 источников, правила
  нарезки.

## Перед тем как строить

Одна проверка на 20–30 наших примерах, стоимость меньше цента:

- 10 вопросов экзамена × привязанные и непривязанные блоки — различает ли Noul
  релевантность на русском (для предложений 2 и 3);
- 10 попыток ответа с уже известным вердиктом LLM-судьи — совпадает ли итог (для
  предложения 1).

Если на русском совпадение плохое, остаются только предложения 4 и 7: там варианты
закрытые и короткие, и ошибка видна пользователю сразу.
