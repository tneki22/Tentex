## Что ещё не перенесено в main

`codex/chat-repair`: два отдельных коммита сверх main (рендер Markdown,
формулы и источники; явные операции, области поиска и второй материал для
сравнения), а также незакоммиченная работа над контекстом и бюджетом.
План состоит из четырёх срезов: A/B уже имеют коммиты, окончательная приёмка
ветки и перенос ещё впереди. Для текущего main остаются проблемы, которые
этот план исправляет: форматирование ответов, подтверждение стоимости,
потеря настроек при повторе, запись вопроса до успешного preflight,
дублирование контекста и неоднозначные S-ID в истории.

Другие проверенные рабочие ветки либо уже являются предками main, либо
их правка присутствует в main отдельным коммитом. В частности,
`git cherry main codex/textbook-step1-controls` помечает коммит знаком `-`:
отсутствие merge-коммита здесь не означает отсутствие функции.
В `coverage-pilot` есть незакоммиченные исследовательские документы;
это не готовая продуктовая функция для переноса.

## Что требует улучшения

### Поиск и ответы по материалам

В PLAN зафиксирован замер на реальном корпусе:

- Поиск возвращает места даже для запроса, ответа на который в материалах нет.
  Нужен измеренный сигнал релевантности и честное состояние отсутствия ответа.
- RRF может вытеснять хороший смысловой результат шумной лексической выдачей.
  Выбор веса/отбора/rerank делать на контрольном наборе.
- Одинаковый материал в разных форматах даёт дубли. Chat-repair меняет сборку
  контекста, но схлопывание самой поисковой выдачи надо проверить отдельно.
- «Определение», «Теорема» и отдельные номера иногда становятся путями разделов.
- Нужен набор 100–200 русскоязычных запросов с релевантными местами. Ручные
  привязки экзаменационных вопросов могут стать исходной разметкой.
- Скрипты предыдущего замера лежали в scratchpad; для повторяемости их следует
  перенести в `backend/scripts/`.

Данные текущей установки требуют отдельного внимания: зафиксированный в PLAN
кандидатный индекс был неполным и неактивным. Это не отсутствие функции и не
предположение о сегодняшнем содержимом БД: перед живым прогоном надо проверить
актуальный индекс и его состав. Старые OCR-материалы и предметные метаданные
могут требовать переобработки/ручной нормализации.

### Фоновые задачи и интерфейс

По STATUS не все виды завершённых/ошибочных задач доступны в общем архиве,
переходы к результату покрывают не все kind. Для руководства важно проверить
«ушёл со страницы → нашёл результат → открыл → принял/отклонил» для основных
видов задач. Три представления проектов и дашборды остаются пожеланием TODO;
сначала исправлять непонятные состояния и навигацию, декоративную отделку
можно отложить.

## Рекомендуемый порядок

1. Завершить и проверить chat-repair, затем перенести согласованную ветку в main.
2. Довести поиск: отсутствие релевантных материалов, контрольные запросы,
   дубли и реальное качество top-k; проверить состав индекса.
3. Проверить копию и восстановление на отдельной установке, перенос полноценного
   проекта в профилях «Для себя» и «Поделиться».
4. Провести живой прогон программы/уроков на 2–3 учебниках и отдельный длительный
   экзаменационный прогон; закрыть найденные препятствия.
5. Если цель — законченный учебниковый режим к приёмке, реализовать ИИ-уроки,
   задания и «Занятия». Это крупные вертикали, не мелкая полировка.
6. Зафиксировать границу версии, актуализировать документы и начать чистый прогон
   одновременно с первой редакцией руководства. Поздние расширения отложить.

## Прогон с чистого листа и руководство

Использовать отдельный каталог данных и отдельный контур запуска, а также чистый
профиль браузера. Рабочую data не очищать: иначе проверяется сброс настоящих
данных, а не опыт нового пользователя. Это предложение для следующего этапа;
изолированная установка пока не создавалась.

Порядок сценариев:

1. Первый запуск: пустые Проекты/Библиотека, «Состояние», понятность Параметров.
2. Экзамен без внешних моделей: импорт вопросов с подпунктами, ответы, материалы,
   привязки, конспект, карточки, календарь, «Начать день», учёт и история.
3. Учебник: загрузка, установка локального OCR при необходимости, проверка текста
   и оглавления, программа, быстрый и ручной урок, исправление, прохождение.
4. Свободное изучение: сначала без материалов, затем подбор и подключение источника,
   поиск по теме и урок из найденного.
5. Опциональный ИИ: настройка провайдера/ролей, выключение моделей, стоимость,
   источники чата и сетевой поиск. Проверять платные ходы в согласованных пределах.
6. Фон: уход со страницы, перезапуск, продолжение, отмена и поиск результата.
7. Копия, экспорт/импорт, восстановление только внутри тестовой установки.

Каждый непонятный момент фиксировать как «шаг → ожидание → фактический результат →
исправить интерфейс / добавить объяснение». Руководство строить по этим задачам
пользователя, а не по перечню экранов. Для каждой главы нужны предусловия,
действия, ожидаемый результат и восстановление после типичной ошибки.
