# AGENTS.md

Инструкции для агентов, работающих над Tentex. Этот файл — единственный источник правды; `CLAUDE.md` его импортирует.

## Что это

Tentex — локальный тренажёр подготовки к экзамену. Курсовая по ТРПС, МГТУ им. Баумана, защита в декабре 2026. Один пользователь, одна установка, всё работает офлайн; внешние модели опциональны и всегда выключаемы.

Отличие от аналогов в одной фразе: остальные идут от документа к карточкам, Tentex идёт от цели обучения к программе и к **измеримому покрытию в обе стороны** — показывает и чего у тебя нет, и что ты собирался пропустить.

Подробности лежат в трёх файлах, и переписывать их в код не надо:

| Файл | Что внутри | Когда открывать |
| --- | --- | --- |
| `BRIEF.md` | Рассказ о продукте, зачем всё это | Не понимаешь смысл функции |
| `REQUIREMENTS.md` | Требования: FR-*, NFR-*, §20 модель данных, §21 экраны, §23 стек | Вопрос «как система должна себя вести» |
| `PLAN.md` | Порядок работ по этапам и что уходит в записку | Вопрос «что делаем сейчас и что после» |

Перед тем как что-то придумывать — проверь, нет ли ответа в `REQUIREMENTS.md`. Обычно есть.

## Где сейчас находимся

**Этап 0 завершён:** монорепо поднято, UI-кит перенесён из virtex, четырнадцать экранов существуют заглушками, темы работают.

**Дальше — этап 1:** проектирование экранов. Правило этапа: *описал экран → тут же сверстал его на выдуманных данных → пошёл к следующему*. Формат описания — в скилле `tentex-screens`.

## Структура

```
backend/          FastAPI. app/main.py — приложение, app/config.py — настройки
frontend/         Vite + React + TypeScript
  src/app/        screens.ts (реестр всех экранов), AppLayout, ThemeToggle
  src/screens/    По файлу на экран. Пока все через ScreenStub
  src/components/ ui/ — кит из virtex; рядом — компоненты покрупнее
  src/hooks/      usePanelLayout, useVoiceInput, useTheme
  src/styles/     tokens · base · ui-kit · layout
  tests/          Vitest
.claude/skills/   Скиллы проекта
data/             SQLite и файловое хранилище. В git не едет
virtex/           Прошлый проект, только для чтения. В git не едет
```

**`frontend/src/app/screens.ts` — единственный список экранов.** Навигация, роутинг и заглушки строятся из него. Добавляешь экран — добавляешь строку туда.

## Команды

Из корня:

```bash
npm run dev
```

Поднимает FastAPI на 8000 и Vite на 5173. Либо `docker compose up` — то же самое в контейнерах.

```bash
npm test
npm run typecheck
npm run build
npm run lint
```

Только фронт: `cd frontend && npm run dev | test | typecheck | build`.
Только бэк: `cd backend && python -m pytest -q` и `python -m ruff check .`.

## Стек

React + TypeScript + Vite · Python + FastAPI · SQLite с WAL везде, включая учебные базы · `sqlite-vec` для векторов · FTS5 для BM25 · PyMuPDF · Tesseract · pymorphy3 · SymPy · SM-2 · aiogram · pytest + Vitest + Playwright.

Обоснование каждого выбора — §23 требований. Не меняй решение из этой таблицы, не сказав об этом: почти каждое защищается у доски.

Тяжёлые вещи приезжают на своих этапах, а не сейчас: OCR — этап 5, эмбеддинги — этап 6, шлюз моделей — этап 7.

Python: целевая версия **3.13** (так в контейнере). Локально стоит 3.14 — для этапов 0–4 разницы нет, но к этапу 6 понадобится PyTorch под CUDA 12.8, а он отстаёт от свежих версий Python.

Серверная часть virtex не переносится вообще — там Node/TS, у нас Python. Из virtex взят только клиентский UI-кит.

## Правила работы

**Готовое вместо своего.** Прежде чем писать механизм — проверь, есть ли библиотека или опубликованный алгоритм. Обоснование выбора ищется в литературе, а не в собственных замерах. При равном результате выбирается вариант, который рисуется блок-схемой: её потом надо защищать.

**Не разрастаться.** Проект пишется одним человеком за 10–15 часов в неделю. Всё, что нельзя объяснить за две минуты, — обуза. Не предлагай исследований и замеров, если о них не просили.

**Этап заканчивается тем, что можно показать.** Если у куска работы нет демонстрируемого результата — он нарезан неправильно.

**Открытый вопрос закрывается там, где он впервые мешает, и не раньше.** Пять открытых вопросов §27 уже расписаны по этапам в `PLAN.md`.

**Схема рисуется тогда, когда делается подсистема.** Час сейчас против дня в декабре — и та, что восстановлена по коду, содержит враньё. Что куда уходит — таблица в конце `PLAN.md`.

**Разведка не превращается в продакшн.** Скрипт разведки главной идеи выбрасывается, а не дорастает до этапа 8.

## Как писать

**Код.** Русские тексты интерфейса, английские идентификаторы. Комментарий объясняет почему, а не что. Цвет — только через токен из `tokens.css`. Компонент — сначала посмотри в кит (скилл `tentex-ui-kit`).

**Ответы и документы.** Конкретно, без промежуточных абстракций. Предлагаешь формат — сразу давай один заполненный пример, а не описание формата. Пункт плана должен выполняться без вопроса «а что это значит». Абстракция допустима только после конкретного случая.

**Тесты** пишутся там, где поведение легко ломается: разбиение на блоки (этап 5), интервалы SM-2 и нормализация ответов (этап 9), сравнение результатов SQL (этап 10). Сплошное покрытие не нужно. TDD в проекте выключен сознательно.

## Словарь

Термины из §20 требований. Пользуйся ими, не изобретай синонимов.

| Термин | Что это |
| --- | --- |
| **Узел программы** | Строка программы: раздел, тема или подпункт. Дерево до 4 уровней |
| **Тема** | Узел программы, по которому занимаются. Центральное понятие продукта |
| **Материал** | Загруженный файл: PDF, DOCX, TXT, MD, изображение |
| **Страница** | Страница материала с текстом и флагом качества: `native` · `ocr` · `ocr_low` |
| **Фрагмент** | Кусок текста страницы с координатами. Единица привязки и поиска |
| **Блок** | Смысловой кусок материала по заголовку. Бывает содержательный и служебный |
| **Привязка** | Связь темы и фрагмента. Статус: машинная · подтверждена · снята · ручная |
| **Проход 1** | Материал → программа. Map-reduce по главам |
| **Проход 2** | Полный перебор блоков: к какой теме относится каждый. Главный алгоритм проекта (А2) |
| **Покрытие в обе стороны** | Две метрики: сколько программы обеспечено материалом и сколько материала разнесено по программе |
| **Пробелы** | Темы без материала |
| **Неразобранное** | Блоки материала, не попавшие ни в одну тему |
| **Эталонный ответ** | Образцовый ответ по теме, с которым сравнивается твой |
| **Сила свидетельства** | Насколько активность подтверждает знание темы. Влияет на статус и на вес в повторениях |
