# Фронтенд Tentex

Парный скилл к `tentex-api`. Он про то, как здесь уже принято, а не про React вообще.

Источники, которые этот файл не пересказывает: **`DESIGN.md`** — дизайн-система целиком, почему Radix, полная таблица токенов. **`SCREENS.md`** — что на каждом экране. **`/ui-kit`** в приложении — живая витрина.

## Где что лежит

| Что | Где |
| --- | --- |
| Примитивы без знания предметной области | `src/components/ui` + `styles/ui-kit.css` |
| Доменные виджеты Tentex | `src/components/domain` + `styles/domain.css` |
| Экраны | `src/screens/<Экран>.tsx`, крупные — каталогом |
| Клиент API | `src/api/*.ts` — типы и функции, `request<T>()` в `projects.ts` |
| Состояние экрана поверх API | `src/hooks/use*.ts` |
| Значения | `styles/tokens.css` — единственное место |

**Список компонентов смотри в `components/ui/index.ts` и `components/domain/index.ts`, а не в этом файле.** Перечислять их здесь — заводить второй список, который разъедется с первым.

Куда класть новое: знает слово из словаря проекта (тема, привязка, качество страницы, стоимость) — доменный виджет; не знает — примитив; нужен одному экрану — лежит рядом с экраном и переезжает в систему, когда понадобился второму. Новый примитив или виджет добавляется в `index.ts` **и в витрину** `screens/UiKit.tsx`: не показан — значит им не воспользуются.

## Экран не перестраивается по дороге

Визуальная структура, порядок блоков и взаимодействия закреплены тегом `ui-stage-1-baseline`. Читается так:

```bash
git show ui-stage-1-baseline:frontend/src/screens/Projects.tsx
```

Правило из AGENTS.md: **отсутствующий API — не причина менять компоновку.** Элемент остаётся на прежнем месте честной заглушкой. Новый каркас — только после явного согласия пользователя и записи причины в `docs/ui/stage-1-interface-baseline.md`; там же таблица «экран → исходник baseline → семейства CSS-классов».

Это не бюрократия: шесть коммитов `fix: restore ... interface` подряд и отдельный аудит восстановления в логе — цена нарушения.

## Реестр экранов — два файла

`app/screens.ts` — полный список из `REQUIREMENTS.md`, включая ещё не сделанные. `app/views.ts` — что уже сверстано; роутинг и навигация строятся отсюда, поэтому ссылок в никуда не бывает. Сверстал экран — добавил строку в `views.ts`.

## Раздел экрана в SCREENS.md

Заголовок `## Название — /путь`, дальше проза «что на экране», потом четыре помеченных абзаца: **Действия** (что происходит по каждому нажатию) · **Состояния** (пусто · грузится · ошибка · внешние модели выключены) · **Данные** (поля, а не «нужны данные о покрытии») · **Переходы**.

Реализация отстала от описания — сверху раздела блок-цитата `> **Состояние <вертикали> (дата).**` с тем, что живо на сегодня, и ссылкой на контракт в `docs/architecture/`. Целевое описание при этом не переписывается: видно и что есть, и куда идём.

## Данные экрана

Экран берёт данные из `src/api/*.ts`, обычно через хук в `src/hooks`. Как принято:

- Тип ответа описан в `api/*.ts` и совпадает с Pydantic-схемой бэкенда. Не пересобирай форму ответа на экране.
- Хук держит `loading` · `error` · данные и отдаёт `refresh`. Запрос принимает `AbortSignal`; после `signal.aborted` состояние не трогается.
- Три состояния рисуются китом: `LoadingState` · `ErrorState` · `EmptyState`. Пустота — не ошибка.
- Ошибка с бэкенда приходит как `{detail, code}`. Показывай `detail` (он по-русски), ветвись по `code`.
- Экран без серверного контура живёт на демо-данных в файле рядом: `workspaceDemo.ts`, `mockCards.ts`, `lessonsDemo.ts`. Это честная заглушка, а не временный костыль — она ждёт свой этап.

## Цвет

Палитра статусов: `--accent` — действие и текущий выбор · `--tone-success` — подтверждено · `--tone-warning` — «верь осторожно» (`ocr_low`, источника нет, провайдер молчит) · `--tone-danger` — необратимое и упавшее · `--tone-info` — привязано · `--project-color-1…8` — знак проекта.

**Цвета не жалей.** Схемы, диаграммы, подсветка синтаксиса, разные сущности разными цветами прямо в тексте, цветные маркеры терминов — это показательно и читается лучше монохрома. Требование одно: значение берётся из токена и проверено в обеих темах. Хардкод `#2d4edb` мимо `tokens.css` — вот это ошибка, а не насыщенность.

## Стили

Обычный CSS, никакого Tailwind и CSS-in-JS. Файлы в `src/styles`, **порядок импорта в `main.tsx` значим**: `tokens` → `base` → `ui-kit` → `domain` → экранные (`lessons`, `cards`, `chat`) → `layout`. Новый экранный файл вставляется перед `layout.css`.

- Значение — только через токен: `var(--accent)`, а не `#2d4edb`; `var(--space-4)`, а не `16px`. Полупрозрачное — `color-mix(...)` или готовые `--accent-wash*`.
- Темы — один набор через `light-dark()` в `tokens.css`. Отдельного блока тёмной темы нет и заводить не надо. Тень в `light-dark()` завернуть нельзя, по теме едет только её цвет.
- `transition` — по конкретным свойствам, не `all`.
- Иконки — `lucide-react`, 15–16px. Шапка экрана — `PageHead`, не свой `<header>`.

## Чего нет сознательно

`Toast` — фоновые задачи показывает виджет «Фон». `Drawer` и полноценный мобильный режим — продукт настольный, брейкпоинт 900px только держит вёрстку. Голосовой ввод — этап 10, лежит в `virtex/` (только чтение), при переносе перекрашивается под наши токены.

## Своё к общему циклу проверки

Общий порядок (сборка → `docker compose restart web` → коммит) — в `CLAUDE.md`. Фронтенду сверх него:

- Посмотреть глазами: `preview_start` с конфигурацией `web`, дальше браузерные инструменты. Для видимых правок — скриншот.
- Менял поведение или состав экрана — обнови его раздел в `SCREENS.md`.
