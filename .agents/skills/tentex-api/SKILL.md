# API Tentex

Бэкенд живёт в `backend/app`, это FastAPI. Один пользователь, одна установка, всё офлайн. Контракт — по-русски, ошибки — с кодами. Прежде чем менять API, прочти этот файл: он про то, как здесь уже принято, а не про FastAPI вообще.

Полные контракты этапов — в `docs/architecture/*.md`. Модель данных — `backend/app/models.py` и `REQUIREMENTS.md` §20.

## Слои — не смешивать

| Слой | Где | Отвечает за |
| --- | --- | --- |
| Роутер | `<домен>/router.py` | Только HTTP: пути, коды статусов, разбор тела. Тонкий. |
| Схемы | `<домен>/schemas.py` | Pydantic-модели запроса/ответа (`response_model`). |
| Сервис | `<домен>/service.py`, `answers.py`, `program.py`, … | Вся бизнес-логика и работа с БД. |

Домены: `projects`, `materials`, `bindings`, `ai` (шлюз моделей), `exam` (чат, попытки, оценки). Роутер не лазит в БД напрямую и не собирает логику — зовёт функцию сервиса. Сервис не знает про `Request`/`Response`.

Сессия приходит через зависимость: `session: Annotated[Session, Depends(get_session)]`. Не создавай `SessionLocal()` в обработчике запроса — это для воркера и скриптов. Единственное исключение — генератор `StreamingResponse`: зависимость закрывается до отправки тела, поэтому поток открывает свою сессию (пример и обоснование — `exam/router.py`).

## Ошибки — только доменные

Не бросай `HTTPException`. Бросай подкласс `ProjectDomainError` из `app/projects/errors.py`:

- `ProjectNotFoundError` → 404 `not_found`
- `ProjectConflictError` → 409 (по умолчанию `invalid_status_transition`)
- `ProjectInvariantError` → 422 `program_invariant`
- или свой `ProjectDomainError(detail, status=..., code=..., context=...)` с человекочитаемым русским `detail` и стабильным машинным `code`.

Единый handler в `main.py` превращает их в JSON `{detail, code, context}`. `code` — контракт с фронтендом, не переименовывай существующие. Необработанные исключения ловит глобальный обработчик (см. ниже) и отдаёт `code: "internal_error"` — наружу текст исключения не утекает.

## Логирование

Настройка — одна на процесс: `app/logging_config.py:configure_logging()`, зовётся из `create_app()` и `worker.main()`. Логгеры бери по имени области: `logging.getLogger("tentex.http" | "tentex.worker" | ...)`. Уровень — `TENTEX_LOG_LEVEL` (дефолт `INFO`).

- Не пиши `print()` в `app/` (print допустим только в `scripts/`).
- Проглотил исключение — залогируй его: `log.exception(...)` с `exc_info`, а не молча в поле БД.
- Долгую фоновую работу логируй с таймингом и `material_id`/`task_id`.
- Не логируй тела файлов, содержимое материалов и персональные тексты — только идентификаторы и метрики.

## SQLite и сессии

- Движок — `NullPool` намеренно: для SQLite соединение дешёвое, а `QueuePool` исчерпывался пачкой параллельных GET с экрана. Не возвращай пул.
- WAL, `busy_timeout=5000`, `foreign_keys=ON`, `mmap_size=0` ставятся в `db.py` на каждом коннекте. `mmap_size=0` — из-за bind-mount с Windows-хоста; не трогай.
- Пиши через `with session.begin():` — явная транзакция на единицу работы. Не размазывай запись по нескольким транзакциям без причины.
- Схему меняешь только миграцией Alembic в `backend/migrations/versions/` (`upgrade_database()` гонит `head` при старте). Правка `models.py` без миграции — ошибка.

## Файлы и хранилище

- Загрузка больших файлов — потоком с обрубанием на лету (`storage.store_upload` / `store_answer_upload`), а не `await file.read()` целиком в память. Лимит проверяется посреди потока.
- Дедуп по sha256, путь — `materials/<хеш[:2]>/<хеш><суффикс>`. Проверяй расширение по белому списку.
- Любой путь из БД перед отдачей прогоняй через `material_path()` — он держит guard от выхода за корень хранилища. `FileResponse` строй только на его результате.
- `data/` в git не едет; база и хранилище там же.

## Воркер разбора

`materials/worker.py` — отдельный процесс (`npm run dev:worker`). Аренда задач с lease/heartbeat, чекпоинты по страницам (возобновляется после сбоя), `_finish` идемпотентен. Правила:
- Не превращай poll-цикл в вечную транзакцию: чекпоинт страницы — своя короткая транзакция.
- Осечка вторичного шага (автопривязка ответов) не должна ронять уже сделанный разбор — лови и логируй, но не откатывай разбор.
- Падение задачи → `state=FAILED` + `material.error` + `log.exception`, а не тихо.

## Внешний мир опционален и защищён

Загрузка по URL/YouTube (`materials/external.py`) валидирует публичный URL, режет приватные IP (анти-SSRF), лимитирует размер и content-type. Любой новый исходящий запрос — по этому же образцу. Внешние модели всегда выключаемы; офлайн — режим по умолчанию.

## Перед тем как сказать «готово»

1. `cd backend && python -m ruff check .` — чисто (правила `E,F,I,UP,B,SIM`, line-length 100, py313).
2. Затронул домен — прогони профильную проверку из `backend/scripts/`: `check_stage2.py` · `check_stage3.py` · `check_stage4.py` · `check_stage5.py` · `check_manual_binding.py` · `check_ai_gateway.py` · `check_exam_chat.py` · `check_library_workspace.py`.
3. Есть тест на поведение — `python -m pytest` в `backend/`. Новую логику покрывай тестом в `backend/tests/`.
4. Меняешь контракт (путь, тело, код ответа, `code` ошибки) — обнови соответствующий `docs/architecture/*.md`.
5. Новая настройка — только через `Settings` в `config.py` (префикс `TENTEX_`), не `os.environ` напрямую.
