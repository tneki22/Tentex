# Тесты

Открывается из `tentex-code-quality`, когда пишешь или правишь тесты.

На защите два вопроса: «как тестировался продукт» и «какие методы оценочного тестирования применяли и почему». Тесты — часть защищаемой работы, а не служебный файл.

Сплошное покрытие не нужно. Тесты пишутся там, где поведение легко ломается: разбиение на блоки (этап 5), календарное распределение, открытия по учебным дням, долг, undo и нормализация ответов (этап 9), сравнение результатов SQL (этап 10). TDD в проекте выключен сознательно — проверка после реализации.

## Как писать

- Проверяй наблюдаемое поведение, не реализацию. Рефакторинг без смены поведения не должен ломать тест.
- Обязательные краевые случаи: пустой ввод, отсутствующий файл, дубликаты, повторный запуск (идемпотентность), гонка при одновременном изменении.
- Однотипные случаи — `pytest.mark.parametrize`, не десять похожих функций.
- Повторяющаяся подготовка — в фикстуры.
- Имя теста — предложение с проверяемым правилом.
- Удаляя функционал, назови число тестов до и после. Иначе потеря тестов пройдёт незаметно.

## Где они

`backend/tests/` — pytest, гоняется `cd backend && python -m pytest` и включён в CI. Общего frontend test script нет; два точечных файла на встроенном `node:test` — `frontend/src/screens/workspace/referenceAnswerMedia.test.ts` и `sourcePlaces.test.ts` — запускаются вручную и не входят ни в `npm run build`, ни в CI. Frontend автоматически проверяется TypeScript typecheck и Vite build; ESLint и метрика покрытия не настроены.
