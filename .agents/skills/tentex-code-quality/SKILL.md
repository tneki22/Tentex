# Качество кода Tentex

Код защищается на курсовой, и качество оценивается в баллах отдельно от функционала. Правила ниже — прямое следствие критериев оценки. Слои, доменные ошибки и сессии — в `tentex-api`, здесь про ремесло.

Отдельно, когда понадобится: **`references/docstrings.md`** — формат, полный пример и замер покрытия · **`references/tests.md`** — что и как тестируем · **`references/new-checks.md`** — как включить новое строгое правило, не покрасив CI.

## Докстринги

Обязательны у модуля, класса, публичной функции и у приватной длиннее 20 строк. Python — докстринг, TypeScript — TSDoc. Документация должна собираться генератором: методичка требует «комментарии в формате doxygen, javadoc, rdoc».

Пиши про **почему** и про инварианты — пересказ имени функции мусор. Обработчику HTTP хватает одной строки. Полный пример и как мерить покрытие — `references/docstrings.md`.

## Границы размера

| Что | Предел |
| --- | --- |
| Цикломатическая сложность | 12 |
| Вложенность | 3 уровня |
| Вызовов хуков в React-компоненте | 15 |

`match` или `if/elif` больше чем на 5 ветвей, где каждая длиннее трёх строк, — это не функция, а диспетчер. Вынеси ветви, оставь таблицу соответствия.

## Исключения не глотать

```python
# запрещено
except Exception:
    pass          # или молчаливый откат на резервный путь

# правильно
except LayoutParseError as exc:
    logger.warning("Разбор через layout не удался, откат на текстовый слой: %s", exc)
    diagnostics.append("layout_fallback")
```

Три требования: конкретный тип, логирование причины, признак в диагностике при откате. Молча проглоченное исключение — единственный класс ошибок, который невозможно найти по логам, когда что-то не заработает на демонстрации.

## Независимость модулей

Ядро домена зависит от **интерфейса** внешней системы, не от реализации. Если `projects` импортирует `ai.gateway.ModelGateway` напрямую — это нарушение, ставь порт. Обратных импортов между пакетами нет; проверяется `import-linter`, а не глазами.

Перед тем как что-то удалить — найди обратные ссылки. Связи здесь держатся вручную, `relationship()` в модели нет, компилятор про них не знает. Один и тот же смысл бывает вшит в перечисление на бэкенде, тумблер в настройках, пункт меню и вкладку рабочей области одновременно.

## Одно правило — одно место

Перед новой функцией поищи, нет ли её уже. Места, где дубли появляются незаметно: проверки инвариантов («узел принадлежит проекту», «проект доступен для записи») · обходы дерева программы и поиск узла · нормализация и сравнение заголовков · сериализация сущности в ответ API · границы транзакции · расчёты, которые есть и на сервере, и на клиенте.

Скопировал вместо выноса — через неделю копии разойдутся, и это будет баг, который придётся ловить дважды.

## Значения не в логике

Любой порог, таймаут, лимит — именованная константа с комментарием, откуда взялось число. Зависит от окружения — в конфигурацию. `timeout=15` прямо в вызове недопустимо: на защите спросят «почему пятнадцать».

## Типы честные

`any`, `as any`, `@ts-ignore` запрещены — сейчас их в проекте ноль, не начинай. В Python `Any` только для действительно разнородных данных и с комментарием, почему. Типы ответов API не писать руками, генерировать из OpenAPI.

## Термины и язык

Одна сущность — одно имя везде: модель, схема, тип на клиенте, интерфейс, записка. Не «тема» в одном месте и «вопрос» в другом. Комментарии и докстринги — по-русски. Терминологическая путаница на защите читается как непонимание предметной области.

## Мёртвый код

Удаляешь функцию — удаляй целиком: код, стили, типы, маршруты, тесты, записи в реестрах модулей, значения перечислений. Половина удаления хуже, чем ничего: остаётся тумблер, который ничего не включает.

Закомментированный код не коммитить. Демо-данные и сеятели не включены по умолчанию. Артефакты прогонов — в `.gitignore`.

## Чеклист правки

- [ ] Докстринги у всего публичного, что добавил или тронул
- [ ] Ни одного `except Exception` без логирования
- [ ] Ни одного нового `any`
- [ ] Долговые списки в конфигах не выросли
- [ ] Удаление доведено до конца: ни одного осиротевшего тумблера, пункта меню или значения перечисления
